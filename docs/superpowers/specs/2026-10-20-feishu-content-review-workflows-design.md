# 飞书内容审核与问答工作流规格说明

**状态：** 实施中  
**依据：** 飞书《内容审查 Agent PRD-第一阶段》v1.4 正文（2026-10-20 只读获取）；仓库内对应副本目前是旧版且基线自证报漂移。  
**目标用户：** 在飞书群 @守衡的内容提交人，以及向守衡询问审核规则、能力和已完成审核结论的团队成员。

## 1. 目标与范围

打通一条可验证的飞书对话闭环：收到被 @ 的消息，识别是一般问答还是内容送审；对文字、图片、链接按各自方式取材；送审素材必须进入审核链；将审核结论、依据和读取边界回到原会话。一般问答应直接回答，不应因出现“审核”等词就误送审。

本阶段仅覆盖最终发布内容中的文字、图片与链接。图片读取采用 OCR 与视觉识别；链接素材由 Agent 的受限读取器读取公开 HTTP(S) 页面正文，再把读取正文交给既有审核链，Agent 不根据 URL 猜测页面内容。消息带正文和 URL 时，正文原文与 URL 都保留；只有链接素材路径会将页面正文补入审核链。

不在本阶段实现：视频、brief 文件解析、Word/PDF、NAS/多维表批量扫描、人工审批或自动派单、sign-off、复核结果回流、知识库维护闭环。PRD v1.4 包含这些更宽的目标；本阶段不宣称完整满足整份 PRD。

## 2. 已知实现与需守住的职责边界

- `tools/ws_daemon.mjs` 接收飞书长连接事件、调用 Agent、发送回复。
- `tools/agent/agent.mjs` 读取消息上下文与素材，控制工具调用和回复。
- `tools/agent/review_gate.mjs` 是送审触发和审核链输入的代码判据；`mechanismQuestion()` 拦截有关审核机制的纯文字问句，`isSubmission()` 决定内容是否送审，`chainInput()` 组装实际审核输入。
- `agent-skills/内容合规审查/SKILL.md` 是人工/Agent 可读的判定规程，不会在运行时自动装载；它必须与代码判据及当前 PRD 对齐。
- `agent-skills/守衡语域/SKILL.md` 约束回答表达与卡片呈现；保持它负责“如何回”，不要让它成为第二套审核路由器。

新增或更新的飞书审核工作流 skill 是操作说明和开发契约。自动化是否真正生效，仍由代码接线与行为测试证明，不能用“skill 已写”代替运行证据。

## 3. 交互与处理契约

### 3.1 消息入口

1. 群聊仅响应明确 @守衡 的消息；沿用当前身份、会话隔离、去重和单实例约束。
2. 消息以 Feishu `message_id` 和 `chat_id` 关联处理与回复。事件重复投递不得重复启动审核或重复回话。
3. 对需要读取图片的送审，先回复简短收到提示，再读图和启动审核链。收到提示不构成审核结论。
4. 答复关联原会话；最终回复最多一条。不得向不同群或私聊转发素材/结论。

### 3.2 问答与送审分流

路由保留三类结果：

| 结果 | 判据与行为 |
|---|---|
| 一般问答 | 询问 Agent 能力、规则、依据、审核流程或已有结论；不把问题本身当作待审素材。按问答路径回答。 |
| 内容送审 | 用户明确要求审查；或按项目既有约定，直接发送的图片/链接素材本身就是送审输入；走 `kb_review_chain` 完整审核链。纯文字遵循现有明确意图/阈值判据。 |
| 不确定/无法处理 | 无法识别内容、素材无法读取、链未运行或结果缺失；明确说明阻塞点，不得用 PASS 或“没问题”代替。 |

问审核规则的问题，即使包含“审查/合规/依据”等词，也不能触发内容送审。显式送审动作仍需进入审核链。图片/链接的既有强制送审策略不在本轮放宽；读取失败必须在链输入或最终答复中保留失败状态。

### 3.3 文字工作流

1. 还原 @提及并移除 Agent 自身 mention，保留用户原文和同一事件中的其他正文。
2. 机制问答走一般问答；明确送审或命中既有纯文字送审判据时，原文逐字送入审核链。
3. 正文内的 URL 作为原文一部分保留；不得把长文误分类为“链接素材”，也不得在报告对象中把正文里的普通 URL 猜成待审链接。
4. 最终输出按 PRD v1.4 结果规则：PASS、仅 P3 时的非阻断 SUGGEST、REVIEW、BLOCK；具体字数和字段约束从当前权威注册表读取。

### 3.4 图片工作流

1. 支持消息正文、富文本 post 和被明确引用消息中可解析的图片；遵循已有单消息图片数量上限。
2. 通过飞书资源键与来源消息 ID 读取正确的图片字节；执行 OCR 和视觉场景识别。记录每张图的成功、部分成功或失败，不把 OCR 空结果解释成视觉安全。
3. 审核输入包含原始用户问题、图片读数和未读到的部分。不得只送模型转述或 OCR 字符串来冒充完整视觉审核。
4. 取图、OCR 或视觉识别失败时，用户可见结果必须明确“未完整读取/无法判断”；不得给出安全通过结论。

### 3.5 链接工作流

1. 提取独立 URL；链接单独发送或以短说明附带时，按素材送审。
2. 若消息含较长正文与 URL，原文和链接必须分别保留并一起传入审核链；URL 不可覆盖正文。
3. 链接素材路径使用 `tools/agent/link_reader.mjs` 读取公开 HTTP(S) 页面：仅公网 DNS/IP、固定到已校验 IPv4 公网地址、最多 3 次重定向、8 秒超时、1 MB 响应体上限，只接受 HTML/纯文本；IPv6/非标准端口暂不支持；不携带 cookies/凭据、不执行 JavaScript、不下载附件。
4. 登录限制、非公网目标、超时、拒绝访问、超限或正文抽取为空时，内核直接回复“无法形成审核结论”，跳过审核链和审核写入；不得根据 URL 文本推断页面内容或给 PASS。正文与 URL 同发时保持文字工作流，不自动抓取 URL。

> **2026-10-22 修订（事故驱动，Owner 转发守衡在群里的回复）**：上一版把“链接素材”等同于“公开网页”，
> 于是**任何飞书链接都读不了** —— 飞书页面一律 302 到 `accounts.feishu.cn`（登录页），
> 公开读取器报“域名解析到非公网地址”，原因指偏了（实测 `/docx/`、`/base/`、`/file/` 三种全红）。
> 现在链接按域名分流（唯一分流点 `tools/agent/feishu_link.mjs` 的 `readLink()`）：
> 飞书域名走只读正文接口（`docx/v1/.../raw_content`、工作表值、多维表格记录、`wiki/v2/spaces/get_node`）；
> 云空间附件 `/file/`（pptx/pdf/xlsx…）在飞书 OpenAPI 里没有原文读取接口，按 §2.6 红线**不下载、不探测**，
> 回复改为“这是附件、按红线不取”＋替代路径。幻灯片、思维笔记、旧版 `/docs/` 同样说清“飞书没有该形态的读取接口”。
> 失败话术按形态分开（红线 / 没接口 / 权限或不存在），三种不许揉成一句。

### 3.6 审核链与结果

送审走唯一既有链路：L4 发号 → L5 P0 → L6 召回 → L7 跨层闸门 → 评审链 → 按配置写入飞书。Agent 回复使用链的实际结果，不依赖模型是否自行记得调用工具。

最终状态与 PRD v1.4 一致：

- PASS：未发现已知底线风险；不得描述成绝对安全/合规。
- SUGGEST：仅为非阻断建议；若只有 P3，流转 decision 为 PASS 并附建议。
- REVIEW：需要人工判断，展示问题、原因、依据与相应边界。
- BLOCK：必须修改；不得把 BLOCK 自动转给审核人。
- `chain_not_run`、工具失败、未读素材和空结果与上述审核结论区分呈现。

报告与卡片字段遵循 PRD、现有卡片契约和权威限制表。模型不直接构造飞书卡片 JSON。

## 4. skill 工作流审计与调整

### 当前问题

1. `内容合规审查` skill 仍写“图片/视频判定只用文本”，与本阶段图片 OCR+视觉审核目标冲突；输入范围和问答/送审触发也不完整。
2. 同一文件把终态写成 DP0–DP4 且主要面向本地判定引擎；当前 PRD v1.4 另有 PASS/SUGGEST/REVIEW/BLOCK 业务输出，两者需明确分层，不能把 DP 层当成群消息状态。
3. `守衡语域` skill 的职责是回复方式，不是内容路由；要通过新工作流 skill 明确调用关系，避免复制一套词表和审核流程。
4. 代码实际执行不由 `agent-skills` 自动驱动；必须将每个 skill 声明的入口和分支映射到 `review_gate`、`agent` 及离线行为测试。

### 调整原则

- 新增 `agent-skills/飞书内容审核工作流/SKILL.md` 作为三类输入的入口、步骤和失败态说明，并链接到内容规程和语域规程。
- 更新 `agent-skills/内容合规审查/SKILL.md`：把规则引擎判据与业务四态拆开；标明图片、链接能力边界；明确机制问答不送审、送审必须走完整链、未测不能当通过。
- `守衡语域` 只补充“问答”和“审核结果”分别选用何种表达契约，不复制审核逻辑。
- 每项对外约束至少有一条行为自证；静态检查 skill 文案不能代替行为测试。

## 5. 非功能与隐私要求

- 输入和回复按会话隔离；同一素材的读数不能泄漏到下一条文本消息。
- 去重键、消息 ID、来源消息 ID必须保持一致；失败可定位到单条事件。
- 运行日志记录状态和关联 ID；新增实现不得额外写入原始图片/全文副本。沿用项目现有保留期限和权限策略。
- 发给飞书的最终回复使用现有卡片/纯文本降级路径；任何卡片校验失败都不得静默吞掉答复。

## 6. 验收标准

### 离线验收

1. 机制问答、闲聊、明确文本送审、文字+URL、纯链接、纯图片分别按上表进入正确路径。
2. 图片的正确来源消息 ID、OCR/视觉读数与失败态进入审核链输入；上一条图片数据不会进入下一条纯文字消息。
3. 纯链接正文实际读取并进入链；读取失败时审核链、评审写入均不发生且回复不含 PASS；链接+长正文保持文字分类并保留正文与 URL；正文中的 URL 不被自动抓取。
4. 送审必由 Agent 内核调用链一次；答复/链失败不得误报 PASS；重复事件不重复执行。
5. 答案有依据时保留可回源信息；未知/不可读时使用未测/阻塞状态。
6. 新工作流 skill、内容合规 skill、语域 skill 与代码判据具有可运行的一致性验收。

### 飞书验收

在专用测试群各发送一条普通问答、文字送审、图片送审、链接送审和一条重复事件。检查 ingress 日志、链运行日志、飞书表/报告实际回读、最终回复关联和去重。不得仅以群里“看得到卡片”判定完成。

用户已授权在专用测试群发送机制问答、文本、图片、链接四条验收消息。联调时记录消息 ID、回复关联、工作流分支、审核链调用与飞书回读；发送图片使用无品牌测试图。
