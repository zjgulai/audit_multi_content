# DSH 知识库规则加固规格

日期：2026-10-22  
状态：实施中；首批只读审计工具已进入实现阶段  
依据：`PRD/feishu/内容审查Agent-PRD-v1.0.md` §5.2–5.4、§6.1–6.6、§7.1–7.2、§15–16；项目 `AGENTS.md` 验收约定

## 1. 目标与约束

把知识库规则的来源、适用范围、匹配、生成、运行时加载和报告证据串成可复核链，降低 P0 漏放/误报、过期规则、仓库与活动库漂移、规则命中后报告失真的风险。所有改动必须保留当前 skill 自动化工作流：输入路由、入口 skill、专项 skill 让位表、L0–L7 阶段顺序、三态协议和发布闸门不得改变。

首批交付以只读审计和反向对照为主，不写活动 KB、不自动改变规则严重度、不扩展 P0、不改 skill 路由、不重启守衡。任何需要业务、法务或医学裁定的内容只登记缺口，不自动补值。

## 2. PRD 对齐

| PRD 条款 | 本项目要求 | 验收含义 |
|---|---|---|
| §5.2 | 文字、图片 OCR/视觉、视频字幕/旁白/关键帧/OCR | 覆盖报告按模态区分“有规则、无规则、未测”，不能把文本词表覆盖等同于完整图片/视频审查 |
| §5.3–5.4 | PASS/REVIEW/BLOCK 与结构化风险项、依据链接、位置、建议 | 验收报告必须保留原文命中片段、规则号、来源、建议和唯一计数；不把内部路径/正则源码当业务依据 |
| §6.2–6.3 | P0 快路；P1/P2 深审；P3 建议；P0 命中即 BLOCK | 首批不得改变处置策略；P0 覆盖、豁免和失效状态必须显式检查 |

| §15–16 | 指标与 P0 定期回归 | 报告说明分母、数据版本、回归集、假阴性/误伤读数；没有可复算分母时标未测 |

## 3. 设计决策

1. **运行时根目录动态发现。** 审计器从 `tools/agent/tools.mjs` 导出的 `KB_ROOT` 发现活动根；允许 `--root` 仅用于离线 fixture/明确指定的副本。不得另写固定运行时路径。
2. **只读、可重复。** 审计器不写 KB、缓存、报告或运行态文件；默认输出人读报告，可选 JSON 输出；相同输入产出相同业务结果（不含耗时/当前时间）。
3. **发现与裁定分离。** 错误结构/无法解析/找不到运行时根返回 2（未测）；已成功读取但发现契约缺项返回 1；通过返回 0。警告不被计成通过，PRD 要求但无法由数据确认的字段报告为缺口。
4. **活动库与仓库快照分开呈现。** 审计记录两边路径与文件 SHA-256；快照不等同活动根。内容差异先报告，不自动同步、不整树覆盖、不影响审核流。
5. **工作流保持原样。** 生产入口、skill 描述/路由、L0–L7 调用顺序和三态输出不改。新审计器由人工/CI 显式调用，不挂入每条素材的审核热路径。

## 4. 首批审计契约

`tools/verify_dsh_kb_rules.py` 提供纯函数 `audit_kb(root, repo_snapshot=None)` 与 CLI：

- `python3 tools/verify_dsh_kb_rules.py`：动态读取运行时 `KB_ROOT` 并审计。
- `python3 tools/verify_dsh_kb_rules.py --root <path>`：只对指定 KB 做离线审计。
- `python3 tools/verify_dsh_kb_rules.py --json`：输出稳定 JSON，供 PMO/CI 留痕。
- `python3 tools/verify_dsh_kb_rules.py --selftest`：运行内置离线正反对照，不读取或写入活动库。

必须检查：

1. L3 `rules.jsonl`、L3 `external_standard.jsonl`、L5 `p0_patterns.jsonl` 存在且 JSONL 全行可解析。
2. L3 中 P0 规则码集合与 L5 快路规则码集合相等；缺失/孤儿规则码均逐个报告。
3. L5 每条 P0 模式有唯一 `pattern_id`、唯一 `rule_id`，有 `rule_code`、条款号、锚点、来源摘要/证据单元；引用证据单元字段格式正确。
4. PRD §6.5 元数据按显式字段或已登记等价字段检查：`p_level`、`risk_level`、`applicable_scope` 的产品线/渠道、`content_type`、来源锚点及证据摘要、`kb_version`/`rule_version`、`owner`。`null`/空串/“未知”只报告缺口，不推断补齐。每条记录带 `gap_codes` 和 `rule_id`。
5. 对比活动库与仓库快照的路径、文件数和 SHA-256；差异作为 `snapshot_drift` 明确报告，不自动判成规则错误，也不静默称为一致。
6. 输出 `workflow_impact: none`，并通过自证确认审计器没有调用审核入口、没有写入知识库、没有编辑或调用任何 skill。

## 5. 后续 ticket 与完成标准

### KBH-01：活动规则库只读审计器（本轮实施）

实现上述 §4 契约、CLI、JSON 输出及 fixture 自测。活动库文件不变；现存契约缺项如实报告，不通过给数据填默认值来“转绿”。

### KBH-02：规则来源与法域/时效治理

把 §6.5 元数据缺口映射到实际规则 ID；和 Owner/法务/医学确认法域、渠道、内容类型、负责人、来源版本与复核周期。只将有来源和审批依据的值写回权威规则层，并由既有生成器重建下游。没有外部裁定时保留 `unknown`/待核，不自动升降 P0。

### KBH-03：类别与九场景域覆盖盘点

以活动库同一快照建立分母；逐场景 × 产品线 × 渠道 × 模态输出规则数、测试例数、已审/缺口状态。覆盖率分母没有业务应审清单时明确未测。分类更名或重归类不得改写规则含义。

### KBH-04：匹配器与例外回归

将规则边界、放宽裁定、否定/引用、全角标点、大小写正则、中文/英文变体、折扣/成分等误伤对照纳入自动回归。每条放宽规则必须有 positive/negative pair 和裁定指针；规则名字面命中与普通素材判断分开度量。

拆分为两个有不同授权边界的子票：

- **KBH-04A（机器可做）**：以活动库唯一 `rule_id` 为连接键，将 L3 来源锚点、L5 `pattern_id`、逐字来源/规则边界样例、实际 matcher 命中 ID 和稳定 `test_id` 汇成只读索引。每条样例调用活动 matcher，并核对返回的 `rule_id`；同 `rule_code` 不得代替精确 ID。无直接映射标 `UNMEASURED`。正例都命中才可标 `TESTED`；任一漏命中标 `FAIL`；缺来源锚点最多 `PARTIAL`。此票不写规则数据、不生成否定预期。
- **KBH-04B（需人裁定）**：逐条决定否定、引用/清单、全角标点、英文/中文变体及例外表达是否应命中；每个正反例都记录来源、裁定人/指针、预期结果。裁定缺失的规则留 `PENDING_OWNER`/`UNMEASURED`，不进入通过分母。机器不得按规则名字、规则码、相似度或常识补 verdict。

### KBH-05：L7 输出证据与唯一计数

验证命中原文片段、位置、规则码/条款号、证据链接、建议、同图身份/记录级归因、报告条数和三态回执一致；正则源码、KB 内部相对路径和重复回执不得进入用户报告。已有报表字段不删改，按 PRD 兼容。

输出契约以固定、可复现的 JSON fixture 表示：至少包含 PRD §5.3 PASS、REVIEW 1–2 条、REVIEW ≥3 条、BLOCK 1–2 条、BLOCK ≥3 条；输入携带媒材/源消息身份、finding 唯一键、规则依据直链和稳定样本 ID。执行器必须调用现有三态、合并、卡面及报告产出函数，校验状态、唯一计数、2/3 门槛、逐条/汇总布局、原文/依据 URL、动作行与字段清理。媒材归因和处理回执可复用已存在的 L7 行为测试，但 fixture 必须保存其测试 ID 与源位置；指针不存在即验收失败。线上资源可达/有效期须另有在线证据，离线保留域 URL 只能证明字段透传。生产链变化时必须对同一冻结输入跑改前/改后 A/B；仅改审计器或验收夹具时 A/B 标 N/A 并说明变更面。

### KBH-06：skill 工作流兼容性回归

锁定现有输入路由、skill 让位、L0–L7 层前置、判定 owner、freshness、图片/视频原件闸门、发送/发布闸门及三态格式为兼容契约。审计与回归工具不插入生产热路径。验收跑 `verify_skill.py`、`verify_engine_contract.py`、`test_agent.mjs`、KB 各层自证并比较改前基线。

### KBH-07：登记、读回与验收留底

每批已验收知识库改动按项目约定写 `kb_ingest` 和 PMO 留底，并跑 `verify_ingest_coverage.py`。若无权威 ingest 接口，不伪造账本；在验收中列为未闭合外部动作。

## 6. 验收门槛

- KBH-01 单测先红后绿；正例覆盖完整 P0 对齐，反例覆盖缺规则、孤儿规则、重复 ID、缺来源/元数据、无效 JSONL、不可读根目录。
- 新工具只读：临时 fixture 与活动目录的文件清单/哈希在运行前后不变。
- 现有 P0 matcher、快路、P0 回归结果不退化；`verify_engine_contract.py` 与 skill 路由自证不新增失败。
- 生产 skill 文件、路由实现和审核入口不因本 ticket 改动；CI/报告只新增显式审计入口。
- 输出区分 PASS、FAIL、UNTESTED；所有未测项不得汇总为通过。
- 只有活动库、回归、skill 工作流和 ingest 读回均有证据时，才可称知识库优化闭环完成。外部裁定缺失时只可称审计器交付，不能称规则覆盖已补齐。
