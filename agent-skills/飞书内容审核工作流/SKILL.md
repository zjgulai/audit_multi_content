# 飞书内容审核工作流

> 本规程覆盖飞书群里的问答，以及发布前文字、图片和链接送审。它描述正确的操作次序，**不会在运行时自动装载**；真正的自动化由代码判据和接线执行。
>
> 自证：`python3 tools/verify_skill.py --workflow-check` 检查本规程与代码锚点；`node tools/agent/review_workflow.test.mjs` 检查行为；`node tools/test_agent.mjs` 检查 Agent 全链。

## 1. 入口与分工

1. 飞书群消息先由 `tools/ws_daemon.mjs` 接收并交给 `tools/agent/agent.mjs`。沿用 @守衡、身份校验、会话隔离、消息去重和回复回原会话的约束。
2. `tools/agent/review_gate.mjs` 是唯一送审路由判据：`mechanismQuestion()` 识别有关审核机制的问答；`isSubmission()` 判定是否送审；`chainInput()` 组装实际送审材料。
3. `agent-skills/内容合规审查/SKILL.md` 解释规则证据与判定边界；本规程负责消息分流和素材流转；`agent-skills/守衡语域/SKILL.md` 负责回复表达。不要在本规程复制规则词表、卡片 schema 或审核结论算法。

## 2. 问答还是送审

### 问答

用户问 Agent 能力、审核方法、规则依据或已有结论时，回答问题本身，不把问题文字当作发布素材。命中“审核/合规/依据”等词不是送审的充分条件。纯文字机制问答必须经过 `mechanismQuestion()`，不得启动 `kb_review_chain`。

### 送审

- 明确要求审核的文字按原文送审。
- 图片单独发送时，按素材送审；文字说明也随素材保留。
- 链接单独发送或附短说明时，按链接素材送审。
- 长正文含 URL 时，按文字送审；正文和 URL 都保留，不把普通来源链接误报成待审核页面。

送审必须由 Agent 内核进入 `kb_review_chain`，不能依赖模型自行记得调用工具。完整顺序为 L4 发号 → L5 P0 → L6 召回 → L7 跨层闸门 → 评审链 → 按当前配置写入飞书。没有完成链的消息不能展示审核结论。

## 3. 三类素材的处理

### 文字

1. 还原 @提及并去掉 @守衡 本身；保留用户正文。
2. 用 `review_gate.isSubmission()` 区分机制问答与文字送审。
3. 文字送审逐字交给审核链；正文里的 URL 也保留在素材中，并另列为链接输入。
4. 依据不足或链未运行时，明确说未测/未完成，不说“没问题”。

### 图片

1. 从当前消息或明确引用的消息读取图片资源，关联正确的 `message_id` 与图片资源键。
2. 对每张图读取 OCR 与视觉识别结果；多张图分别保留来源和读数。
   OCR 判据识别为重复覆盖式截图/审阅水印时，按截图层处理：不计为素材问题、不据此判 REVIEW；若水印遮住文字，只说明局部识读受限。只有原图能确认水印属于最终交付创意时才按成品审查，不能据此推断消费者会误认。
3. 将用户原问题、图像读数和读不到的部分一起交给审核链，不能仅用模型转述代替原始机读读数。
4. 判定主体（`图片安全审查`）在流程里**判出的问题逐条都要变成条目**，不能只活在这一轮回复的散文里：`tools/agent/skill_findings.mjs` 从「八、分级结论 → 问题清单」抽出「描述 ｜ 位置 ｜ 改：…」，按模型侧形状并入合并列表（`source='model'`、合并语义不变、**不单独定 BLOCK**），并用 `origin_track='skill'` 标出来路；落表 `sides` 因此分得开 `skill` 与 `model`。抽不到时内核要出声（`🧩 判定主体核查：一条都没上卡`），不许静默为空。
4. 取图、OCR 或视觉识别失败时，显式标记未读取/部分读取；识别不到文字不等于图片安全。
5. 必须通过 DSH 的 `skill` 工具完整加载并执行「图片安全审查」全流程。每张图的「婴儿睡眠位置」须独立于泛化的「婴幼儿姿势」核对：逐个婴儿、逐个面板记录仰卧/侧卧/俯卧/看不清，并与图中文字、箭头和安全建议配对。床共享与睡姿是两项独立风险；不能因图只警示同床就漏掉侧卧。睡眠场景的睡姿须按该 skill 的步骤 4B 对照 AAP 权威指南；看不清、读数缺失或最终回复未复述画面读数的睡姿时，结论必须为 `NEEDS_INPUT`，不能输出 PASS/REVIEW/BLOCK 三态结论。

### 链接

1. 由 `review_gate.findLinks()` 提取 URL；短说明+链接走链接素材路径。
2. 长正文含 URL 时，使用文字送审分支，并通过 `chainInput()` 同时带入正文与 URL。
3. 链接按**域名**分两条路，分流点只有一个：`tools/agent/feishu_link.mjs` 的 `readLink()`。
   - 外部网页：`tools/agent/link_reader.mjs` 读取公开 HTTP(S) 正文；限制公网 DNS/IP、固定已校验 IPv4 公网地址、最多 3 次重定向、8 秒、1 MB，仅 HTML/纯文本；IPv6/非标准端口暂不支持，不带凭据、不执行脚本、不下载附件。
   - 飞书链接（`*.feishu.cn` / `*.larksuite.com`）：**不走公开网页抓取**（飞书页面一律 302 到登录页，抓不到正文）。按路径取只读正文接口：`/docx/` → `docx/v1/.../raw_content`；`/sheets/` → 工作表值；`/base/` → 多维表格记录；`/wiki/` → `wiki/v2/spaces/get_node` 解出 `obj_type` 再按上面三种读。云空间附件 `/file/`（pptx/pdf/xlsx…）**没有**原文读取接口，按红线「飞书内容禁止下载」不下载、不探测 —— 直接说明「这是附件、按红线不取」，并给替代路径（贴正文 / 转成飞书文档 / 发 docx 链接）。幻灯片、思维笔记、旧版 `/docs/` 同理说清「飞书没有该形态的正文读取接口」。
4. 读取失败或正文为空时，内核直接说明无法形成审核结论，跳过审核链与审核写入；不得根据 URL 猜内容或给 PASS。失败原因必须**分形态说清**（红线不取 / 飞书没接口 / 权限或不存在），三种原因不许揉成一句 —— 否则人会去申请一个不需要的权限。长正文附 URL 时仍走文字路径，不自动抓取 URL。

## 4. 结果和失败

业务输出遵循当前 PRD 的 PASS / SUGGEST / REVIEW / BLOCK 状态。DP0–DP4 是本地判定引擎的处置层，不是飞书业务状态。只有 P3 建议时，decision 为 PASS，并附非阻断 SUGGEST；REVIEW 需人工确认；BLOCK 返回修改；PASS 仅表示未发现已知底线风险。

下列结果必须和业务状态区分：消息未识别、素材不可读、链未运行、链调用失败、空结果、报告或飞书写入未确认。未测/不可读/链失败不得转换为 PASS，也不得用“已审核”概括未完成的步骤。

## 5. 回答格式与执行点

- 普通问答用 `agent-skills/守衡语域/SKILL.md` 的问答表达要求；审核结果使用现有卡片契约和审核链返回，不让模型直接写卡片 JSON。
- 卡片发送失败时走已验证的纯文本降级路径；不能静默丢回复。
- 主要执行点：`tools/agent/review_gate.mjs`、`tools/agent/agent.mjs`、`tools/ws_daemon.mjs`。
- 行为验收：`node tools/agent/review_workflow.test.mjs`、`node tools/agent/link_reader.test.mjs`、`node tools/agent/feishu_link.test.mjs`、`node tools/test_agent.mjs`。
- 本阶段覆盖文字、图片、链接。视频、brief 文件、Word/PDF、批量入口、自动派单和 sign-off 按各自 ticket 实施，不从本规程推导成已交付能力。
