# 守衡图片回复强制登记模板修复 · 2026-10-26

## 问题与原因

用户发送图片后，守衡的回复仍可能出现自由格式，与 PRD/登记模板不符。提示词要求用模板，但模型有时漏写 `[[card:类型]]`；此前发送层会把这种文本原样发出。另一个绕过点是 `handleMessage()` 的异常出口直接发送文本，图片读取或审查异常时也可能不经模板转换。

本轮日志显示，用户图片已进入图片/OCR处理，但该条任务在守衡重启时仍未完成；没有查到这张图片对应的最终外发。因此不能据此声称线上图片答复已成功验证。

## 修复

- `tools/agent/persona.mjs`：提示词要求每条答复使用登记模板，移除“一句话能答完就一句话答完”；短确认走 `receipt` 模板。
- `tools/reply-cards/envelope.mjs`：`toCardOrText(..., { requireTemplate: true })` 在模型漏写卡片信封时，将内容包装为已登记的 `query-answer`；识别“差异：”格式时用 `turn-diff`。清理孤立的结束标记，保留原始答复正文。
- `tools/ws_daemon.mjs`：正常回复已启用模板闸门；`handleMessage()` 的异常出口也改走 `replyTo()`，保留原消息引用，并经同一模板转换。
- `tools/verify_cards.mjs`：J5c 用图片自由格式答复反向验证模板包装及正文保留；L0b 断言异常出口经 `replyTo()`；保留既有的发送接线断言。

## 验收与运行读数

- `node tools/verify_cards.mjs`：355 项通过，0 项失败。J5c、L0b 均通过。
- `node tools/test_agent.mjs`：311 项通过，0 项失败。
- `python3 tools/verify_shouheng_ops.py`：重启后自证全过；进程在运行、飞书 WebSocket 已连接，重启留痕可读。
- 部署：通过 `tools/restart_shouheng.sh` 重启，当前 PID 需以运行时读数为准；部署时确认旧图片任务尚未完成，未将它记作成功答复。

## 判据位置

- 模板提示词：`tools/agent/persona.mjs`
- 强制解析与包装：`tools/reply-cards/envelope.mjs::toCardOrText()`

- 异常出口反向对照：`tools/verify_cards.mjs` L0b

## 二、本机这一份的真实缺陷（两道，都已修）

**① 送审单拿不到 §5.3 结论行时，模型那段自由文本成了答复。**
`envelope.toCardOrText` 里那个「审查未完成」固定模板（`reviewRequired`）**写好了却没有任何调用方** ——
又一个「名字出现过 ≠ 它拦得住」（§2.4）。实测本机 12:21 那一单就是这样：`gate.yes=true`、无结论行
⇒ 走通用 `query-answer`，抬头是模型第一句话。

**② 判定引擎的内部字段名可以进用户可见正文。** 原先只挡 `internalLeak` 那一族（工具名 / `call_xxx` / 栈帧），

## 三、修复

- `tools/reply-cards/jargon.mjs`（新）：`isJargonLine()` / `stripEngineJargon()` / `scrubCardData()`。
  **认「赋值形态」（`字段 = 值`）＋ 层 ID（`DP0`–`DP4`）＋ `待放行`**，不认单独的 `coverage` 这种正常英文词
  （误报比不报更糟，§2.1.1）。摘的是**整行**，不改写成「判定为 REVIEW」—— 改写等于替模型补一条它没被授权下的事实结论。
- `tools/reply-cards/envelope.mjs`：卡片块走**数据层**清理（`scrubCardData`，坏不了 JSON 结构）；
  纯文本走 `plainOut()`。⚠️ **绝不能先动 `raw`** —— 卡片块是**单行 JSON**，按行摘会把整段 JSON 一起摘掉
  （第一版就写错过，J13a3f2/f5/f6、J13a3g2/g3、J11c3 六条精确变红）。另：`applyReportLink` 的候选格补上 `impact` ——
  `alert` 那一档原先**没有能放链接的格**，换模板会把报告链接静默丢掉（实测跑出来的）。
- `tools/ws_daemon.mjs`：`replyTo` 新增 `reviewOrder`，调用方传 `result.meta?.gate?.yes === true`（内核读数，不猜文字）；
  这次 `toCardOrText` 调用带上 `reviewRequired: !!reviewOrder && !v53?.line`
  —— **只在「送审 ＋ 没结论行」时**启用固定模板，PASS 单「只留一句话结论」那条口径一个字不动。
- 判据：`verify_cards.mjs` **J5d**（送审无结论 ⇒ `alert`，黑话不上卡，报告链接仍在）、**J5e**（卡片字段里的黑话逐行摘、同组其余不动）、
  **J5f**（两条反向对照：不带赋值的正常句子不许被吃、非送审单不许套这个模板）；
  `test_agent.mjs` Z20b 的调用断言从「逐字一行」改成「同一次调用内三个读数各就各位」＋两条新接线断言。

- `tools/agent/retry_queue.mjs` ＋ `tools/ws_daemon.mjs`：**补发那一跳也交同一条读数**
  （`send(it, text, { reviewOrder })`，取自 `res.meta.gate.yes`）—— 补发的正是「答失败/没跑成」那一类，
  最容易拿不到结论行；不接线的话它会绕过刚部署的模板闸门。
