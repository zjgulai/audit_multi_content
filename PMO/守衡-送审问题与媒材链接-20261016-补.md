## 一、我造成了什么（先写损伤，再写理由）

在 Owner 同意后跑 `clean_legacy_questions.mjs --apply` 清洗旧行时，
**3 行的链接标签被吃掉**：

```
改前：…来源页（美国站）：https://…
      [图片](https://momcozy-in.feishu.cn/file/B8HnblYmUoG3FnxKmqGcoHNvnQh)
改后：…来源页（美国站）：https://…
      (https://momcozy-in.feishu.cn/file/B8HnblYmUoG3FnxKmqGcoHNvnQh)
```

受影响行：`AUTO-b69fc8e0dac8`、`AUTO-3fe369af9311`、`AUTO-e0ba2a737c19`。

**根因**：`stripInternal` 第一步写的是

```js
s.replace(/\[(图片|媒体|视频)\]/g, '')      // ← 错：它会匹配 markdown 链接的**标签**
```

`[图片](url)` 里那一小段正好是 `[图片]`，于是标签被替换掉，只剩 `(url)` ——
**一个点不开的半截形状**。占位符（`[图片]` 单独出现）与链接标签（`[图片](…)`）
在这个正则眼里长得一样，而它们要做的事**正好相反**：
占位符要删，链接标签是链接的一部分。

**修法**：`/\[(图片|媒体|视频)\](?!\()/g` —— 后面紧跟 `(` 的**不删**。

## 二、同一次还发现第二处过宽（还没造成损伤）

`PROBE_MARKERS` 第一版写成字面量 `'【视频 '`，于是它匹配**提交人自己写的**头注：

```
【视频封面图 —— 本次只审封面图与标题；视频本体（口播 / 字幕 / 画面）未审】
```

真表里 `AUTO-e0ba2a737c19` 就是这么一行 —— **把人的话当成我们的探针切掉**。
仓库自己的 `questionForReport` 一直写的是 `视频\s*\d`（**要求后面跟数字**），
我抄词面时把数字丢了。

**修法**：改成与仓库同一套正则 `PROBE_RE`，只多一个 `★ 这是送审素材`
（那是 `MEDIA_ROUTE_HINT`，报告那侧的正则其实没盖住它）。
