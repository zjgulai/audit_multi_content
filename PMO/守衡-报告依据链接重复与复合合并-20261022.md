# 守衡 · 报告「依据文档链接」重复与复合合并（2026-10-22）

> 一句话：同一份记录的多条规则共用同一个 URL，**合并时把已拼好的依据串回写进源对象**，
> 下一轮又当一条输入读回来 ⇒ 每合并一条复制一遍（4 条 findings → 7 段、6 条一样的链接）。

## 现象

报告 `https://momcozy-in.feishu.cn/docx/HD8Td5RjuouYIDxrZ2ocoshVn9Z`（以及上一份
`Ij6qdenpAozaWIxnmOCcmMoOnSf`）的「依据文档链接」一格：

- 7 个同一 URL（`record=recvw7XIUgXEvk`），条款号只有 4 个：
  N-1.307 / N-1.312 / N-1.312 / N-1.364 / N-1.312 / N-1.364 / N-1.365；
- 第一条被链化成 `[点开核对](…recvw7XIUgXEvk；《内部正负样本库…》第)` —— **中文被吞进 URL**。

## 根因（两个独立缺陷，都在 `tools/agent/dual_track.mjs`）

1. **复合重复（`mergeFindings` 的 `pushUnique`）**：合并结果被写回
   `prev.basisLine` / `prev.kb.basisLine`，下一轮 `raw.flatMap` 又把这份**已拼好的整串**
   当一条输入读回。复现（只读）：`node test/_diag/dup_basis_repro.mjs`：
   n=1→1 段、n=2→2、n=3→4、n=4→**7**；`suggestionLine` 同一形状（≥3 条建议时）。
   现有自证 ⑦b 只检查 `.includes('N-1.307')`，看不见重复段 —— 所以一直是绿的。
2. **链接化吞中文（`renderMergedItem`）**：`/(原始出处[:：])(https?:\/\/\S+)/` 用 `\S+`，
   中文标点不是空白 ⇒ URL 把 `；《内部正负样本库…》第` 一起吞进链接目标。

## 修复

| # | 位置 | 改法 |
|---|---|---|
| 1 | `mergeFindings` | 原始串只进 `_basisParts` / `_suggestionParts`，**不回读展示字段**；按 `库名\|条款号` 去重 |
| 2 | `mergeFindings` + 新 `collapseDuplicateBasisUrls` | 同一 URL 只留第一条 `原始出处`，后面的段只留「《库》第 X 条」⇒ 一条链接 + 四条条款号 |
| 3 | `businessBasis` | 内部坐标只摘「锚点：…」**标签与值**，不再整段丢（URL 收成一条后，锚点与下一条条款落在同一 `｜` 段，整段丢会把后两条条款一起吞掉） |
| 4 | `renderMergedItem` | 链接正则改成 `[^\s)）」』；;，。、]+` 并加 `/g` |
