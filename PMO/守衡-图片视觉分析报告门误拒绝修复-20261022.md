# 守衡图片视觉分析报告门误拒绝修复（2026-10-22）

## 现象与根因

图片完整审查虽然返回了模型侧结果，但视觉分析没有进入合并报告/卡片。根因在 `tools/agent/agent.mjs` 的图片报告门：

- `runSubmissionGate()` 在报告构建阶段先计算 `reportImageEvidenceFailure`；
- 该处原来传 `dual?.model`，但 `dual` 只有后续双轨合并完成后才赋值；
- 因此报告门看到的是 `null`，误判为“模型侧原图视觉/语义审查未完成”，令 `imageSkillReview` 为空；合并报告不含图片 skill 全流程节，返回卡片也没有 `imageAnalysis`；
- 同一个函数作用域内的 `model` 已是本轮模型侧请求结果，并且比报告构建更早产生。

这解释了“知识库结论仍在，但视觉模型读数和完整审查流程没显示”：模型侧请求/视觉读数可能已经完成，报告组装门却因为读取尚未赋值的变量而拒绝它。此前用户提出的“模型必须收到原图”判据仍保留：此修复只纠正模型结果引用时机，不把 OCR 或视觉描述当作原图替代品，也不放宽模型失败时的阻断。

## 修复与回归判据

将报告阶段的图片证据检查改为使用已解析的局部 `model` 结果。新增 `tools/test_agent.mjs` 行为级回归：以完整图片 skill 阶段、引擎图片闸通过、模型侧 `ok: true`、原图 OCR 与场景读数构造 `runSubmissionGate`；断言合并报告包含“图片安全审查 skill 全流程结果”，返回卡片字段包含原图 OCR 与“视觉模型读数”。另保留模型侧失败、知识库图片闸拒绝及文字单不受影响的反向断言。
