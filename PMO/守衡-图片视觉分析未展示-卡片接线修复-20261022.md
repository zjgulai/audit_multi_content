# 守衡图片视觉分析执行了但未展示：卡片接线修复（2026-10-22）

## 现象与定位

用户指出图片审查回复没有视觉分析内容。检查 2026-10-22 01:40:29Z 的图片审查记录：

- `question` 保存了原图 SHA-256、OCR 读数和完整视觉模型读数；视觉读数包含卧室场景、人物关系、婴儿姿势、物品及画面线索。
- `model.ok=true`、`model.count=5`，证明独立模型侧有 5 条发现。
- 本轮知识库链也生成了审查结论。
- 用户看到的卡片只有逐条结论，没有“视觉分析与 OCR”段。

因此这次缺陷不是“没有做视觉分析”，而是**做完后没有把读数送到卡片**。`reviewShape` 分支会用权威 §5.3 结论块重建卡片，模型原回复正文不保留；完整图片 skill 内容此前只进合并报告，没有进入发出的卡片。

## 修复

1. 图片 skill 与视觉核对闸门全部通过后，内核生成 OCR 摘录和视觉模型读数，并作为 `meta.imageAnalysis` 返回；闸门不完整时不展示成已完成的分析。
2. `ws_daemon.mjs` 把该读数传进 `replyTo`，`replyTo` 再交给 `toCardOrText`。
3. `envelope.mjs` 在权威结论后把“视觉分析与 OCR”放入最终可见卡片正文；汇总卡与逐条卡都覆盖。没有可信读数时不伪造该区块。
4. 场景读数补充多面板、逐个婴儿的睡姿字段与位置，最终视觉核对要求同一面板内复述；这让画面分析更可核查，不把睡姿识别当成本次用户报告缺陷的根因。
5. 内核自证曾发现 `imageAnalysis` 在双轨内层作用域定义、外层返回时报 `ReferenceError`；已提升至审查函数作用域，并将行为断言加入自证。
