## 〇、这次要蒸什么（一句话）

近 10 天（2026-10-05 ~ 10-15）**505 个 DSH 会话**（`audit_multi_content` 6 个 +
`skill-test` 知识库项目 499 个，其中 461 条是守衡转进来的送审单）→ 正误判定 →

## 一、四行必填

| 字段 | 本轮的取值 |
|---|---|
| `must_include`（≥2） | ① **每条 Schema 陈述必须带依据指针**：`case_id` + (`session_id:seq` 或 飞书 `message_id` 或 层 `RUN-id`) —— 指不出指针的不许进卡片。<br>② **每个被改的评审链 skill 必须同时给出三类**：可执行动作 / 禁止动作 / 风险点，且**禁止动作至少 1 条**（只有「该怎么做」没有「不许怎么做」的卡片 = 没蒸完）。<br>③ **分层候选必须长成 `kb_ingest` 能收的形状**：`id/title/collection/tier/topic/summary/owner/evidence_level/data_level/half_life_days/created_at/valid_until/asks/not_proves/source{kind,ref,fingerprint,captured_at}` 一个不少。<br>④ **「正例」与「反例」都必须指得出三源之一**（见 §三）；指不出的一律落 `待人工复核`。 |
| `must_not_include`（≥1） | ① **不许出现无指针的断言**（「应该先理解需求」这类裸模型也会说的话，删）。<br>② **不许把「未命中」写成「合规」**：库里没有可依据的条款 ⇒ 只能写「覆盖缺口」，不许写「没问题」。<br>③ **不许把「我方提问」写成「对方承诺」**（AGENTS.md §2.4.3）。<br>④ **不许含凭据 / 密钥 / 个人敏感信息**（`~/.dsh/credentials` 一律不读）。<br>⑤ **不许写「生产就绪 / 已上线 / 已验证可用」** —— E 级上限 = **E2（草稿级、可审查、未获批）**。 |
| `confidence_floor` | 评分 **> 0.8 → keep**；**< 0.4 → discard**；中间 → **review**（人工定）。<br>佐证要求：**≥2 处跨会话或跨源的独立佐证**（同一会话里说两遍不算）。<br>**淘汰率低于 30% 先怀疑自己放水了** —— 够格进正文的判断通常只占 25%~50%。 |
| `owner` | **刘华丽**（内容治理数据组；KB 登记表里 `owner` 字段的具名人，见 `kb/l7/registry/failure-playbook.yaml:19`）。<br>为「这条判断的正确性」负责的是她，不是「团队」。 |

## 二、四条入库验收谓词（全过才收）

| 谓词 | 本轮的判据 |
|---|---|
| `structural_completeness` | 元字段齐全，且 `data_level` / `valid_until` / `owner` **非空率 100%** |
| `source_traceability` | 每条都能回到**哪个会话的哪一句**（`session_id:seq`）+ 原文 `sha256` |
| `no_duplication` | 与 `kb/l3/candidates/sample_cases.jsonl`（946 条）与 `kb/l1/2_内部正负样本库` 逐条比对，重复的**合并**不新增 |
| `boundary_declared` | 每条带 `not_proves`（不能由它证明什么）与 `valid_until`（半衰期到期日） |

**缺任一条 → 该条不产出正文，只产出一份缺口清单。**

## 三、「正误」只认三源（模型不单独定正误）

**这是本轮最硬的一条纪律。** 「错误」标签只认**有对象的依据**：

| 源 | 是什么 | 指针落在哪 |
|---|---|---|
| **① 人的原话** | 你（或群里的人）当场纠正 / 追问 / 确认 | 会话内 → `session_id:seq`；飞书侧 → `PMO/logs/ws_events.jsonl` / `ws_outbound.jsonl` 的 `message_id` |
| **② 链自己的红** | 层闸门红 / 四道审计红 / 回归基线漂移 / 引擎拒答（`NEEDS_INPUT`） | 会话内 → 层 `RUN-id`、退出码；库内 → `kb/l7/registry/regression-baseline.json` |
| **③ 库里已有裁定** | KB 已经人工过闸的记录 | `kb/l3/candidates/sample_cases.jsonl` / `kb/l4/canonical/sample_case.jsonl` 的 `polarity` / `reason_category` |

**模型（含 Jev）只做四件事**：聚类、写 `reason_analysis`、给错型**候选**标签、算置信度。
**判不动的一律落 `待人工复核`，不许默认成「正确」。**

> 为什么这条不能松：判错的会被当正例沉淀进库，而**假正例和真正例长得一模一样、
> 没有任何东西会红** —— 下一轮评审就照着这条假正例判（AGENTS.md §2.4.1 那个病）。

## 四、负例校验（fail-closed：过不了负例就不算过）

产物定稿前拿这六条打自己，**任一条命中 → 回炉**：

| # | 负例 | 命中说明 |
|---|---|---|
| N1 | 把最关键的那条 Schema 删掉，卡片还成立吗？ | 成立 → 这条没进正文或在凑数 |
| N2 | 把素材换成同类但结论相反的一份，产物会变吗？ | 不变 → 是模板填空，不是从会话蒸出来的 |
| N3 | 每条 Schema 追问「你从哪条会话来的」，都答得出吗？ | 答不出 → 出处造假 |
| N4 | 有几条是「裸模型自己也会说」的？ | >0 → 同质化，删掉 |
| N5 | 有没有把「待人工复核」悄悄写成结论？ | 有 → 违反「不猜」纪律 |
| N6 | 有没有把实时 / 易变数据写成了判断？ | 有 → 该走 CACHE 档，不蒸 Schema |

| 要求 | 判据 |
