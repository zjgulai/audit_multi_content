## 二、② 模态覆盖写死，图片送审永远「结构上不可判」

### 证据

* `with_kb_evidence.py:234`：`"content_type": "text"` —— **写死**
* `with_kb_evidence.py:238-241`：
  `"coverage": {"text": "complete", "image": "not_applicable", "audio": "not_applicable", …}`
  —— **七个模态全部写死**，还带一句自证话术 `note: 「本批只送审文字；其余模态不适用（不是缺口）」`
* `review_engine.py:40` 的 `_coverage_ready()` **本来就会**：`content_type == "image"` 时
  要求 `{"image","ocr"}` 都是 `complete`/`not_applicable` —— **判据早就在，只是永远收不到 image**

⇒ 于是一张**图片**送审，payload 里却写着"图片模态不适用"，
而 KB 自己 `confirmed_by_user` 的口径是 *"Do not emit PASS until a URL or file is actually
readable and required modality coverage is complete."* —— 两句话正面冲突。

### 补丁方向（比 ① 大，需要接线而不是改一行）

1. `run()` 增加一个**声明**入口（如 `declared_modalities={"image": True}` 或 `content_type`），
   由调用方（守衡 / AGENTS.md 步骤③）如实传；
2. `coverage` 由「**实际提供了什么 + provider 状态**」推出，不再写死：
   图片送了但拿不到 `multimodal-provider-contract.json` 要求的
   `provider / provider_version / content_hash / status` ⇒ `image: "incomplete"`（**缺口**，不是 not_applicable）；
3. `content_type` 不再写死 `text`；
4. `_coverage_ready()` 保持原样 —— 它会自动把 `incomplete` 挡在 PASS 之外。

### 判据

`content_type=image` 且 `coverage.image="incomplete"` → **不许出 PASS**；
`content_type=text` 的既有样本 → 结论**一字不变**（相容级断言，防误伤）。
