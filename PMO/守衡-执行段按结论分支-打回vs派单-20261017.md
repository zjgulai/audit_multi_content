# 执行段按结论分支：BLOCK 打回（不 @ 人）／REVIEW 才派单

> Owner 原话，逐字：
> 「按照 prd，命中 block，审查报告**不会 @xx @xxx 去修复，直接打回建议修复**；
> 命中 review 的，审查报告才会 @xx @xx 去修复。
> **目前审查报告的执行 3 适合 review 模版，若结论是 block 要按照 prd 优化**」

---

## 一、PRD 原文（查过，不是转述）

在 PRD（wiki `NB55wAq8liEOdKkquL2cgtPEnmg` → docx `PXfBdjTwFokEQixtmTscqm7knNh`）里，
两种结论的收尾**逐字不同**：

| 结论 | PRD 收尾（每处都是这一句） | 有没有 @ |
|---|---|---|
| **REVIEW**（§5.3.2 / §5.3.3） | `建议转 @法务 @医学顾问 复核。` | **有** |
| **BLOCK**（§5.3.4） | `请修改后重新提交。` | **没有** |

⇒ Owner 的读法就是 PRD 的写法。而报告里的「三、执行」**不分结论、一律逐角色 `@xx` 派单**，
字面上是 REVIEW 的模版 —— 于是一份 BLOCK 的报告，一边说「请修改后重新提交」，
一边把六条问题分摊给四个人去「跟进」。

---

## 二、改成两支

### BLOCK ⇒ 打回（不派单、不 @）

```
## 三、执行（打回，修改后重新提交）

> 结论是 BLOCK：这一单打回，不派单、不转人复核。请按上面每一条的「修改建议」改完，再重新提交一次。

请修改后重新提交。
```

- **不出现任何 `@`**；
- 不出现「跟进问题（第 N 条）」这种派单句式；
- 收尾仍是 PRD §5.3.4 那句 `请修改后重新提交。`（一个字符不改）；
- 页面上的「承办」列保留 —— 那是**这是谁的责任范围**，不是派单通知（它不带 @）。

### REVIEW ⇒ 派单（原样保留）

```
## 三、执行（按问题分派）

- **@法务**：跟进问题（第 1、2 条）
- **@医学顾问**：跟进问题（第 1 条）

建议转 @法务（未配置） @医学顾问（未配置） 复核。
```

## 三、判据

`test_agent` 第 48 组新增 **Z48g**，并把 Z48 的 ⑥（执行段）改成 BLOCK 分支断言：

| 判据 | 盯什么 |
|---|---|
| Z48（夹具 BLOCK） | 标题必须是「打回，修改后重新提交」；**一个 `@` 都不许有**；不许出现「跟进问题（第」；必须有「按修改建议改完再提交」；收尾 = `请修改后重新提交。` |
| Z48g①（夹具 REVIEW） | 标题「按问题分派」；逐角色 `@… ：跟进问题（第 N 条）`；收尾 `建议转 @… 复核。`；**不许**出现 `请修改后重新提交。` |
| Z48g②（反向对照） | 同一批条目换成 BLOCK ⇒ **一个 `@` 都没有**、收尾换句 —— 证明分支真的按结论走 |
| Z48g③ | 两支的标题**必须不同**（同名就等于根本没分支） |

## 五、边界

1. **卡片没动**：卡片的收尾本来就是 `orderActionLine()` 算的（BLOCK ⇒ `请修改后重新提交。`），
   它一直是 PRD 口径 —— 只有**报告**那一节套错了模版。Owner 也说过「卡片格式不要动」。
2. **只按 BLOCK/REVIEW 分两支**：PASS 单本来就不出报告（问题数闸门）；NEEDS_INPUT 不走这条渲染。
3. **「承办」列留在总览表里**：它回答「这是谁的责任范围」，与「@ 谁去修」是两件事。
   若 Owner 认为 BLOCK 单连承办也不该有，那是一行改动（说一句即可）。
