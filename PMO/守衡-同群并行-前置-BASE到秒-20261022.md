# 同群并行 · 前置：`--base` 到秒（2026-10-22）

> 本文件是留底件（引用必须回这里核对）。判据在 `tools/agent/chain_base.test.mjs`。

## 一、为什么先修这一处

并行的第一件事不是改锁，是**让两条链不撞同一个 RUN**。

`review_run.sh` 开跑第一步调
`rerun_ledger.py --check-base "$BASE" --text-sha8 "$TEXT_SHA8"`，判据是
「**同一个 BASE 已经跑过 ⇒ 硬拒**」（退出码 **2**）。
而 `BASE` 是守衡给的模板 `date +%Y%m%d-%H%M` 生成的 —— **分钟级**。

于是「同一分钟起两条链」（同群并行的常态，跨群两人同时发也一样）⇒ 两单 BASE 同名 ⇒
后一单被判「同一个 RUN 跑第二遍」⇒ 退出码 2；而守衡侧 `RETRYABLE_REFUSALS` 只认
`claim_busy / layer_gate_red / layer_audit_red / preflight_aborted` ⇒
**退出码 2 不进补发队列，那单直接失败**。

判据钉住的四件事（缺一件就等于没修）：

1. 模板**必须**秒级；
2. 旧格式**出现即红**（`/%H%M(?!%S)/`）——防止哪天被改回去；
3. `review_run.sh` 的 `usage` 与模板**同格式**（两处漂了，照抄手册就撞）；
4. `rerun_ledger._norm()` **真的不截断** —— 喂「台账里已有 `20261022-1146`、本单 `20261022-114647`」
   必须 `same_base=false` 且 `rerun_seq=2`；反向对照：同一个 BASE 仍必须 `same_base=true`。

> ★ 判据第一次跑就红了两项，红的是**我自己写错的正则**：格式串 `%Y%m%d-%H%M%S` 里
> `%H%M` 后面紧跟的是 **`%`** 而不是 `S`，所以 `(?!S)` 恒真、把秒级也判红。
> 改成 `(?!%S)` 才对。这条记下来，是因为「一个会误报的检查器比没有更糟」。
