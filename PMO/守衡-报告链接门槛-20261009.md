## 二、★ 一次自我更正：先说错了一半

我最初的判断是「一单里有**三个**问题数在打架，抬头那个数是从链的正文里**正则抠**出来的」。
**前半句对，后半句错。**

真相在 `tools/agent/dual_track.mjs:1140`：

```js
const total = n + kbGap + covEntries;
//             ↑ 能并的条目  ↑ 库侧有明细但没并进来的  ↑ 覆盖缺口那 1 条
```

19:08 那张图的 12 是这么来的：**合并 7 条 ＋ 库侧未并进 5 条** —
它是 `total` 的**正确读数**，而且卡里另有一句「另有 5 条未并进本卡」写着这件事。
**抬头从来就没有和条目分家。**

真正挂错的是**报告门槛**：它读的是**机读旁挂的 `issue_count`**（那一单是 5），
而人看到的是 `total`（12）。两个数不同 ⇒ 人觉得「明明 ≥3 却没链接」，
库里却认为自己「按 PRD 正确执行了」。

### 差点发出去的回归

我第一版把 `mergedCount` 接成 `dual.merged.items.length`（=7）——
那会**把库侧那 5 条丢掉**，并与卡里自己那句话自相矛盾。

抓住它的是**把夹具换成真实那个形状**：库侧判到 5 条、但 PRD §5.3.3 规定 ≥3 时只出分类汇总
⇒ 逐条抠不出来（`txtN=0`）⇒ `kbGap=5`；模型侧 7 条 ⇒ `total=12 ≠ merged=7`。
**夹具要是随手挑的（两边数字恰好相等），这个回归会一路绿着上线。**
判据见 `tools/test_agent.mjs` 的 `Z14`。

### 顺带记一条：验证动作改掉了它要保护的东西

变异脚本跑全量套件、被 harness 的 **60 秒超时杀掉**，于是 `agent.mjs`
**停在了变异态**（`mergedCount: 12`）。而守衡 **09:25:18** 恰好在那前后起来过一次 ——
**它读到的是哪一版，我无法从盘上判定，如实标未测。**

这正是 `AGENTS.md` §2.4.4 那个形状。修法两条，缺一条还会再犯：

1. 变异/自证脚本整段包 `try { } finally { 还原 }`；
2. **别跑全量套件** —— 跑**聚焦探针**（只验那一条不变量）。超时就是因为跑了全量。

### 原始诊断（保留）

Owner 的原话：

> 「发给守衡文案/图片/视频，守衡输出的建议都是『**转对应负责人复核**』。

### 根因（已全部定位，不是推测）

| 位置 | 现状 |
|---|---|

### 修法（5 处，全在本仓）

1. `kbFindingsOf` 抠出 `**建议**：…` → `suggestionLine`
2. `pickKb` 带上 `suggestionLine`
3. `pickModel` 带上 `suggestion`
4. `model_side.mjs`：SYSTEM 与 JSON 字段里加 `suggestion`（要求**可执行的改法**，不是「转人」），`parseFindings` 保留它。
   ★ 这一处**必须真调一次 LLM 验证**模型确实会给具体改法 —— 只改提示词不验输出，等于没改
5. `renderMergedItem`：`建议` 用库侧／模型侧给的原话；**两侧都没给时如实说**
   「（两侧都没给修改建议 —— 这一条只有现象，没有可执行的改法）」，**不许**再用「转对应负责人复核」冒充

### 两条边界

- 块尾那行动作行（`建议转 @内容治理负责人 复核。`）**不动** —— 那是 PRD §5.3 的**收尾**，
  与**逐条的**建议是两件事。改它会把 §5.3 的格式契约打破（`prd53.conforms` 在核）。
- 建议**必须标来源**：库侧的带条款号（可回源），模型侧的要标「模型给的改法，无库内依据」——
  否则读者会把模型编的改法当成库规要求。
