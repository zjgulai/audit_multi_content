## 一、现象（Owner 看到的那张卡）


同一单在盘上同时存在**两个结论**：

| 落点 | 结论 | 读数 |
|---|---|---|
| 链发布的知识库报告 `rv-20261022-163806.feishu.md`（链自己的 KB：`~/Documents/skill-test/…/知识库/内容治理/kb/l7/reports/`） | **PASS** | 0 条 / 0.93 |
| 链回答（agent 正文，§七「合并结论」） | **REVIEW** | F1 软物贴近、F2 监护器暗示 |
| 飞书表：链自己那一行 `reczz28QOQbeo7Ug`（内容 ID `AD-20261022-021`） | **PASS** | 引擎读数 |
| 飞书表：守衡另建的一行 `reczz28QOSDyDcFU`（内容 ID `AUTO-de10735dbcc2`） | **REVIEW** | 0 处 / 0.93 |

**同一张图、两行、两个结论** —— 读表的人无法判断以哪行为准。

## 二、根因（两处，缺一条都不成）

### 1）落表去重只认两把锁，认不出「链自己建的那一行」

`tools/agent/review_publish.mjs::ensureReviewRow` 原先按：

1. **时间窗内的「送审问题」匹配**（`sameQ`）；
2. 兜底：**内容 ID**（我们算的 `AUTO-<sha(送审文本)>`）。

而链发布时用的是**它自己的内容 ID**（`AD-20261022-021`），送审问题也不同
（链写它的审核任务、守衡写「原文＋媒材链接」）⇒ 两把锁全不中 ⇒ **新建第二行**。

机读旁挂 `kb/.work/last_review_result.json` 里其实带着链的 `content_id`
（本单 `AD-20261022-021`），但这条读数**从来没进过落表**。

### 2）引擎读数与最终结论不一致时，汇总格不说

`tools/agent/agent.mjs` 的 `summaryText` 分支只覆盖了
「图没进来 / 视觉核对缺项 / 链没跑成 / P0 / 拒答 / 库侧没读数」六种，
**引擎 PASS、最终 REVIEW** 这一种掉进兜底话术：

> 链已跑完（201s）。结论原文见对话与报告；本行由守衡在链返回后核对落表。

于是表行读起来像「0 处问题的正常结论」，而结论却是 REVIEW。

## 三、修法（两处，各带执行点与反向对照）

| # | 改哪 | 判据 |
|---|---|---|
| 1 | `review_publish.mjs::ensureReviewRow` 新增 `chainContentId`；在**本次时间窗内**按**全等**认链那一行（第三把锁，排在「窗口里唯一一行」之前） | `tools/agent/review_publish.test.mjs` 新增「链自己建过这一行（内容 ID 与我们不同）⇒ 必须补它，不许再建第二行」＋反向对照「不传 chainContentId ⇒ 不许动窗口里那一行」 |
| 2 | `agent.mjs` 落表时传 `chainContentId: res.review.content_id`；新增汇总分支：`conclusion` 与 `res.review.state` 不一致时写「引擎读数 X（N 处 / 置信度）／最终合并结论 Y —— 两者不一致，以最终结论为准」 | `tools/test_agent.mjs` 新增 **Z46b**：正向（PASS→REVIEW 必须写出不一致）＋反向对照（一致时不许写）＋**接线断言**（落表真的拿到 `chainContentId`；链没给时不许编） |

**边界**：
- 第三把锁**只在时间窗内**、且**全等** —— 不给它「猜」的权力；
- 汇总格**只搬读数、不解释原因**（覆盖判据是链判的）；
- 不改任何判定（PASS/REVIEW/BLOCK 的判据一个字节没动）。

### 3）判定主体的 F 型条目抽不进结构化（同一单，第三处）

本单链的回答里 5 条实质问题是 `**F1（优先 2｜…）**` ＋
`- 位置：…` / `- 为什么：…` / `- 建议：…` 的形状，而 `skill_findings.mjs`
只认「粗体问题清单/问题优先级」+「八、分级结论」三种锚点、以及 `1.` 编号行
⇒ 抽出 0 条。后果不是"没上卡"（模型把这些写进了卡片正文），而是：

- 表行「问题数量」= **0**（5 条只在散文里）；
- `renderMerged` 返回 null ⇒ **不建合并报告**、报告链接空（门槛 ≥3 条）；
- 卡片结论/证据全靠模型自拟 —— 模型少写一条，**没有任何东西会红**。

修法：`skillFindingsOf` 增加
① 标题级锚点（`### 问题清单（按 skill 优先级排序）`）；
② F 型条目解析（`**F<n>（…）**` + `- 位置/为什么/建议`，`降权` 整条不上卡，没位置就丢）。
执行点：`tools/agent/skill_findings.mjs` 的自证（10/10，新增 2 条，含反向对照）
+ `test_agent` 的 **Z46c**（F 型条目必须进双轨：问题数 ≥3、回建报告）。

真单回放（把本单链的回答原文喂给 `skillFindingsOf`）：抽出 **4 条**
（F1 安全 / F2 图文一致性 / F3 事实无法确认 / F4 型号字形），F5 按「降权」跳过；
接进 `runSubmissionGate` 后：`issueCount 0 → 4`、结论仍 REVIEW、
汇总格变成 PRD 结论块并带报告链接。**卡面抬头会由「BM04/BM01 对比图：…」
变成 `【审查结论：REVIEW】共发现 4 处需人工确认。`**（PRD 要求的形状；
原抬头按「搬不是砍」进正文/证据）。
