## 一、改成了什么

### ① 审查对象（报告第二节之前新增一节）

```
## 审查对象

> **送审内容**：文案 951 字
> **文案**：<对方真写的那段原文，超过 400 字截断并写明「全文 N 字」>
> **图片 1**：[点开查看](https://momcozy-in.feishu.cn/file/…)
> **图片 2**：链接未生成（取字节没成：403）
```

三条口径（每条对应一个坑）：

| 口径 | 为什么 |
|---|---|
| **文案取 `userText`，不取 `question`** | `question` 是拼给模型看的那一轮，里面夹着我们的探针（`【对方这条消息里附了图…】`）与 OCR 全文 —— 直接印就是**内部指令外发**（`media_link.mjs` 头注记着 54 行这么写过）。不传 `userText` 时退回 `question`，但**必须过 `stripInternal`**。 |
| **图/视频只印能点开的链接** | 链接来自 `media_link.collectMediaLinks()`：上传到飞书云空间 `守衡送审素材/<YYYY-MM>/` ＋ 设「组织内可阅读」＋ **回读确认**。没拿到 ⇒ 照实写「链接未生成」并带原因。 |
| **裸 URL 单列一格** | markdown 里长链接会被折断；素材里真带着网址（本单就有 `production.it`）时，单独一格更稳、更明显。 |

### ② 原因只说原因（`businessReason()`）

改前那一条逐字：

```
原因：H02 催乳/增产/奶量产出承诺（含裸 more milk、…、无 FDA/临床证据）；
      放松叙事+限定语（natural let-down/may help）走 M07 语境守卫；
      M01 静音程度夸大（建议改为 low noise / quiet mode）
```

改后：

```
原因：催乳/增产/奶量产出承诺（含裸 more milk、…、无 FDA/临床证据）
```

丢掉的是三类东西，一样都不是「原因」：

1. **规则码**（H02 / M07 / M01）—— 内部编号，业务侧读不懂；
2. **别条规则的编排**（`走 M07 语境守卫`）—— 那是在讲规则之间怎么分工，不是这条为什么命中；
3. **改法**（`建议改为 low noise`）—— 改法本来就有「修改建议」那一格，原因里再写一遍，
   读者分不清「这是判定理由」还是「这是要我做的事」。

### ③ 禁止后台词（`stripBackendTokens()` / `businessBasis()`）

只认**有形状的内部标识**：内部坐标 `#广告文案明细/rec…/命中片段`、记录主键 `recv…`、
消息/会话/用户 id、表 id `tbl…`、应用 id、模式 id `p-…`、图片 key、≥32 位十六进制（sha/md5）。
**裸数字、条款号（W-1.18）、产品型号（M6/M8）、`P0`/`合规`/`全文` 这类正常短值一律不动。**

清扫范围是**整份报告**：问题清单六格 ＋「问题总览」表的每一格（上一轮只清六格 ⇒
记录主键会从表里再漏一次，判据 Z49c 当场抓住）。

## 二、当天改完第一版就翻车的两处（都留了反向对照）

这两条值得单独记：它们都是**「判据太宽、把正常东西一起删了」**，而不是漏删。

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 依据里的直链被改成 `…?table=&record=` ⇒ **点开是错页** | 对整段文本做替换，把 **URL 的 query** 也当正文挖了 | 先把 URL 存成占位符，清扫完再放回来（Z49c 钉死：直链**一个字符都不许变**） |
| 2 | 总览表六列只剩「命中描述」，清单的**维度/位置全空** | 「≤3 字的分段一律丢」把 `P0`、`合规`、`全文` 当成了空标签 | 只丢**那几个内部标签名**（指纹/锚点/模式/表/记录/坐标/主键/id/sha） |
| 3 | `best/#1/No.1/最佳` 被删成 `best/.1` | 内部坐标判据 `#…/…` 没有要求**第一段含中文表名** | 加约束：`#` 后面第一段必须含汉字 |
| 4 | 原因结尾的 `。` 被剃掉 | 「清残渣」的正则把句号也当成了残渣 | 只清 `；，、`：句号是正常标点 |

四条现在都钉在 `Z49b`/`Z49d` 里，**拆掉修法就精确变红**。
