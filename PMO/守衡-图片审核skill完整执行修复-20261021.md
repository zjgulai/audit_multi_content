# 守衡图片审核 skill 未完整执行：根因与修复

日期：2026-10-21

## 问题与证据

Owner 报告：在飞书向守衡发送图片后，DeepSeek harness 没有完整执行知识库中的「图片安全审查」skill。

复核 2026-10-21 11:33 的真实事件 `om_x100b62b7667cd4accf232231c052fab`：守衡入站解析到 1 张图，本地画面识别与 OCR 均有读数；知识库评审链也运行并产出报告 `kb/l7/reports/20261021-113433.review.md`。这证明图片接收和评审链不是断点。链的 RUN 把 `图片安全审查` 写在 `loaded_skills`，但 `decision_owner.mode=declared`、`declared_by=agent`；知识库适配器明确标记这是 agent 自述，不能证明 DSH 实际调用了 `skill` 工具或执行了技能的完整规程。

根因在守衡向 headless DSH 拼装的任务：图片任务的前置命令模板写了 `--decision-owner` / `--loaded-skill`，但这些只是传给评审引擎的声明字段。真正的「用 DSH skill 工具加载专项 skill」要求位于较后的长 playbook 中，任务没有在前置步骤中强制执行整个图片审查流程。因此 DSH 可以执行知识库命令并形成审核报告，却跳过或只执行图片 skill 的部分步骤。

## 修复

在 `tools/agent/tools.mjs::reviewTaskFor()` 为图片任务添加最高优先级的专项执行指令：

1. 要求先真实调用 DSH `skill` 工具加载完整的「图片安全审查」规程。
2. 要求对本轮原图逐张完整执行 skill 的审核范围、视觉/OCR、主张拆分、4A 知识库规则符合性、4B 事实核查、图文一致性/完整性与分级结论步骤。
3. 将 `review_run.sh` 唯一命令作为 4A 的组成步骤，只跑一次；命令不能替代 skill 其他步骤，也不能重复起链。
4. skill 未加载、原图不可读或任何完整流程步骤未完成时，返回 `NEEDS_INPUT`，不得输出三态结论；不再接受 `--loaded-skill` 自述作为真实执行凭据。

在 `tools/test_agent.mjs` 的 N4c 回归断言中检查任务顺序、原图路径、完整技能步骤、4A 命令唯一性与 fail-closed 约束。该测试在改动前按预期失败（293 过 / 1 失败），最终完整内核自证 294 过 / 0 失败。

定位到三个具体缺陷：

1. `kb/l7/skills/kb-content-review/scripts/review.py` 两层结果按 `article_no` 去重。语义层先命中条款时，图身份层更强的精确匹配被直接丢弃，致使 `match_rank=4` / 精确图像 / subject 归属没有进最终命中。

3. 报告没有带出 `trace.image_identity` 的检查/命中/升级读数；记录级说明还硬编码为“同一记录多图”，本例实际记录只有一张图。

修复已同时写入 DSH 知识库代码和图片审查 skill：

- 新增 `self_negative.merge_image_identity_hits()`：仅同一 `article_no + record_id` 才由身份命中升级同一条语义命中；保留被升级的语义审计信息；跨记录身份命中另行保留，避免按条款号串图。`review.py` 已接线，并把新增数、升级数分开写入 trace。
