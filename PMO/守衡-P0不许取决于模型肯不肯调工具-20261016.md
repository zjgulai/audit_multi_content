## 二、修法：内核在闸门不起链时**自己**跑一遍，且**只读**

| 层 | 落在哪 |
|---|---|
| **一个产出者** | `tools/agent/tools.mjs`：把注册体里 P0 那一整块（报告复用/生成 → 回执重渲染 → 两端对齐 → 返回体）抽成 `runP0Preflight()` ＋ 内层 `p0HitPayload()`。工具那一支改成一个转发（`allowPublish: true`，行为逐字不变） |
| **只读那条路** | 同一个 `runP0Preflight()` 的默认参数是**纯只读**：`reportOut=''`（不落报告文件）、`allowPublish=false`（不建云文档、不写飞书）。理由见下 |
| **接线** | `tools/agent/agent.mjs`：`if (!gate?.yes) p0Preflight = await runP0Preflight({ text, question })` —— 排在闸门之后、模型之前；失败一律按未命中算 |
| **兜底两来源** | `verdict53Final`：`g.verdict53` → `p0Payload`（工具来的 / 内核前置来的）→ `toolTrace` 那一支。**先判有没有载荷，再决定走哪一支** |
| **报告链接** | `reportLink: g.dual?.reportUrl ?? (p0Preflight?.report || null)` |

### 为什么前置那一遍必须**只读**（Owner：「你的优化不要影响现有的工作流」）

- 「闸门判不是送审」那条路**以前从来不建云文档**；在这里开始建，等于顺手改了别人的工作流。
- 代价说清楚：这一条路上**报告链接可能是空的**。而 PRD §5.3.3 对 1–2 条**本来就不要求报告链接**
  （≥3 条才要），所以卡面契约不受影响；已有报告时仍按内容 ID **复用**那个链接。
- 一行都不往飞书写 ⇒ 也正好回答模型那个顾虑：**同一句话再问一次不会多写一行**。

### 顺带钉住的一条：**「块在卡里」不等于「人看得见」**

验的时候我差点被自己骗过去：纯文本降级渲染器 `registry.renderText()` 对**所有** collapsible
一律打成 `（已收起 N 条证据：…）` —— 拿它当判据会**误报**成「块没上卡」。
真正要钉的是**建出来的那个元素**：

```json
{"tag":"collapsible_panel","expanded":true,
 "header":{"title":{"content":"逐条问题"}},
 "elements":[{"tag":"markdown","content":"1.【绝对化】…\n  原因：x\n  依据：y\n  建议：z\n\n请修改后重新提交。"}]}
header: {"title":{"content":"【审查结论：BLOCK】共发现 1 处必须修改。"},"template":"green"}
```

`expanded: true` ＋ 那一组**内部**有原因/依据/建议/动作行 ⇒ 群里默认展开，看得见。
★ Owner 两次看到的那个形状（只有一行结论），正是这一格为 `false` 时长出来的 ⇒ `Y8` 现在钉它。

> ⚠️ 一处形态口径：**数据层**（`r.data.groups[0].content`）保留 `**原因**：` 原文，
> 而**卡元素那一格**是渲染后的形态（`原因：`）—— markdown 元素把 `**…**` 转成了 rich text。
> 两边都查（数据层查四要素、卡元素查默认展开那一组），因为「数据层有、卡上没有」也是真事故。
