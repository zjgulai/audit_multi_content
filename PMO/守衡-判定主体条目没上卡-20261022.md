## 二、根因（一句话）

> 卡内逐条来自**双轨合并结果**；库侧条目抽的是**机读旁挂的 `risk_items`**（结构化优先）。
> 引擎这份只给了 3 条负面样本命中，位置全是「顶部，图 1 第 1 处」、类目全是「品牌信任与声誉」
> ⇒ 按对齐规则「位置相同 + 类目相同」压成 **1 条**。
> 而 skill 那 5 条判在**散文**里，**没有结构化产者** ⇒ 一条都上不去。

复现（离线，喂真实回答与真实旁挂）：

```
kb.findings = 3   合并后 = 1
```

### 合并语义一个字没改（这是要守的边界）

`source` 仍是 `'model'` ⇒ 仅模型侧命中：**并集、倾向 REVIEW、不由它单独定 BLOCK**、
不参与 PASS 的成立条件。真正的 BLOCK 仍只来自引擎 P0 / 条款层。

### 四条边界（都在自证里钉着）

1. 没有位置 ⇒ **丢**（位置是合并对齐键的一半，编一个会把两条不同问题并成一条）
2. 标了「参考 / 非本图判定 / 降权」⇒ **整条丢**（那是历史意见，不是本单问题）
3. 严重度**只给 REVIEW**
4. 抽不到 ⇒ `note` 里写清原因，日志出 `🧩 判定主体核查：**一条都没上卡**`

## 七、追加：两件 Owner 点名要查的（同日）

### 7.1 模型侧 1006ms / 0 条 —— **不是故障，是真的答了空数组**

| 检查 | 读数 |
|---|---|
| 是否走缓存 | **否**（缓存命中会打 `[image-review-cache] image findings reused` 且 `ms:0`；日志里一条都没有） |
| 是否被解析过滤掉 | **否**（缓存里空结果均 `dropped: []`、`basis.total: 0`） |
| 原图是否送到 | **送到**（`requiredImageCount=1`，不足会 `ok:false`） |
| 失败与 0 条分不分得开 | **分得开**：失败印 `模型侧 没跑成：输出里没有 JSON 数组｜raw=N 字`；本单印 `模型侧 0 条 / 1006ms` |

结论：接线正常，模型回了个合法 `[]`。**不是 bug**，是这一遍判据偏保守（单发语义复核、`temperature 0`、
`thinking disabled`、提示词带「不许编」三处硬约束）。要动它是行为变化，不是修缺陷。

### 7.2 「建议」两份 —— **确认是 bug，已修**

卡上印的是库侧历史原文，本单生成的那份被静默丢掉（`建议生成 ok/4139ms｜覆盖 1 条` 却不上卡）。

复现（只改 `relatedArticleNos` 长度）：
- `['N-1.360','N-1.132']` → 卡上：不要过于完美…（历史原文）
- `['N-1.360']` → 卡上：本单生成的那句

根因：`renderMergedItem` 的 `hasAggregatedKbAdvice`（>1 条同位置条款）分支直接返回 `sugKb`，`adv` 不再参与。

修法：**`adv` 优先**（回到 Owner 2026-10-09 口径），库内聚合建议留在**报告**（「卡短、报告全」）。
⚠️ 这一改**反转了同日早些时候钉下的断言 ⑦b2**（原断言：「聚合的库内建议优先」），已按后令更新并写明理由。
反向对照：没有生成改法时，卡上行为**逐字不变**（仍印库侧原文）。

自证：`dual_track --selftest` 55/55、`test_agent` 303/303、`verify_cards` 350/350。
