## 一、病灶的形状（一句话）

**一个固定路径的中间产物 ＋ 一个「判据看见了但没拦」的分支 ＝ 别人的结论贴到你的素材上。**

知识库那条链跑完后，把机读读数写在**两个固定文件**里：
`kb/.work/last_review_result.json`（旁挂）与 `kb/.work/last_engine_out.json`（引擎 JSON）。
**每跑一单，整份覆盖** —— 并发时后写的那个把先写的盖掉，与"谁的单"无关。
守衡这一侧是**读文件**取读数，于是：**读的那一刻文件里是谁的，就拿谁的。**

实测（2026-10-15）：她那单 17:53:33 跑完（0 条），批跑那单 17:54:39 跑完（1 条），
守衡 17:55 去读 ⇒ 拿到批跑那单的结论，并随报告发进了群。

## 二、四把锁（各自怎么算、实测底细）

| 锁 | 算式 | 实测底细 |
|---|---|---|
| **令牌** | 链把收到的 `--material-file` **路径**原样回写进旁挂 `review_token`；守衡比对自己造的那个路径 | **能用但基本是空的**：全量日志里只对齐过 **1** 次 —— headless 常常不转发那个路径 |
| **文本指纹** | 两端同一个算式：`sha256(素材文本)[:8]`（守衡算，链写进 `text_sha8`） | **最可靠**：2026-10-09 16:21 起连续 **34 次**对齐；归档对也已核（旁挂 `52412e4d` == 报告 `20261015-195446` 的 `sha256(input_manifest.text)[:8]`） |
| **内容指纹** | `content_version` = `sha256(素材文本)` **全值**（只在引擎 JSON 里） | **可靠**：抽查最近 44 份评审报告 **44/44** 相符 |
| **内容ID** | 守衡算 `AUTO-<sha12>`；旁挂里却是 `AD-<日期>-<序号>`（业务号） | **按构造永不相等** ⇒ 它**不是一把锁**，留着只为万一对方改写法 |

## 三、判定与拒收语义（**别退回「按时间口径采纳」**）

判据只有一处：`tools/agent/tools.mjs` 的纯函数 `identityVerdict({sinceMs, at, want, got})`。

| 情形 | 结果 | 对外表现 |
|---|---|---|
| 任一把锁对上 | **认**（`level` 说明靠哪把） | 照常出结论 |
| **四把全不成立** | **拒收**（返回 `null`）＋ 一行 ⛔ 日志（带四个读数与旁挂自报的 `base`） | 按「**库侧没读数**」走 ⇒ 回落成「库侧本次未参与」，**不是**「库里说没问题」 |
| 旁挂缺失 / 不新鲜（`at` 早于本次起链） | 同拒收 | 同上 |

**为什么必须是拒收而不是告警**：`AGENTS.md` 里那句「宁缺勿错 —— 张冠李戴比没有更坏」。
2026-10-08 曾经把「拒收」降级成「只告警」，理由是当时两把文本锁**实测 6/6 全不成立**
（链把身份算在它自己组装的那段文本上）；那件事后来修掉了（令牌锁 ＋ 算式对齐），
**只告警留下的口子就是 10-15 那次串单** ⇒ 别照着旧注释退回去。

## 四、执行点（改这条链必须同时改它们）

| 执行点 | 拦什么 |
|---|---|
| `tools/agent/tools.mjs` 的 `identityVerdict` / `readReviewSidecar` | 旁挂的身份判定与拒收 |
| 同文件的**引擎 JSON 读取**（`last_engine_out.json`） | 它此前**只核"新鲜"、不核身份** —— 而逐条依据（条款号/锚点/L0 直链）全从它来 |
| 素材规则排在任务**第 0 条**（`kb_review_chain` 的 task 组装） | 让链真的带上 `--material-file`（令牌锁的前提；带漏了不会报错，但并发时会认错结论） |
| `node tools/test_agent.mjs` 的「旁挂身份」两组 | 判据表（含两条反向对照）＋ 行为级（真读文件：别人的必须拒、本单的必须采纳）＋ 接线（`--material-file` 必须排在 playbook 之前、素材文件用后即删） |
| `tools/re_review_reply.mjs` 的**起链前预检**与「链没跑成就不发」 | 人工重审这一路不许在注定失败的环境里发卡（实测吃过一次：故障卡进了群，而根因是跑它的沙箱） |

## 五、人工重审为什么不能走「补发队列」

`retry_queue` 的补发走 `handleMessage(event, { force: true })`，而 **`force` 的语义是「重放不重跑」**
（链会真写飞书，重跑等于同一单写两遍）⇒ `runSubmissionGate` 见到 `force` 直接回
`gate:null / chainRan:false`，**一条链都不起**。重审要的正好相反：**必须真跑链**。
⇒ 入口是 `tools/re_review_reply.mjs`（人工触发）：隔离状态目录（去重表在模块加载时读，
不隔离只会回 `duplicate`）、台账指回真文件、形态与发送复用同一条链、**不做「新发一条」的兜底**。
