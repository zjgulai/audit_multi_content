# 守衡模型端点切到中转站（2026-10-22，Owner 明确同意）

## 为什么要切（一句话 + 一条读数）

DeepSeek 官方端点的账户**额度耗尽**：`PMO/logs/llm_failures.jsonl` 里 **67 条**
`HTTP 402 Insufficient Balance`（`model=deepseek-flash`、`base_url=https://api.deepseek.com`、
`retryable:false`），时间窗 **2026-10-22 11:23:04Z → 11:49:26Z**（北京 19:23–19:49）。
它同时打死三处：主模型（`llm.mjs`）、画面层（`scene.mjs`）、4B 事实核查（`web_search`）。

后果不是「慢一点」，而是**答话退化成代码兜底**：19:23 之后群里那几条回复的正文
（包括 Owner 截图甩回来的那句「请重新发送原图」）**是 `agent.mjs` 里拼出来的字符串**，
模型一个字都没写。重启后启动横幅第一屏就写着 `画面层(吃图模型) = ❌ 不可用（HTTP 402）`。

## 为什么密钥不写进 plist / 仓库

`plist` 在版本库里，写进去等于提交密钥；仓库里的 `.env` 同理。所以放在 `~/.dsh/shouheng-llm.env`
（600）。launchd **不继承 shell 环境**（plist 里只有 `PATH`/`LANG`），这正是必须由
`run_shouheng.sh` 去读它的原因 —— 而不是「顺手 export 一下」。

**删掉那个文件 = 一键切回 DeepSeek 官方端点**（因为 `config.mjs` 的默认值没动）。

## 红线口径（§2.6 此次变更的实质）

换端点的真实后果是：**人发给守衡的图片字节、以及素材文字，现在会经过第三个服务商**。
这一条不因为「端点是 OpenAI 兼容」而消失。所以：

- 这次变更是**一次口径变更**，不是一次配置调整 ⇒ 已在 `AGENTS.md` §2.6 按日期留痕；
- 进那条链路的仍然**只有**：当前这条消息（或它引用的那一条）里的图/帧、以及素材文字；
- 仍然**不归档、不进知识库、不转发**；临时件用完即删；
- 这台机器上用的那个密钥建议**轮换一次**（它在 2026-10-22 的对话里明文出现过）。

## 边界（明着留着）

1. **换端点不等于换模型能力**：中转站是 DeepSeek 兼容层，但它的**算力与版本**由对方决定，
   我们只验了上面那张表里的能力，**没验**长上下文、并发上限、限流策略。
2. **`deepseek-flash` 这个名字在中转站上指向哪个具体版本，我们无法确认**。所以本件只声称
   「这个端点上的这个名字满足守衡的四项能力」，**不声称**「与 2026-10-15 那次实测是同一个模型」。
3. **额度不再是 DeepSeek 那边的事**：再出 402 只会出现在中转站上；`humanizeSceneError`
   与横幅都会如实报，但「余额还有多少」我们读不到。
4. 探针脚本（`test/_probe_relay*.mjs`）读 `RELAY_BASE` / `RELAY_KEY` 环境变量，
   **不含任何硬编码密钥**；它们只发合成的 64×64 PNG，可以随时重跑。

### 第一次重启没生效 —— 一个「看得见 ≠ 生效」的实例

第一轮改完 `run_shouheng.sh` 重启后，启动器打了
`端点配置 = ~/.dsh/shouheng-llm.env（base=中转站）`，**而进程横幅仍是
`llmBaseUrl = https://api.deepseek.com`、`llmKeyFrom = DEEPSEEK_API_KEY（凭据库）`，画面层还是 ❌ 402。**

真因：`. 文件` **只赋 shell 变量、不导出** —— `exec node ws_daemon.mjs` 那个子进程一个变量都看不到。
**启动器自己那句「端点配置 = …」读的是它刚读到的值，不是子进程会看到的值**，
所以它打印得很像成功（AGENTS §2.2 第 3 条：界面上看得见 ≠ 已经生效）。

修法：`set -a` 把 source 包起来，并且启动器**改打「密钥=35 字符」这种能证伪的量**
（变量名写错 / 没导出，这一格就会是 0 字符）。

## 部署时顺带修掉的第二处：**重启闸门看不见「启动器」**

第一轮走闸门时它报的是：

```
重启会生效    无 —— 启动之后没有任何被 import 的模块或被调起的脚本被改过
              （那这次重启不带来任何运行时变化，先想清楚为什么还要重启）
```

而那一轮我改的正是 `tools/run_shouheng.sh` —— **它就是 launchd 要执行的那个文件**。
闸门只扫两类：图里的 import、图内代码 `path.join(REPO_ROOT,'tools','x.py')` 指到的 spawn 目标；
**launchd 的 `ProgramArguments` 不在任何一类里**。

这条读数是 §2.7 里「判断时机的唯一硬依据」，它说错话的直接代价是**让人放弃一次该做的重启**
（我差点就信了「没有变化」而跳过）。

修法：闸门新增第三类「另（启动器）」——从 plist 的 `ProgramArguments` 取（**不写死文件名**），
与本仓 `tools/` 下同名副本对齐后按 mtime 过滤；`--check` 现在会打
`另（启动器） 1 个启动器在启动后被改过 —— tools/run_shouheng.sh`。
执行点：`verify_shouheng_ops.py` 的 **B8 / B8b / B8c**（`--since=0` 必须列出启动器；
`--since=未来` 必须为空；「无变化」那句话必须提到这一类）。台账 `FIX-065`。
