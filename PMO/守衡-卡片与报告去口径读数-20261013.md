## 二、改动（四个文件 ＋ 三处自证）

### 2.1 `tools/agent/dual_track.mjs` —— 口径读数不上卡

`renderMerged` 的 `block` 里原先拼着六样东西，**其中五样**属于「我们自己核对用的口径读数」：

| 字段 | 印出来是什么 |
|---|---|
| `tally`（含 `candNote`） | 「知识库侧 **未报内容问题**；另有 **1 条覆盖缺口**… ／ 模型侧 7 条（其中 7 条**无库内依据**，只能转人工）」 |
| `gapNote` | 「⚠️ 知识库侧另有 **N 条**未并进本卡：PRD §5.3.3 规定问题数 ≥3 时…」 |
| `covNote` | 「ℹ️ 知识库侧给了 **覆盖缺口**（`coverage_not_covered`）…」 |
| `noReadNote` | 「⚠️ **本次知识库侧没有读数**…」 |
| 汇总页脚 | 「（问题数 **8 ≥ 3** ⇒ 按 PRD §5.3.3 只出分类汇总…）」 |

⇒ 这五样**整族**搬进 `internalNotes`（新出口），`block` 只剩 PRD §5.3.3 要的四样：
**结论行 · 报告链接 · 分类汇总 · 动作行**。

⚠️ **只删了两样东西**，两样都不是「读数」而是**错误措辞**：
`categorySummary` 里「（见报告与**计数口径**）」那半句（报告里已经没有这一节了）、
以及那句页脚（搬走，不是删）。

**为什么是整族一起搬，而不是只搬 Owner 点名的那三句**：`gapNote` / `noReadNote` 与它们
是**同一种东西**（讲「哪一侧说了话、有几条没并进来、与 PRD §5.3.3 什么关系」），
Owner 的原话是「**类似**以下的文案都去掉」。留着它们，下一次截图还是同一张。

### 2.2 `tools/agent/agent.mjs` —— 「我问的时候你要能回答」的执行点

`chainBlock` 后面追加一段**明确标注**的笔记：

```
【★ 我的查证笔记 —— **只用来回答对方的追问**。它**不上卡、不进报告**：这一轮的回复里
**一个字都不许出现**（要转述的只有上面那一块）。】
知识库侧 … ／ 模型侧 …
ℹ️ 知识库侧给了 覆盖缺口…
【★ 查证笔记结束】
```

**位置就是判据**：`chainBlock` 既是**这一轮**发给模型的正文，又被 `mem.append` 写进
**会话记忆** ⇒ 这一轮答得出、下一轮也答得出。而卡片与报告都只从 `rendered.block` 渲染，
**不经过这一段**。

### 2.3 `tools/reply-cards/envelope.mjs` —— 两件事

1. **组标题改名**：代码建卡（模型没给卡片块时）那一组原先叫 **「模型原话（原文照留）」**，
   改成 **「详细说明」**。「模型」是我们的说法，对群里的人是零信息量。
   ⚠️ **改名不是删标题** —— `cards.mjs` 的 `collapsible(String(g.title ?? ''))` 会把空标题
   渲染成一个**空头的折叠面板**，那不是「去掉废话」，是换了一种坏法。
2. **`stripInternalNotes()`（新，纯函数，已导出）**：模型若把查证笔记照抄进回复，
   **进群之前按行摘掉并留痕**。判据是**我们自己的那几种固定形状**（8 条正则，逐条能指得出
   产者），不做泛化匹配 —— **理由与反向对照写在函数头注里**：写成「凡出现『知识库侧』就摘」
   会把 `知识库侧 3 条与素材相关` 这种**如实转述**一起摘掉（J13c 钉着）。
   位置在 `toCardOrText` **最前面**（早于 `extractCardBlock`）—— 晚一步摘，抄进卡片块 JSON 的就认不出来了。

> 「不许写进回答」不能只是一句提示词（AGENTS.md §2.4）⇒ 执行点两处：
> **产者**（`renderMerged` 不再把这几行放进 `block`，模型没有可逐字转述的源）
> ＋ **兜底**（信封层按行摘 + 留痕）。

### 2.4 `tools/agent/merged_report.mjs` —— 报告按 PRD 字段收口

| 改前 | 改后 |
|---|---|
| `# 内容审查报告 · 2026-10-12T07:31:24.329Z` | `# <用户原问题> 内容审查报告`；没有原问题（对方只发了素材）时 `# 内容审查报告` |

| `- 结论：**REVIEW** ｜ 问题数量：**8**（知识库侧 0 条 ／ 模型侧 7 条）` | `- 结论：**REVIEW** ｜ 问题数量：**8**`（那半句就是 Owner 要去的那行计数） |

| `## 二、模型侧（无库内依据，只能转人工）—— 7 条` ＋ blockquote | 去掉 |
| `## 三、计数口径`（三条） | **整段去掉** |

★ **反向对照（Z21 最重要的一条）**：去掉的是**外层的标题与免责**，
**条目一条都没少**，且**逐条仍带来源标记**（`—— **知识库侧**` / `—— **模型侧**（无库内依据）`）——
「这条回不回得了源」决定下一步，比那两个小标题重要得多。

### 2.5 标题的一个取舍（**摆在明处**）

`titleForReport()` 把原问题**折成一行**（换行会让人掉出标题、变成正文首段）、
去掉 `` ` `` `#` `*`，并**截到 120 字**（尾附 `…`）。这是**唯一一处有意截断**：
H1 就是飞书云文档标题，而送审问题可能是**整段字幕**贴进来。
⚠️ 代价说清楚：原问题超过 120 字时，**标题里看不到后半段**，
而 `- 用户原提问：…` 那一行已被 Owner 点名去掉 ⇒ 后半段在报告里没有第二处落点。
要不要给个上限/换一种口径，**等 Owner 判**（见 §五 残余）。

## 七、三条改动

### 7.1 那两个词换掉，但「回不回得了源」必须留着

`dual_track.renderMergedItem` 的来源标记重写：

| 原来 | 现在 |

| `（**模型侧给的改法**，无库内依据…）` | `（**无库内依据的改法建议** —— 不是库规原文）` |

`NEEDS_INPUT`（库侧拒答/库忙）那一张卡里的 `知识库侧**未判**` / `**模型侧**的初步观察`
