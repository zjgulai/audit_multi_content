## 二、根因（一行）

`tools/agent/model_side.mjs::readingsForModelSide`：

```js
const body = String(inbound.text ?? '').trim();
if (body) parts.push('【素材正文】\n' + body);      // ← inbound.text 是**消息原文，含 @守衡**
```

`inbound.text` 是**消息原文**（mention 就在里面），而它被贴上了 **【素材正文】** 这个标签。
那一段是**模型侧**唯一的输入 —— 模型照着标签判，于是产出了「素材正文（发布账号名）」这条。

**链那一侧没这个问题**：`chainInput` 只在「**没有媒材**」时才把 `inbound.text` 当素材
（这条图单走的是「图内文字 + 画面读数」那一支）⇒ 唯一入口就是上面那一行。

## 三、修法（两点，缺一都不算修好）

1. **取剥掉 @ 之后的那份** —— `userText`（`handleMessage` 早就算好了：`stripBotMention(display, mentions)`，
   今天上午刚被用在落表那一格上）。`agent.mjs` 现在把它传进 `readingsForModelSide(inbound, { userText })`。
2. **标签说实话** —— 有媒材时它是**对方的提问/说明，不是素材本身**（素材是下面那些读数）：

```
【对方这条消息里写的字（这不是素材本身，是对方的提问/说明；素材是下面的读数）】
```

   纯文案单照旧是 `【素材正文】`（那时它**就是**素材）。**剥完为空就一节都不印**
   —— 不印空标签，更不拿它去判「正文为空」。提示词里那条定位规则（第 4 条）也补了这个新标签。

## 四、同一根因的第二处（顺手修掉）

置信度台账那把键也是拿消息原文算的：

```js
const materialSha8 = sha256(inbound.text)[:8];    // ← 纯图单的 inbound.text 就是「@守衡」
```

⇒ **所有纯图单会撞成同一个键**，而那一格的全部意义是「与"这一单是哪条素材"一一对应」。
改成 `input.text`（链那一侧的素材文本：图上是 OCR、视频是读数、纯文案才是原文）。
⚠️ 它**只**影响台账这把键 —— 行上的 `内容 ID` 是另一处独立计算，不在本改动范围内。
