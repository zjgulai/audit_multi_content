## 根因（一行）

`tools/agent/agent.mjs`（2026-10-22 09:54 版）：

```js
// 1225: let dual = null;
// 1549-1550（报告块，在 dual 赋值之前）：
const reportImageEvidenceFailure = reportImageCount > 0
  ? imageEvidenceFailure(res, reportImageCount, dual?.model) : null;   // ← dual 此时是 null
// 1666：
dual = { model, kb, merged, state, rendered, kbSide, mergedConf, reportUrl: reportUrlOverride };
```

`dual` 在 **1666 行**才赋值，这里读 `dual?.model` 恒为 `undefined` ⇒
`imageEvidenceFailure` 恒返回「模型侧原图视觉/语义审查未完成」⇒
`imageSkillReview` 恒为 `''` ⇒（a）报告不带 skill 全流程节；（b）`imageAnalysis` 恒空 ⇒ 卡片不带视觉分析。

> 注意：第 1811 行的同一调用在 `dual` 赋值**之后**，所以它是好的 —— 这也解释了为什么
> 「视觉核对闸门失败时能拒答（10:03/10:15）」，但「闸门通过时视觉分析仍不出现（10:07）」。

## 修法

把第 1550 行的 `dual?.model` 换成作用域里**已经存在**的模型侧结果 `model`：

```js
const reportImageEvidenceFailure = reportImageCount > 0
  ? imageEvidenceFailure(res, reportImageCount, model) : null;
```

（`const model = ...` 在 1247 行左右定义，与报告块同一个 `try` 作用域；不要改成 `dual?.model` 再挪位置也行，但挪位置要连带 `imageSkillReview`/`imageAnalysis` 一起往后放，改动更大。）

## 追加规则（Owner 2026-10-22 10:47，交接给 Codex）

> Owner 原话：「视觉分析 有问题才展示，跟结论无关；视觉分析无问题就不展示。」

### 现状（不符合这条规则）

- `agent.mjs:1557`：`imageAnalysis = imageSkillReview ? imageAnalysisDisplay(inbound) : '';`
  —— 只要求 skill 闸门通过，**不看视觉分析有没有看出问题**。
- `envelope.mjs:1258`：`visibleImageAnalysis = reviewShape ? s(imageAnalysis).trim() : '';`
  —— 又加了一道「必须是评审卡」的门 ⇒ PASS 单永远不展示；REVIEW 单无论有没有视觉问题都展示。

### 要达到的行为

| 视觉分析结论 | 卡片 | 报告 |
|---|---|---|
| 五类核对里**任一 = 有**（看得出问题） | **展示**「视觉分析与 OCR」（与 PASS/REVIEW/BLOCK 无关） | 照旧全量 |
| 五类全为 无 / 不适用 | **不展示**（PASS、REVIEW 都不展示） | 照旧全量（报告是留痕件） |

### 改法（两处）

1. `tools/agent/agent.mjs`（第 1557 行附近）

   ```js
   // 视觉分析自己有没有看出问题 —— 与结论无关（Owner 2026-10-22）
   const visualHasIssue = reportVisualGate?.ok === true
     && Object.values(reportVisualGate.found ?? {}).some((x) => x?.verdict === '有');
   imageAnalysis = imageSkillReview && visualHasIssue ? imageAnalysisDisplay(inbound) : '';
   ```

   `reportVisualGate.found` 是 `checkVisualChecklist()` 的五类结论（`{verdict, basis}`），
   是「视觉分析看出问题」的唯一现成判据，不要另造一套。
   ⚠️ `未测` 不算「有」（Owner 只说了「有问题」）；报告里仍能查到。

2. `tools/reply-cards/envelope.mjs`（第 1258 行附近）

   ```js
   const visibleImageAnalysis = s(imageAnalysis).trim();   // 去掉 reviewShape 前置门
   ```

   落点按卡型分：
   - **评审卡**（`reviewShape`）：保持现状 —— 汇总块走 `body`、逐条卡走 `groups`；
   - **PASS/query-answer 卡**：`cards.mjs` 的 `queryAnswer()` **没有 `groups`**，
     需要给它加一个折叠区（例如 `d.visual` → `<details>视觉分析与 OCR</details>`），
     或者在信封层把它塞进 `queryAnswer` 的 `evidence` 折叠区（现成的 `d.evidence`）。
     不要直接往 `data.groups` 里塞 —— `queryAnswer` 不渲染那一格，等于**静默丢弃**。
   - 注意 PASS 的「只留一句话结论」收口（`envelope.mjs` 第 1362 行）**不能把这一块一起收掉** ——
     加完要跑一条反向对照：PASS + 视觉有问题 ⇒ 卡上**必须**有这一块；PASS + 视觉无问题 ⇒ 一个字都没有。
