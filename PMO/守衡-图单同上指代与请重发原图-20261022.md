## 根因（两层，各修各的）

### ① 判据错杀：真实报告里的「同上」被当成「没给原因」

按 `kb/.work/last_chain_answer.txt`（`base=20261022-193423`，那次链的原始回答，11052 字节）回读，
报告第七节本来就是合格的：

```
| 产品状态 | **未测** | 画面层未测；OCR 里无产品名/产品物件可推 |
| 场景关系 | **未测** | 同上 |
```

「同上」是**人写表格的正常写法**，指的就是紧挨着上一条那句原因。
`basisOf()` 把这一格原样当依据 ⇒ 长度 2 字 < 判据要求的 4 字 ⇒ 判「没给原因」⇒
一份**写得很完整**的报告被判成「流程没有完成」。同一份回答里其它四类都写了原因，
链侧 `checkImageSkillWorkflow` 也是 ok（审核范围 / 视觉分析与 OCR / 主张拆分 / 4A / 4B / 图文一致性 / AAP 来源全在）。

这是 FIX-062（`上图/下图` 别名）之后**同一个病的第五次**：判据的输入范围与生产输出形状不一致，
按单次措辞补别名，没覆盖「同一语义的另一种写法」（这次是**指代**，不是新词）。

### ② 回话错位：卡点在我们这一侧，却让对方重发原图

同一单的画面读数是**没读到**，不是「没有画面」：

```
[scene] ⚠️ 端点不认 thinking 参数（HTTP 402）⇒ 退回带思考的那次请求
[agent] 🖼 画面读数**没读到**（不是「没有画面」）：图 1｜画面模型 HTTP 402：{"message":"Insufficient Balance",…}
```

也就是说**我们一眼都没看到那张图**，画面类事实（姿势 / 产品状态 / 场景关系 / 隐私）只能是「未测」。
而回话把这件事说成「**请重新发送原图**」——对方照做，重发了几次，每次都是同一句。
一句话里三处不对：

1. 判据的原话（`判"未测"但没给原因`）与内部阶段名（`逐面板视觉核对`）直接进了群；
2. 卡点在**我们**的画面模型端点（余额不足），却把责任推给对方的素材；
3. 没写清「**没测完 ≠ 没问题**」，读起来像一次放行。

## 为什么还要加「画面读数没读到 ⇒ 不出结论」这道闸

1. PRD §5.1 把图片输入写成两半（OCR ＋ 基础视觉）；画面那一半没跑成时，
   「图片安全审查」里的**视觉分析**这一步无从执行 —— 而判定主体照样能交出一份格式齐全的
   清单（这一单就是：五类全「未测」，依据写「画面读数没跑到」）。
2. 那一单链给了 `REVIEW`（依据是 OCR 文字）。**没看过画面却给出画面类结论**，在卡面上读起来
   跟「审过了」一样 —— 与 2026-10-21 Owner 批的那条（「看到了图、一张都没解析出来 ⇒ 本单不收」）
   是同一个形状：**零条不是没问题**。
3. 边界一个字没松：只挡图单、只挡「画面这一半没读数」；`P0` 确定性命中照旧豁免
   （PRD §6.3 命中即停止后续审查，那张图本来就不该被看）；`skipped`（按设计不跑）不算缺口。
   反向对照在 N4d ⑤d：同一份回答 + 画面读数正常 ⇒ **不许**被这道闸拦。

## 边界（明着留着）

1. **这是判据与话术的修复，不证明任何一张具体图片安全或合规。**
2. **画面层端点余额不足是我们环境的问题，不是本修的判据问题**：修完之后的每一个图单
   都会如实收到「画面这一层我没读到（HTTP 402 · 额度不足）」，而不是一个三态结论 ——
   **充值之前，图单拿不到画面类结论**。这一条必须让 Owner 知道，不能让它伪装成「又拒答了」。
3. **不做自动补跑**：现在没有「端点恢复后自己重跑」的机制，所以话术里只说
   「等端点恢复你再发一次」，不承诺自动化（§2.4.2：承诺必须有执行点）。
4. `agent.mjs` 是**多个会话同时在改**的文件；部署时重启会加载它**当前磁盘上的全部内容**，
   不止本修。
