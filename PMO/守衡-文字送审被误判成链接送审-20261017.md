## 二、修法：判「链接送审」要加一条 —— 贴的链接**就是**素材

判据落在**闸门**（一个入口，两处都用它）：

```js
// tools/agent/review_gate.mjs
export const LINK_ONLY_MAX_BODY = 40;
export function linkOnly(text) {
  const links = findLinks(text);
  const body = bareText(text);                  // 去掉链接之后的正文
  return { links, body, isLinkOnly: links.length > 0 && body.length <= LINK_ONLY_MAX_BODY };
}
```

- `isSubmission` 的「② 链接」那一支改用 `linkOnly(text).isLinkOnly`；
- 报告的 `material.links` 也用它（`agent.mjs`）：**只有 linkOnly 为真时才把 URL 列成链接**；
- 判成纯文字**不等于丢掉链接**：`links` 照样回给调用方（链接仍在正文里，该读还是会读）。

阈值取 **40 字**：正常的「贴个链接让我看」那句话都在里面
（「审一下这个落地页」=8 字、「这条视频的落地页能发吗」=10 字），而任何一段真文案都远超它。

## 五、边界

1. **40 字是启发式，不是 PRD 条款**。PRD 没定义「怎样才算链接送审」。这条阈值只解决
   「长文案里粘着链接」这一类；若将来出现「正文很长、但真正要审的就是那个链接」的单子，
   它会被判成文字送审 —— 那时人说一句「读这个链接」即可。
2. **闸门判词会变**，所以 `kind` 会影响落表的「类型」那一格（`图片/视频` / `链接` / `文字`）——
   这一单今后会记成「文字」，这是对的。
3. 这条修的是**入口**（判词），不是报告版式：报告侧那三条规矩（链接只来自两处、引用不降级为入口、
   全写不截断）一个字没动。
