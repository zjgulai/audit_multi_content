# 守衡「假回执」修复 —— 回执前置先过「这条是不是在对我说话」（2026-10-22）

## 现象（逐字，生产）

群 `oc_49a7cfb2861cffa4365ca8491f398d32`，消息 `om_x100b62a37c9fc8b4dc0ba2a61cc3e7d`（正文
「不应该出现历史审核意见作为依据」，@ 的是刘华丽、**没有 @ 守衡**）：

| 时刻 | 发生了什么 |
|---|---|
| 10:21:25 | 守衡回了一张 **62 字**的卡：`【⏳ 处理中…】完整审核正在运行，完成后会在此回复；遇到故障会明确提示。本次按美国市场口径审查（PRD 第一阶段范围）。` |
| 之后 | **这条消息再没有任何回复**（同一 chat 台账里没有第二条） |

`PMO/logs/ws_daemon.log` 逐行：

```
[agent] 🧭 回执前置：text —— 命中送审词：审、依据｜先回一句，再读素材
[+ 42.679s]    · 不回复（not_mentioned）
```

也就是说：**承诺发出去了、链一次都没起**。对方看到的是「处理中」，实际没有任何东西在跑。

## 根因

「回执前置」（`tools/agent/agent.mjs`，2026-10-20 Owner 批准 ①）判断要不要发「处理中」时，
只用 `reviewGate.isSubmission()` 这一把尺子（正文关键词 / 媒材）——
**没有一把尺子问过「这条消息是不是在对我说话」**。

而它下游的 §4 有一条独立规则：「群聊里不 @ 不理」（`not_mentioned` 直接 return）。
两条各自都对，合起来就是**先说一句「我在处理」，再说一句「我不理你」**。

这正是 AGENTS.md §2.4.2 的形状：**一句对外说出去的话，指不出哪一行在执行它**。
`ackMessage()` 里那句「完成后会在此回复」当时没有任何执行点。

## 修法（一处判据，两处共用）

`tools/agent/agent.mjs`：

1. 新增 `addressedToMe()` —— **唯一判据**：私聊恒真；群里看 `feishu.isBotMentioned()`。
   赶在 `readInboundContent`（读图 + OCR + 画面读数，实测 5.8 s、抖动到 27.8 s）之前，
   它先用 `bodyToText` + `resolveMentions` 取一次「早判」；§3 拿到正文后用权威读数
   `_botMentionedFromInbound` 覆盖它。
2. **回执前置**多一道门：`if (gateEarly?.yes && addressedToMe())` —— 没在对我说话，就不许先许一个诺。
3. §4 改为调用同一个 `addressedToMe()`（不再自己写一遍 `chatType==='group' && !botMentioned`），
   两处判据同一个函数，不许以后各改一半。
4. 早判与权威读数**分歧**时打一行读数（`⚠️ 早判说「在对我说话」、权威读数说没有 —— 回执已发出`）：
   回执已经撤不回，至少让这件事在日志里看得见，而不是又一次静默。
