# 守衡 · 读视频这条路是怎么打通的（2026-10-05）

> 这份记录只讲**一件事**：人发视频给守衡，守衡能不能读到、读到的是什么、读不到时说什么。
> 每一条结论后面都跟着**复现命令或读数**（`AGENTS.md` §2.2 第 1 条：文档里的数字要算出来）。

---

## 一、起因：两次真实事故，同一个形状

| 时刻（北京） | 人做了什么 | 守衡回了什么 | 哪里错了 |
|---|---|---|---|
| 09:22:43 | 私聊发来一条视频（`type=file`、`file_v3_00166_48a0a140…`、`momcozy-one-click-foldable-baby-playard-hero-1080p.mp4`） | **0 毫秒**回了 108 字拒绝：「视频是附件，按红线不取；且本机无转写/抽帧通道 —— 审不了」 | 两半都错：①「按红线不取」当时**不适用于人直接发来的那条**（Owner 当天批的窄豁免）；②「本机无转写/抽帧通道」是**没做**，不是**做不到** —— 系统自带 AVFoundation 与 Speech.framework |
| 09:23:17 | 追问「这个视频能过审吗？」 | 1255 字解释 | 解释得再清楚，她要的事（审这条视频）仍然没有一条走得通的路 |

判据（可复现）：

```bash
grep -n "hero-1080p" PMO/logs/ws_events.jsonl          # 那条入站消息（行 240）
grep -n "视频是附件，按红线不取" PMO/logs/ws_outbound.jsonl   # 那条 0 毫秒的拒绝
```

**结论**：这不是「答得不好」，是**那条路根本不存在**，而拒绝的措辞让人以为缺个开关。

## 二、修成了什么形状

PRD §5.2 对视频的要求是「字幕/旁白 + 关键帧 + OCR」。现在这条路是**三段本机处理**拼起来的，
没有任何一个字节出网：

| 段 | 做什么 | 落点 |
|---|---|---|
| 取字节 | `im/v1/messages/{id}/resources/{key}`，`type` 取自闭集 `{image, file}` | `tools/agent/feishu.mjs` 的 `fetchMessageResource`（**全仓唯一**调用点） |
| 画面 | AVFoundation 按时长**均匀抽 8 帧** → Vision OCR 读画面上的字 | `base/video_probe.m` → `.tools/bin/video_probe` → `tools/agent/video.mjs` |
| 声音 | `afconvert` 抽 22.05kHz 单声道 wav → Speech.framework **本机**转写 | `base/asr_speech.m` → `.tools/bin/ShouhengASR.app` → `tools/agent/asr.mjs` |

**红线没有松**（`AGENTS.md` §2.6 同日加宽，Owner 现场确认）：同一个调用点、只落系统临时目录、
用完即删、不归档不入库；`file` 里的**非视频附件**（xlsx/pdf/docx…）、`audio`、群历史、
云文档、多维表格、Drive 的 `download` 与 `medias/` **一个字都没松**。

**「是视频」在取字节之前就判出来**（`videoKeysOf`：`media` 消息，或**名字后缀是视频**的 `file`）——
不许「先取回来再看看是不是视频」，那等于把附件也拉进来了。

## 四、打通路上踩到的四个坑（每个都留了读数，别再踩）

### 1. 语音识别是 TCC 隐私服务：裸 CLI 一调就 `Abort trap: 6`

```
$ .tools/bin/shouheng-asr a.wav zh-CN out.json
Abort trap: 6        ← namespace:TCC … without a usage description
```

必须打成 `.app` + `Info.plist` 写 `NSSpeechRecognitionUsageDescription` +
**用 `open -n` 启动**（LaunchServices 当发起者，用途说明才算在这个 app 头上）。
所以这个模块**没有 stdout 可读** —— 结果是靠「`open -n` 写文件 + 轮询那个文件」拿的。

### 2. `LSBackgroundOnly` 的 app **弹不出授权框** → 回调永远不来

症状是「进程一直挂着，等到超时才报 `timeout`」，读起来像「识别太慢/模型没装」。
抓它的读数是系统日志里这一对：

```
Failed to match existing code requirement for subject local.shouheng.asr …
AUTHREQ_PROMPTING: service=kTCCServiceSpeechRecognition, subject=Sub:{local.shouheng.asr}
```

改用 `LSUIElement`（有 UI 能力、无 Dock 图标）之后，框能弹、点了就通。

### 3. TCC 按 cdhash 记授权：**每重编一次二进制，授权就失效一次**

所以 `tools/agent/asr.mjs` 的 `ensureAsr()` **只在产物缺失时才编译** ——
不因为「源码改过了」顺手重编。真要重编，得先跟人说一声：她会看到一个新的授权框。

### 4. 三处「安静地回空」，报出来**都是 `text:""`**（最花时间的一处）

| 坑 | 读数 |
|---|---|
| `shouldReportPartialResults = NO` | 立刻回一个 final 但空的结果（244~539ms），与「这段音频里没人说话」长得一模一样 |
| 识别器建在授权回调**里面** | 回调一返回就被 ARC 释放、识别随之取消，同样回空。★ **只在 zh-CN 上稳定复现，en-US 一直好使** —— 「一个语言能用」不给另一个语言作证（§2.4.1） |
| **跨线程读结果** | 结果回调不在主线程上；「回调里写进全局缓冲区、主线程再读出来」读到的是**没写进去的样子**。实测 `callbacks:19, partial_max:19, final_seen:1` 而 `text:""` |

第 3 条最值得记：前两条是「识别没跑」，这一条是**识别跑对了、我读错了**，
而三者在群里表现完全一样（都是一句「听不清」）。修法：**结果在回调里就地成形、就地落盘**，
主线程只等一个 `done`。

## 六、**没做到的**（写清楚，省得下次有人以为都做完了）

1. **画面只看到抽样的 8 帧**。硬字幕/贴片文案/logo 大概率在抽样里，但**一闪而过的画面看不到**。
   这一条必须由模型转述出去（视频块的头注 + 人设第 3 条各写了一遍），
   不许说成「整条视频我都看了」—— PRD §11 那条「PASS 误放率」的地基就在这里。
2. **语音授权依赖人点一次**。重编 `base/asr_speech.m` 会换掉二进制签名，TCC 的授权随之失效，
   下一次识别会挂在那儿等一个弹窗。这不是 bug，是 macOS 的形状；代价写在 `build_asr.sh` 头上。
3. **外部网页链接没有通道**。飞书的 wiki / base / 云文档链接读得到，`/file/` 是附件形态
   （按 §2.6 红线不取，且明说「这是策略边界，不是能力边界」）；
   但**非飞书的普通网页 URL** 目前一条都取不到 —— `run_readonly_command` 的白名单里没有它。
   截至本记录，入站链接里非飞书的只有 2 条，都是知识库自己的 OpenAPI 地址（走 KB 那条路读）。
   **这是一处真实缺口，不是「已经打通」** —— 要补得先定它的形状（谁能取、取多大、要不要留痕）。
4. **帧 OCR 的质量**：logo 这类艺术字会读成 `mOMCOZY`（大小写错），
   宣称类正文比它清楚得多。不许把 OCR 结果当逐字原文引用（图块/视频块的头注都写了）。

### 现场露出来的一件事（值得记，因为它差点被我读成「接线断了」）

她实际发的是**两条**：先发视频，**再单独发一句**「审核下这个视频」（不是「回复那条视频」）。
那是**两轮**：

* 视频那条 → 拿到视频块，答得对（上表那条回话就是它）；
* 「审核下这个视频」那条 → 它自己**没有** `parent_id`，按 §2.6 **不许**去捞那条视频，
  于是守衡手上确实只有那 7 个字。它去工作区里搜，只找到日志里的 `🎬` 读数行，
  就对她说了一句「**那 51 个字没到我这儿……这像是一条接线缺口**」。

**「那 51 个字没到我这儿」那一句是准的**（那一轮里确实没有）；**「接线缺口」是猜的**，
而它猜错了。两条消息本来就是两轮 —— 这不是 bug，是「不翻历史」那条红线的**正常表现**。

但它暴露了一个真问题：**当时没有任何断言看得住「读数有没有进真正发给模型的那一轮」**——
第 15 组那条叫「必须走到模型那一侧」的用例，其实只走到 `readInboundContent`，
**名字比它验的事大**（§2.4.1 那个形状）。所以当天补了：

* `agent.mjs` 导出 `buildUserTurn()`（**纯函数**，把「人问的话 + 图块 + 视频块」拼成那一轮）——
  这一跳从此有名字、有调用点，判据能真的走进去（§2.4.7 那条「拆成能被调用的纯函数」）；
* `test_agent.mjs` 第 16 组加一条端到端：**帧上的字与音轨转写的原文必须出现在那一轮里**，
  外加两条反向对照（没有块时那一轮必须逐字等于人问的话；只有视频时那一轮就是视频块）；
* **反向对照实跑过**：把「拼视频块」那一行删掉 → `89 / 失败 1`；恢复后 sha1 逐字节一致。

## 九、紧接着暴露的第二个缺陷：**读到了，但一次链都没起**

现场验收之后委托方问了一句：「视频守衡读了，但是无结论，**读取了 dsh 知识库吗？**」

**没有。** 判据（都在盘上）：

| 读数 | 值 | 出处 |
|---|---|---|
| 视频那一轮的工具调用 | **0 次** —— 回复行前面**没有** `🔧 工具:` 那一行 | `PMO/logs/ws_daemon.log:2498` |
| 对比：这条链在本机是通的 | `kb_review_chain(691496ms)`（11.5 分钟），另有 771s / 1809s 两次 | 同文件 `:2302` / `:1760` / `:2030` |
| 它答的是什么 | `query-answer` 卡片：把 8 帧 OCR 与音轨读数描述了一遍，**没有一句条款级依据** | `PMO/logs/ws_outbound.jsonl` |

**不是「查了没查到」，是「压根没去查」。** 两个缺口叠在一起：

1. **路由规则是按问句写的** —— 人设里那句是「『这个能不能发 / 有没有问题 / 审一下』这类问题，
   走 `kb_review_chain`」。一条**光秃秃的媒体消息不匹配任何问句**，于是模型只做了描述。
2. **我给图块/视频块写的头注全在讲「你能判什么、不能判什么」**，一个字没提该走哪条路 ——
   等于把「就地判」这个方向又推了一把。

### 修法（三处同一句话 + 一个读数）

Owner 现场定的口径：**只要带了媒材（图 / 视频 / 飞书文档链接）就自动起链，不看他写没写「审一下」。**

| 落在哪 | 是什么 |
|---|---|
| `agent.mjs` 的 `MEDIA_ROUTE_HINT`（**唯一出处**） | 图块与视频块末尾都挂上：「这是**送审素材**：不管对方写没写『审一下』，都要走 kb_review_chain……只回一段『我读到了什么』不算回答」 |
| `persona.mjs` 的「走哪条路」那一节 | 同一句话写进常驻人设（提示词长度上限 8500 是冻结的，所以**等量削了别处的措辞**，K5 仍过） |
| `agent.mjs` 的 `mediaWithoutChain(meta)` | ★ **读数**：这一轮带了媒材、却没成功起过链 → 回一个读数。daemon 每轮问一次，答「是」就打一行 `⚠ 带媒材但没起链` |

**为什么第三处必须有**：那次事故在盘上的**全部痕迹，就是一行没有出现的日志** ——
而「一行没出现的日志」不是判据（§2.4.1：判据没盖住的那一跳，就是事故所在的那一跳）。
现在它是一行**会出现**的读数。

判据（`tools/test_agent.mjs` 第 16 组，共 5 条断言全是纯函数级、离线可跑）：

* 图块与视频块**必须**含那句路由提示，且点名 `kb_review_chain`；
* 没有媒材时两个块**必须为空**（反向对照：那句话是跟着媒材走的，不是恒挂）；
* `mediaWithoutChain` 五种形状各自落对：起链→不报 / 一次工具都没调→报 /
  只调了别的工具→报 / 没媒材→**永远不报** / 链**跑失败**→照样报
  （「跑了但没成」不许记成「跑过了」）。

### 还没验的那一跳（说清楚）

上面证的是「**指令在提示词里、读数有效**」。真正那一跳是「模型看到这条指令之后**真的去调链**」——
那要一次带媒材的真实消息才验得了（链本身跑一次 10~30 分钟）。下一次有人发图/发视频时，
看 `PMO/logs/ws_daemon.log` 里那一轮有没有 `🔧 工具: … kb_review_chain(…)`；
没有的话，新的 `⚠ 带媒材但没起链` 那行会当场把它点出来。

调用 L4,L5,L6,L7 层每层 skills + 评审层 skills + 出报告溯源（L0 层）写入飞书。」

第九节那条改法是「把规矩写进人设 + 加一个读数」。委托方再重申一次，说明那还不够 ——
**人设是声明，不是约束**。所以这一次把它搬进了内核：

| 落在哪 | 是什么 | 为什么在这一层 |
|---|---|---|
| `tools/agent/review_gate.mjs` 的 `isSubmission()` | 纯函数判「这条算不算送审」 | 判据能被单测直接调，离线可反向对照（喂「在吗」不许触发） |
| `tools/agent/agent.mjs` 的 `runSubmissionGate()` | **内核自己把链跑完**，再把结论交给模型 | 模型**不需要「想起来」要调它** —— 这就是「必须走」的落点 |
| `agent.mjs` 的 `defaultChainRunner()` | 跑 `kb_review_chain` 并**拆掉 `executeTool` 的信封** | 见下面那条实测踩到的坑 |
| `buildUserTurn({ chainBlock })` | 链的结论排在那一轮**最前面** | 排在读数后面会被盖住，模型又开始「描述我读到了什么」 |
| `ws_daemon.mjs` 的 `notify` | 链一启动先回一句「收到，正在走链（6~30 分钟）」 | 不吭声会被当成没动（09:22 那次就是这样） |
| `mediaWithoutChain()`（已升级） | 兜底读数：闸门判成送审却没跑成 → 打 `⚠ 该送审却没起链` | 闸门失效时**还得有人喊** |

**什么算送审**（Owner 现场定的口径）：媒材（图/视频）**只要发就一定算**；链接**贴了就算**；
纯文字**像送审的才算** —— `≥ 30 字`，或命中「审 / 能不能发 / 合规 / 过审 / 依据 / 踩线」这类词。
「在吗」「你能干什么」不算。（判据全在 `review_gate.mjs`，词表也是逐词点名的。）

### 写完当场踩到的坑：`executeTool` 回的是**信封**，不是链的返回

第一版默认跑法是内联一行 `(args) => executeTool('kb_review_chain', args)` ——
而 `executeTool()` 回的是 `{tool, ok, result}`。于是闸门拿到的是那个信封：
`res.error` 是 `undefined`、`res.answer` 也是 `undefined`，
**每一次送审都会被写成「链跑完了但没返回结论 —— 结论未知」**。

链明明跑成了、飞书也写了，而回给群里的是「未知」。这是一个**安静地把成功说成未知**的形状 ——
比报错更坏，因为它不会让人去查。修法两处，缺一处都还会再犯：
① `defaultChainRunner()` **拆信封**并写明为什么；
② `review_gate.formatChainBlock()` **两种形状都认**（信封与裸返回），
判据在第 18 组里两种形状各喂一次。

### 判据（`tools/test_agent.mjs` 第 18 组，5 条，离线可跑）

* **什么算送审**：8 个「该走」的样本各判对（含 kind），5 个「不该走」的必须闭嘴；
  外加长度闸门的两面（29 字不走 / 30 字走）。
* **素材怎么取**：帧上的字、音轨转写、文件名与时长都要进；三种「声音那侧没结果」分开写。
* **链的三种结局**：跑成（逐字 + 不许改写）/ 没跑成（**结论未知**，明确否认「通过」）/ 回空的。
  外加**信封形状**两条。
* **行为级闸门**：该走链的**恰好走一次**、回执先发、结论排在问题**之前**；
  三条反向对照 —— 闲聊**一次都不许起链**、链炸了不许产出结论、**补发重放不重跑**（链会真写飞书）。
* **接线**：`handleMessage` 里必须**恰好一处** `await runSubmissionGate(` 调用
  （剥注释后再数 —— 本文件到处在解释这个函数，不剥会恒真）。

**反向对照实跑过**（不是写在注释里）：把结论挪到问题后面 → 那条行为级断言红；
把闸门调用换成 stub → 接线断言红；两次都恢复回 sha256 逐字节一致。

### 顺手堵掉的一个隐患

`tools/_dryrun_link.mjs`（一次性干跑脚本）的契约是「只返回不发送」，而闸门现在会
**自动**把链接送进链 —— 那条链**会真写飞书**。一条「干跑」把一次真实发布动作做出去了，
比结果错更坏。已在该脚本里显式把跑链那一步换成会说话的桩。

## 十一、送审链到底要跑多久：**6~30 分钟那句回执是错的**

Owner 2026-10-05 20:10 看到回执，当场一句「**太长了，不正常**」。核完——**他是对的**。

### 实测摊开（全部出自 `PMO/logs/ws_daemon.log` 的 `送审链返回｜<ms>`）

| 情形 | 实测 | 当时库里有没有别人 |
|---|---|---|
| **图片（20:08 那条）** | **212s ≈ 3 分 32 秒** | 空闲 |
| 图片（本机 replay） | 290s ≈ 4.8 分 | 空闲 |
| listing 文案 | 329s ≈ 5.5 分 | 空闲 |
| 图片 | 1072s ≈ 17.9 分 | **日更任务占着锁** |
| 视频 | 1812s ≈ 30.2 分 | **日更任务占着锁** |

**结论：链本身 3.5~5.5 分钟；多出来的十几二十分钟全是排队。**
知识库那条链同一时间只准一单（`kb_loop_claim`），日更或别人的单在跑，你就得等。

### 错在哪一层（这条比数字本身更值得记）

那句回执把**两个不同的东西糊成了一个数**：

* 「链要跑多久」—— 本机可测、相对稳定（≈5 分钟）；
* 「要不要排队」—— 取决于**此刻**有没有别人在跑，与链无关。

糊在一起之后，人看到的永远是那个悲观上限，于是要么不敢用、要么白等。
**这类错和 §2.4.1 是同一个形状**：一个读数里混进了它没测的那部分，而混进去之后
**没有人能看出来** —— 直到有人真的掐着表等了一次。

### 修法：分开说，而且**排队与否要真读一把锁**

`tools/agent/review_gate.mjs` 的 `ackText(gate, { queued })`：

* 常态：`本机实测：一条图/一段短文约 5 分钟，视频略长（要抽帧 + 整条转写）`
* 排队：`知识库那边现在有别的任务在跑（同一时间只准一单），这条要排队；排上之后约 5 分钟，最坏情况约半小时`

`queued` 由 `tools/agent/tools.mjs` 的 **`claimStatus()`** 现读（`kb_loop_claim status`，
只读、不释放、超时 8 秒）——**实测 200ms 返回「无认领」**。取不到就说「不知道」，
退回常态那套话：**不许谎报排队，也不许谎报空闲**。

判据（`tools/test_agent.mjs` 第 18 组）：常态文案里**不许**出现「6~30」、
没排队时**不许**说排队、两种文案**必须真的不同**（否则 `queued` 就是个死分支）。

**这一处要重启才生效**（回执在 `review_gate.mjs` 里，进程启动时加载）。
