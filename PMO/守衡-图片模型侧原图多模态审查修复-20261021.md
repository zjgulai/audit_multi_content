# 守衡图片模型侧没有收到原图：根因与修复

日期：2026-10-21

## 故障表现与根因

Owner 报告图片审查回复只有知识库侧结论，没有模型侧视觉审查和语义理解结论。追踪模型侧运行记录后，发现模型分支返回 `ok=false`，错误为“输出里没有 JSON 数组”，原始输出为空，模型侧 findings 为 0；知识库侧仍有 4 条结果，因此最终回复看起来像只跑了知识库。

原因有两层：

1. 图片请求构造给模型的内容只有 OCR 文本和视觉描述，没有原图的多模态内容。模型因此无法直接观察画面或理解图中文字与场景之间的关系。
2. 模型侧解析只接受带外部依据的发现，纯视觉观察/语义理解的发现会被过滤；同时模型输出空白或格式不符时没有足够的重试与明确的阻断条件，知识库结果仍可能成为唯一可见结论。

## 修复内容

- `tools/agent/llm.mjs::ask()` 接受原图临时文件路径，校验路径后将图像内容编码为多模态 `image_url` 输入；图像缩放仅用于模型传输，图像语义仍来自原图像素。模型请求失败重试时保留图像内容。
- `tools/agent/model_side.mjs::reviewModelSide()` 要求原图数量与应审图片数量相符，并将图片路径传给模型请求；OCR 与视觉描述是辅助上下文。原图可用时允许模型输出不依赖外部资料的直接视觉/语义判断，但必须给出具体 `visual_anchor`；涉及法律、平台政策、行业标准或专家安全结论仍须外部依据。
- 模型空输出、截断或 JSON 无效时重试一次并提高输出预算；模型侧最终失败时返回明确失败态。
- `tools/agent/agent.mjs` 在原图下载并暂存后才启动模型审查，并在模型调用完成前保留临时图像；图片审查完成闸门要求模型侧成功。模型侧缺失或失败时不得用知识库单边结果给出正常三态结论，必须明确说明审查未完成。
- `tools/agent/dual_track.mjs` 将无外部依据的视觉观察及其画面锚点带入最终结果与依据字段，防止解析成功但展示层丢失。
- `tools/agent/model_side_limit.test.mjs` 增加传输层断言，校验请求体包含与原图字节一致的图像数据 URI；并覆盖模型图片输入、视觉无外部依据但有画面锚点、缺原图拒绝以及结果展示。
- `tools/test_agent.mjs` 覆盖模型侧失败时图片审核闸门必须阻断，以及模型侧成功且没有发现时可正常通过。

## 生效边界

上述是本地代码与离线回归验收结果。当前守衡进程尚未因本轮修改而重启，因此不能声称线上已经加载新代码，也不能声称新版本已通过飞书图片端到端实测。已生成重启闸门影响报告后，需在用户确认重启后加载代码；随后以一张新图片确认模型请求实际含原图、多模态模型侧有成功运行记录，并且最终报告同时呈现知识库发现和模型视觉/语义发现。模型凭画面直接判断的内容可以没有外部依据，但报告必须标出具体画面观察锚点。

## 可执行判据

1. `node tools/agent/model_side_limit.test.mjs` 的 wire-level 用例必须证明模型请求中的图像数据解码后逐字节等于输入原图。
2. `node tools/test_agent.mjs` 的图片失败闸门必须证明模型侧失败时不能发布正常结论。
3. 飞书在线回放中，模型请求轨迹必须显示本次原图已作为图片输入；模型侧必须有成功状态，且最终报告能分别保留 KB 发现与模型发现。缺其中任一项即判图片审查未闭环。
