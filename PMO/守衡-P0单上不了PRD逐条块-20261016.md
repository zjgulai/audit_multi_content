## 二、坏在哪一条链路上

PRD §5.3.3（BLOCK，1–2 条）要的是：

```
【审查结论：BLOCK】共发现 1 处必须修改。

1.【绝对化与安全承诺-绝对化用语】全文，逐字命中 `最好`
  **原因**：…
  **依据**：《外部标准库 v0（试用版，未发布）》第 E-2.124 条（链接：…）
  **建议**：…

请修改后重新提交。
```

而**链其实给了完整的这一份** —— 现场实跑复核（`kb/kbpy l5/p0_fastpath.py --file …-json`，
输入就是那一句），`rendered` 字段逐字是同一份结论行 + 四要素 + 动作行。
也就是说：**PRD 那一段从来没缺过，它只是没被搬到卡上。**

搬它的唯一那一跳是信封层的 `reviewShape`：

```js
const reviewShape = !!(verdict53 && verdict53.line && verdict53.block) && !!s(raw).trim();
if (reviewShape) { … blk 收敛成 evidence，逐条块作第一组 … }
```

`verdict53` 为 null ⇒ `reviewShape=false` ⇒ **模型自拟的那张 `evidence` 卡原样发出去**
（四组折叠摘要就是这么来的）。再看 `verdict53` 怎么来的 —— `agent.mjs`：

```js
const verdict53Final = g?.verdict53                                   // ← 闸门给的
  ?? ((toolTrace ?? []).some((x) => x.tool === 'kb_review_chain' && x.ok)
       ? deriveVerdictLine({ replyText: reply ?? '', reviewedByTool: true })   // ← 兜底
       : null);
```

两条都没成：

| 来源 | 这一单为什么是空的 |
|---|---|
| `g?.verdict53` | 闸门判「**不是送审**」（它在问「过审」这件事怎么运作）⇒ `runSubmissionGate` 直接 `return { verdict53: null }`。链不是闸门跑的，是**模型自己**调的 |
| 兜底那一支 | 它**只喂 `replyText`** —— 也就是「**模型有没有把链那一行抄进回复**」。这一单模型没抄（它写 `**结论：BLOCK —— 共 1 处必须修改。**` 加自己那四组），于是 `leadsWith` 不成立 ⇒ `null` |

★ `toolTrace` 那一跳**结构上就不可能**补上：它的元素是
`{ tool, ok, ms, args, error }`（`agent.mjs` 工具循环里 push 的），**不记返回体**
—— 链那份渲染好的块从来就没进过兜底这一支。

## 三、根因一句话

> **PRD §5.3 块的启用条件，压在「模型有没有把链那一行抄进回复」上。**

`prd53.mjs::deriveVerdictLine` 的第 ② 支**专门**处理 P0 快路
（按 `p0Fastpath.matched_patterns` 派生 `【审查结论：BLOCK】共发现 N 处必须修改。`），
`test_agent.mjs` 的 `W1` 也**一直在喂它**，自证**一直是绿的** ——
而全仓**没有任何一个调用点给它传过 `p0Fastpath`**。

这与 `FIX-021` 是同一个形状，只是换了个接缝：

| | 判据 | 调用方 |
|---|---|---|
| FIX-021 | `toCardOrText(..., machineAnswer:true)` 判据写对、行为级验过 | `batch_review_runner` 没传 ⇒ 线上照样漏 |
| **FIX-043** | `deriveVerdictLine({ p0Fastpath })` 判据写对、`W1` 验过 | `agent.mjs` 兜底那一支没传 ⇒ 线上照样漏 |

这也直接回答了 Owner 那句「**修复多次了，怎么还出现了**」：
前几次修的是**产物层**（FIX-020/023/025/037 都在治「卡面上出现了不该出现的字」），
而这一条是**启用条件**层 —— 产物层再干净，**那一段压根没被启用**时也看不出来。
而每次修完，自证都是绿的：绿的是**判据**，不是**接线**。

## 四、修法（两层，缺一层都还漏）

| 层 | 落在哪 |
|---|---|
| **读数**：`kb_review_chain` 命中 P0 快路时，把链返回里那几格留下来（`answer` = 渲染好的 §5.3.3 块、`p0_fastpath`、`p0_findings`） | `tools/agent/tools.mjs` 的 `p0PayloadOf()`（**纯函数**）+ `executeTool` 里那一行装填 + `beginP0Turn()`（每轮清空） |
| **接线**：兜底那一支读它并喂进 `deriveVerdictLine` | `tools/agent/agent.mjs`：`const p0Payload = p0MemoRead()` → `deriveVerdictLine({ replyText, reviewedByTool, answer, p0Fastpath })` |

三条纪律（都是照着本仓已经踩过的坑定的）：

1. **只装跑成的** —— `{error}` 是「结论未知」，拿它派生结论行等于把未测说成已判（§2.4.2）。
2. **每轮清空** —— 与链缓存同一处（`beginChainTurn()` 后面紧跟 `beginP0Turn()`）、同一套理由：
   不清就会把**上一单**的结论行与逐条块搬到这一张卡上（方向不对称：漏跑只是慢，串轮是答错）。
3. **不许从中文里抠** —— 读的是链返回的**结构化字段**（`p0_fastpath.matched_patterns`
   与 `rendered`），符合库里那条规矩：结论与条数只读结构化字段。

★ 顺带给「模型自己调链」那条路加了一个**注入点**（`deps?.executeTool ?? executeTool`，
默认值就是原来那一行、生产一个字不用改）：这一条缺陷的判据**只在接线上**，
而那段此前**没有任何缝**能喂桩 ⇒ 只能靠源码文本断言，正是 §2.4 点名的假执行点。

## 六、这一条为什么之前那几次都没拦住（给下一个人）

- **产物层的判据测不到启用条件**：FIX-020/023/025/037 都在断言「卡面上有什么／没什么」，
  而这一单的病是「**那一段没上卡**」—— 前者全绿时后者照样发生。
- **夹具比现场窄**：`Y1`（第 22 组）当初就是为「模型自己调链那条路」写的，
  但它的夹具**假设模型会把结论行抄进回复**（`reply` 里写着一行 `【审查结论：REVIEW】…`）。
  实测这条假设**不成立** —— 模型会写自己那句。**夹具里的假设，就是判据的边界。**
- **`W1` 一直在喂 `p0Fastpath`，而没人接** —— 「判据被验过」与「它被接上了」是两件事；
  本仓同一条已栽过两次（FIX-021、本条）。
