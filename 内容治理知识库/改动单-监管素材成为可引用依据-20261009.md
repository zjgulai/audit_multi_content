# 改动单：让「监管/政策类素材」成为可引用依据（命中原文 + 飞书链接）

> 状态：**待批**。本单是提案，未改任何数据。
> 日期：2026-10-09 ｜ 触发：Owner 目的 =「让守衡读取视频后，输出依据：命中原文 + 飞书链接」

## 一、目标（Owner 原话）

守衡对一条素材给结论时，每条结论要能带出：**命中原文**（逐字）+ **飞书链接**（可点回源）。
按库既定的四段溯源，就是：条款号(L4) + 规则与命中片段(L3) + 单元/锚点/`source_sha256`(L2/L1) + 逐字原文与直链(L0)。

## 二、现状（逐条实测，非推断）

| 事实 | 读数 |
|---|---|
| 库里**监管/政策类**素材 | **11 条 / 206,646 字**，`kb_type` 全部 `external_standard` |
| 它们的 L2 单元 | **1,629 个** |
| **其中进了 L6 索引的** | **28 个**（其余被尺寸/质量护栏挡掉） |
| FTC《Health Products Compliance Guidance》 | **109,724 字 / 1,023 单元 → 进 L6 **0** 条** |
| `rules.jsonl`（评审引擎唯一认的依据） | 1,018 行（509 个 `rule_id`，各 2 代）｜`kb_type` **全为 `wording`**，证据 **1018/1018 来自 bitable** |
| `scoped_clauses.jsonl`（"外部标准条款"） | 750 条，**全部来自一张 bitable 表的 30 条记录**；抽样见 `clause_text: "郭嘉"`、`evidence_strength: "资料登记元数据（field_value），非条款正文"` ⇒ **大量不是真条款** |
| `sample_cases.jsonl` | 946 条，**冻结件**（2026-10-01 10:07 起无活写入者） |

⇒ **病因不是「视频没进库」，是「监管原文进不了可引用的依据层」。** 库里最有价值的那批合规原文（FTC/Google/Meta/FDA）**几乎全部不可检索、也不可引用**。

## 三、拟改三处（可分别批准）

### 改动 ①（先做）：让监管/政策类素材的正文**进得了 L6**

- **改什么**：查出这 11 条（1,629 个单元）被哪道护栏挡掉，逐类说明。已见线索：`external_standard | quality_flag` 在 L6 过滤里挡了 **1,875 个单元**（全库口径）。
- **判据**：对每条被挡单元给出**原因码 + 一个反例**（同一原因码下不该被挡的单元）。
- **反向对照**：不动尺寸阈值；不放宽 `quality_flag` 白名单本身，而是**证明这批单元的 flag 归错了类**。
- **代价**：改的是过滤口径 ⇒ 要报批；L6 需重建（上次 379s）。
- **回退**：`kb/l6/index/l6.jsonl` 与 `SCOPE.txt` 均有批次留痕，可逐批撤。
- **收益**：守衡**立刻**能检索到 FTC 109,724 字原文 —— 这是「命中原文」那一半。

### 改动 ②：把那 11 条（或先取其中 5 条核心的）**蒸成条款**

- **改什么**：唤醒 `scoped_clauses` 这一路（现有写入者已冻结），令其从 `external_standard` 单元产出条款：`clause_text`（**逐字**）、`anchor`（`#l.a-b`）、`source_sha256`、`resource_id`、**飞书直链**。
- **为什么不能只是「重跑老的」**：老的 750 条里大量是 `field_value`（如「郭嘉」），`evidence_strength` 已自述「非条款正文」⇒ **不能拿它当现状基线**，必须**重新定"什么算条款"**。
- **条款号**：`article_no` 属 **L4**（库口径：条款号 = L4）。本改动**只产 L3 候选**，发号仍走 L4 现有流程，**不在本单里自造号**。
- **反向对照**：①`field_value` 类单元**不许**成条款（判据：`unit_type=entry` 且字段角色非 content）；②长度 < 40 字的单元不许成条款；③同一 `resource_id` 产出的条款必须能逐条回指 L2 单元（`l3_gate.py` 已在核）。
- **代价**：写库动作；`scoped_clauses` 口径由「一张表」变「多来源」，**L4 canonical 需一起接**；`kb/l3` 是**覆盖式写入且无归档兜底**的层 ⇒ 跑前必须手工归档（本单已备好范例：`kb/l3/_archive/pre-distill-20261009-093434/`）。
- **收益**：守衡引用「指名比较竞品」时给的是 **FTC 原文命中片段 + 飞书直链** —— 这是「飞书链接」那一半。

### 改动 ③：让评审引擎的覆盖闸门**认这些条款**

- **改什么**：闸门现在只认 `rules.jsonl`（判据「既被规则引用、又达门限」）。改为**也认新产出的外部标准条款**。
- **反向对照（必须做，否则是放宽）**：③**只许把「无依据」变成「有依据」**，**一个 PASS 都不许多**；改完必须验：同一批素材在改动前后 **PASS 数不变**。
- **代价**：改判据、要报批。

## 四、明确**不做**的事（附理由）

| 不做 | 理由 |
|---|---|
| 把 946 条素材样例塞进 `rules.jsonl` | 样本变「条款」，**L4 条款号体系会被冲垮** |
| 只让闸门认 `sample_cases` | 那条视频**不在**样例集里（wiki 资源 0 条），改了也盖不到它 |
| 把「素材自身的库内登记」当合规依据 | 引擎自己标为「自己匹配自己，不是库对这条素材的相关性」。**可作读数（给链接），不可作依据** |
| 动 `rules.jsonl` 的去重（1018→509） | 已试过并**已回退**：无收益（`scoped_clauses` 不由此路产出）、有代价（`article_no` 509→0），留痕见 `kb/l3/rejected.history.jsonl` 第 6 行 |

## 五、前置条件与报批点

1. **本单整体是写库动作**（①改过滤口径、②写 L3、③改判据），**逐条报批**，不打包。
2. ② 跑之前**必须**归档 `kb/l3/{rejected.jsonl, candidates/*.jsonl, manifest_l3.jsonl}`。
3. 每步都要有：**原因码 + 反例 + 反向对照 + 回退路径**，缺一条不算完成。
4. 完成后按既有惯例跑 `l1_gate / l2_gate / l3_gate / l6_gate` 与 `envelope_census`。

## 六、我的推荐顺序

**① → ② → ③**，且 **①②之间可停**：
- 只做 ①，守衡能**检索到** FTC 原文（能被召回、能出现在候选里），但**还不能被引成条例依据**；
- 做完 ②③ 才形成「条款号 + 命中原文 + 飞书直链」的完整引用。
- **①最便宜、风险最低、且不动任何判据**（只是证明那批单元被错误挡掉），**建议先单独批这一条**。
