# 改动单 · 图片单「必跑专项 skill」闸门 · 2026-10-21

> 一句话：把「每次图片审核都必须真的加载 `图片安全审查`」从**散文纪律**落成**两道代码闸门**
> —— 入口（`review_preflight.sh` ⓪b）与出结论（`with_kb_evidence.py` 图片单专项闸门），
> 判据是「skill 文件 harness 读得到吗」＋「本会话日志里有没有**成功的** skill 调用」。
> 两件事都是**观测**，不是自述。

## 一、病灶（本机实测，不是假设）

同一份 `~/.dsh/skills/图片安全审查/SKILL.md`，两侧读数相反：

| 读者 | 读数 |
|---|---|
| `stat` / `ls -l` | **18180** 字节 |
| 顺序读到 EOF（python / `wc -c` / node `readFileSync`） | **14084** 字节，UTF-8 合法、无 NUL |
| `dd skip=14084` | 乱码（`f4ba 2d9e 4f42 …`） |

差正好 **4096** —— 本库登记过的「信封态」（`tools/envelope_gate.py` 头注释：python 写
`.py/.txt/.md` 会落成 stat 虚高 4096 的信封，宿主 Electron 侧读成乱码）。

后果不是报错，是**静默降级**：

```
09:56:44 [skill-filesystem]  skill file …/图片安全审查/SKILL.md ignored: … binary file
10:03:31 / 10:09:34 / 10:12:32   同一条反复出现
（日志：~/Library/Application Support/DSH Desktop/logs/dsh-2026-10-21.log）
```

⇒ harness 读该文件抛 `FS_NOT_TEXT`（`dsh-fs-local/lib/index.js:313/355`）⇒ skill 被跳过 ⇒
**不进会话 catalog** ⇒ `skill` 工具报 `unknown or no longer available` ⇒ 模型改成"直接读文件"，
照样申报 `--loaded-skill`。**10:02 那一单就是这样：报告已发、判定主体 skill 一次没加载过，
而层前置与四道审计全绿。**

## 四、怎么用

```bash

python3 kb/l8/verify_skill_loaded.py --skill 图片安全审查
```

## 五、已知边界（摆出来，不藏着）

1. **观测的是「加载过」，不是「照着做了」**。真正的天花板是把专项的**必备产出**也判据化
   （图片单的定位四形态 / 4B 逐条核查 / 权威来源比对），那是下一步。
2. **无会话日志就观测不到**（机器入口、kb_api 那条路）：此时记 `unverified` + warning，
   **不算通过**，也不拦 —— 拦会把守衡（加载不了 skill）那条路一起打死。
3. `verify_skill_loaded` 依赖 DSH 的 session 日志格式；格式变了会落到 **exit 5（未测）**，
   不会误判成「没加载」。
4. 本次**没有**动 `~/.dsh/skills/图片安全审查/SKILL.md` 的内容（只按原字节重写过一次，
   消掉信封态；备份在 `_tmp-review/图片安全审查.SKILL.md.bak-1792548872351`）。
