## 一、为什么要有这个东西

目标原话：**「整链入口 = skill kb-pipeline，每到达一层，就调用该层的 skills」**。

`--via-skill` 让编排器不跑层引擎、把执行交给层 skill —— 通路是通的。
但**这一跑到底调没调**那些 skill，全库没有任何判据能回答，因为唯一声称「调了」的物证
`kb/l7/runs/<RUN>.json` 的 `skills` 字段，在 `kb_pipeline.py` 里是这么来的：

    skills_here = _layer_skills(x)      # 读 layers.yaml 的 skill: 字段
    called_skills.extend(skills_here)   # 名字来自注册表
    ...  skills=["kb-pipeline"] + uniq  # 写进 run 记录

**它会一模一样地生成，无论 agent 到底加载了几个 skill —— 包括一个都没加载。**
该字段因此**结构上不可能为假**，不能当证据。这与本库反复栽的
「自报失真 / 闸门静默说谎」是同一类缺陷（对照 `kb/l2/runs/20260929-1754-l2-unscheduled-run.json`）。

**实证（本单落笔时的真值）**：旗舰 run `20260930-152910` 判决「全走完」、`skills` 列了 8 层 10 项，
而各层 `runs/` 里**一个 skill 落章都没有** ——

    🔴 E1 记账即复述（1）：skills=10 项（去重后 9）与本跑走到各层的声明**逐项相同**；skill_evidence=缺失
    🔴 E2 逐层无落章（7）：L0…L6 全无落章
    ⚪ 豁免 L7：跨层统一闸门，不是 L7 的层主
    结论：❌ 未过 ｜ 红 8

### 2.1 新闸门怎么读

    kb/kbpy l7/scripts/skill_invocation_audit.py                 # 看最近一次 via-skill run
    kb/kbpy l7/scripts/skill_invocation_audit.py --all-runs      # 核全部

    kb/kbpy l7/scripts/skill_invocation_audit.py --json

退出码：**0 = 过 ｜ 1 = 未过（有红）｜ 2 = no-data**（没有可核的 run —— **既不算通过也不算失败，不凑分**）。

判据：

- **E1 记账即复述**（红）：run 的 `skills` 恰等于「本跑走到各层的声明（去重保序）」，
  且 `extra.skill_evidence` 缺失或为 `registry_echo`。
- **E2 逐层无落章**（红）：该层在 `kb/<layer>/runs/` 里没有本 RUN 的落章。
- **E3 落章与声明不符**（黄）：有落章但 skill 名对不上。
- **豁免 L7**（明写不静默跳过）：`kb-check` 是跨层统一闸门（注册表 `layer=「—」`），
  与 `skill_conformance.py` C7 的同款豁免一致；且 `kb/l7/runs/<RUN>.json` **就是编排器自己的
  记账文件**，结构上不能自证。

**边界（本闸门不重写别人的判据）**：
「层 ↔ skill 存不存在 / 登记没登记 / 装没装」→ `skill_conformance.py` 的 **C7**；
「源 ↔ 装位副本一致」→ `skills_check.py` **第 3 类**。

### 2.3 编排器侧改了什么

- 新增 `--invoked <SKILL_ID>`（可重复）：agent **实际加载过**的层 skill。
  传了 → `skills` 写上报值，标 `skill_evidence: "agent_reported"`；
  没传 → 照旧写声明值，但标 `skill_evidence: "registry_echo"`（**证据闸门会判它不算数**）。
- `extra` 新增：`layers`（本跑真走到的层，拓扑序）、`declared_layer_skills`（层 → 声明）、
  `invoked_reported`。老字段 `layer_skills` / `layer_skills_uniq` 保留。
- **向后兼容**：不带 `--invoked` 时行为与改动前一致，只是多标了一个 `registry_echo`。
- `--invoked` 不带 `--via-skill` → 报错退出 2。

## 五、留给对方的三件（分工决定：本会话不做）

1. **①(a) 层侧落章** —— 让每个层 skill 跑完往自己那层 `runs/` 里盖 `skill`。
   这是 ① 的另一半，也是让上面「验收条件」能变绿的唯一路径。**不落章，目标就只能"相信"不能"证明"。**

   「被 kb-pipeline 以层身份调用时」的契约（其余 7 个 0 处）。风险具体：
   `kb-l0-feishu` 不知道自己被调用时禁 `--full`（该档会越层重跑 L1→L2→L3 与 L6）；
   `kb-clause-extractor` 的表格写着「跑 L0→L7 → kb-pipeline」，在链里照自己的表走会**回头递归**。
   三个该收的参数（`RUN` / 库根 / **只跑本层**）也没有任何层 skill 声明会接收。
3. **③ `l6_bench.py` 归属** —— `layers.yaml:361` 自己写着「**没有任何层 skill 认领**」，
   所以 L6 那层调了 `kb-recall`，`l6_bench` 仍无主。

**另有两处覆盖不到（要不要做另定）**：
- 没有任何判据核 `skill_write` 与 skill 正文自述是否对得上（B2 之后最容易出这种漂移）。
