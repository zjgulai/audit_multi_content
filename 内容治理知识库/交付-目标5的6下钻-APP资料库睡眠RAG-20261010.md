## 二、修掉的三个引擎缺陷（**两旧一新**）

本件没有另写引擎，而是**扩源 + 修缺陷**（`kb/l8/drill_links_2levels.py`）。

**缺陷①（既有）lark-cli 参数过期**，两处：
```python
cli("docs", "+fetch", "--token", obj)    # ❌ unknown flag "--token"
cli("docs", "+fetch", "--doc",   obj)    # ✅
```
报错 JSON **照样被写进产物文件**（所以看文件像"有内容"，其实正文是报错）。
→ 修后 level-1 **54 → 57 ok**。同批把 `sheets +workbook-meta/+read` 改成 `+workbook-info/+cells-get`
（两者已 `--help` 核实存在）。

**缺陷②（既有）产物文件里混进报错正文** —— 引擎的 `ok/fail` 判定是**对的**
（我逐条独立审计 54/10，与它自报逐条一致），**假绿只在产物文件**。**本件未改这个行为**，只报出来。

**缺陷③（★ 我自己扩源带进来的）产物命名碰撞**：
`save(f"L1-{rid}")` 是**一条记录一个文件名**；原来源只有「材料收集 × 材料链接」一个字段，
每条至多 1 个 URL ⇒ **撞不上**。扩到 ⑥ 的**两个字段**（`文件/链接` + `资料名称`）后，
同一条记录出 2 个 URL ⇒ **后者覆盖前者**。首轮实测 **64 条边只落 52 个文件，12 份正文被覆盖丢失**。
→ 修法：同一记录出多个 URL 时文件名带 **URL 短哈希**（内容派生、可复算）；只出 1 个时沿用旧名。
→ 修后 **碰撞 12 → 1**，且那 1 个是**两个字段指向同一个 URL**（同内容，**非数据丢失**）。
