# 诊断：飞书群回执 1 次 15.8 秒超时 —— 归因结论

> 对象：PRD **v1.3 §12「响应」**「飞书群 @Agent ≤ 5 秒」
> 判据：`kb/l8/measure_group_response.py` ｜ 登记处：`kb/l7/registry/perf-known-drift.yaml → group_response`
> 归因日期：2026-10-17 ｜ 数据源：`~/Project/audit_multi_content/PMO/logs/ws_daemon.log`

---

## 一、一句话结论

**不是常态，也不是我们变慢了。** 57 次观测里只有 **1 次**超过 5 秒；
那 1 次的 15.8 秒里，**约 15.55 秒花在「把回执卡发出去」这一段外部调用**上，
判定只用了 **224 ms**，而且同一时刻同一条消息**被飞书重复投递**了一次。
⇒ 指向**平台侧偶发尖峰**。

> ⚠️ 这是**推断**，不是证死 —— 见第四节「局限」。

---

## 二、实测读数（现读，不是快照）

```
观测数 57 ｜ min 796 ms ｜ **中位 1053 ms** ｜ max 15807 ms ｜ 门槛 5000 ms
结论：❌ 未达标 —— 1/57 条超 5000 ms（最慢 15807 ms）
```

超线分布：**1/57 = 1.75%**。次慢的几条是 3985 / 3564 / 3489 / 2720 / 2676 ms —— **都在门槛内**。
（判据口径：`measure_group_response.py:71` = **任一条超门槛即 FAIL**。本件**不改这个口径**。）

---

## 三、证据链（那 15.8 秒花在哪）

### 3.1 出问题那一次的原文（`ws_daemon.log` 行 16490–16497）

```
[+72425.655s] ★ 收到消息 … 原文="…你读不到你怎么做审核呢？"
[agent] 🧭 送审闸门：text —— 命中送审词：审｜起链
[+72425.906s]    🃏 卡片 receipt · column_set(1栏) · markdown      ← 建卡完成，ingress 后 251 ms
[metric] group_response_ms=15807 ack_decision_ms=224 prd_limit_ms=5000 verdict=FAIL
[+72447.165s] ★ 收到消息 …（同一条 msg_id）  · 不回复（duplicate）   ← 平台重复投递
```

### 3.2 对照：一条正常的回执（行 22761 附近）

```
[+443.556s]    原文="Playard & Smart Baby Monitor BM04 Bundle…"
[+443.810s]    🃏 卡片 receipt · column_set(1栏) · markdown      ← ingress 后 254 ms
[metric] group_response_ms=1004 ack_decision_ms=178 prd_limit_ms=5000 verdict=pass
```

### 3.3 相减得出「发送」那一段

| 段 | 正常那次 | 出事那次 | 差异 |
|---|---|---|---|
| ingress → 建卡 | 254 ms | 251 ms | **一样** |
| 判定（`ack_decision_ms`） | 178 ms | 224 ms | **一样** |
| **建卡 → 发送完成**（= 总时长 − 建卡时刻） | **~0.75 s** | **~15.55 s** | **慢约 20 倍** |

⇒ 三段里只有**发送**那一段异常。**判定路径、建卡逻辑、LLM 全部排除**
（那一次根本没调 LLM：日志里 `LLM 调用 0` 心跳紧挨着）。

### 3.4 第二条旁证：同刻事件重复投递

事故 21.3 秒后（`+72447.165s`），**同一条消息、同一个 `msg_id`** 又被投递一次，
守衡按去重规则回 `· 不回复（duplicate）`。同一时间窗内出现「发送慢 + 事件重投」，
两者都是平台侧行为。

## 四、局限（不许当成已证死）

1. **日志没有记「发送完成」的时刻**。上面的 15.55 s 是用
   `group_response_ms(15807) − ack_decision_ms(224) − ingress→建卡(251)` **相减**得出的，
   不是直接观测到的。
2. 因此**不能排除**「我们的发送调用被别的东西串行挡住」这种可能 —— 只能说
   该窗口内日志**没有记录任何其它工作**（+72425.9 → +72447.1 之间是空的）。
3. 单点样本（n=1 超标）。**不能**据此推断超时率。
