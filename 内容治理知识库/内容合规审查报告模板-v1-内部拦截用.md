# 内容合规审查报告 · 模板 v1（内部发布前拦截用）

> **用途**：内部发布前拦截。读者 = 投放/内容团队（改什么）+ 法务复核人（认不认这个结论）。
> **不作对外合规证明**，不提交平台申诉，不替代法律意见。
> **本模板与库内口径对齐处**：三态取值、置信度分档、问题分类汇总口径、五段溯源、层前置闸门 —— 均照 `kb/l7/registry/report-output-contract.yaml` 与 `confidence-policy.json` 现行口径写，未另立标准。

---

## 0. 使用说明（先读这 5 条，再填）

1. **六段全填才算报告**。缺任一必填段 ⇒ 该件降级为「工作记录」，**不得当作拦截依据**，也不得写进飞书结论表。
2. **`{{ }}` 是占位符**，`（ ）` 是填写提示。占位符没换掉就发出去，等同于伪造。
3. **「事实」与「判断」必须分栏**。这一条是审计报告与普通总结的唯一分界线 —— 混写之后没人能复核，也就没人能负责。
4. **不许写没有锚点的依据**。每条发现至少要有：定位（能点开落到原处）+ 依据（条款号/准则号/政策 URL）+ 指纹（sha256 或快照时间）。三样缺一样，这条发现只能写成「观察」，不能进发现清单。
5. **结论只能是四个枚举之一**，不许写「基本合规」「问题不大」「建议优化后发布」这类话 —— 它们无法被机器读，也无法被追责。

## 二、结论

### 2.1 结论枚举（四选一，无第五种）

| 取值 | 定义 | 触发条件（满足其一） |
|---|---|---|
| **PASS** | 可以发布 | 无 P0/P1 发现；置信度 ≥ 0.90；覆盖面声明已填且**无未声明盲区** |
| **REVIEW** | 改完再看，或转人工确认 | 存在 P1/P2 发现；**或**置信度落在 0.70–0.89（强制 REVIEW，不许直接 PASS） |
| **BLOCK** | 不得发布 | 存在任一 P0 发现。**P0 不看置信度**，命中即 BLOCK |
| **NEEDS_INPUT** | 本次未判 | 素材/上下文缺失、覆盖不足、层前置未过、引擎拒答。**不得折算成 PASS，也不得当拦截依据** |

**P0 例外口径（照 `confidence-policy.json` 现行实现）**：P0 命中 ⇒ 结论恒 BLOCK、置信度记 **1.0**，且**不合并模型侧置信度**（模型侧记为"未参与"，不是记 1.0）。

### 2.2 结论栏

```
结论：{{PASS | REVIEW | BLOCK | NEEDS_INPUT}}
发现数量：{{n}}   分维度：合规 {{a}} ｜ 安全 {{b}} ｜ 权利 {{c}} ｜ 本地化 {{d}}
置信度：{{0.00}}（{{direct ≥0.90 直接输出 | confirm 0.70–0.89 强制人工确认 | p0 命中恒 1.0}}）
能否外发：{{可直接群发 | 仅内部 | 不得外发}}
```

### 2.3 一句话结论（≤ 40 字，供直接贴到群里）

> `{{例：本版 listing 有三处功效/等级宣称需替换，其余可发。}}`

**禁写**：`未发现违规`、`内容合规`、`无风险`、`应该没问题` —— 这四句在无覆盖声明的情况下**等于伪造证明**。

## 三、发现清单（报告的主体）

### 3.1 字段定义 —— 九个字段，缺一个这条就不能进清单

| # | 字段 | 必填 | 写法 | 反例（别这么写） |
|---|---|---|---|---|
| 1 | `F-ID` | ✓ | `F-01`，可被整改单引用 | `问题1` |
| 2 | `发现类型` | ✓ | **违规 / 偏差 / 证据缺口 / 指标异常**（四类**不许混**，处置完全不同） | `风险`（太笼统） |
| 3 | `严重度` | ✓ | `P0 立即停发` / `P1 24h 内` / `P2 本版改` / `P3 记录` | `高`（形容词不绑定动作） |
| 4 | `定位` | ✓ | 逐字原文片段；或 `表@记录ID`；或 `视频 @00:32` | `第三段`、`标题里`（落不到原处） |
| 5 | `判定依据` | ✓ | 条款号 `W-1.44` / 准则号 / 政策 URL | `平台规定`（等于没引） |
| 6 | `证据指纹` | ✓ | 源记录 sha256，或快照时间+来源 | 无（事后改了不认账） |
| 7 | **`事实 / 判断`** | ✓ | 机读命中（哪条规则、命中什么词）**还是**人判（谁、按什么语义） | 两样混在一句话里 |
| 8 | `处置 + 责任人 + 期限` | ✓ | 改什么、谁改、几号前改完 | `建议优化` |
| 9 | `边界` | ✓ | 这条**不能**证明什么 | 空着（会被拿去做它证明不了的事） |

> 第 7 条是命门：`事实` = 可以复跑出同一个结果的（关键词命中、阈值越界）；`判断` = 需要人确认语义的（分级归类、场景适用性）。**查不到的，写「证据缺口」，不要写成「违规」。**

### 3.2 严重度 → 处置映射（不许现场拍）

| 严重度 | 含义 | 处置 | 谁批可以放行 |
|---|---|---|---|
| **P0** | 红线：绝对化用语、医疗功效、无依据资质背书、儿童安全、侵权实锤 | **立即停发**，存量下线 | 无人可批（只许改，不许放） |
| **P1** | 高：可能被平台下架/限流，且证据链不完整 | 24h 内改完再送 | 法务复核人 |
| **P2** | 中：措辞风险，影响权重/合规评分 | 本版内改，不阻塞排期 | 内容负责人 |
| **P3** | 低/提示：最佳实践 | 记录，下版优化 | 无需审批 |

### 3.3 单条发现填写块（复制这段）

```markdown
### F-{{01}}｜{{发现类型}}｜{{P0 立即停发}}
- 定位：`{{逐字原文片段}}` ｜ {{表@记录ID 或 视频@时间码}}
- 依据：{{《规则库名 vX》第 W-x.yy 条}}（{{可点链接}}）
- 证据指纹：`{{sha256}}`
- 事实：机读命中「{{命中词}}」（规则 {{rule_code}}，扫描 {{N}} 条中的第 {{i}} 条）
- 判断：{{语义归类理由，一句话}}（{{谁判}}）
- 为什么是 {{P0}}：{{绑定 3.2 表里的哪一行}}
- 处置：{{改成什么话 / 删掉 / 补证据}}｜责任人 {{谁}}｜期限 {{MM-DD}}
- 边界：这条只说明「{{表述}}」有问题，**不说明**{{别的方面}}没问题
```

### 3.4 条数 ≥ 3 时怎么写

- 报告正文**只出分维度汇总**（`合规类问题：3 个`），完整清单放附录或链接，避免刷屏。
- **汇总必须是数字，不许在汇总格里塞口径说明**（口径进运行日志，不进表格）。
- 条数汇总与附录清单条数**必须相等**；不相等 ⇒ 报告作废重出。

## 四、覆盖面声明（必填，缺此段整份报告不得用于拦截）

> 这一段的理由只有一句：**隐去覆盖范围的合规报告，比没有报告更危险** —— 因为它会被当成安全证明。

### 4.1 三栏

| 栏 | 填什么 |
|---|---|
| **本次实际查了什么** | 逐项点名：文字规则 {{N}} 条｜图片 OCR {{是/否，provider+版本}}｜视频转写 {{是/否，模型}}｜商标图搜 {{通道}}｜人工语义复核 {{哪些维度}} |
| **本次没查什么（逐项点名）** | 例：`未做外观专利/图形商标图搜`、`未查在审未公开专利`、`未核达人肖像授权原件`、`未做竞品对比取证` |
| **本结论在什么情况下失效** | 例：`送审内容有任何改动`、`渠道变更`、`规则库版本变更`、`投放国家变更` |

### 4.2 标准句式（直接抄，别改写）

> **本次覆盖**：{{逐项}}。
> **本次未覆盖**：{{逐项}}。以上未覆盖面**不在本结论的保证范围内**。
> **查不到不等于安全** —— 在审未公开的专利、刚受理的商标、未入库的版权登记、未送审的投放变体，本报告一律看不见。
> 本报告用于内部发布前拦截，**不构成合规认定或法律意见**。

### 4.3 申报纪律（硬）

- **没真跑过的模态不许填「已覆盖」**。填了等于伪造覆盖面，比漏检更严重。
- 模态覆盖信息可由调用方申报，但报告里必须留痕「这份 complete 是谁说的」（申报 ≠ 引擎自测）。
- 覆盖不足时，结论只能是 `NEEDS_INPUT`，**不许**因为"看起来没问题"给 PASS。

## 九、本模板的边界（写在这里，防止被误用）

1. **未命中 ≠ 合规**。没查出问题只说明"按这一版规则、在本次覆盖范围内没命中"，不说明内容安全。
2. **本报告是内部拦截件**，不是法定审计报告、不是法律意见、不能用于平台申诉举证。
3. **模板不保证结论对**。它保证的是"结论可复核、可追责、错了知道错在哪一段"—— 这是审计式的价值，不是全知。
4. **规则库本身可能是错的**。规则有版本；报告里已绑定版本，规则改了，本报告的判定依据就作废，要重出。
5. **跨市场不通用**。同一句文案在美国站与欧盟站的结论可能相反，换市场必须换报告。
