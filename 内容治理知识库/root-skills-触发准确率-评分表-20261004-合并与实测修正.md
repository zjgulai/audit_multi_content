## 3. 两份旧报告为什么打起来：口径冲突（已查清，非数据冲突）

读原文核实（逐字）：

```
~/.dsh/AGENTS.md  L46  「1. 评测主执行：root-skills-eval」
                  L48  「3. 前置诊断：…先走 root-skills-doctor（D001-D007 + D100 系列）」
                  L49  「4. 放行闸门：出报告前加载 root-skills-check」
```

⇒ **一次「评测」按规程就必须共载 `eval` + `doctor` + `check`。**

而原始数据里 `doctor`/`check`/`eval` 的 FP 绝大多数正是这种共载：

| 用例 | 3 轮实际加载 | 性质 |
|---|---|---|
| `P-eval-1`（评测 doctor 并出评分） | `eval`+`doctor`+`check` ×3 | **规程强制共载** |
| `P-eval-3`（schema 体检 + 触发评测） | `eval`+`doctor` ×3 | 共载（doctor 自称覆盖 description 触发质量） |
| `P-batch-1`（批量评测 60 个） | `batch-driver`+`eval`+`doctor`+`check` ×2 | 共载 |

⇒ **严格口径把「按规程办事」记成了「误触发」**，于是 `eval` 的 P 被压到 0.379、`doctor` 0.586。
**这是口径产物，不是触发缺陷。** 复核轮的口径（只看「该接的接住了没」）正是为了避开这一点，所以给了 eval 88.3 而不是 0.515——**两边各自自洽，分歧在分母**。
⚠️ 按此口径，下一步若自动去修 `eval`/`doctor` 的「误触发」，**会去改本来正确的东西**。

4. **24 次全新盲测**（§4）：修法验证、安全尾巴、泛指话术、目录可见性。

**没做 / 做不到**：
1. **没跑 `root-skills-eval` 的合规双轨评测**。按各成员声明的 complexity，A 卷 6×100+1×50=650 条 ×3 轮 + B 卷 7×10×3 ⇒ **约 2160 次子会话**，另加出题自检、轨道 A 静态六维、轨道 C 综合评分与单一 HTML 报告。**正确入口是 `root-skills-batch-driver` 驱动 `root-skills-eval`。**

## 7. 一句话结论

**这个家族「该接的都接住了」——7 个成员里 6 个真实漏触发为 0，用例级通过率 94.4%；唯一真缺口是 `root-skills-manage`（`P-manage-3` 3/3 被判给 `kb-manage`），而它同时还有一处与模型无关的确定性错误（registry 登记 7 个、正文只写 6 个、漏 `batch-driver`）——所以先修 `root-skills-manage`：补路由表 + 给 description 加家族域限定（改法已实测 3/3 有效）；`root-skills-eval` 的低分主要是 `AGENTS.md` 规程共载被记成了误触发，那是口径问题、不是 skill 的问题，动它之前先裁口径。**
