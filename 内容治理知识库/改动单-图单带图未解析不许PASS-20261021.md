# 改动单 · P0「带图但一张都没解析出来 ⇒ 不许 PASS」· 2026-10-21

> 一句话：把「图没被解析出来就退化成文字单」这条 **fail-open** 堵掉 ——
> 消息**意图上带图**、而**解析出 0 张**时，本单结论一律压成 `NEEDS_INPUT` 并在卡上写明原因，
> 不再允许出 `PASS / 0 条`。判据是纯函数（12 条自证），接线两处（入站 + 出结论），测试两组（N4e/N4f）。

## 一、病灶（实测，不是假设）

模态是**猜**出来的（`tools/agent/agent.mjs`）：

```js
const _chainModality = (inbound?.videoCount ? null
  : (inbound?.imageCount ? 'image' : 'text'));
```

而 `imageCount` = **解析成功的图数**（`feishu.imageKeysOf`）。以下情形全部解析出 0 张，
于是 `--content-type` 退化成 `text` ⇒ **「负面样本规则」那一层整层不跑** ⇒ 出 `PASS / 0 条`：

| 情形 | 为什么会 0 张 |
|---|---|
| 飞书里**以文件方式发的图** | `imageKeysOf('file', …)` **恒返回 []**（该函数只认 image / post） |
| 图消息但 content 缺 `image_key` | 客户端拆过/改过 |
| 富文本 `post` 的图节点解析不到 | 结构变体 |
| 引用一条带图的消息、**回读失败** | `parentNote.kind='parent_unreadable'`（这是**未测**，不是「没有图」） |

代码里自己记着实测（`tools/agent/tools.mjs` 约 1944 行）：

```
10:06:48 --content-type text  → PASS / 0 条（负面样本规则层根本没跑）
11:10:00 --content-type image → REVIEW / 5 条
```

—— **同一份图，只差这一个词**。这是全链路里最坏的一种结果：**零条被当成没问题**。

## 五、边界（说清楚，别期待它做不到的事）

1. **只管「图有没有进来」**，不管「图看没看懂」。侧卧/仰躺这类画面判断仍归 P1b 的视觉核对清单。
2. **视频单不归本闸管**（`videoCount>0` 不介入）—— 视频要五个模态的佐证，另案。
3. **图取到了但 OCR 空 / 取失败**（`imageCount>0` 而 `images[].failed`）**不归本闸管**，
   走各自已有分支（OCR 空 → 视觉层；取失败 → 如实报）。
4. 本闸是 **单向**的：只把 PASS 挡住，不动 `BLOCK / REVIEW / NEEDS_INPUT`。
