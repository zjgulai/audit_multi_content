# 验收判据 A1–A4 与判读口径

> 读取条件：过验收、判「这轮算不算过」时读本文件。

## A1 — 闸门退出 0

```bash
kb/kbpy l7/scripts/l3_gate.py ; echo "exit=$?"
```

退出 0 的含义是两件事同时成立：

1. 候选的 `evidence_units[]` **全可回指** L2（`unit_id` 存在、`source_sha256` 匹配、`anchor` 落得上）；
2. 注册表**自报键全已声明**（不可复算的键必须逐键登记，登记 ≠ 豁免）。

红的三种常见形态：引用悬空（单元被重切）、指纹不匹配（源被改写）、
自报键未声明（新增统计口径没登记）。

## A2 — 归档在且指纹一致

```bash
shasum -a 256 kb/l3/_archive/rejected-pre-<RUN>.jsonl kb/l3/rejected.jsonl
```

两个值必须一致；不一致说明归档不是当次跑的基线，**不许**拿它当回滚点。

## A3 — 只追加

判定方法：跑前对 `kb/l3/candidates/*.jsonl` 做逐行 sha256 清单，跑后逐行比对：

- 旧行**逐字节未变** → 通过；
- 旧行被改写 / 消失 → 不通过（哪怕总行数变多了）；
- 新行只能出现在末尾（追加）。

## A4 — 六要素在定稿上仍可物化

```bash
kb/kbpy l7/scripts/l7_gate.py ; echo "exit=$?"
```

L3 变红会顺着链路打到 L4/L5/L6。A4 是「本层没把下游带崩」的收口判据。

## 四步结果怎么写进结论

结论必须带 **run_id + 时间戳 + 四项 exit code**，
写成「L3 于 `<时间戳>` 由 `RUN=<YYYYMMDD-HHMM>` 跑完，A1=0/A2=一致/A3=只追加/A4=0」。
没有 run_id 与时间戳的「跑完了」**不算结论**；库内是并发环境，没有时间戳无法界定读到的是哪一版。

## 闸门红了怎么办

1. 只做**只读取证**：定位是哪一类红、涉及哪些 `rule_id` / `unit_id`；
2. 不猜原因、不手改数据、**绝不删台账行**让闸门变绿（删行 = 毁出处）；
3. 交 **kb-repair**：它要求以一条已红闸门为输入，按原因码定位 → 修 → **重跑同一条闸门**证明修好。

## 常见误判

| 误判 | 事实 |
|---|---|
| 候选条数涨了说明质量变好 | 涨可能是放水；要比质量得固定同一把尺子，把两轮放一起量 |
| 拒绝台账行数少了说明蒸得更好了 | 台账是逐单元记账，行数受上游切分粒度影响，不是质量指标 |
| 候选 + 台账条数对得上就没漏 | 只对总量对不出漏；要用 L2 `unit_id` 做分母做集合差，归因到 0 |

## 缺料与异常处理（2026-10-04 由 SKILL.md §4 下沉，逐字保留）

| 缺料/异常情形 | 动作 |
|---|---|
| 没给源文本 / 没说哪一批 / 没给 RUN | **追问**，不猜、不按「上次那批」续做；追问时同时给可执行跑法与判读口径 |
| 「按老规矩跑」但没说哪批 | 先复述「老规矩」三步征得确认，再要素料 |
| 看不出漏没漏 | 只数行数**证明不了**漏没漏（规则按 `rule_code` 聚合、台账逐单元）；用集合差归因到 0 |
| `l3_gate.py` 非 0 退出 | 只做只读取证 → 交 **kb-repair**（按原因码修）；**禁止**删台账行让闸门变绿 |
| 台账被覆盖 / 行数掉了 | 查 `kb/l3/_archive/` 与 `kb/l3/runs/` 的 pre-snapshot；恢复不了就**如实说恢复不了** |

**永远不做**：凭印象说「跑完了」；编造 `unit_id` / `article_no` / 条数 / 原因码实例当实测结果。
