## 一、病灶：**度量被测量行为本身抬高**

`kb/l7/runs/index.jsonl` 是评审台账，而 **`with_kb_evidence.py:1223` 每跑一单都记账**：

```python
_rr(source="review_machine", trigger=(text[:60] + …), …)      # → run_record.record()
```

`kb/l7/scripts/run_record.py::record()` **无条件**追加 `index.jsonl`。
而 **回归跑批**（`kb/l8/regression_run.py`）一次 subprocess 跑 **100 单**
⇒ **跑一次回归就往评审台账灌 100 行**。今天两个会话合计跑了**至少 6 次**跑批。

**代价不是"台账脏"，是"指标被抬高"** —— xlsx 的 G 列与多份交付件里的
「**文字链路跑通 · 累计评审单数 562 / 580**」，来源逐字是 `.work/task_xlsx_g_values*.py`：

> 「评审 run 累计 **562 条**（`kb/l7/runs/index.jsonl` 的 `source=review_machine`，10/10 现读）」

**它数的是行数**，而行数 = 「跑过多少次」，不是「受理过多少条」。

## 二、真读数（`kb/l8/review_run_count.py`，2026-10-12 11:56 快照，可复跑）

```
· 原始行数（source=review_machine）        ：1110   ← 会被重跑与回归跑批抬高
· 按素材去重的单数（同一 trigger 算一单）   ：254    ← 该引用的是这个
· 重跑行数（原始 − 去重）                  ：856
    其中来自回归集素材的行                 ：318（涉及 44 条不同素材）
· 单条素材最大重复次数                     ：65
· 按天（原始 / 去重）：10-12  532 / 51 ｜ 10-09  139 / 36 ｜ 10-06  73 / 56 ｜ 10-08  61 / 28
```

⇒ **「累计 580 单」与真实「254 条不同素材」差 2.3 倍**，而**差额几乎全是重跑**。
⇒ 今天（10-12）更极端：**532 行 / 51 条不同素材** —— 91% 的行是重跑。

**口径（已落成工具，可复算）**：引用「累计单数」一律用 **按素材去重的单数**；
原始行数量的是「跑过多少次」。两条都打出来，**不许只给一个数**。

★ **口径的边界（照实说）**：去重键是 `trigger = text[:60]` ——
① 前 60 字相同的**不同**素材会被并成一条（低估）；
② 同一素材**改过字**再送审不会并（高估）。所以 254 是**近似**，
但比「1110」离「受理过多少条」近得多。

## 三、修法：**写入侧隔离**（只读测量不许进评审台账）

### 3.1 `kb/l7/scripts/run_record.py`

```python
_SKIP_ENV  = "KB_RUN_RECORD_SKIP"     # =1 ⇒ 跳过记账，**但往 stderr 打一行**（不许静默）
_FORCE_ENV = "KB_RUN_RECORD_FORCE"    # =1 ⇒ 压过 SKIP（写要写出来）
```

两个变量**只有显式设置才生效** ⇒ 日更 / 守衡 / API 那些既有调用方**行为一字未变**。

### 3.2 `kb/l8/regression_run.py`

跑批**默认**给子进程带上 `KB_RUN_RECORD_SKIP=1`；要记账得显式 `--record-runs`。

### 3.3 真数据反向对照（三种取值，实测）

| 跑法 | 台账增量 |
|---|---|
| 引擎直调（不带开关，＝改前行为） | **+2**（那次命令里我写了个失败回落的第二次调用，两次都记了 —— 顺带演示了污染） |
| `KB_RUN_RECORD_SKIP=1` | **+0** ✅，且 stderr 有说明：<br>`[run_record] 已跳过记账（KB_RUN_RECORD_SKIP=1）：source=review_machine ｜ trigger='100% safe breast pump'` |
| `KB_RUN_RECORD_SKIP=1 KB_RUN_RECORD_FORCE=1` | **+2**（FORCE 压过 SKIP） |
| `regression_run.py --out … --limit 1` | **+0** ✅ |
| `regression_run.py --out … --limit 1 --record-runs` | **+1**（该条 review_machine；同期另有 2 行 `daily_health` 是 30 分钟巡检写的，不是跑批） |

**判据自证**：`regression_run.py --selftest` 加 ⑥a / ⑥b（默认带 SKIP、`--record-runs` 摘掉它）⇒ **7/7 ✅**；
`review_run_count.py --selftest` **7/7 ✅**（含「原始行数只数 `review_machine`」「按天去重 ≠ 总量去重」等反向对照）。

## 四、★ 本件**没有**做的三件事（都写清理由与推荐）

### 4.1 没有回洗 `index.jsonl`

它是**审计台账** —— 记的是「发生过什么」。**抹掉重跑记录 = 抹掉证据**，
而且抹了之后「今天跑过 6 次回归」这件事就查不到了，下次会再犯。
⇒ **推荐：不回洗**，改成**引用侧带口径**（本件已给工具）。
**代价**：台账会继续变大（今天 532 行是历史事实），且**任何仍按行数引用的旧文档都会继续偏高**。

### 4.2 没有改 xlsx 的 G 列，也没有改另一会话的脚本

`.work/task_xlsx_g_values*.py` 与 `build_week_closeout.py` 是**另一会话的产物**，
本件不越界改。⇒ **推荐：由它或 Owner 用本件的读数重跑一次**，
把 G 列那句改成「累计 **254** 条不同素材（原始 1110 行，含重跑）」。
**代价**：那个数是**快照**，重跑一次回归就会变 —— 所以**口径**要跟着写进去，光改数不够。

### 4.3 没有关掉引擎的记账

`with_kb_evidence.py` 的记账**不能关**：守衡真实送审的台账是审计要求。
本件做的是**按调用方隔离**（跑批、自证、离线探针带上开关），**不是**全局阉割。

## 七、★ 收口时被真实事件照出来的**我自己的**一个缺陷（当场修了）

收口复跑时 `regression_gate --strict` 突然从 **GREEN** 掉成 **未测(4)**。查因：
**另一会话为「风险分类」改动跑了一份 8 行、旧读法的** `kb/.work/regression-rc-check.jsonl`，
mtime 最新 ⇒ 我的 `newest_artifact()` **只按 mtime 取件** ⇒ **半成品劫持了读数**，
而库里明明躺着一份 **100 行、同源读法、刚比对过**的产物。

「未测」不算红，所以它**不会误判成回归**；但它会**把真读数盖住** —— **同样是错**。

**修法**：取件口径改成「**可判优先，旧读法垫底**」——
① 同源读法 **且** 覆盖基线 ≥90% solid 的最新一件；② 同源但覆盖不足；③ 都没有才取旧读法。
输出里加一行 **`取件：<理由>`**，让「这次读的是哪一份、为什么是它」**看得见**。

**判据**：`--selftest` 加 **R8 / R8b**（临时目录造「旧的同源」＋「新的旧读法半成品」，
必须选前者；同源那份删掉后必须选后者并写明「旧读法」）。
**变异自证**：把取件退回「只按 mtime」⇒ **R8 精确红**（选到了半成品）。自证 **8/8 → 10/10 ✅**。

★ 这条值得单记：**是「复跑一次」照出来的，不是想出来的** ——
与 §一 那条（度量被测量行为抬高）是同一类病：**测量工具本身也要有人测它。**
