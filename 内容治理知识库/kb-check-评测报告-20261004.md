## 4. 实测缺陷清单（每条含复现命令与证据）

### 4.1 `envelope_census.py` 在文档口径下 100% 崩溃（**真坏，最严重**）

- **文档口径**（`SKILL.md` §1 与 `l7/selftest_f_family.md` §0 一致）：`cd "<本次库根>"`，命令写 `kb/kbpy l8/envelope_census.py`。
- **实测**：

```
$ cd <内容治理>/kb && sh kbpy l8/envelope_census.py     # cwd = 库根
node 扫描失败：Error: Cannot find module '…/内容治理/kb/kb/.work/sizes_node.mjs'
exit=1

$ cd <内容治理> && sh kb/kbpy l8/envelope_census.py      # cwd = 库根的父目录
信封普查：扫了 8747 个 .md，其中 1079 个 node 侧读不到（差值 [4096] 字节）
结论：OK    exit=0
```

- **根因**（代码级）：`kb/l8/envelope_census.py:58` 定义 `KB = "kb"`（相对路径），而同文件 `node_sizes()` 把 `f"{KB}/.work/sizes_node.mjs"` 传给 node，node 再按**进程 cwd** 解析 ⇒ cwd 是库根时变成 `kb/kb/.work/…`。
- **旁证**：同文件 §0 的口径 `kb/kbpy l8/_interp.py` 与 F1 的 `kb/kbpy l7/scripts/skills_check.py` 在 cwd = 库根时 **exit 0 正常**；F5a 是**唯一**要求 cwd = 父目录的命令，而文档没写。
- **影响**：**体检档 6 道闸门中的 ⑤ 有一半是死的**（`envelope_gate.py` 那半靠 skill 自身措辞侥幸对齐）。信封闸门存在的理由是本库实测"1248 个 .md 被宿主读成乱码"，是**高危可读性闸门** —— 它跑不起来等于这道防线不存在。

### 4.2 `skills_check.py` 的 `~` 路径判据缺陷仍成立（**warning，文档正确**）

- 文档称第 1001–1002、1018–1019 行不做 `expanduser`。实测确认：同文件有 `home()`（含 `expanduser`，:73），**但第 1018 行用的是 `st if st.startswith(("~", "/")) else …`，没调 `home()`**。
- 实证：登记 `~/.dsh/skills/kb-check/SKILL.md`（文件**确实存在**）会被判 `os.path.exists → False` ⇒ **误报"路径不存在"**。
- 物料性：当前 `skills.yaml` 里 168 条 `depends_on_*` 路径与 9 条 `selftest` **无一条以 `~` 开头** ⇒ **今天零影响**，但坑仍在，文档的规避建议（写库根相对路径）是对的。
- **结论：这一条是 skill 做得对的地方** —— 它诚实登记了自己的工具缺陷，值得保留。
