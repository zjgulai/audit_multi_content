### 1.1 为什么非做①不可（这是本单的**正解**）

旧跑手（`kb/.work/run_regression_set.py`）把两样东西读成**两个来源**：

```python
state    = out["decision"]["decision"]              # decide() 的产物
findings = cache["payload"]["findings"]             # review.py 的产物
```

而 `decide()` 的输入是（`with_kb_evidence.py:1180` ＋ `:1199`）：

```python
payload["risk_items"] = [_to_risk_item(f) for f in findings]
payload["risk_items"] += scan_text(text, product_line=product_line_seed, channel=channel)  # 无条件并入
```

再加上 `decide()` 自己的两条结构性差异（**P3 不进结论**、**覆盖缺口支路自造条目**），
两个来源**必然**对不上 —— **实测那 5 条「矛盾」5/5 是读法造成的假象**。

⇒ 判据落成三个字段，各归各的性质：

| 字段 | 含义 | 性质 |
|---|---|---|
| `orphan_p3_n` | 证据有、结论没采纳，且 `p_level=P3` | **合法**（§6.3 执行规则3） |
| `orphan_non_p3` | 证据有、结论没采纳，且**不是 P3** | **异常** ⇒ 闸门**判红** |
| `unbacked_n` | 结论有、证据侧查无此条 | **必须看得见**（结论由种子规则扫描器等**别的来源**驱动） |

## 三、基线（重采口径）

```
python3 kb/l8/regression_run.py --out kb/.work/regression-<tag>.jsonl   # 跑一遍（100 条 ≈ 9 分钟）
```

| 项 | 口径 |
|---|---|
| **收谁** | **只收 solid（80 条）**。fragile 20 条**不进基线** —— `regression-set.yaml` 自己写着它们「会合法变」（依赖库覆盖度），当断言等于把「库长大了」报成回归 |
| **拒收条件** | 有任何一条没拿到三态 ⇒ **拒收**（基线上不许有空洞） |
