## 一、病灶（实测，不是假设）

2026-10-21 那张母婴插画（床头柜上奶瓶**倒着放**）没被审到。逐段核过：

| 环节 | 实测结果 |
|---|---|
| skill 加载 | **真的加载了** —— 引擎 `image_skill_gate.load.verdict=loaded`，会话日志里有 `skill("图片安全审查")` 返回 `<skill_content>` |
| 判定主体 | 出了 2 条意见，但都是**模型侧**的「北美本地化 / Listing 准确性」（依据是 OCR 德语原文） |
| 四类画面事实 | **一条都没写** —— 婴幼儿姿势／产品状态／场景关系／隐私全缺 |
| 画面读数 | 认出了「白色小奶瓶」，但**没有朝向这一维**（schema 只有 setting/people/products{what,in_use}/marks/text_script/risk_cues/unclear） |

⇒ 根因不是模板，是 **「加载了 skill」≠「执行了 skill 里那道视觉核对」**，而流程上没有任何东西会红。

## 二、判据（`tools/agent/visual_checklist.mjs`，纯函数）

四类，缺一类就不收：

| 类别 | 结论闭集 | 额外要求 |
|---|---|---|
| 婴幼儿姿势 | `有` / `无` / `未测` | 判 `有` ⇒ 依据 ≥6 字（看到了什么、在哪）；判 `未测` ⇒ 原因 ≥4 字 |
| 产品状态 | 同上 | 同上 |
| 场景关系 | 同上 | 同上 |
| 隐私 | 同上 | 同上 |

认两种写法：紧凑一行（`视觉核对：婴幼儿姿势=无；产品状态=有（…）；…`）或分条（`- 产品状态：有（…）`）。
**只认「类别名 + 结论」同段出现** —— 光提名字不给结论不算覆盖（否则这条判据恒真）。

## 三、接线（三处）

1. `agent/agent.mjs`：结论算出来之后、`machineNumbers` 之前 —— 图单（`inbound.imageCount > 0` 且链跑成）
   调判据；不 ok ⇒ `conclusion = 'NEEDS_INPUT'`，卡/表那一格写明缺了哪几类（`summaryText` 新增一支）。
2. `agent/tools.mjs::reviewTaskFor`：**图单任务里下发**这份清单要求（`第 0 条之三`）；
   文字单/视频单**不下发**（它们没有这四类）。
3. `kb/l8/review_playbook.md`（知识库执行手册）：补一节「图单：四种画面事实必须逐项写」，
   写明判据与闸门位置 —— 手册与守衡下发的那份**不各写一套**。

## 五、边界（说清楚，别期待它做不到的事）

1. **只判"有没有写"，不判"写得对不对"**。写的对不对要人复核 —— 把"判内容"混进来，
   等于允许用一句话骗过闸门。
2. **只管图单**。视频单的视觉核对是五模态（关键帧/音画对齐…），另案，不这次塞。
3. **它不补画面能力**：读数里没有的事实，判定主体写不出来 —— 所以「产品状态=有（奶瓶倒置）」
   这一条**要求 scene 读数先有"朝向"这一维**（见下）。
