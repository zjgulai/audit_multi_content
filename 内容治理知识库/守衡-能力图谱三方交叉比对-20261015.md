### 2.2 §5.3 那条红灯——**代码与判据有一方必须改** 【事实】
- 失败断言：`②a 结论行后恰好一个空行`，实际 `-1`（即正则 `/。\n+·/` **根本没匹配上**）。
- 我把 ≥3 的真实渲染打出来看过：

```
【审查结论：REVIEW】共发现 5 处需人工确认。
                         ← 空行
逐条问题                  ← ★ 这一行是新插进来的
· 合规类问题：3 个
· 措辞表达类问题：1 个
· 消费者安全类问题：1 个
                         ← 空行
→ 查看完整问题清单与修改建议：https://feishu.cn/review/x
```

- 成因：**今天（10-15）新增的未提交改动**在分类汇总前插入了「逐条问题」标题行（`git diff` 里注释写「Owner 给了逐字格式」），而旧判据仍按 PRD §5.3 的原形状断言 `/。\n+·/`。
- 该测试自己打印：**「❌ 分段与 PRD §5.3 不符，别拿去发群。」**
- ⇒ **裁**：要么把「逐条问题」从 block 里挪回卡面分组、要么同步改判据。**改之前，「三态输出符合 §5.3」这一验收项只能记"未通过/未测"，不能记通过。**

### 2.3 三处假阳性——**都是我自己造成的，已排除** 【事实】

| # | 现象 | 实际成因 | 怎么排除的 |
|---|---|---|---|

⇒ **①②③ 一律不作为守衡的缺陷。** 但①派生一条**观察项**（非缺陷）：`judge_copy` 失败时返回的是 `ok:true` + `result.error`（含 1200 字原始 traceback），而不是 `ok:false`——模型侧收到的是"调用成功"。建议把失败收敛成 `ok:false` 或明确的 `未测` 状态。

### 2.4 实跑发现的真问题

**① `search_workspace` 已无法完成整仓检索** 【事实，已独立复现】

- **诚实之处**：工具**没有说谎**——它照实报「未测」，配套判据 `✅ 扫不完时必须说「未测」，不许下「没找到」的结论` **是绿的**。所以这是**能力退化**，不是诚信问题。

**② 生产数据里的字段污染** 【事实】

   - `kb_type = "external_standard"`（`matched_rule = R27`）
   - `rule_eligible = true`，理由「**独立登记的飞书侧来源**（不在任何受控表里），不受「材料收集」门槛约束」
   - `path = "[内容治理/已登记来源/PRD]"`
3. **实测可达**：`kb_search(query='安全座椅', collection='1_外部标准库')` 返回 `[LNK-cgtPEnmg-001]`，**命中正文就是 PRD §5.3.4 的 BLOCK 示例**（「【合规-绝对化用语】图片文字"最安全"为绝对化用语」）；`query='医疗宣称'` 返回的是 **PRD §5.2 的审查维度清单**。`cgtPEnmg` = PRD wiki token `NB55wAq8liEOdKkquL2cgtPEnmg`。

**风险（【推测】，附推翻条件）**：守衡的"条款级依据"通道**已能检索到被审对象自己的规格文档**。一旦某单检索命中它，就会出现**"用 PRD 证明内容合规"的循环论证**。
