## 一、缺陷（已复核，可复算）

`kb/l7/skills/kb-content-review/scripts/review.py` 第 982、1015 两处（逐字）：

```python
sev = "BLOCK" if (h.get("p_level") == "P0" or h.get("risk_level") == "高危·红") else "REVIEW"
```

`h["risk_level"]` 取自 **L3 规则行**（`review.py:261` 建 `hits` 时搬的 `r.get("risk_level")`）。
而 **2026-10-10 的换词表**（`kb/l3/registry/dimension-policy.json → risk_level_map`）

⇒ `== "高危·红"` **恒假**。这是**哑失败**：不抛异常、不报错、分布上也看不出来。

**代价（实测）**：**41 条**规则 `risk_level=Critical` 但 `p_level≠P0` ⇒ 本该 BLOCK 的落了 REVIEW
（改前 35 条）。靠前半句 `p_level == "P0"` 兜住的只有 **15 条**。

## 五、边界与已知代价

- **本单会改三态结论**（REVIEW → BLOCK）—— 这是**唯一一处**工作流可见的行为变更，
  正是它必须带回归集前后对照才敢动的原因。
- 单调性方向：**只升不降**（REVIEW → BLOCK），符合库规「合并只许保持或升级，不许降级」。
- ⚠️ **PRD §11.1 的「BLOCK 精确率 ≥ 95%，避免误伤」要重新量**：本单把一批命中升成 BLOCK，
  精确率只能靠**人工金标**（11/30 那行的金标集）验，**回归集验不了**（它的 expected 已过期）。
  ⇒ 本条**如实留作未闭合项**，不许拿回归集的 delta 冒充精确率。
