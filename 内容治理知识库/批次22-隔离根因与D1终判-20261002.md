## 0. 隔离失效：根因（代码级）+ 三条可证措施 + 回溯 + 登记

### 0.1 ✅ 根因 —— **定位到代码，并已复现**（不是猜的）

**病灶文件**：`kb/l7/registry/layers.yaml`
**病灶内容**：**每一层**的 `cwd` 都是**写死的绝对路径**：

```yaml
L0/L1/L2/L3/L4/L5/L6/L7  →  cwd: ~/.dsh/Momcozy知识库
```

**谁用它**（三条，逐字）：

| 位置 | 代码 |
|---|---|
| `kb_pipeline.py:608` | `cwd = home(x.get("cwd") or "")` |
| `kb_pipeline.py:711` | `argv = [py, os.path.join(cwd, sp["script"])]` |
| `kb_pipeline.py:724` | `subprocess.run(argv, cwd=cwd, …)` |

**为什么逃逸（机制）**：
子进程的工作目录**永远是那个写死的绝对路径**，**与「我在哪个副本里跑」无关**；
各层引擎又都用**相对路径** `kb/...` ⇒ **全部落在真库**。
而副本里那份 `kb/` **什么都没被写** ⇒ **「副本跑」看起来一切正常（静默失效）**。

**同实体证明**：工作区 `kb/` 与 `~/.dsh/Momcozy知识库/kb/` 的 `l0/registry/kb.json`
**inode 相同**（实测均 `69082025`）⇒ **同一实体**。
⇒ 「工作区」与「真库」在本机**不是两个地方**。

**复现（本批实做）**：
```bash
cd <副本根> && sh kbpy l7/scripts/kb_pipeline.py --sync --only L2 --apply --run 20261002-2098
```
⇒ 落章出现在**真库** `kb/l2/runs/20261002-2098.json`（sha256 前16 `126bde11a89cce51`），**副本内没有**。

★ **一个必须说清的加害面**：`~/.dsh/Momcozy知识库` 这个 `cwd` 在本机**是存在的**
（不是 fallback 到 cwd）—— 所以它不是「路径不存在所以回退」，而是**写死的路径本来就在**。
