## 3. 为什么「同步副本」会把库**改坏**（本单拒做的硬理由）

对当前权威库跑一次 F7 回填脚本的**只读预演**（`--dry-run`，脚本自证「不写盘」）：

```
sh kb/kbpy .work/fix_f7_backfill.py --dry-run
rules.jsonl：1018 行（全部为规则）
✅ 序列化自检通过（写回不会改变既有字节）
── half_life 分布：A(P0/365)=0  B(90)=0  C(180)=1018      ← 全落 C 档
── valid_until 取值（1 种）：2027-03-28=1018               ← 又变成「全是同一个数」
[dry-run] 不写盘 ｜ 退出码 0
```

推演链条（每一步都有实测依据）：

1. 视图生成器**只从权威库读**这四个字段（`kb/.work/gen-host-library.py:917-928`；`derivation.json` 的
   `governance_source` 三行原文指向 `kb/l3/candidates/rules.jsonl`）；
2. 当前权威库这四字段**全空** ⇒ 生成器走**兜底分支**：`OWNER_FALLBACK="法务"`（:92）、
   `DERIVED_HALF_LIFE_DAYS=180`（:93）、`valid_until = 生成当天 + 180`、`effective_from = 生成当天`；
3. ⇒ 现在「重跑生成器 + 回填」会：把 43 条（21＋22）的**正确档位压成 180**、
   把 `valid_until` **归零成「今天+180」** —— 这正是 `half-life-policy.json` 的
   `why_not_created_at_today` 处**明令禁止的假绿**（「每次重生成把时钟归零 ⇒ 永远不过期」）；
4. 而且 **R4 修不掉**：R4 比的是「视图值 vs 权威库值」，权威库仍是空串 ⇒ 重生成后 2036 处**照样红**。

另有一个**照文档跑会毁证**的坑：`kb/l8/build_view.py`（`projection_reconcile` 提示的修法路径）第 96–98 行是
`if os.path.exists(OUT): shutil.rmtree(OUT)` —— `OUT` 默认就是 `kb/view`。而 `kb/view/_meta/` 躺着**只此一份、删了不可重建**的活状态：

⇒ **不许原样跑 `build_view.py`**；正确的回填必须**只覆盖 509 条 md 与派生 `_meta`，保留上面四件**。
