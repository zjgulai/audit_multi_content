## 3. ★ 硬故障与本轮查到的根因：**两列同叫「链接」，字段类型不同**

第一次试跑（`_rerun1019/pilot-1.log`）回填直接失败：

```
↳ 回填你的表：❌ TextFieldConvFail ｜ 第一次：{"ok":false,"code":1254060,...} ｜ code=1254060
```

**根因**（raw API 才看得见，shortcut 看不见）：

| 列 | 字段 ID | raw API `type` | `ui_type` | 正确写法 |
|---|---|---|---|---|
| `报告链接`（旧） | `fldRYtTxrD` | **15** | Url | 对象式 `{link, text}` —— 写字符串会 `1254068 URLFieldConvFail` |
| `10/19 报告链接`（新） | `fldoE9JECI` | **1** | Text | **裸 URL 字符串** —— 写对象式会 `1254060 TextFieldConvFail` |

而 `lark-cli base +field-list` 把**两者都显示成 `text`** ⇒ 按 shortcut 认字段类型，
必然在一列上写错；写错的代价不是"这一格没写进去"，而是**整批 batchUpdate 被拒**
（同一批里的 结论/状态/问题数量/置信度/汇总 **一个都没落**，症状像"回填静默失败"，根因完全不同）。

⇒ 判据改成**按 raw API 的 type 号**决定形状（`GET /open-apis/bitable/v1/apps/{app}/tables/{table}/fields`）。

⚠️ **留给 Owner 的一句实话**：新列是**文本**字段，所以格内落的是**裸 URL**；
旧列是**超链接**字段，格内是蓝色的「内容审查报告」四个字。两者长相不同，**都能点开**。
要统一成「蓝色 + 短标题」，把该列类型改成「超链接」即可（一句话的事，**等 Owner 点头再动**，
因为那是改表结构，不是改数据）。
