## 5. 顺带发现：`kb/kbpy` 现在是挂的

`kb/kbpy` 会调 `kb/l8/_interp.py` 解析解释器；而 `_interp.py:105` 对每个候选解释器
起子进程 `import numpy, fastembed`，**超时 120 秒**。实测：

```
/usr/bin/python3 kb/l8/_interp.py        → 30s 未返回，被 SIGTERM
kb/kbpy -c "print('ok')"                 → 60s 未返回，被 SIGTERM
```

**fastembed 导入挂住 → 整个 `kb/kbpy` 通道挂住。**
影响面不小：进程表里那些 `kb/kbpy …` 的 etime 都很长（03:00–07:00），有可能就是在挂。
这也解释了为什么 §4.1 里几个 `--check` 迟迟不结束。

**本次绕过方式**：`.kb-python` 里写的就是 `/usr/bin/python3`，而
`l4_article.py` / `l4_gate.py` 只用标准库（json/glob/collections）
→ 直接用 `/usr/bin/python3` 运行，**等价于 `kbpy` 解析后要 exec 的那条命令**，不涉静默降级。
（`kbpy` 只是「解析 `.kb-python` 再 exec」，没有别的副作用。）
