## 3. 阻断理由 ③：删了也换不到「对的号」—— 号永不复用，重跑算出同一个号

两条写在台账与引擎里的红线（原文）：

```
# kb/l4/registry/l4.json → numbering.no_reuse
号码一经发出永久占用：重跑时已在册的 rule_id 沿用原号；新规则取该段 next_seq；
即使某条规则后来消失，它的号码也不回收、不再发给别的规则

# kb/l4/registry/l4.json → numbering.order_key / order_key_note
order_key = ['kb_type（库）', 'form 对应的形态段', 'rule_id（字典序）']
只用规则自身的不变量排序；不用 support_count、风险等级、时间或文件行序，
避免规则增删让已发条款号错位
```

于是「删掉 → 重跑 → 号变对」这条路**在机制上不存在**：

- 删一条定稿 = 把这个号**永久烧掉**（不回收、不重发给别人），同时让台账里那条 `rule_id → 号` 指向一条不存在的记录；
- 重跑的号是 **`order_key` 的函数**，与「谁被删过」无关 —— 输入不变，算出来一字不差；
- 本会话实测**候选输入没变**：`kb/l3/candidates/rules.jsonl` **1018 行 / 509 个 `rule_id`**，每个 id 恰好 **2 行**（一行带号、一行空号），与台账现存已发号集合完全吻合。

**结论：这个操作拿不到任何想要的号，只会净损失定稿记录 + 若干个永久作废的号。**
