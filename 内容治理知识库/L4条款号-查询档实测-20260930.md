## 四、只报告、不擅判的异常（建议交 `kb-check` / `kb-repair` + 人裁）

### 1. 现行台账 509 ⟷ 文件/闸门 1242 冲突（最主要）
- 现行 `kb/l4/registry/l4.json`：`numbering.totals.assigned = 509`、`segments = 2`、`issued` 键只有 `W-1`/`W-2`。
- 旧台账 `kb/l4/_pre-rebuild-20260930-1550/l4.registry.json.bak`（run `20260929-1100`）：`assigned_total = 1242`、`segments_used = [E-1,S-1,W-1,W-2,W-3]`、`canonical.state = 已填…共 1242 条定稿记录；status=stable`，并记 `newly_assigned_first_run = 733`（= W-3 157 + S-1 201 + E-1 375）。
- **本次查明冲突根因（此前只是"口径不一致"）**：`sample_case.jsonl`(358) 与 `scoped_clause.jsonl`(375) 这 **733 条定稿根本没有 `rule_id` 字段** —— 它们的键是 `case_id` / `clause_id`。现行 20260930-1550 批只对**带 `rule_id` 的措辞类**发号，于是 `assigned = 56 + 453 = 509` 是**真实值**，不是被截断。
  ⇒ 现行台账**不是算错**，是**登记面收窄**：733 个已发号（W-3/S-1/E-1）在现行台账里**无 `rule_id` 可登记**，`no_reuse` 的台账依据出现缺口。
- 三个口径并存需人裁一次：**文件口径 1242 ≠ 闸门口径 1242 ≠ 台账口径 509**（前两者一致，差在台账）。
- 附带：现行 `l4.json → canonical.path` 指向 `kb/l4/canonical/rules.jsonl`（0 字节），**台账指向的不是真定稿文件**；`canonical.state` 写「空（本批不写）」—— 与四个文件 1242 条 `stable` 相抵。
