## 步骤 1 ✅ 观察件产出规范（零风险）

规范做成了**可执行的判据**：`kb/l8/check_observations.py`（**自证 14/14**）

### 1.1 四条硬规则（针对 `text`）

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **不许是否定式**（`无/未见/没有/未使用/未坐/未系/…`；英文 `no / not / without / absent`） | ★ 见下 §1.2 |
| 2 | **必须带 `timecode`** | B1 的命中位置就是取自它（`00:00:05`） |
| 3 | **必须标 `fact_or_inference`** | 「观察」与「推断」不能混（库规：不把推断写成观测事实） |
| 4 | **必须标 `reader`** | 谁产出的，否则无法追溯与复核 |

另：`text` 不许把**素材自己的字**搬进来（那是 `ocr[]` / `transcript[]` 的活）—— 混一起会骗过「这是画面观察」的性质标注。

### 1.2 ★ 为什么禁「否定式」——这是判据存在的唯一理由

B1 反向对照里实测到的陷阱：

```
干净读数：「无车辆、**无安全座椅**、无危险动作」
规则模式：「**没有安全座椅**」        ← 字面子串匹配，两者极像
```

规则**收宽**几乎是必然的（B1 里 `危险动作示范` 就因为少一个语序而漏掉）。
⇒ 口径：**`text` 只写「画面里有什么」**；要记「没看到什么」，写进**另一个字段 `absent`** —— 它**不会被扫**。

### 1.3 反向对照（判据自己必须能红）

```
② 「无安全座椅」这类否定式 ⇒ **必须被拒**（B1 实测的那条陷阱）
③ 四条必填逐条缺失 ⇒ 逐条红
④ 坏 timecode / ⑤ 闭集外取值 ⇒ 红
⑥ 英文否定式也拒；⑥b 「note」不许被 `no ` 误伤（反向对照）
⑦ 一份里混一条坏的 ⇒ 指名报 `observation[1]`
```
**14/14 通过。**

### 2.3 ★ 不过的根因：**画面类红线在库内没有依据来源**

P0 模式的契约要求四格**溯源信息**：`article_no` ＋ `anchor` ＋ `source_sha256` ＋ `evidence_units`。
现有 11 条的出处分布实测：

```
anchor 来源表：品线内容边界规则库 ×4 ｜ 广告文案明细 ×7
```

于是我逐条查了那两处能不能承载画面类红线：

| 查什么 | 实测 | 结论 |
|---|---|---|
| `品线内容边界规则库`（21 条） | **全是文案/宣称类**（H01–H09 / M01–M07 / U01–U04），**一条画面类都没有** | ❌ 不能承载 |
| `广告文案明细` | 是**广告文案**明细，不是画面规则 | ❌ 不能承载 |
| **PRD §7.3（红线的真正出处）在不在库** | **L0 只有 2 个件提到它的名字、L2 单元 0** ⇒ **PRD 没进库** | ❌ 溯源断在这 |
| 负面样本里的画面类提及 | **0 条**（见 §3） | ❌ 不能承载 |
| 往飞书源表加记录 | **Owner 明令飞书源一律不许改** | ❌ 禁止 |

⇒ **我填不出那四格**（也不该编）。副本里的 4 条 `article_no` / `anchor` / `source_sha256` / `evidence_units`
**留空如实反映这一状态**。

**另一条顺带发现**：⑩d 那把判据还**写死了条数**（`len(_rows) == 11`）——
即使将来四条都有了出处，这把尺子**照样会红**，得同步改。

### 2.4 结论：**按你的规矩不替换**

「副本验证通过后才替换」——**验证没过，所以不替换**。活件仍是 11 条、sha 未变。
**这一步的正确做法不是"再想想办法把模式塞进去"，而是先补上游**（§4）。
