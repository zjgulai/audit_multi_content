## 六、★★★ 比 ① 更大的发现：**链拿到的不是正文**

### 6.1 根因（一行 if）

`tools/agent/review_gate.mjs:270-274`（守衡侧）：

```js
if ((inbound.images ?? []).length === 0 && (inbound.videos ?? []).length === 0) {
    const links = findLinks(inbound.text ?? '');
    if (links.length) parts.push(`【待读的链接】\n${links.join('\n')}`);   // ← 正文在这里被整个丢掉
    else if (inbound.text) parts.push(inbound.text);
}
```

**只要「无图无视频 且 正文里有链接」，链就只收到那行链接，素材正文全部丢弃。**
（视频/图片走上面另一条分支，不受影响。）

### 6.2 对 80 条的影响：**35 行在结构上必然被喂占位符**

| 80 行 | 行数 | 素材里有 URL | 后果 |
|---|---|---|---|
| 文案 | **35** | **35/35 有** | **必然走 `【待读的链接】` 分支，正文全丢** |
| 图片 | 35 | 35/35 有 | 走图片分支，不受这条影响（但 OCR 空时同样是空内容） |
| 视频 | 10 | 10/10 有 | 走视频分支，拿到真内容 |

**本轮实测 9 条，预测 9/9 命中**：4 条文案＝链接占位符、3 条视频＝真内容、1 条图片＝「图上没识别出文字」。

### 6.3 全库口径

| 链收到的输入 | 全库 206 份报告 | 80 条批次窗口（10-13 15:00–23:00） |
|---|---|---|
| 链接占位符 | **54** | **46** |
| 图无文字 | 5 | 4 |
| 其它 < 100 字（需人核） | 51 | 24 |
| 文案真内容 | 70 | 20 |
| 视频真内容 | 26 | 13 |
| **非真内容合计** | **110/206 = 53%** | **74/107 = 69%** |

### 6.4 这件事对已有结论的影响（据实说）

- 「**87% 的发现没有库内依据**」这个数**要重新解释**：对文案行，库侧压根**没看到素材**
  ⇒ 「没依据」里混着「没输入」，两者必须分开，否则会去补一个并不缺的库；
- 「表里 PASS = 0」这个事实**不受影响**；
- **`NEEDS_INPUT → REVIEW` 那 3 条**：链侧 0 条读数（因为收到的是占位符），
  合并态的变化由**模型侧**驱动 —— **不能算作库侧修好了**。

**推荐**：把这条当 P0 修 —— `parts.push(链接)` 改成**链接与正文都保留**
（`parts.push(inbound.text + '\n【待读的链接】\n' + links.join('\n'))`），
并给「链收到的正文长度」加一条旁挂字段 ＋ 一条闸门（**< 200 字且原素材 > 500 字 ⇒ 报红**）。
**为什么**：现在这条 bug 让**一半以上的评审在空输入上出结论**，且**看不出来** ——
报告、卡片、表行全都长得像正常结论。**代价**：要动守衡侧（不在本库），
且改完必须重跑那 35 条文案行才能知道真实结论。
