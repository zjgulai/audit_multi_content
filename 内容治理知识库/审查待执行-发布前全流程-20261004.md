## 4. ⚠️ 已实测到的引擎缺陷（送审前须知，建议先修）

**空素材 + 走完全部前置 = PASS，置信度 0.99。**

复现（只读、未发布）：
```bash
sh kb/kbpy l7/review-engine/core/with_kb_evidence.py --text "" \
  --require-layer-preflight PIPE-20261003-2354 \
  --decision-owner 文案合规审查 --loaded-skill 文案合规审查 --no-publish-to-feishu
```
实测输出：`"decision": "PASS"`、`"confidence": 0.99`、`"issue_count": 0`、
`"content_id": "AUTO-e3b0c44298fc"` —— 该 12 位前缀正是**空串**的 sha256
（`printf '' | shasum -a 256` → `e3b0c44298fc…`），即**送审内容确实是空的**。

机制（读代码定位，三处叠加）：
1. `with_kb_evidence.py:238` **写死** `coverage = {"text": "complete", …}` —— 文本覆盖是常量，与送审内容无关；
2. `review_engine.py:40-51` 的 `_coverage_ready()` 只校验 `coverage` 字段的**取值字面量**，
   **从不校验正文是否为空**，也不与 `input_manifest.text` 交叉核对；
3. `review_engine.py:157-160`「无命中 ⇒ PASS / 0.99」是兜底分支，空输入正好落到这里。

为什么这违反硬闸门：`内容审查总控` 写着「Never emit PASS when required modality extraction … is incomplete」。
空送审「每模态都没抽取」，`coverage.text` 却报 `complete` —— **覆盖声明与事实相反**。
（对照：非空种子文本同一命令 → `BLOCK`、`issue_count: 7`，说明引擎对真材料工作正常；
另有 `media_adapter.py:76` 对空文本有 `if not str(text).strip()` 挡了一下 —— **主链路漏了同样的挡**。）

⇒ **风险**：在素材到位前，任何一次「审一下」只要落到 `--text ""` / 纯空白，
就会拿到一份 0.99 的 PASS，而它**什么都没审**。
⇒ 建议：给 `with_kb_evidence.py` / `review_engine.decide()` 补一条空输入闸门（`NEEDS_INPUT`，退出码 3）。
