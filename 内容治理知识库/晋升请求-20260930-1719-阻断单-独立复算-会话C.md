| 字段 | 备份（真值） | 现在 | 性质 |
|---|---|---|---|

| `canonical.files`/`dedup`/`legacy_*` | 有（逐文件 lines/bytes/sha256） | **整块消失**（9 键→7 键） | 完整性锚点丢失 |

`numbering.issued = 唯一台账`（`layers.yaml` L4 `outputs` 原话）——丢的不是备注，是**唯一台账的 733 行**。

### 3.2 它现在自相矛盾，且「号不复用」这条红线**已经守不住**

```

```

15:50 那次没炸，只是因为喂进去的输入里没有这三批候选（`newly_assigned_this_invocation=0`）——
**不是幂等成立，是撞号面恰好没被覆盖。**

### 3.3 所以「顺手改一个字段」是错解法

- ❌ **手改**：把 `canonical.state` 写成「已定稿」= 绕过 `write_mode: overwrite_in_place_atomic`
  （tmp → 逐行 `json.load` 验 → `os.replace`），且**只补一句备注、不补 733 行台账** → 下一个人会以为台账是全的。
- ❌ **同一块内自相矛盾**：`state` 与 `path`/`bytes` 同属 `canonical` 块。单改 `state` 会让这块同时写着
  「已定稿」和「`path=kb/l4/canonical/rules.jsonl`，`bytes=0`」。要改就得**整块一致地改**
  （`state` + `files` + `dedup` + `numbering`）——这正说明它是**修复**，不是单字段编辑。
- ✅ **正确解法**：这是一次**写坏了的库内写入**，走 `kb-repair`（台账修复）或 `kb-pipeline --only L4` 重跑；
  验收判据 = 「修完 `l4_gate.py` 仍 ✅ 过 + `numbering.issued` 回到 1242 + `canonical.state`/`promotion_rule`
  回到带判据的整块 + 补一条 run 记录」。**用备份回灌还是重发，要人定。**
