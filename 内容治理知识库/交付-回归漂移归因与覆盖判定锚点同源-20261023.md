## 二、6 条漂移逐条归因：**不是引擎回归**

### 2.1 判据（怎么证明「不是回归」）

**同一条素材，命中集合一字未变，只有 `p_level` 变了。** 引擎的匹配逻辑要是坏了，
命中的 `article_no` 会变、条数会变；实测 5 条的 `(rule_code, article_no)` 集合
**与基线逐条相同**，只有严重度列不同 ⇒ 变量是**分级表**，不是匹配。

来源：`kb/l3/registry/rule-taxonomy.json`（**2026-10-17 建，owner 刘华丽，
`taxonomy_provenance.status: AI-proposed / owner-adopted`**）把它自己的
`dual_axis.impact_of_engine_axis` 写得很清楚：

```
severity_flips: 26 ｜ review_to_block: 23 ｜ block_to_review: 3
```

即：这次分级重标**本来就预期**让 23 条从「转人工」升级成「拦」。我们这 5 条正是落在那 23 条里。

## 三、自查里又量出 5 条：这是**真缺陷**（fail-open）

复跑时多出 5 条 **REVIEW → PASS**，我逐一挖到同一处：

| case | 素材 | 覆盖是怎么被"撑"起来的 |
|---|---|---|
| `RC-d3cae0769539` | Wellness 1 英文商品描述 | 命中单元来自 **uk.momcozy.com 另一个商品页**，锚点同为 `#l.1-1`（BM25 37.25）⇒ `covered_by=rule` |
| `RC-6214550d4bce` | **AAP 技术报告**开头 | 命中单元锚点 `#l.1-1`、BM25 **118.31** ⇒ `covered_by=rule` |
| `RC-ecf67146fd0c` | OCR 乱码行 | 同形 |
| `RC-2694cc2ea7e0` | **德语文案** | 走同源支路：命中 `#l.1-3`，回表取到 `support.google.com/adspolicy` 的 `resource_id`，而它在被引池里 ⇒ `covered_by=same_source` |
| `RC-53a4e85faf9b` | 秋促英文促销（与 #6 同一批 OCR 变体） | 假同源把**案例层整条挡掉**（`coverage_judge` 里 `case` 只在 direct/same 都空时才跑）⇒ 0 条依据 ⇒ 安全词撑覆盖 ⇒ PASS |

### 根因（实测，不是推测）

1. `review.py::rule_cited_anchors()` **只比锚点名字**。
2. 而 L2 的锚点里有**页面位置型**写法：`#l.1-1` 在 `kb/l2/units.jsonl` 里被 **921** 个单元共用、
   `#l.1-506` 被 **101** 条 `external_standard` 规则共用 —— 它们**不是记录身份**，
   是「某页的第 n 个列表项 / 某个小标题」。
3. 2026-10-21 `review.py::load_rules()` 把 `kb/l3/candidates/external_standard.jsonl`
   并进了 `rules`（本意：让 V01–V06 / E-2.12x 能被**规则层**命中）。副作用：这些规则的
   **位置型锚点**也一起进了**覆盖池**。
4. ⇒ 只要检索命中的单元**同名**，哪怕完全是另一份文档，覆盖判据就成立 ⇒ 0 findings ⇒ **PASS**。

**方向是 fail-open**：覆盖缺口本来是「库不认识这个题材 ⇒ 转人工看覆盖」，
现在被同名锚点骗成了「库认识、而且没问题 ⇒ 放行」。按本库口径这比漏判更坏
（`未命中 ≠ 合规`，PRD §6.3）。

## 四、修复（只收窄，不放宽）

落点：`kb/l7/skills/kb-content-review/scripts/review.py`
（备份 `review.py.bak-pre-anchor-sha-20261023`；自证件同批改 `selftest_coverage.py`）

1. **`direct` 支路要求「同源」**：新增 `rule_cited_anchor_shas()`，
   `coverage_judge(..., cited_shas=)` ⇒ 命中单元要**锚点相同 且 `source_sha256` 相同**
   （同一份文档里的同一个锚点）。取不到 sha 的规则单元**不进池**（保守一侧）。
   - 会不会误伤本该认的命中？实测：965 个被引锚点在 `kb/l2/units.jsonl` 里**都有**单元，
     且 sha **逐条一致（965/965）** ⇒ 同文档命中零影响。
   - `cited_shas=None`（老调用方 / 自证件）时行为与改前**逐字一致**，不搞"顺手改"。
2. **`same_source` 支路要求「锚点带身份」**：新增 `anchor_has_identity()`，
   位置型锚点（`^#[lh]\.\d`）**不许**判同源 —— 它们指不回一份文档，「同源」在它们上面没有意义。
   带记录 id 的（`#<表>/rec…/<字段>`、`#素材/rec…/…`）照旧认；
   真正的同文档命中由 `direct`（锚点 + sha）兜着，**不会因此丢**。
3. **门限一个字没松**：`bm25_raw_min=8.0`、`coverage_bm25_min=16.0` 均未动；
   安全词支路、案例支路、三态形状、§5.3.2 / §5.4 的报告字段一个都没动。
