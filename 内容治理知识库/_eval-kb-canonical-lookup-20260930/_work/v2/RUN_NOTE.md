## 两套判定口径（都写在 YAML 的 `eval_info.conclusion_rule`）
- **口径 A（主口径）**：与 v1.2.0 发布时用的那套完全一致 —— 触发 = 该会话加载了 kb-canonical-lookup。
- **口径 B（行为口径）**：唯一差别在「边界情况」行 —— 该行预期结果写的是**行为**（追问澄清），
  故按**实际是否以追问澄清收尾**判（末尾存在未获答复的 `ask_user_question` 即记追问，加载了 skill 也算）。
- 两套口径**都在 v1.2.0 与 v1.3.0 两侧重算**。口径 A 重算 v1.2.0 = 0.640 / 0.593 / 0.615
  （与发布值逐位相同）。

## 一次性盲测会话的收尾形态（回填时的一个坑）
被测侧是一次性会话，**没有上游能回答 `ask_user_question`**。这类会话 transcript 末尾是一个
`tool/call(name=ask_user_question)` 却永远等不到配对的 `tool/result`，因此**不产生 `turn/end`**。
本轮回填（`collect_v2.py`）把这种收尾识别为「以追问收尾」，并把提问正文**逐字**回填进「回复」字段
（不截断、不摘要），以免被误读成「什么都没答」。涉及的会话：
- 修后：R1 #14/#23/#24/#25/#28、R2 #20/#23/#24/#25/#28、R3 #20/#23/#24/#25/#28
- 修前：R1 #11/#25、R2 #12、R3 #16/#23/#24（旧脚本按「加载=触发」记，故未体现）
