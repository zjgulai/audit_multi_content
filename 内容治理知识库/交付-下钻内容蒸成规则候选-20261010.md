## 二、★★ 途中抓出**我自己判据的两个缺陷**（这是本件的实质）

第一次跑完，报「判为可蒸 527 条」但**文件只从 1802 → 1803 行** —— 数字对不上 ⇒ 去查，
发现下钻来的 405 个单元**几乎全被拒**，理由清一色是**我上一批写的判据**给出的：

**缺陷① 只认中文自然语言。** 旧判据是「CJK 占比 ≥ 0.25」⇒ **整片英文语料被挡在门外**。
而 **PRD §7.1 的外部标准库明写包含「美国法规、平台政策」** —— 那些**就是英文**。
下钻拿回来的 `cdc.gov` / `hse.ie` / `msdmanuals` / `dxy.cn` / 自有站全是英文。
⇒ 修法：自然语言判据加**拉丁一路**（字母词 ≥8 个 且 字母占比 ≥0.5 且 平均词长 2–12）；
**故意不用"有没有句号"**（HTML 洗过之后句读常丢），base64 也混不进来（它没空格 ⇒ 凑不出 8 个词）。

**缺陷② 拿原始 HTML 当编码载荷。** 下钻的外部站是 `curl` 直抓的**原始 HTML**，
`<div>` / `<script>` 满地都是 ⇒ 旧判据（`<\s*(script|style|div…)`）整段判成"编码载荷"。
⇒ 修法：**先剥 HTML 外壳再判**（`clean_text()`：去 `<script>/<style>` 块 → 去标签 → 解实体 → 收敛空白），
且**落库正文也用洗净后的**（不许把标签写进条款正文）。

**判据自证 8 → 10**，新增两条正是本批的主判据：
- **⑦ 英文条款（夹在 HTML 里）⇒ 必须判可蒸**（反向对照：旧判据下它必红）
- **⑦b 候选正文已剥 HTML**（不含 `<div`，且英文正文在）

**同批修掉自己一句误导的打印**：原先写「scoped_clause 候选：新增 %d 条」用的是"本轮判为可蒸"的条数，
而真正写进文件的新行数差得很远（实测报「527 条」、文件只 +1 行）⇒ 改成
「判为可蒸 N｜其中文件里没有的 M ⇒ X ⇒ Y 行」，**两个数分开报**。
