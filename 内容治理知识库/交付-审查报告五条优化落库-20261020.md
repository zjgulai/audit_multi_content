## 二、逐条：根因 → 裁定 → 落点 → 判据

### 1｜未归类 2 个 —— 归不上，是因为**案例层从来不带分类**

- **根因**（查过代码，不是猜）：`review.py` 的案例层分支直接拼 finding，**没有 `taxonomy_category`**；而 `taxonomy_index()` 只读 `rules.jsonl` ＋ `external_standard.jsonl` —— 案例层（`sc-…` / `S-1.195` / `N-1.337`）两条都不在那张表里 ⇒ `stamp_taxonomy()` 记 missing ⇒ 渲染层落兜底类"未归类"。
- **为什么又犯一次**：`owner-fix-locks.yaml::L04`（2026-10-19）修过一次"未归类"，但那次只修了**模型侧**（`model.taxonomyCategory`）——案例层这一路没动。**一条锁只钉了一条来路**，所以同一句话回来了。
- **裁定**：案例层**在提取这一层**就归类（Owner 原话"图片提取规则的时候要归类"）。新增唯一真源 `kb/l7/registry/case-taxonomy-map.json`：

  | 案例原因分类 | A3 落点 | 依据 |
  |---|---|---|
  | 原则性错误 | 品牌信任与声誉 | 案例实测是**设计/创意方向**的要求与反馈（S-1.195：德国社媒贴…），非受监管宣称、非产品事实 |
  | 文化禁忌 | 北美本地化与标签要求 | 文化语境＝本地化；该类 meaning 含"美国市场表达/育儿语境" |
  | 审核问题 | 平台与渠道政策 | 该类含子类"素材提交与形式规范" |
  | 品牌一致性 | 品牌信任与声誉 | 同名语义 |
  | 措辞表达 | 北美本地化与标签要求 | A3 无独立"措辞"类，该类是唯一落点 |
  | 合规红线 | 合规与受监管宣称 | 类别名即语义 |

- **顺带销账**：`risk-category-policy.json` 原把「原则性错误 / 文化禁忌」写成"不编、**留空待裁**"—— Owner 这条令把它们销了账（PRD 四维都给"措辞表达"，A3 见上表），`unmapped` 只剩 `未分类` / `unknown` 两个**真兜底**。
- **改动**：`case-taxonomy-map.json`（新增）｜`review.py::case_taxonomy()` ＋ `stamp_taxonomy()` 不再抹掉条目自带的分类｜`risk-category-policy.json`。
- **判据**：`report_conformance.py::R1`（B 组反向对照）＋ `pytest …test_owner_20261020_case_vocab_now_mapped`。
- **守衡侧不用动**：`taxonomyCategoryOf()` 读的就是库侧 `taxonomy_category` ⇒ 库侧补上，报告那一格就对了。

### 2｜"（本条未提供问题描述）" —— 库侧压根没给这一格

- **根因**：`with_kb_evidence._to_risk_item()` **没有 `description` 字段**。而守衡 `descriptionOf()` 的取值顺序是 `description → kb.description → excerpt → 占位句`；这一单 F-02/F-03 的 `excerpt` 又是空的（历史意见不许冒充逐字命中）⇒ 必然落到占位句。
- **裁定**：问题描述**必须有**，≤50 字（PRD §5.3.3）。新增 `_desc_of()`：`条目自带 → 逐字命中（标明是替代）→「库内条款命中（规则码/类别）」`。**不发明内容，也不留空。**
- **改动**：`with_kb_evidence.py::_desc_of()` ＋ `risk_items[].description`；`review.py` 案例层直接写描述（"库内反例 S-1.195 的问题要点：…（非本单画面）"）。
- **判据**：`report_conformance.py::R2`（C 组反向对照）。
- **未做**：占位句本身在守衡 `dual_track.mjs::descriptionOf()` 最后一行，**本会话改不了那仓**。库侧补齐后它不再被触发，但模型侧条目仍可能走到。

### 3｜位置"图 1" —— 顺便回答 Owner 那一问

**Owner 问："这里第x处你如何判定的？"**

**答（据实）：今天这个 X 是模型自报的，不可复核。** 守衡 `model_side.mjs:129` 的提示词逐字是
「图片 ⇒ `图 N 第 X 处`（N=第几张图、X=该图上的第几处，**从 1 数**）」——没有区域锚点，也没有和素材块
`【图 N 内文字｜M 行】` 的行号对齐。所以读者看到"第 3 处"，无从知道是哪一块字。

- **裁定（可复核的定义）**：**第 X 处 = 该图内文字块的阅读顺序行号（自上而下、同一行自左而右，从 1 数）**，而且**必须能被那一行文字复核**：声称第 3 处，这一条的引文/描述就要落在第 3 行。
- **位置四形态**（登记件 `prd533-constraints.yaml::location`）：`图 N 第 X 处`｜**区域前缀版** `图片顶部，图 N 第 X 处`｜`视频 MM:SS`｜`正文第 X 段`。**裸"图 1"判红**。
  - ⚠️ 区域前缀是对 2026-10-20 早前"写法逐字照抄、不许加括号补充"的**后令**：那条禁的是**括号补语**（`图 1 第 4 处（奖品说明句）`），不是**区域词**。区域词只许 顶部/中部/底部/左侧/右侧，且必须在"图 N 第 X 处"前面、用逗号隔开（开放式写法会把括号补语放回来）。
- **改动**：`prd533-constraints.yaml`（新增 `figure_area` 形态 ＋ `figure_index_basis`）｜`material_evidence_gate.py::strip_area_prefix()`（新写法不许被旧判据误杀）｜`report_conformance.py::R3/R3b`。
- **判据**：`R3` 四形态（D 组）｜`R3b` 第 X 处可复核（G/G2 反向对照）｜`material_evidence_gate --selftest 6/0`。
- **未做**：渲染层还是自报口径（守衡提示词 ＋ `normalizeLocation()`），素材块也还没给行号。本令做到的是"**编了就红**"＋"新写法不被误杀"；要它天然对，得两仓一起改。

### 4｜依据里写【问题要点】 —— 摘录取的是整段评审留痕

- **根因**：`review.py` 案例层摘录是 `str(reason_analysis or sample_body)[:120]`，而 `reason_analysis` 开头就是 `【原则性错误】图片 图1 …` ＋ `【问题要点】 1./2./3.` ⇒ 120 字正好把标记和头两条要点抄进依据格（实测 181 字）。
- **裁定**：依据格 = 「《库名》第 X 条 ← 一段命中片段（**≤60 字**）｜原始出处：链接」。源记录的**分节标记与它下面的清单不是命中片段**，不许进这一格；要说就写进"问题描述"。60 字的来路：§17 逐条预算 200 − PRD 五格已占（50＋50＋30）＝70，留 60 给引文。
- **改动**：`review.py::case_excerpt()`（按 `【问题要点】` 切段 → 取最长一条要点 → ≤60 字 → 去序号与【】标记）｜`prd533-constraints.yaml::basis.forbidden_fragments ＋ max_chars: 60`｜`report_conformance.py::R4`。
- **实测**：S-1.195 的摘录 **181 字 → 38 字**（"图3：妈妈照料宝宝，自然使用 Momcozy 产品，在日常里舒适、自信、自在"），标记 0 处。
- **判据**：`R4`（E/E2 两组反向对照）。

### 5｜建议 30 字、标点不算 —— 口径早定了，两处实现没接线

- **根因（不是新口径）**：`prd533-constraints.yaml::counting.advice_no_punct` 2026-10-19 就定过，文件里逐字写着"标点不计入 30"；但 `kb/l5/advice_book.py` 仍按 `len(text)` 逐字符量（那句注释自己写的就是"是逐字符量的"），守衡的 `_clip` 也按字符数截。
- **裁定**：**度量与截断同一把尺**：先按实词数（去标点）数，≤30 原样给；>30 才截，截完仍按实词复核。
- **改动**：`advice_book.py::advice_chars()`（标点不计入，标点类从 `prd533_check` 取，不另写一份）＋ selftest ②/⑥3 改量口径 ＋ **新增 ⑦4 口径对照**｜`prd533-constraints.yaml::advice_clip_no_punct`｜`report_conformance.py::R5`。
- **判据**：`advice_book --selftest ⑦4`（30 实词＋标点**不红**、31 实词**红**）｜`R5`（F 组）。
- **未做**：守衡 `dual_track.mjs::renderMergedItem` 的 `_clip` 仍按字符数截。**反例**：一句 30 实词 + 6 个标点的合规建议，在那侧会被截成约 24 个实词的残句。
