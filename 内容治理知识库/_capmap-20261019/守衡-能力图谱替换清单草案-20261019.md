# 守衡 · 能力图谱替换清单（草案，81 行 + 底座 13 行）

**目的**：把 ①能力图谱 的 174 行 Emily 数据、②底座健康 的 13 行工作台数据，替换成守衡（飞书机器人本体）的数据。
**本文是什么**：**行清单 + 每行锚点**，用来先把「填哪些行、怎么归类、证据从哪来」定下来。
**本文不是什么**：不是最终数据 —— `状态` 与 `案例类型` 标「预判」，`代码引用` 只到文件级，**行号与实测证据在正式填写时逐条补并回源核**。

---

## 0. 命名与归类（需你拍板）

Emily 版用 5 个命名空间：`BOT-`（机器人）/`WB-`（Web 工作台）/`SYS-`（系统底座）/`OPS-`（运营）/`GAP-`（缺口）。

守衡版本建议改用 **`SH-` + 域**：

| 命名空间 | 对应 ① 表的 `L1底座` | 说明 |
|---|---|---|
| `SH-ACT-*` | 交互编排 | 群内/私聊怎么进来、卡片怎么出 |
| `SH-CHAN-*` | 数据通道 | 文字/图片/视频/链接 **输入通道** |
| `SH-JUDGE-*` | 分析判定 | 判定引擎、双轨、P0、置信度、格式判据 |
| `SH-KB-*` | 知识治理 | kb_* 工具 + L0–L7 链路 |
| `SH-PUB-*` | 推送投放 | 结论表 / 报告云文档 / 群回执 |
| `SH-OPS-*` | 运营交付 | 自证、巡检、补发、台账 |
| `SH-SYS-*` | 底座 | LLM / 飞书 / 知识库服务 / launchd |
| `SH-GAP-*` | 按实际归属 | 缺口（状态填 gap / not_built） |

**为什么不沿用 `BOT-`**：④表 与 ③表 都用 `能力ID` 做跨行引用。若守衡也写 `BOT-QUERY-04`，
v1.0（Emily）与 v2.0（守衡）会出现**同 ID 不同义**，以后查「这条 ID 是什么」必然打架。
**代价**：读者要重新认一套前缀；③表将来若启用，历史 ID 不能直接续用。
