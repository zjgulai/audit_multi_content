## 4. 试判查出的两个事实（都不是"能不能抽"，是"接没接上"）

### 4.1 ★ 「位置」里那个 `视频 00:00` 是**写死的占位串** —— ★★**但卡片上另有一处真时间码，2026-10-13 更正见本节末尾**

### 4.2 画面类红线**根本没有实现**（比"命中 0"更硬的一句）

`kb/l5/p0_patterns.jsonl` **11 条模式（H01–H09 / M03 / U04）全是文本类**（词表 / 正则）。

# 附录（2026-10-13 加）：两条赛道的**根因**与优化建议

> 加这一节的原因：查根因时发现，**§0 那两档的定性都不够准** ——
> 「ASR 只能作线索」不是"文本质量差"，是**时间码被引擎丢掉**；
> 「画面语义判不了」不是"通道不存在"，是**通道通着、两头没人供料**。两条都更正如下。

## A. 口播 / 字幕（ASR）

### A.0 ★ 更正：不是"抽得不好"，是**逐句时间码被扔掉了**

```
/Users/lute/Project/audit_multi_content/base/asr_speech.m:143
    NSString *s = [res.bestTranscription formattedString] ?: @"";
```

`bestTranscription` 上**本来就有** `segments`（每段带 `timestamp` / `duration` / `substring`），
而这一行用 `formattedString` 把它**拍平成一根字符串** ⇒ 时间码在**引擎内部**就没了。
该助手自述的输出字段（同文件 :41）逐字：`{ok, text, ms, locale, on_device, ondevice_supported, callbacks, partial_max}`
—— **没有 segments**。

⇒ **Speech.framework 给得出，是我们没取。** 「无逐句时间码」是**实现选择**，不是能力上限。

### A.1 ★ 推荐：补逐句时间码（改一行 ＋ 落 L1 加一格）

| 项 | 内容 |
|---|---|
| 做法 | `asr_speech.m` 改为遍历 `res.bestTranscription.segments` 输出 `[{text, t, dur}]`；L1 `video_asr_segments[]` 增加 `segments` 字段 |
| 收益 | 位置从"没有"变成 **`视频 00:12–00:15 口播`**；满足 PRD §5.3「位置（视频 00:12 字幕）」的形态；人工复核能**直接跳到那一刻** |
| 代价 | **改动在另一个仓库**（`audit_multi_content/base/`）；要重跑 14 条视频的 ASR；L1 字段形态变化 ⇒ 需定锚点格式 |
| 前提 | 与守衡那边的会话**错开窗口** |

### A.2 推荐一起做：把「非逐字」显式化

现在 ASR 落库**没有**"这不是逐字"的标记（`suspect` 只标 `script_mismatch`）。
建议落 L1 时加 `verbatim: false`，**让下游一眼知道它不能当逐字依据**。代价：一处字段，不改识别质量。

### A.3 **不推荐**：靠提高识别率去"够到逐字"

**方向错了**。逐字核验要求「引用的话在原文里一字不差找得到」，而 ASR 输出**本身就是派生物**，
再准也不是原文。该做的是 **A.1（定位）＋ A.2（标非逐字）**，不是让 ASR 变成逐字。

## B. 画面语义（危险动作 / 安全座椅 / 出镜 / AI 标识）

### B.0 ★ 更正：**通道是通的**，缺的是两头

```
kb/l7/review-engine/knowledge-base/multimodal-provider-contract.json   ← 契约在（9/29）
kb/l7/review-engine/contracts/offline-extraction-result.json            ← 离线契约在（9/29）
kb/l7/review-engine/core/offline_review.py                              ← 收离线抽取件 → decide()
kb/l7/review-engine/core/media_adapter.py:65                            ← ★ 这一行是关键

```

⇒ `observations[]`（**画面观察的文本**）**已经被当文本读**，并送进**同一个** `scan_text` 规则扫描器
⇒ **画面语义可以判，只要有人把画面写成文本**。

**缺的两头**：

| 缺 | 实测 |
|---|---|
| ① **没人产出 `observations[]`** | 契约件建了，但 **`.py/.mjs` 活代码 0 引用**；没有视觉模型、也没有人工标注件 |
| ② **没有画面类规则** | 11 条 P0 **全是文本类**；`安全座椅/危险动作/出镜/AI标识/车内` 各 **0 命中** |

**顺带一条已经接好的**：`validate_extraction()` 对 image 报 `missing:observations`、
对 video 报 `missing:keyframes`，且 `apply_extraction()` 按状态落 `coverage.video/keyframes`
⇒ **「缺音轨 / 关键帧不完整」会被记成覆盖缺口**（正是 skill 里写的口径）—— 这半边**不用新建**。

### B.1 ★★ 推荐先做：**先立规则 ＋ 先用「人工观察件」把通道跑通**（不引模型）

| 项 | 内容 |
|---|---|
| 做法 | ① 给那四类各写**文本可判的观察表述规则**（例：「没有使用安全座椅」/`no car seat`/`infant sleeping on soft bedding`）；② **手工**对这 14 条视频的关键帧写一份 `observations[]`（按契约格式），走 `offline_review.py` 跑一遍 |
| 收益 | **当天就能证明通道通不通**，并拿到真实三态读数；正是库内既有做法（「先人工搬也行，**通道要真实存在**」） |
| 代价 | 规则要**你或业务给判据**（哪些观察表述算红线）；人工观察 14 条有工作量 |
| 为什么先做它 | 现在连"规则长什么样"都没定。**先引模型只会得到一堆无法判定的文本** —— 那是把问题从"没数据"变成"有数据没法用" |

### B.2 推荐第二步：把观察件接到多模态 provider（守衡侧模型或别的）

契约 `multimodal-provider-contract.json` 就是为此留的位；接上后 `observations[]` 自动产出。
**代价**：需要你确认守衡侧模型能否做视觉；产出的是**模型观察** ⇒ 按库规**不得当逐字**，
只能支撑 REVIEW，且要记 `fact_or_inference=推断`。**前提**：B.1 的规则先立好。

### B.3 **不推荐**：直接把关键帧丢给视觉模型让它自由判

① 判据没定 ⇒ 结果不可复现、无法回归；② 与 PRD「先标注维度、可追溯」冲突；
③ 库内刚因「判据没定就量」栽过一次（外部标准那次）。
