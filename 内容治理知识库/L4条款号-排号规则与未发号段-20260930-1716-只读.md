## 一、排号规则（scheme `article-no-2`）

**格式**：`<库前缀>-<形态段>.<序号>`，例 `W-1.12`。

### 1.1 库前缀 —— 指「这条规则**来自哪一类库**」，与形态无关

| 前缀 | 库（`kb_type`） | 库名 |
|---|---|---|
| `E` | `external_standard` | 1_外部标准库 |
| `S` | `internal_sample` | 2_内部正负样本库 |
| `W` | `wording` | 3_措辞表达库 |
| `P` | `product_desc` | 4_产品描述库 |
| `X` | `unknown` | 9_未归类 —— **不得分配**（`blocked_policy`：先归类再编号，不允许发出 `X-*` 号） |

### 1.2 形态段 —— **每类库各自一套**，不是全局 form→段 映射

真源：`numbering.block_by_library`（**唯一权威分段表**，含已发段与预留段）。
权威表自己写明：旧 `numbering.form_block`（`entry=1 / revision_pair=2 / boundary=3 / saythis=4`）
**自 `20260924-1320` 起废止** —— 原因是它全局映射的 `boundary=3` 与 `W-3` 直接冲突，
继续沿用会让「同一个段号指两个形态」。旧表只作历史留痕。

⚠️ **这正是 `W-` 会跨三种形态的原因**：同一个 `W` 前缀下，`W-1/W-2/W-3` 是措辞库里
**三种不同形态**各自的段，不是「W 就是某一种形态」。

### 1.3 序号与排序

- 序号在**同一 `(库, 形态段)` 内**从 `1` 起连续，**不跨段、不跨库连号**；每类库各自一套，不全局连号。
- 段内排序键是**内容派生的稳定不可变 id 升序**（`order_key_per_form`）：
  `wording_entry`/`wording_revision_pair` → `rule_id`；`sample_case_*` → `case_id`；`scoped_clause` → `clause_id`
  （`case_id = sha1(unit_id|sample_case)[:16]`，`clause_id = sha1(...)[:16]`）。
- **明令不用** `support_count`、风险等级、时间、文件行序 —— 免得规则增删让已发条款号错位。
- `no_reuse`：**号码一经发出永久占用**。重跑时在册的 id 沿用原号；新规则取该段 `next_seq`；
  某条规则后来消失，它的号也**不回收、不转给别的规则**。
