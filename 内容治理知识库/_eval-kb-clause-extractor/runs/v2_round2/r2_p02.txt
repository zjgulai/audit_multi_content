- **handling action:** **BLOCK** on explicit treatment/curative verbs applied to a named condition; **REVIEW** on the broader “medical-adjacent” set (structure/function-style phrasing), because that boundary is a judgment call, not a string match.
- **why this one is genuinely determinable:** the object is open-class but the *test* is decidable — “does this wording assert a therapeutic effect?” is answerable from the text alone.

## 2. “no fake reviews” → candidate

- **hit expression:** review-manipulation surface forms — incentivized-review offers (`review for a free unit`, `refund in exchange for a review`) · review-swapping · `5-star reviews guaranteed` · solicitation of specific star ratings. 
- **handling action:** **BLOCK** on explicit compensation-for-review and guaranteed-rating offers; **REVIEW** on ambiguous solicitation.
- **a caveat that matters:** this rule is mostly about **conduct**, not wording. The text is only the *evidence trail* — a compensated-review scheme can be entirely absent from copy and still violate. So this candidate is weaker than #1 as a *content* rule: expect it to catch the advertising half of the problem, not the whole rule.

## 3. “refund requests must be answered within 48 hours” → **not derivable as a content rule**

- **reason code: `no_rule_derivable`** — there is no “hit expression → handling action” pair to extract, because there is nothing in *content* to hit. The rule's object is an **operational SLA** (an agent answers a customer ticket within 48 hours).
- **what hard-distilling it would mislead downstream into:** a rule that scans copy for the string “48 hours” and fires on refund-policy pages — i.e. it would flag compliant refund-policy text and miss the actual violation (a late reply). That's a rule that fires wrongly rather than not at all, which is worse.
- **what would reverse this (翻案条件):** if the intent is a *disclosure* rule — “refund terms must state the 48-hour response window in the policy copy” — then it **is** extractable as a content rule, with hit expression = refund-policy pages lacking a stated response window, handling = REVIEW. That's a different rule from the one written, so it needs your confirmation, not my assumption.
- **where it actually belongs:** the operational SLA is a customer-service governance item, not L3 content-rule material. L3 is the wrong home for it.

Note on the reason code: `no_rule_derivable` is the ledger's defined code for “information insufficient to derive a hit → replace pair.” The codes are an **enumeration — I don't invent new ones.**
