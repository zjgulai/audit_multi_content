好问题 —— 这正是引用契约的「**哪些字段能用、哪些不能用**」那份清单。我把能用的和不能用的分开列，你照这份对，就能判断你手上的候选字段够不够格进评审结论当依据。

**一、能用的字段（六个必带 + 两个标注）**

| 字段 | 取值 / 要求 | 说明 |
|---|---|---|
| **库名** | 四类库之一：**外部标准库 / 内部正负样本库 / 措辞表达库 / 产品描述库** | 从 `kb/l0/registry/kb.json → kb_types` 取（label + dir），**不得自造** |
| **版本** | `v0`（试用版，未发布） | 引用里必须出现版本 |
| **条款号** `article_no` | 形如 `W-2.137` | **L4 分配、永不复用**；一个 `rule_id` 只能对应一个号 |
| **`anchor`** | 形如 `#广告文案明细/recvuJYdOb61lT/命中片段` | 行级定位 |
| **`source_sha256`** | 源文件指纹 | **只有锚点不算完整定位** —— 锚点是行号，会漂移 |
| **逐字摘录** | 原文照打 | 不许转述 / 概括 / 润色 |
| `事实` / `推断` | 二选一 | 这条依据是源里逐字写着的，还是被归纳出来的 |
| **置信度** | 高 / 中 / 低 | 给结论定重量 |

引用串的格式固定是：

```
《<库名> <版本>》第 <条款号> 条（链接：<url>）
```

**二、不能用的字段 / 用法（四条禁止）**

1. **只给 `anchor` 不给 `source_sha256`** —— 锚点会漂移，指纹才能钉住源。
2. **转述 / 概括 / 润色摘录** —— 摘录必须逐字。
3. **裸 URL 当依据** —— 链接是辅助，不是依据本体。
4. **引用不存在的库名** —— 例如《合规措辞库》《广告法禁用语》，**即使源文档里这么写过也不许写**。

另外这几类字段**不在引用契约里**，别拿来当引用字段用：`p_level` / `risk_level`（那是**分流标签**，不是放行结论）、`suggested_replacement`（改写建议，**不构成「这条能发」**，且源表里它可能是多段拼接的）、源表自己的行号、内部路径。

**三、硬闸门（决定这条字段能不能进结论）**

下面三条**任一不满足，整条结论作废、不许输出**，并记入「无法满足引用契约的结论」清单：

1. `anchor` **解析失败**；
2. `source_sha256` **对不上**；
3. **摘录与原文不逐字一致**。

这三条是**防幻觉闸门**，没有例外通道。候选字段里只要缺 `source_sha256` 或只是「我记得大概这么写的」，就进不了结论。
