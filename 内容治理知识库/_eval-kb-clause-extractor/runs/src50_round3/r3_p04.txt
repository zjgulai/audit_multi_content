**禁止项（这四条出现即作废）：** 只给锚点不给 `source_sha256`；转述/概括/润色摘录；裸 URL 当依据；引用不存在的库名（例如《合规措辞库》《广告法禁用语》这类**不存在，不许出现**）。

**硬闸门：** `anchor` 解析失败 **或** `source_sha256` 对不上 **或** 摘录与原文不逐字一致 —— 三者任一不满足，**这条结论一律不输出**，并记入"无法满足引用契约的结论"清单。

## 三、可以直接拿的字段清单（照这个填）

```json
{
  "cited_library": "措辞表达库",
  "kb_version": "v0（试用版，未发布）",
  "article_no": "<L4 分配，候选态留空>",
  "anchor": "<#表名/记录ID/字段名>",
  "source_sha256": "<64 hex>",
  "quote_verbatim": "<原文逐字>",
  "unit_ids": ["<evidence_units[].unit_id>"],
  "judgement": "事实 | 推断",
  "confidence": "高 | 中 | 低",
  "link": "<url>（可空，不得单独作依据）"
}
```

形态差异（这条会绊人，注意）：不同形态的定稿，字段位置不一样 ——
- `wording_entry`：行上 `anchor` 有值，但 `source_sha256` 常在 `evidence_units[i]` 里；
- `sample_case`：`case_id` 标识，`anchor` + `source_sha256` 齐；
- `scoped_clause`：`clause_id` 标识，另带 `clause_text` / `threshold` / `term_list` / `effective_period`，`cite_check` 里给了 `anchors_in_l2` / `evidence_units` / `unresolvable` 可先自检。

所以**不要假设"每条都能从行上直接取到 sha256"** —— 取不到就说明这条的引用不完整，不能硬填。

## 四、我会怎么把契约落到这批候选上（可执行的下一步）

1. **先分离两批**：已发号的（有 `article_no`，可直接进契约）vs 未发号的（候选态，条款号留空 → **不能当依据**）。
2. **逐条预检**（这一步最值钱，能提前挡掉假引用）：对每条做一次 `cite_check` 式核对 —— `anchor` 能否在 L2 解析、`evidence_units` 是否非空、`unresolvable` 是否为空、`source_sha256` 是否 64 位 hex。
3. **过不了的单独列**：不要"修一修凑上"，直接进"无法满足引用契约的结论"清单，注明缺哪一件。
4. **出契约**：能过的逐条出六件套；不能过的只出清单。

## 五、一个提醒

**引用契约只保证"这条结论有出处"，不保证"这条结论是对的"。** 出处齐全 ≠ 判定正确 —— 判定的正确性要靠评审链的判据（P0 命中 / 规则层命中 / 覆盖信号），别把引用契约当质量背书。
