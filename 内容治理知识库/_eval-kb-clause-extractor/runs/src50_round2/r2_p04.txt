先把一句话摆平：**「引用契约」不是一份要新出的文档，它是一条既有的格式 + 字段规则。** 我不生成它，我按它把依据写出来。下面这份就是它的全文口径（来自 `kb/l7/registry/l7.json` 的 `citation_contract`），你要的「能用哪些字段」在第 2、3 节。

## 一、引用格式（照抄，别自由发挥）

```
《<库名> <版本>》第 <条款号> 条（链接：<url>）
```

- **版本**：`v0`（**试用版，未发布**）—— 是契约字段，必须原样带；
- **库名**只能从 `kb/l0/registry/kb.json → kb_types` 取。本库当前 509 条候选的 `kb_type` **全是 `wording`** → **引用库名一律《措辞表达库》**。《外部标准库》《内部正负样本库》《产品描述库》在本库暂无规则，库名只登记备用，**不许当引用来源**。

## 二、字段清单（能用的 / 有条件能用的 / 不能用的）

| # | 字段 | 结论 | 说明 |
|---|---|---|---|
| 1 | **库名** | ✅ 必带 | 只能用真实存在的四类库，**不许自造**（《广告法禁用语》《合规措辞库》都是编的） |
| 2 | **版本** | ✅ 必带 | `v0` |
| 3 | **条款号** `article_no` | ✅ 必带 | 形如 `W-1.1`、`W-2.17`；由 L4 台账发放，**只读，不自造** |
| 4 | **anchor** | ✅ 必带 | 例：`#广告文案明细/recvuJYdOb61lT/命中片段` |
| 5 | **source_sha256** | ✅ 必带 | **只有锚点不算完整定位** —— 锚点是行号，会漂移 |
| 6 | **逐字摘录** | ✅ 必带 | **不许转述、概括、润色** |
| 7 | `事实` / `推断` | ✅ 必标 | 二选一 |
| 8 | **置信度** | ✅ 必标 | 高 / 中 / 低 |
| 9 | `suggested_replacement` | ⚠️ 有条件 | 只解决「怎么写更稳」，**不构成「这条能发」的结论**；该字段可能是**多段拼接**的（源表「修改建议」列本身混了别的违规类型），**只输出与命中片段同源的那段**，拿不准就只给该规则的豁免 / 允许表达 |
| 10 | `p_level` / `risk_level` | ⚠️ 有条件 | 它是**分流标签**（P1 = 优先处理），**不是放行结论** |
| 11 | 裸 URL | ❌ 禁止 | 不许当依据 |
| 12 | 凭据类（token / key / `.credentials*`） | ❌ 不读不回显 | — |

**明令禁止**：只给锚点不给 `source_sha256` · 转述 / 概括 / 润色摘录 · 裸 URL 当依据 · 引用不存在的库名。

## 三、硬闸门（这一条决定「你这批候选有几条真能当依据」）

> **引用不到本地锚点的结论，一律不输出。**

判定方式：`anchor` 解析失败 **或** `source_sha256` 对不上 **或** 摘录与原文不逐字一致 —— **三者任一不满足，这条结论丢掉**，并记入「**无法满足引用契约的结论**」清单。**不是**降级成「大致意思是…」继续用。

**所以：候选要「接进评审结论当依据」，必须逐条过闸，闸门不过的不进结论。** 具体两步：

1. 在**四个形态定稿文件**里查该条有没有 `article_no`：`kb/l4/canonical/{wording_entry,wording_revision_pair,sample_case,scoped_clause}.jsonl`；
   ⚠️ **跳过 `kb/l4/canonical/rules.jsonl`** —— 它**恒 0 字节**（历史迁移留痕，保留不删）。查它一定返回空，**不等于「这条没定稿」**。
2. 命中 = 已定稿（已发号），可引；**未命中 = 仍是 `kb/l3/candidates/rules.jsonl` 里的候选**。

## 四、必须提醒你的一条现状（会直接影响你的评审结论）

你这条请求的落点是「拿候选当依据」。但库里的真实状态是：

- `kb/l3/candidates/rules.jsonl`：**509 条，全部 `provisional`**；
- `kb/l4/canonical/`：**1242 条 `stable`**（wording_entry 56 / wording_revision_pair 453 / sample_case 358 / scoped_clause 375），但**人工抽查未做、无发布版本**，`kb_version=v0`。

**含义**：把**候选**说成定稿 = **引用越级**，我不能这么写；而即便是已发号的那 1242 条，**在正式验收前也不能对外当合规结论**。所以我会给每一段引用挂上这两句边界，不会省。

## 五、我需要你给我的输入

**条款号 / 锚点 / 逐字摘录都不是我凭结论编的，是从库里按 `anchor` 逐一查出来的。** 所以请给我这批候选的落点（任一即可）：

- 文件路径（`.jsonl` / 表名 + 记录号）；
- 或每条的身份标识（`rule_id` / 候选行号）；
- 或那份**已有的评审结论**本身（我按结论回查依据，这是 `kb-content-review` 的标准用法）。

拿到之后我按既有的**分层下探**取依据（顺序写死、不跳层）：**P0 确定性匹配 → 规则层逐字命中 → 单元层 BM25 为主 / 向量为辅 → 原文层按 `anchor` 回 `kb/l0/records/`**，并给你**检索轨迹**（查询 → 各模式 Top-N + 原始分 → 采用 / 舍弃理由 → 最终依据）。

**输出形态**：条数 ≤ 2 逐条出；**≥ 3 条只出分类汇总 + 报告文件**（完整清单会真的落到 `kb/l7/reports/<run_id>.review.md`，不会只说「详见报告」）。过不了闸的那些，单独列一张「无法满足引用契约的结论」清单给你。

## 六、三条边界（先挂上，免得后面对不上）

1. **无命中 ≠ 合规**。索引层没有拒答能力，Top-N 永远会给结果；没有规则层命中又没有覆盖信号时，我按 `no_hit_semantics` **原文拒答**并说明「查了什么、用了哪几种模式、为什么判断没有依据」，**不给 PASS**。
2. **`L0` 层只许引用、不许摘要成结论**；本库大量条目证据级就是 `L1`（检索结果会标「⚠ 证据 L1，只能当线索、不能进决策」），遇到我会明确标出来。
3. **本库不能替代合规 / 法务意见**；条款号对不上时以权威库 `kb/l3` 为准，派生视图的字段改动不写回权威库。

给我落点，我出契约。
