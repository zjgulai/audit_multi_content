五、v2 做了什么（按人拍板的 H1 构造）

#动作实测效果
1description 回到 v1.0.0 的 474 字符基线做减法：不加「不接」清单、不放安全边界（v2 最终 482 字符，只加了输入形态一句）FP 未降（8/4/7 → 9/11/6）
2让位/不接逻辑整体下沉正文 §5「让位表」（正文不参与路由）路由类误判略降（组合 FP 3 → 2）
3精度靠「正面收窄」：在 description 里写明输入形态（要一批外部标准/平台政策/内部规则原文或条款级单元）未奏效；近邻任务（77 NDA 对照表、81 目录清点、83 归档压缩、87 目录树、97 PDF 汇报）仍被接管
4保留 v1.1.0 的内容增益：references/ 4 篇 + scripts/ 2 个只读脚本有效：Progressive 10→14、Script 3→9、Spec 8→10，轨道 A 89.7→98.3
H1 的可证伪结论：假设未被证实，且方向相反。
H1 断言「把让位/不接/安全边界写进 description 会抬高显著度、招来更多误触发」。v2 已把这三类内容全部撤出 description（482 字符 ≈ 基线 474）， 若 H1 成立，FP 应显著下降；实测 FP 由 8/4/7 升到 9/11/6，P 由 0.721 降到 0.653，F1 由 0.837 降到 0.789。

可分离出的两条线索：
① 让位清单确实属于正文 —— 它撤出 description 后，组合标签 FP 由 3 降到 2，说明「写进 description 会招误触发」这半句对让位/不接是成立的；
② 但误触发的主因不在 description 的负面清单：v2 只加了「输入形态」这一句正面表述，FP 就反弹；被接管的仍是带「政策/规则/条款/台账」字样的近邻任务。 这说明误触发更可能来自 catalog 层面的关键词共现与排序（本 skill 与近邻成员同时命中时本 skill 排前），而不是 description 的措辞结构。

另一条可复用的观察：v2 的正例召回丝毫未动（16/16/16，R=1.000），说明本轮所有改动只影响精度侧 —— 符合「这是一道精度题」的判断，只是本轮没找到有效的精度杠杆。
