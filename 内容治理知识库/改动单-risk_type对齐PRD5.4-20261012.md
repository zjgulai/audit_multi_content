## 一、先说结论：**不要改 `risk_type`**

### 1.1 ★★ 决定性实测：改它会**静默改「转给谁」**

`kb/l7/review-engine/core/review_engine.py::route_owners()` 拿 **`risk_type`**（＋ `reason`）做**关键词匹配**来定责任人：

```python
text = f"{item.get('risk_type', '')} {item.get('reason', '')}".lower()
if any(t in text for t in ("医疗","health","功效","安全","睡眠","喂养")): owners += ["医学顾问","法务"]
if any(t in text for t in ("产品","型号","功能","规格","容量","认证","product")): owners += ["产品负责人","法务"]
if any(t in text for t in ("背书","endorsement","达人","排名","绝对化","平台")): owners += ["法务","渠道负责人"]
```

**逐条对比（真调 `route_owners`，只读）**：

| 现 `risk_type` | 现在转给 | 若改成「维度-子类」 | 会变成 |
|---|---|---|---|
| `功效宣称-催乳与通乳宣称` | 医学顾问 + 法务 | `合规-催乳与通乳宣称` | **法务 + 北美同事** ← **医学顾问丢了** |
| `绝对化与安全承诺-虚假安全承诺` | 医学顾问 + 法务 + **渠道负责人** | `合规-虚假安全承诺` | 医学顾问 + 法务 ← **渠道负责人丢了** |
| `背书与资质-监管认证宣称` | 产品负责人 + 法务 + **渠道负责人** | `合规-监管认证宣称` | 产品负责人 + 法务 ← **渠道负责人丢了** |
| `婴幼儿安全与场景-睡眠安全` | 医学顾问 + 法务 | `消费者安全-睡眠安全` | 同 |
| `品牌一致性-禁区（库内反例条款）` | 法务 + 北美同事 | `措辞表达-禁区（库内反例条款）` | 同 |
| `表述与术语准确性-术语与口径` | 法务 + 北美同事 | `措辞表达-术语与口径` | 同 |

**受影响 3 / 6 条**，且方向全是**降级**（少找人）。
⇒ 打的是 **PRD §9 逐字「REVIEW **自动转对应专业团队**（法务、医学、专家、北美）」** —— 属最坏的一类。

**机理**：把「库内类别」换成「四维度」，是**多对一压缩** —— `功效宣称`/`绝对化与安全承诺`/`背书与资质`/`平台与促销`/`人物肖像与 AI` 五类都会变成同一个 `合规`，
而那些**承担路由的关键词（功效/安全/绝对化/背书/认证）全在类别名里，一压缩就没了**。

### 1.2 影响面（`risk_type` 的四个活消费点，逐个取证）

## 二、那 PRD §5.4 的示例怎么办？—— 它要的东西**已经用另一格满足了**

PRD §5.4 的 JSON 规范**同时**给两格（逐字）：

```json
"risk_type": "合规-医疗宣称",      ← 细分类型
"risk_category": "合规",           ← 维度（**本库已落地**）
```

⇒ `risk_category` 已经把「维度」这一格填上了。**`risk_type` 不需要也变成维度** —— 那会让两格**冗余**（都是四选一），
同时把细分信息丢掉。**两格各司其职**才是 §5.4 的原意。

### 我的推荐：**方案 B**

- **哪一条**：改 `core/report_memory.py:51` 的分组键 —— `risk_type` → **`risk_category`**（取不到时**逐字退回** `risk_type`，与 `dual_track` 那条「引擎给了就照搬、没给才回落」同一条纪律）。
- **为什么**：PRD §8.3 逐字要的是「**按维度分组展示**」，而「维度」= 四维 = `risk_category`。
  现状按 `risk_type`（库内类别）分组，那是**细分**不是**维度**。方案 B 让两格各就各位，且**一条信息都不丢**。
- **代价 / 前提**：① 这是**工作流可见**的改动（报告的分组标题会变）⇒ 必须带回归集前后对照；
  ② 报告落点 `kb/l7/reports/`，改动只在**新单**生效，**历史报告不重写**；
  ③ `report_memory.py` 属于评审链，改完要跑 `workflow_smoke` + 端到端一单。
- **未闭合**：`原则性错误`/`文化禁忌`/`未分类`/`unknown` 这四类**没有维度**（Owner 2026-10-12 裁「暂留空」）
  ⇒ 按 `risk_category` 分组时它们会落进一个**显式的「未标注维度」桶**（不许悄悄并进别的桶，也不许丢掉）。
