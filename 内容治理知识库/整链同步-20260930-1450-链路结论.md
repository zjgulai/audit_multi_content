## 本次实质发现：链是绿的，但「最新」没到（19 条源更新未下沉）

**这不是闸门报出来的，是我按 sha 逐资源对账查出来的。**依据链：

1. **L0 今天有真实源更新**：`kb/l0/manifest.jsonl` 14:40 被写，最新一行

2. **逐资源对账**：L0 活跃 1447 个资源 ∩ L1 可比对 1414 个 →
   **1394 个 sha 逐字节相同**（哈希基准一致，排除基准不同造成的假阳性），
   **20 个不同，其中 19 个 L1 侧 `status=ok`**。
3. **这 19 条的形态**：L0 侧 `status=updated`、`sha256_input ∈ {file_bytes, pdf_ocr_v1, url_text_refresh_v1, feishu_content_v1}`
   （即 L0 真的重取了字节并重算了内容 sha）；L1 侧仍是**旧 sha + status=ok 的既有抽取**。
   例：`TsCLw5uU2iOOUlkEcvqcbH` L1 记「飞书 API 取原件 PDF（68 页，6296468 字节）→ pypdf 抽文本 139468 字」，
   但 L0 已给出新 `file_bytes` sha。
4. **为什么链传不下去**（两条独立原因，都读代码确认）：
   - **编排器没接这条边**：`kb_pipeline.py:243-253` 的 `SYNC_SPEC["L1"]` **只登记了 `ocr_attachments.py`**，
     `layers.yaml` L1 段登记的 `kb/l8/extract_l1_new_resources.py`（L0→L1 对齐引擎）**不在编排清单里** →
     `--sync --all` 跑到 L1 时**根本不会执行它**。
   - **就算接上也不管用**：`kb/l8/extract_l1_new_resources.py:91` 的缺口判据是
     `to_extract = [k for k in l0_active if k not in l1_latest]` —— **只看资源键在不在，不看 sha 新不新**。
     我直接干跑它，自报 `[计划] L0 活跃 ⊖ L1 = 0`（空转），**这 19 条一条都进不了抽取名单**。
5. **L2 也接不住**：这 19 条 L1 artifact 的**旧 sha** 在 L2 units 里存在（所以 L2 判「已覆盖」、补切 0），
   **新 sha 从未进入 L2** → 下游 L3/L4/L5/L6 全部继承旧内容。

**一句话**：L0 说「这 19 个源变了」，L1/L2 说「我这有」，两边各自自洽，**中间没有一条边负责把新 sha 推下去**。
