## 1. 三问的原文出处

### 问一：审查覆盖率 —— 在 **PRD §10「记录与统计」**

```
10. 记录与统计
  审核记录绑定内容版本。
  支持统计：
    审查覆盖率              ← 七项的第 1 项
    PASS / REVIEW / BLOCK 比例
    各优先级层级命中率
    人工复核负担
    误报 / 漏报
    规则命中率
    知识库回流数量          ← 七项的第 7 项
```

★★ **PRD 只写了「支持统计：审查覆盖率」这六个字 —— 没有定义、没有分子分母、没有口径、没有粒度。**
库内 `report-output-contract.yaml:2212` 的转述（「PRD §10 要七项统计」）**与原文一致**，可采信。
⇒ 所以「覆盖率算不出」**不是我们漏读 PRD，是 PRD 本身没给分母**；分母只能由需求侧另行给定。

### 问二：知识库回流数量 —— 出处在 **PRD §9 末句 ＋ §10 第 7 项 ＋ §11.2**

```
§9 人工复核与 sign-off（末句）
  人工复核结论回流知识库，更新规则权重和正负样本。

§10 记录与统计
  知识库回流数量

§11.2 保障机制 → 人工反馈回流
  ：人工复核结论回流知识库，持续优化规则和权重。
```

★ 注意 §9 与 §11.2 各写了一遍，**措辞不同**：§9 说「更新**规则权重和正负样本**」（给了落点），
§11.2 说「持续优化**规则和权重**」（没给落点）⇒ **落点以 §9 为准**（L3 规则权重 ＋ 正负样本）。

### 问三：误报 / 漏报 —— 定义与公式在 **PRD §11.3**，目标值在 **§11.1**

```
§11.3 评估方式
  以人工复核为金标准，计算：
    准确率        = 三态结论一致数 / 总审查数
    BLOCK 精确率  = 正确 BLOCK / 全部 BLOCK
    PASS 误放率   = 人工复核为 REVIEW/BLOCK 的 PASS / 全部 PASS
    REVIEW 召回率 = 人工复核为 REVIEW/BLOCK 且 Agent 输出 REVIEW / 全部人工 REVIEW/BLOCK
    P0 层漏报率   = P0 规则应命中但未命中的数量 / P0 规则应命中总数（目标为 0）

§11.1 目标
  整体三态准确率 ≥ 90%；BLOCK 精确率 ≥ 95%；PASS 误放率 ≤ 5%；
  REVIEW 召回率 ≥ 95%；人工复核负担降低 ≥ 50%
```

★ **§11.3 第一句就是「以人工复核为金标准」** —— 「金标准」= **人工复核**，不是 agent 判读。
★ 任务表 **12/14 那行**要的「错放率 ≤5%」「复核召回 ≥95%」**逐字就是 §11.1 的 PASS 误放率与 REVIEW 召回率**。

## 2. ★★ 核心发现：第 6 项与第 7 项**卡在同一个地方 —— 缺「人判」**

审计 7 项里 3 项 no_data，但只有 2 项同源：

| 项 | 卡点 | 与「人判」的关系 |
|---|---|---|
| 第 5 项 审查覆盖率 | **缺分母**（应审清单） | **无关** —— 要需求侧给清单 |
| 第 6 项 误报 / 漏报 | **缺人判** | **同源** |

**掩盖了它们共用同一个输入这件事**。

## 3. ★★ 「误报/漏报」不必等 11/30 的金标集 —— PRD §11.2 已给第二条路

```
§11.2 → 每周抽检：每周人工抽检 100 条，评估准确率。
```

**而这条路的产物已经就绪、只差人填一栏**（实测）：


⇒ **「机器结论」与「人判」已经是**并排两栏** —— 填完「人判」，「误报 = 机器拦∧人放 / 漏报 = 机器放∧人拦」
就是 §11.3 的现成公式**（`kb/.work/update_xlsx_1012_row.py:49` 自己也写着「★人判栏空、待人工」）。
⇒ 结论：`audit_metrics.mjs` 写的「误报/漏报 —— **等金标集（11/30 那行）**」**只说了两条路里的一条**，
把一条**本周就能跑**的路写成了「等 11/30」。**这是措辞问题，不是事实问题。**

## 4. ★ 「60 个问题」必须问清一件事：**是「素材」还是「带人判的评估项」**

PRD §11.3 明写「以**人工复核**为金标准」⇒ 只有**每条都带人工 PASS/REVIEW/BLOCK** 才能算。
若那 60 条只是**待审素材**（送进去跑、看机器输出），那**一条公式都算不出来** —— 它测的是「跑得通不通」，不是「准不准」。

另两点照实说：
- **PRD 全文没有规定评估集大小**。「文字 40 / 图片 30 / 视频 30 = 100」是**任务拆解表 11/30 那行**定的，
  **不是 PRD 的要求** ⇒ 60 条本身不违反 PRD。
- **60 条要能撑起分母**：§11.1 要 BLOCK 精确率 ≥95% 与 PASS 误放率 ≤5%，
  两个分母分别是「全部 BLOCK」与「全部 PASS」⇒ **类目配比要均衡**。若 60 条里 BLOCK 只有 10 条，
  一条误判就动 10 个百分点，读数没有分辨力。**配比比总数更重要。**
- 业务侧这 60 条**若含视频**，正好补上现有金标集**视频 0 条**的唯一空白（现集子：文字 40 / 图片 30 / 视频 0）。

# 附：**60 题金标集对「3 项 no_data」的覆盖判定**（2026-10-12）

业务侧收到的是「60 条测试题 + 人工标准答案」的征题说明。逐项核它到底解决了什么：

| 审计项 | 卡点 | 60 题解决了吗 | 为什么 |
|---|---|---|---|
| 第 5 项 审查覆盖率 | 缺**分母**（本期应审全集） | ❌ **完全不解决** | 60 条是**人工挑的测试题**，不是「本期实际投放/应审的全集」。更糟：来源列允许「**我构造**」⇒ 里面有不存在的素材，拿它当分母，覆盖率**无意义**（甚至可能 >100%）。**两件事方向相反**：金标集求「边界覆盖」，应审清单求「全集完备」，**不能互相顶替** |
| 第 6 项 误报 / 漏报 | 缺**人判** | ✅ **解决了「有人判」** | 60 条带人工三态 + 理由 ⇒ 卡点消失。但**没到「算得准」**：① 要能逐条对齐系统结论 ⇒ 依赖**稳定题号 + 外键**（缺则结构性接不上 `audit_metrics.mjs`）；② NEEDS_INPUT 语义分叉不澄清会**系统性冤枉系统**；③ 60 条是**一次快照**，不是 §11.2 的**持续**评估 |
| 第 7 项 知识库回流数量 | 缺**机制** | ⚠️ **可能顺带解决，但有前提** | 见下 |

## ★ 第 7 项：60 题**能**喂回流 —— 前提是「**真送进评审链跑一遍**」

回流事件的定义（生成器自己的规格）＝「人工复核结论落成结构化事件（谁/何时/对哪条/改成什么）＋ 带回流到哪一层」。
若这 60 条**只当纸面问卷**（人写答案、不与系统结论对照）⇒ **不产生任何回流事件**，第 7 项照旧 0。
**若这 60 条真的送进评审链跑一遍**（拿到 `run_id`）⇒ 每条就有「人判 × 机器结论」一对，
**「人判 ≠ 机器」的差异正是 §9 要的「纠错」** ⇒ 这批差异可以当**首批回流事件来源**。

⇒ **回填模板最后两列（`送审运行ID` / `机器结论`）不是格式要求，是第 7 项的接线口。**
  不填 ⇒ 60 题只解决第 6 项（且只到「可算」）；填了 ⇒ 第 6、7 项**同时**推进。

## ★★ 一条必须分开的红线：**「我构造」的题可以做度量，不可以做纠错**

来源列有三档：真实投放 / 历史打回 / **我构造**。
「构造」的题用于**测准确率**没问题（这正是边界题的价值）；但**绝不能**把它的人判差异当作「纠错依据」去改 L3 规则权重 ——
**那会把规则朝不存在的素材上调（过拟合虚构样本）**。
⇒ 回流事件必须带 `source ∈ {真实投放, 历史打回, 我构造}`，
且**只有前两档允许进第二步（真写权重）**；「构造」档**只进台账、只计数**。

## 结论一句话

**60 题把 3 项里的 1 项（误报/漏报）从 `no_data` 推到「可算」；覆盖率与回流数量一项都没动**
——除非最后两列被回填（那会把第 7 项一起推起来）。
