## 一、先摆冲突（决定了怎么做）

| | |
|---|---|
| 工作流要求 | 「**调用 L4/L5/L6/L7 每层 skills + 评审层 skills** + 出报告溯源（L0）写入飞书」 |
| 我上一条建议 | 「换入口」= 把 spawn agent 换成常驻服务 —— 那会**去掉唯一能加载 skill 的执行体** |

## 三、诚实读法（不吹）

- **不宣称手册带来 7.7% 提升**：n=4，且同配置方差本身就大（同素材同设置实测出现过 142 s 与 391 s，**2.75×**）。
- 能说的是：**R4 均值最低，且没有出现前两轮那种 500~600 s 的离群单**。
- 真正**不带方差**的收益只有三笔（见下）。

## 五、过程中踩的一个坑（已修，记在这里）

`REVIEW_PLAYBOOK` 的 IIFE 第一次被插到**文件头部** ⇒ 它在 `import fs` 与 `const KB_ROOT` **之前**执行
⇒ 被 undefined 吞掉、**静默返回空串**（手册悄悄不生效，而 `chainMs` 一切正常）。
现位置在 `KB_ROOT` 就绪之后，且**读不到时出声告警**（`console.warn`），不再静默。
**教训**：这类"值没送到但不出错"的形状，只有运行时验证才抓得住 —— `node --check` 只查语法，查不出未定义标识符。
