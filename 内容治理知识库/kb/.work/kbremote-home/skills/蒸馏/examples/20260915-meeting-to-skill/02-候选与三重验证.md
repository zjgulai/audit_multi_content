## 三、淘汰统计（阶段 1.5 产出）

| 项 | 值 |
|---|---|
| 候选总数 | 21 |
| keep（进正文） | 8 |
| review（降级进 references） | 4 |
| discard | 8 |
| 待确认项 | 1 |
| **淘汰率** | **13 ÷ 21 = 62%** |

**判定**：62% 落在正常区间（50%~75%）✔

- 如果只有 25%：说明"非常识"这条判太松，会蒸出同质化内容；
- 如果 90%：说明这份素材本来就不含判断——但这场会议的判断密度明显不止，所以 62% 是可信的。

**判断密度**：8 条判断 ÷ 约 12 千字（纪要 + 妙记折算）= **0.67 条/千字** → 偏事实，但含判断，值得蒸 ✔

## 四、keep 的 8 条，正文里长什么样

| # | 正文写法 |
|---|---|
| 1 | 阶段 2 不许先写 PRD：先用 TUI + 通用 Agent 把问题真解决一次，拿到真实可用的答案，再逆推工作流、补规格。**没跑通过不进阶段 3。** |
| 2 | 判分只用确定性方法（`must_contain` / `must_not_contain` / `answer_non_empty`）。判不了的不留中间态，**拿不出可校验的作答一律判 fail**，绝不编造标准答案。 |
| 3 | 数活儿 = `len(deliverables)`。**交出去的东西不一样才算两件活。** 工具、skill、行为约束、变体都不算活。 |
| 4 | 缺模型端点时如实标 `environment_degraded` / `insufficient_evidence`，**绝不跳过输出、绝不谎报提升**。"证据不足"是合法结论。 |
| 5 | 接缝数理想 1 个、取能找到的最高点、优先用已有。**接缝必须在写规格时和用户确认，改接缝等于返工。** |
| 6 | 三重验证淘汰率 50%~75% 属正常。**报告的淘汰率低于 30% 时，先怀疑自己放水了。** |
| 7 | 归因三分派：`structural` 能自动修，`content` 与 `environment` 不能。 |
| 8 | `content` 不能自动修的理由：改提示词让某个 `must_contain` 通过是**针对测试集过拟合**，不是提升能力。**防过拟合靠留出集，不是让人去拟合已有用例。** |
