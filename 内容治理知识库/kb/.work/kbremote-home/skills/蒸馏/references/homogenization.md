# 同质化检测与竞争壁垒

## 一、要防的是什么

**同质化 = 蒸出来的 Skill，裸模型自己也能做到同样好。**

后果不是"没加分"，而是**降质**：

> 「如果你觉得它没有 skill 跑得比你还好，那你这个 skill 就是废物，就是在降质。」

Skill 池到 2000+ 规模后要做**组合测试减资**，剔除冗余与降质项。同质化 Skill 是减资时的第一批被砍对象——**与其等被砍，不如蒸之前就拦住**。

---

## 二、四类竞争壁垒（占住至少一类才值得蒸）

| 壁垒 | 内容 | 自检问法 |
|---|---|---|
| **私有数据** | 只有本团队有的术语、契约、配额、公式 | "这个东西外部人查得到吗？" |
| **失败案例** | 实测踩过的坑，别处查不到 | "这条是踩坑踩出来的，还是通用道理？" |
| **反共识** | 与主流/直觉相反的做法 | "多数人会不会本能地做反？" |
| **行业洞察** | 本业务场景特有的验收写法、口径 | "换一个行业，这条还成立吗？" |

**一类都占不住 → 不蒸。**

---

## 三、同质化检测：三步

### 第 1 步：逐条过"非常识"

对每条候选问：**裸模型自己是不是也能说出来？**

**必须实测，不能凭感觉。** 方法见 `baseline-compare.md`。

### 第 2 步：与已有 Skill 比对（`no_duplication` 谓词）

```bash
# 先看已有 Skill 目录
ls ~/.dsh/skills/ ~/.agents/skills/

# 再按触发词搜一遍
grep -ril "<你的核心触发词>" ~/.dsh/skills/ ~/.agents/skills/ | head
```

| 比对结果 | 处理 |
|---|---|
| 触发场景重叠 > 50% | **合并进已有 Skill**，不要新建 |
| 触发场景部分重叠 | 收紧 description 的边界，明确"不适用" |
| 完全无关 | 可以新建 |

**"重复则合并而不是新建"是硬谓词。** 多一个重叠 Skill，就多一份路由歧义。

### 第 3 步：算"判断密度"

```
判断密度 = 够格进正文的条数 ÷ 素材总字数千字
```

| 密度 | 判断 |
|---|---|
| ≥ 1 条/千字 | 素材含判断，值得蒸 |
| 0.3 ~ 1 条/千字 | 素材偏事实，考虑只出一份 references 而不是 SKILL.md |
| < 0.3 条/千字 | **放弃蒸馏**，如实说明理由（这是合法结论） |

## 四、常见同质化形态

| 形态 | 例子 | 为什么是同质化 |
|---|---|---|
| 通用最佳实践 | "写测试要覆盖边界情况" | 裸模型必然会说 |
| 教科书流程 | "需求→设计→开发→测试" | 任何模型都背得出 |
| 常识包装成方法论 | "先理解再动手" | 没有信息增量 |
| 摘要冒充 Skill | 长文档的摘要 | 回答"讲了什么"，不回答"该怎么做" |
| 换个说法抄已有 Skill | 与现有 Skill 重叠 70% | 制造路由歧义 |

---

## 五、蒸出来之后的固定动作

**裸模型对照**：同一批场景问题，裸模型 vs 带 Skill，对比**输出质量**与**稳定性**。

- 明显优于 → 保留
- 差不多 → **不保留**（要么合并进别的 Skill，要么丢掉）
- 更差 → 检查是不是 Skill 里的规则把模型带偏了

结果落盘，作为交付物的一部分。方法见 `baseline-compare.md`。
