# 十条反模式黑名单

> 蒸馏过程中**任何一条都不许碰**。正文只留一句指针，细则在此。

| 反模式 | 为什么禁止 |
|---|---|
| 同一个 AI 又改又评 | LLM 自评准确率很低，等于没评 |
| 用 `git reset --hard` 回滚 | 应该用 `git revert`，保留变更历史 |
| 为凑分堆冗余内容 | 分上去了，Agent 调用时 context 也炸了 |
| 跳过评测直接评分 | 等于没有验证 |
| 一轮内改多个维度 | 无法定位是哪个改动带来了提升 |
| 干跑比例 > 30% | Skill 覆盖面不足的信号 |
| 静默跳过异常 | 掩盖失败，累积技术债 |
| 只抄结论不抄判断 | 换场景立刻失效 |
| 把"事实"写进正文 | 正文膨胀，触发精度下降 |
| 字迹/语音识别不确定却照写 | 把识别错误固化成团队标准 |

## 追加三条（v1.1.2，来自 Kb2Agent 的反模式与劣化机制）

| 反模式 | 为什么禁止 |
|---|---|
| **把实时/易变数据蒸成判断** | 库存、价格、当日投放这类字段 48 小时就烂，Agent 会拿过期事实自信作答。走入口四档的 CACHE，只留指针 |
| **蒸完自动写回权威库** | 没有人工过闸的自动写回 = "幻觉复利"：坏判断进高权重层，污染后续所有检索与评估 |
| **把"待确认项"悄悄升级成结论** | 猜出来的判断比没有判断更糟——它会被当成团队标准执行 |
