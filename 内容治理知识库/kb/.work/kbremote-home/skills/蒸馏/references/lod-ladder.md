## 五级阶梯：从碎片到契约

LoD 是**加工深度的选择**，不是质量排名。选层的唯一依据是「Agent 拿它做什么」（§1.2 · "加工深度的选择模型"）。

| 层级 | 形态 | 干什么 | 典型检索路由 | 什么时候别选它 |
|---|---|---|---|---|
| **L0 平铺** | 文本 Chunks | 滑动窗口切片 + 向量化 | 单跳事实查询，相似度召回 | 跨文档问题：存了 50 页的 Token，有效知识点只有 20 个（§1.1 · "50 页 PDF 有效知识点只有 20 个"） |
| **L1 实体增强** | 富化 Chunks | 抽实体附着在 Chunk 尾部，用元数据过滤代替建图 | 向量 + 元数据过滤 | 需要跨文档综合时——实体过滤只缩范围，不做综合 |
| **L2 层级导航** | 目录树 `INDEX.md` | 分层聚类生成目录，让 Agent 逐层下钻 | 导航 + 精确检索，**禁用传统向量检索** | 文档量小、目录一眼看完时——分类层是白建的维护负担 |
| **L3 知识图谱** | 实体关系网络 | 三元组 + 社区摘要 | 全局聚合、跨文档对比、主题综合 | **单文档单跳事实查询**——强行拉入多条边制造噪音，准确率反而低于向量检索，成本高一个量级（§8.2.5 · "低于普通向量检索"） |
| **L4 可执行契约** | `SKILL.md` | 触发条件 + 执行流 + 禁忌，Agent 零推理直接执行 | 不检索，直接执行 | 更新周期短于维护周期（走 CACHE）；四类反蒸馏知识（见下） |

**关于「什么时候换层」**：升降级 8 条阈值与 L4 纠错五步回滚 → `lod-transitions.md`。

**三条选层纪律**：

1. **分层，不是全选最高层**。高频知识做 L4，低频全量做 L1–L3，归档内容做 Raw 原文（§1.1 选层原则 · "高频使用的知识做 Skill 蒸馏"）。
2. **L3 不是 L0 的升级版，是另一条路线**。素材自己下了冷酷结论：图谱并没有全面干掉向量检索；正确解是**意图分类器路由**——只在聚合归纳意图明显时才走 L3（§8.2.5 · "混合架构是唯一解"）。这条对只做蒸馏的人的反面用法是：**有人告诉你「上个图谱更高级」，先问他要解决的是不是全局聚合问题。**
3. **L2 的隐藏价值是「不检索」**。碎片化长尾文档（几万份工单/FAQ 这种量级）的解法是给 Agent 配「浏览目录 + 读原文」两个工具让它自己下钻，而不是让它问检索器要 top-K（§8.2.3 · "Don't Retrieve, Navigate"）。**这条推翻的是本技能默认的「切块入库」姿势**：文档规模够大且天然有分类结构时，先建目录，别先建向量库。

> **本表不引用任何评估分数。** 素材各章给出的命中率、F1、成功率类数字，属于随评测集与版本漂移的量，按本技能的取材纪律一律不作为判断依据（§02 来源与复核 · "任何易漂移的版本、价格、法律或性能结论"）。上表只留**方向性结论**（谁比谁强、在什么问题上强），不留具体数值。

## 反蒸馏四类：蒸了更糟，必须留在原地

蒸馏的本质是**有损压缩**——用结构换可检索性，必然丢原文语境（§1.4 · "你在用结构换取可检索性"）。下面四类，损失大于收益。

| 类型 | 典型内容 | 为什么蒸了更糟 | 替代存法 |
|---|---|---|---|
| **情境依赖型** | 合同条款解释、临床推理过程、产品取舍背景 | 抽离语境后，Agent 会拿着**脱离语境的正确结论**在错误场景下应用（§1.4 · "在错误场景下应用"） | **保留全文原始存储 + 语义索引**，让 Agent 检索到之后自己在上下文里推理，而不是消费一个预提炼的命题 |
| **负向知识** | 失败经验、踩坑记录、被否决的方案 | 把「我们试过 A，在 B 场景失败，因为 C」压成「不要用 A」，后来者无法判断自己的场景是否适用——**价值在完整叙事，不在结论**（§1.4 · "价值在于完整叙事"） | **ADR 格式原文保存**：背景 → 决策 → 被否决的选项 → 后果。可以建索引，**不要摘要化** |
| **高度个人化的隐性知识** | 专家的直觉判断、老手的「感觉」 | 本质是身体记忆与模式识别，蒸成操作步骤只能捕获显性部分，**丢掉的恰恰是最有价值的判断边界**（§1.4 · "遗漏最有价值的判断边界"） | **访谈录音 + 逐字稿原文存储**；AI 只用来生成「提问引导词」供人查阅，**不生成能被 Agent 直接调用的决策函数** |
| **快速迭代的操作性知识** | CLI 参数、SDK 签名、三方平台限制条款 | 更新周期短于维护周期，结构化会制造一个**「看起来权威但已经过期」的陷阱**——过期事实 + 权威外观，比没有更坏（§1.4 · "看起来权威但已经过期"） | **只存指针**：URL + 访问时间戳 + 摘要，需要时实时获取。**不存内容本身** |

**两条使用纪律**：

- **指针必须带访问时间戳**。只存 URL 等于没存——下次谁都不知道这份指针指的版本是什么时候的了。这一条与 `half-life-routing.md` 的 `< 48h` 档是同一个字段要求，两处各自独立提出（§1.4 · "URL + 访问时间戳 + 摘要"｜§2.5 · "只存指针（URL+时间戳）"）。
- **「反蒸馏」不是暂缓蒸馏，是永久保持原形态**。四类知识不是「等它稳定了再蒸」，是**它一旦稳定就不再是它自己**——条款解释脱离合同就不是条款解释，专家直觉外显成步骤就不是那个判断了。`【review 待人工定】`（置信度 0.6；§1.4 · "应保持原始形态存储"）

> `【review 待人工定】` **素材内部差异**（未采用，仅留档）：快速迭代知识的替代存法，§1.4 指「官方文档 URL」，而 §7.1 场景 2 举的例子里含「查询时调外部 API」。**两者指的不是同一类对象**——前者是文档、后者是数据源。本文件按 §1.4 的「官方文档 URL」处理，API 那类归 `half-life-routing.md` 的 `< 48h` 档。归属边界待人工确认。

## 蒸之前的灵魂三问

三问全过才动手，**任何一问答「不确定」，先不要蒸馏**（§1.4 · "有任何一个答案是'不确定'，先不要蒸馏"）：

| # | 问 | 答「不确定」意味着 | 去哪儿找答案 |
|---|---|---|---|
| 1 | 这条知识**六个月后还准确**吗？ | 半衰期没量清 | `half-life-routing.md` 四档刻度 |
| 2 | 它**离开完整语境**后还能被正确理解吗？ | 可能是反蒸馏四类里的第一类 | 上文「反蒸馏四类」表 |
| 3 | 有没有人会因为 Agent 拿它做决策而**承担现实后果**？ | 该走 ESCALATE 回人，不是自己蒸 | `intake-routing.md` 的 ESCALATE 档 |

**三问的严格版在这里**：原文用「不确定」当拦截条件，比常见的「答'是'就停」严格一档——**不是问「会不会出事」，是问「你确不确定」**。对一条看起来明显安全的素材，答不出「确定六个月后还准」，一样停。

第 3 问还有一层用法：它答「有」，不代表不能蒸，代表**蒸完要有人签字**。责任归属不清时，蒸得再好也不该进 L4。

## 与 `intake-routing.md` 的接口

| 问题 | 谁回答 |
|---|---|
| 该不该蒸？ | `intake-routing.md`（四档：SKIP / CACHE / PROCESS / ESCALATE）+ `half-life-routing.md`（时效刻度） |
| **该蒸到哪一层？** | **本文件**（L0–L4 选层 + 反蒸馏四类 + 升降级 8 条） |
| 蒸出来的判断收不收？ | `triple-verification.md`（三条判据 / 置信度分档） |
| 蒸到什么程度算完？ | `acceptance-contract.md`（四条入库验收谓词） |
| L4 出错怎么办？ | `lod-transitions.md`（五步回滚 + 覆盖入库禁令） |

**一句话**：入口四档回答「**该不该蒸**」，本文件回答「**该蒸到哪一层，以及哪一层不许去**」。

## 边界（本文件不管什么）

- **管选层，不管选型**：具体用哪个检索框架、哪个图数据库，素材给的是带版本与评测分数的选型建议，属易漂移输入，本文件不转述。
- **管选层，不管时效**：半衰期四档 → `half-life-routing.md`。
- **反蒸馏四类不给自动化判据**：四类的归属要靠人读原文判断，素材没给可枚举的识别规则——**这是素材未覆盖的缺口**，别假装能自动分。
- **升降级 8 条只给阈值，不给采集方案**：见上文第 5 条读法。落地前需要自己补计数器，缺计数器的判据等于没有。
