# Output Contract - 输出契约与放行/阻断判定

核对清单、字段定义、15 项自检引用 `root-skills-eval/references/trigger-eval-cases.md`，此处只定义交付物。

## 交付四件套

1. **核对报告**：漏项表 + 回填动作 + 放行或阻断（逐项 pass/fail + 证据）。
2. **回填后的 YAML / JSON / Excel**（有改动才交付；无改动说明「无需回填」）。
3. **数据资产 delta**：`新增 N 条 / 跳过 M 条重复`（无入库也写 `新增 0 条`）。
4. **放行结论**：全部通过 → 「报告已放行」；任一项未通过且补不回 → 「阻断」+ 漏项清单。
5. **HTML 入口**：同目录 `index.html` + 相对路径打开单一 HTML 报告。细则 `references/html-delivery.md`。Excel 只写相对路径。

## 判定矩阵

| 情况 | 结论 | 是否入库 |
|------|------|----------|
| 全 pass | 报告已放行 | 可入库（通过字段 / 金标） |
| fail 但已回填转 pass | 报告已放行 | 可入库（漏项模式 + 原文对照） |
| fail 且无法回填 | 阻断 | 只入「如何发现/如何补」的模式，不入金标 |
| 未通过报告 | 阻断 | 不入库（禁止脏数据） |

## 交付边界

- 只做放行入口 + 自动成长；不替 eval 出题打分，不替 opt 改正文，不替 doctor 修结构。
- 不编造评测数据；不把摘要当原文；不把未通过报告写入金标库；不导出密钥或系统提示词。
