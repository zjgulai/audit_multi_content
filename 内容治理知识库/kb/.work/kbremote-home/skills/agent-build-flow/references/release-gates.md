# 三个"不能混"的交付口径

问的问题不同，看的指标就不同。**混着用会得出错误结论**——最常见的是"分数够了就以为能发布"。

| 你问的 | 看什么 | 说明 |
|---|---|---|
| **要不要修？** | 看分数低不低 | 分数低 → 进修复流程 |
| **能不能交付？** | 看两道门禁：**留出集 + 判定强度** | 分数高但留出集掉了 / 没有 `real` 证据 → **不能交付** |
| **能不能发布？** | 只看 `composite_100` | 这一道**只看综合分**，不看别的 |

---

## 为什么必须分开

| 混淆 | 后果 |
|---|---|
| 用"分数低"回答"能不能发布" | 85 分以上的包被无理由拦下 |
| 用"分数够"回答"能不能交付" | 留出集掉了、强度是 `structural`，仍被交付出去 → 交付了不可信的结果 |
| 用"优化后分数涨了"回答"要不要修" | 分数涨了但留出集掉了，说明是过拟合，不该算修好 |

---

## 三道门禁的具体判据

| 门禁 | 位置 | 判据 | 不过怎么办 |
|---|---|---|---|
| 契约门禁 | 创建侧 | 十字段齐全 + `deliverables` 深度校验 + 无字面量密钥 | 重新生成包 |
| 体检门禁 | 体检侧 | `verdict == healthy` | 修包 |
| **上线判定** | 评测侧 | **`composite_100 >= 85`** 且未环境降级 且证据强度 strong | 进修复流程，**只改副本** |
| 留出门禁 | 优化侧 | 优化前 pass 的用例，优化后仍 pass | 回滚该次优化 |
| 强度门禁 | 优化侧 | `real` 用例数不下降 | 回滚 |
| 复现门禁 | 核对侧 | 同一模式 ≥2 次独立 run 才立规则 | 继续采集证据 |

---

## 判定强度：最容易漏掉的一道

| 强度 | 含义 |
|---|---|
| `real` | 真校验了作答内容 |
| `structural` | 只校验协议与结构 |
| `none` | 没校验 |

**任何一轮都没有 `real` 用例时，必须写明"本次评测不代表能力水平"。**

判据：**交付看留出集 + 强度**；**发布只看 `composite_100`**。两件事，两个答案。
