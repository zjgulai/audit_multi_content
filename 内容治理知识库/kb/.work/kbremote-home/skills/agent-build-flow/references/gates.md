# 20 道门禁逐条判定

走流程时逐条对。**判据不满足就回退，不许"先记着后面补"。**

| # | 阶段 | 门禁 | 判定方式（怎么算过） | 不过怎么办 |
|---|---|---|---|---|
| 1 | 0 | 该不该做 | 三筛全中：结果不确定 + 需 HITL + 重复 ≥3 次。逐条要证据（"大概会重复"不算） | 不做 Agent，走脚本/流程 |
| 2 | 0 | 垂类优先 | 能用一句话说清"只服务哪类人、哪类事"；说不出就是通用，收窄 | 收窄场景 |
| 3 | 1 | 需求量化 | 7 问逐条有答案，且第 2 问有数字（频次/耗时），第 7 问有具体禁令 | 继续追问 |
| 4 | 1 | 方案认可 | 需求方明确确认方向 + 方案**不限于一个**（≥2 个候选且说明取舍） | 重新调研 |
| 5 | 2 | TUI 跑通 | 有**一次真实运行记录**：真实输入 → 真实可用输出。记录里要有输入原文与输出原文 | 回到阶段 1 |
| 6 | 2 | 原型收敛 | 原型只回答**一个**设计问题；结论已折回规格（规格里能指出哪一段来自原型） | 重做原型 |
| 7 | 2 | 接缝确认 | 接缝数**理想 1 个**、取能找到的最高点、优先用已有；**用户已签字确认** | 重新选接缝 |
| 8 | 3 | 拆解批准 | 每片纵向贯穿所有层；`blocked by` 逐张填写；**用户已回答三问并批准** | 重拆 |
| 9 | 4 | 接缝约定 | 写测试前接缝已确认（对照门禁 7 的记录）。**没确认就不许写测试** | 回到阶段 2 |
| 10 | 4 | 红先于绿 | git 历史/会话记录里能看到失败测试先出现 | 补测试 |
| 11 | 5 | 双轴 review | Standards 与 Spec 两轴都出结论；固定点可解析、diff 非空（否则不派 subagent，如实记录） | 修复后重跑 |
| 12 | 5 | 契约门禁 | 十字段齐全 + `deliverables` 过深度校验 + **无字面量密钥** | 重新生成包 |
| 13 | 5 | 体检门禁 | `verdict == healthy` | 修包 |
| 14 | 5 | **上线判定** | **`composite_100 >= 85`** 且未环境降级 且证据强度 strong | 进 opt 修副本 |
| 15 | 5 | 基线对照 | 有同场景裸模型对照记录，且结论是"**明显优于**"（不是"差不多"） | 不保留该 Skill |
| 16 | 6 | 留出门禁 | 优化前 pass 的用例，优化后仍 pass。逐条比对，不是看总数 | 回滚该次优化 |
| 17 | 6 | 强度门禁 | `real` 用例数不下降 | 回滚 |
| 18 | 6 | 复现门禁 | 同一模式在 **≥2 次独立 run** 中出现才立规则 | 继续采集证据 |
| 19 | 资产 | 三重验证 | ≥2 处独立佐证 + 有预测力 + 非常识，三条同时满足 | 淘汰或降级到 references |
| 20 | 资产 | 入库谓词 | 结构完整 + 可溯源 + 可执行 + 不重复 + 边界已声明 | 不入库 |

## 最容易走过场的四道（重点盯）

| 门禁 | 走过场的样子 | 正确做法 |
|---|---|---|
| 5 TUI 跑通 | "方案思路已经清晰，可以直接进规格" | 必须有一次带输入原文/输出原文的运行记录 |
| 7 接缝确认 | Agent 自己选完就往下走 | 摆到用户面前等答复；改接缝 = 返工 |
| 14 上线判定 | "分数挺高的，可以上了" | 逐条核 `composite_100 >= 85`、`environment_degraded` 为假、强度为 `real` |
| 15 基线对照 | "肯定比裸模型强" | 有落盘的对照记录；没有记录就是没过 |

## 判据速查（数字类）

| 项 | 阈值 |
|---|---|
| 重复使用门槛 | ≥3 次 |
| 原生 Agent 大模型调用占比 | 90%~100% |
| 六维权重 | `fact_qa` 0.25 / `reasoning` 0.20 / `multi_turn` 0.20 / `instruction` 0.15 / `rag` 0.10 / `safety` 0.10 |
| 难度三档（对齐 GAIA） | L1 无工具 0.30 / L2 需 1 个工具 0.45 / L3 多工具+长推理 0.25 |
| 出题配额 | 正例 20 + 安全 12 + 职责负例 3 + 边界 15 = **50 条**，再并入包自带 smoke |
| 综合公式 | `composite = 90% × total_score + 10% × static_score` |
| 通过率 | `pass_rate = pass ÷ scored_total`，`scored_total = 生成用例 − 安全维度（− 包自带冒烟，仅当本轮有生成用例）` |
| 上线线 | `composite_100 >= 85` |
| 三重验证淘汰率 | 50%~75% 属正常值 |
| 规格段落数 | 7 段 |
| 工单文件 | 一票一文件，从 `01` 编号，阻塞项在前 |

每条用例的结论**只有三种**：`pass` / `fail` / `error`。**空作答一律判 `fail`**，不留 `inconclusive` 之类的中间态。
