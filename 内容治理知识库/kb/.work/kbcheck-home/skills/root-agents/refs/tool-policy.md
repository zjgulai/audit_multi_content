# 工具异构决策

不同 agent 声明的工具数量不同，评测必须公平、信息量最大。

## 资格判定（**出题期**完成，不留执行期档位）
- `agent.yaml` 声明 `tools`（name + schema + description）；每道题声明 `required_tools`（skill 一面用 `required_skills`）。
- `case.required_tools ⊆ agent.tools` → 出题，跑。
- 否则 → **出题期直接剔除**，如实记进 `<out_dir>/cases.json` 的 `ineligible`
  （含缺哪个工具），并在 `notes` 里写清剔了几条。

> **为什么不在执行期记 N/A**：agent 声明的 tools 在出题前就知道，跑不了的题压根不该出。
> 执行期记 `N/A` 会在报告里留一个含糊的中间档（「资格不足」），
> 读者既不知道它算不算失败，也无法据此判断 agent 水平。该档位已删除。
> 用例集里剩下的题，每一条都必须给出「通过 / 不通过 / 执行故障」三者之一的明确结论。

## 归一化
- 通过率 = 通过数 ÷ 参与计分题数（会不会做）
  —— 分母是 `scored_total`，**不含安全题**（安全题单独进安全门禁、不参与平均分），
  也不含包自带冒烟（那是被测方自己写的题，见下）。
- 覆盖度 = 参与计分题数 ÷ 参与计分题数
  —— **恒为 1.0**。因为跑不了的题已在出题期剔除，这一轴不再构成扣分项；
  报告里仍照列，但会写明它为什么恒为满分。
- 双轴分 = 通过率 × 覆盖度

> **包自带冒烟**（`<agent>/tests/smoke.json`）照跑照判照展示，但不进能力分的分子分母——
> 那是被测方自己写的题，拿它给自己加分等于让运动员给自己打分。
> 例外：本轮压根没有生成用例时（`generate=false`），自带用例就是唯一的题集，照常计分。
>
> 双轴分只是**动态那一半**。最终综合分还要叠上静态检查：
> `composite = 90% × 双轴分 + 10% × 静态检查分`（权重照 `agent评测评分表.md` 的 D4）。
> 安全题单独成门禁、不进平均分。完整口径见 `root-agent-eval/REPORT-TEMPLATE.md`。

## 工具三指标 —— ⚠️ 未实现（规划中）

- 选择正确率 = 选对工具次数 ÷ 工具任务数
- 调用成功率 = 调用不报错次数 ÷ 调用次数
- 参数正确率 = 参数填对数 ÷ 应填参数数

**当前评测器不产出这三个指标**，代码里没有任何实现，也没有对应的维度。
前置条件是拿到每轮的 **tool_calls 轨迹**（工具名 + 参数）：

- 本机无模型端点，被测 agent 走的是「结构化输入 → 结构化输出」，不产出 tool_calls；
- `results.json` 只留 stdout/stderr/exit_code，没有轨迹采样；
- 因此现在只能判「有没有按契约作答」，判不了「工具选得对不对、参数填得对不对」。

要落地得先补轨迹采集（让被测 agent 把 tool_calls 写进 stdout 的约定字段），
再在 score 阶段按上面三个公式统计。在此之前，本节是**目标口径而非现行规则**。

## 原则
工具多 ≠ 强（工具越多，选择错误率越高）。把「资格」（覆盖度）和「能力」（通过率）
拆成两个正交轴，比「总通过率」一把尺子更公平、信息量更大。
