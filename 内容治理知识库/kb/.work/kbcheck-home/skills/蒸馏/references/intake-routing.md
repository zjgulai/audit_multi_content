# 入口四档路由：素材先分流，再决定蒸不蒸

> 来源：Kb2Agent（MKD）Stage 0–2 的「输入诊断器 + 类型路由」，按本技能六阶段主干裁剪。
> **用途**：把「值不值得蒸」升级为四档——**该蒸的蒸，该缓存的缓存，该回人的回人，该扔的扔**。

---

## 为什么要有这一档：知识库不是越多越好

三条被反复验证的反模式（照抄 Kb2Agent 导论的五反模式，只留与本技能相关的三条）：

| 反模式 | 信号 | 本技能怎么办 |
|---|---|---|
| **把实时数据入库** | 素材里大量字段 48 小时内就变（库存、价格、当日投放） | 走 **CACHE 档**：不产出 SKILL.md，只留指针与查询接口 |
| **把规则系统做成概率题** | 规则清晰、输出可枚举（退款政策、资质清单、合规检查项） | 走 **CACHE/SKIP**：交给规则引擎或表格，别蒸成要靠模型"重新理解"的 Skill |
| **为感觉先进而蒸** | 素材只用一次、查不到第二次 | 走 **SKIP**：一次性的东西记笔记就够 |

---

## 四档判据（先判档，再动手）

| 档 | 触发条件（满足任一条） | 动作 | 产物 |
|---|---|---|---|
| **SKIP** | 来源不可信（匿名转述、无出处截图）／判断密度 < 0.2 条/千字且验证成本高／一次性事件 | 停下，说明理由 | **不产出任何文件** |
| **CACHE** | 素材半衰期 < 7 天（实时运营数据）／规则清晰且输出可枚举 | 不蒸 Skill，改为**留指针**：写清"去哪查、用什么接口查" | 一行指针 + 查询方式 |
| **PROCESS** | 会重复（≥3 次）+ 有判断（"遇到 X 先看 Y"）+ 裸模型做不好 | 走六阶段主干 | SKILL.md + references + tests |
| **ESCALATE** | 素材完整度 < 0.4（缺关键段、缺说话人、缺上下文）／判断必须由人拍板（口径、红线、承诺） | 回人：列出缺什么、要谁定 | 缺口清单（不猜、不补编） |

**半衰期**：看最关键字段多久变一次；变更周期短于你重建 Skill 的周期 → 默认 CACHE。
**完整度**：素材要覆盖「触发条件 + 判断 + 边界」；缺一件 0.67，缺两件 0.33；低于 0.4 直接 ESCALATE。

---

## 蒸馏类型路由（PROCESS 档内部再分一次）

同一份素材常混编，**按段落路由**：

| 段落类型 | 走哪条路 | 产物形态 |
|---|---|---|
| 方法论 / 流程 / 判断 | RIA++ → SKILL.md | 触发条件 + 执行步骤 + 边界 |
| 稳定事实 / 术语口径 | 事实条目（不写进 SKILL.md 正文） | 带出处的原子事实，进 references |
| 规则明确的判定 | IF-THEN 规则表 | 可枚举、可校验的表格 |
| 某人 / 专家的判断 | 人格克隆（**只取决策框架**） | 决策模型，不模仿语气 |

**未知类型默认按"事实"处理**——宁可不蒸，也别硬套。

---

## 与三筛的关系

三筛是 **PROCESS 档的内部条件**，不是入口的全部：先四档分流，进了 PROCESS 才用三筛逐条卡；不过 → 退回 SKIP。

---

## 十类素材 → 入口档映射（含本机能力实测）

用户常问「这些都能蒸吗」。**能蒸 ≠ 现在就能拿到文本**——下表「前置」列写清要谁补齐什么。

| # | 素材形态 | 档 | 走哪条路线 | 前置条件 / 本机现状 |
|---|---|---|---|---|
| A | PDF / 书籍 / 论文（含图表公式） | PROCESS | 论文·长文档 | **需先转文本**。本机无 `pdftotext` / `pypdf` / `MinerU`；朴素复制会丢表格与公式 → 让素材方给可复制的正文或已转好的 md |
| B | YouTube / B站 / 本地教程视频 | PROCESS | 逐字稿·音视频 | **需 ASR 或字幕**。本机无 `ffmpeg` / `whisper` → 要字幕文件或逐字稿 |
| C | 播客 / 会议录音 / 有声书 | PROCESS | 逐字稿·音视频 | 同 B，需转写文本 |
| D | 博客文章 / RSS / Twitter Thread | PROCESS | 长文档 | ✅ 有 URL 即可直接抓 |
| E | GitHub 仓库 / API 文档站 | PROCESS | 工程操作蒸馏 | ✅ 可读可跑；**代码字段必须真跑过** |
| F | 某位专家 / 同事 / 公众人物的经验 | PROCESS | 人格克隆 | ✅ 只要有文本；**要 ≥2 处跨场合原话**，否则全判 review |
| G | Excel / 数据库 / API 数据 | **分裂** | 稳定口径 → PROCESS；实时数据 → CACHE | ✅ Excel 可读（openpyxl）；实时字段只留指针 |
| H | 架构图 / 流程图 / UI 截图 | PROCESS | 白板路线（简化） | ✅ 可直接读图；**认不准的字必须标注，不许猜** |
| I | 会议录音 / 直播 / 在线课程 | 录音同 C；**直播 → SKIP** | 逐字稿·音视频 | 直播是一次性的，不蒸 |
| J | BI 看板 / SPA / WebGL 动态内容 | **多为 CACHE** | — | ✅ playwright 能渲染抓取；但看板数字是实时事实 → 只留查询方式；**看板口径/指标定义**才值得蒸成判断 |

**一句话**：A/B/C/I 卡在没有解析链，得先有文本；D/E/F/H 直接能蒸；G/J 先判是「稳定口径」还是「实时事实」——后者不该入库。
