# 自我蒸馏路线：把「你自己说过的话」压成 agent 能遵守的规则

> **何时走这条路**：用户说「蒸馏自己 / 重新蒸馏我 / 蒸馏我 / 更新一下你的模型 / 再蒸馏一次 / 跑一遍蒸馏」，或明确要蒸**本人的会话记录**。
> 素材是**本机会话归档**（DSH + Codex），不是别人给的文件。

---

## 一、产物是四层，不是一篇传记

| 层 | 回答什么 | 判据 |
|---|---|---|
| **L1 事实上下文** | 他在做什么、在什么环境里 | 环境、路径、术语、在跑的项目 |
| **L2 决策标准** | 遇到 X 时先看 Y | 可执行的判断，不写「要注意」这类没法判的句子 |
| **L3 表达风格** | 他会怎么说（不是他是个什么人） | 长度、句式、标点、禁用词——规则可执行，原话只当例子 |
| **L4 反模式** | **被激怒时他会说什么** | 一句可执行的禁令，不照抄原话 |

**判断标准只有一条**：读完四份文件，一个 agent 应该知道——跟这个人打交道时什么绝对不能做、什么算做得好、他会怎么说、他在做什么。

---

## 二、四条硬约束（违反一条整轮白做）

1. **每条规则必须有证据引用**：写 `会话id#seq`，能点回原始那句。**宁可少给规则，不可编造证据。**
2. **不照抄原话，抽象成可执行的规则**：「你去读文档，不要这么蠢」→「不要在没实际读取内容的情况下下结论」。
3. **单次推断不进产物**：只出现一次的，留在 `candidates/`。
4. **L4 不是行为预测器**：它回答「被激怒时他会说什么」，**不是**「他什么时候会发怒」。实测拿它猜下一句，11 条里 8 条猜成「要发火」，而真实纠错只占 2~3 条。

---

## 三、四步流程（A/D 脚本，B/C 必须真读语义）

| 步 | 谁做 | 干什么 |
|---|---|---|
| **A 确定性采集与提纯** | 脚本 | `~/self-distiller/run-a.sh`：S1/S1b 采集 → S2 三级过滤 → S3 规则法打标 → S6a 表达统计 → S4 聚类 → S8 留出集 |
| **B 语义复标** | **LLM** | 给 `data/labeled.jsonl` 逐条判 `category`（8 类）与 `e_level`（E1/E3/none），产出 `data/llm_labels.jsonl` → 重跑 S4 让并集生效 |
| **C 语义提炼** | **LLM** | 从 `data/clusters_eligible.json` 提炼四层产物，写进 `distilled/` |
| **D 校验与导出** | 脚本 | `~/self-distiller/run-b.sh`：S6 防幻觉核对 → S7 导出到桌面 |

**解释器只能是 `~/.local/bin/python3.12`**（本机 `python3` 是 Xcode 空壳、`node`/`zstd` CLI 不可用）。

**B/C 与跑脚本的区别就在这**：脚本只能机械过滤；哪句话重要、哪个模式成立，必须真读语义。

---

## 四、闸门（不过就停，先修再往下）

| 阶段 | 判据 |
|---|---|
| S1 | 会话索引 ≥ 413；raw_msgs ≥ 3063 |
| S1b | Codex rollout ≥ 27；raw ≥ 129 |
| S2 | 保留条数落在阈值区间内（**上界随笔数窗口增长调整，见脚本注释**）；**长度中位数 < 80** |
| S6 | 所有证据引用有效；0 编造；0 错引 |

**长度中位数是最灵敏的探针**：真人发言中位数约 25 字符，agent 代发的 prompt 约 151 字符。一旦超过 80，说明来源过滤漏了子代理。
**上界不是探针**——语料条数随采样窗口变长自然增长，每次调整都要在脚本注释里写明理由与复核证据。

---

## 五、六个必须避开的坑（都真踩过）

1. **密钥会随被拒内容落到磁盘**：被拒消息全文默认落盘，实测有含真实 API 密钥的被拒消息 → 三个落盘点都必须先 `redact_secrets()`。**写入时脱敏，不能等输出时想起。**
2. **跨会话去重会毁掉最值钱的证据**：本人爱重复同一句话（「继续执行」跨 16 个会话），这些重复**正是 E2「重复行为」的来源** → **绝不按文本去重**。
3. **规则法抓不住没有否定关键词的纠错**：实测规则法与 LLM 的类别一致率只有 53.5%、E3 的 Jaccard 只有 42% → E3 取**并集**。
4. **子代理会去翻答案**：留出法回测时，作题文件不得出现 `actual` 字段、同一会话只放一道题、并检测「预测与答案精确相同且上下文里从未出现」。
5. **校验器自己也会错**：S6 曾报「267 条引用全部不存在」，真相是它按 sid 后 12 位建索引、而引用写的是前 6–8 位。**一个校验器报 100% 失败，先怀疑工具。**
6. **别把 L4 当预测器**（见上文约束 4）。

---

## 六、落点与交付

| 位置 | 内容 |
|---|---|
| `~/self-distiller/distilled/` | 四份规则文件（正式产物） |
| `~/self-distiller/data/` | 中间数据：语料、标签、证据簇 |
| `~/self-distiller/reports/` | 表达统计、校验明细、运行报告 |
| `桌面/自我蒸馏-*` | 给人读的单页入口 + 四份 md |

**汇报只报四项**：闸门实测数字 / 语料量（DSH+Codex，提纯率）/ 产物（四层各多少条、多少证据引用）/ 与上一版比变了什么。**不要铺开过程。**

**最容易出错的地方**：规则若被浓缩进某个 agent preset 的 persona，那份副本是**某一版的快照**；重新蒸馏后必须手动同步，否则 agent 读文件拿到的是新版、内嵌清单还是旧的。
