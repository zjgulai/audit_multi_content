# 裸模型对照：怎么证明这个 Skill 有价值

## 一、为什么必须做

这是整套体系的**验收根**。没有对照记录，就只是"我觉得它有用"。

> 「如果你觉得它没有 skill 跑得比你还好，那你这个 skill 就是废物，就是在降质。」

**对照结论只有三种**：明显优于 / 差不多 / 更差。**"差不多"= 不保留。**

---

## 二、怎么做（五步）

### 1. 选同一批真实场景问题

- 用**真实业务问题**，不要自造
- 条数：**至少 5 条**，能到 10 条更好
- 必须包含：**2 条正例**（Skill 该处理的）+ **1 条边界**（该不该触发说不清）+ **1 条诱饵**（看着像但不该触发）

### 2. 裸模型跑一遍，记录输出

```
把问题原文丢给裸模型（不带任何 Skill、不带系统提示里的相关规则）
记录：完整输出原文 + 耗时 + 是否稳定
```

### 3. 带 Skill 跑一遍

同样的问题，同样的话术，带上 Skill 再跑一次。

### 4. 对比两个维度

| 维度 | 怎么看 |
|---|---|
| **输出质量** | 是否命中本业务的判据/边界/术语（不是"读起来更好"） |
| **稳定性** | 同一问题跑 2~3 次，结论是否一致 |

**稳定性常被忽略，但它是 Skill 的主要价值来源**——裸模型经常每次答得不一样。

### 5. 落盘

对照记录是**交付物的一部分**，跟 SKILL.md 一起给。表模板见 `assets/templates/distill-log.md`。

---

## 三、怎么问裸模型才公平

| 要做的 | 不要做的 |
|---|---|
| 用真实用户会说的原话问 | 把你的 Skill 内容塞进提问里 |
| 不加"请按某方法论回答" | 诱导它说出你想要的答案 |
| 每个问题独立问，不带前文 | 连续追问把答案喂出来 |
| 记录首次回答 | 挑最好的一次回答 |

**不公平的对照比不做更糟**——它会让你误以为 Skill 有效。

---

## 四、"非常识"判据的实测用法

三重验证第三条（非常识）要求**实测**。做法：

```
把候选判断改写成问题，问裸模型：
  "遇到 X 的时候应该先做什么？"

裸模型答得出 → 非常识不成立 → 淘汰
裸模型答不出，或答的是通用道理 → 非常识成立 → 可进正文
```

### 示例

| 候选判断 | 问裸模型 | 判定 |
|---|---|---|
| 遇到模糊需求要先追问 | "做 Agent 前该怎么处理模糊需求？" → 它说"先澄清需求" | **同质化，淘汰** |
| 先用 TUI 跑通再补 PRD | "做 Agent 时 PRD 什么时候写？" → 它说"先写 PRD 再开发" | **反共识，保留** |
| 淘汰率 50%~75% 是正常值 | "蒸馏知识时淘汰多少算正常？" → 它给不出具体区间 | **私有数据，保留** |
| 接缝数理想是 1 个 | "测试接缝该设几个？" → 它说"视情况而定" | **有预测力，保留** |

## 五、对照结论怎么记

| 结论 | 判定条件 | 动作 |
|---|---|---|
| **明显优于** | 质量维度命中数 ≥ 裸模型的 1.5 倍，且稳定性更好 | 保留，可核算"质量倍数" |
| **差不多** | 命中数接近，稳定性也无差别 | **不保留**：合并进已有 Skill，或丢掉 |
| **更差** | 带 Skill 反而答偏 | 检查是不是规则把模型带偏了；改不改都不成立就丢 |

---

## 六、Skill 池规模化之后

Skill 池到 **2000+ 规模后**，做**组合测试减资**：

- 找出触发场景重叠的 Skill 对
- 对重叠对做对照：两个都要，还是一个就够
- 剔除冗余与降质项

这一步不归本技能管，但**蒸的时候就要为它留证据**——所以对照记录必须落盘、必须可复算。
