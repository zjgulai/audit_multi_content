# RED 基线：无该 Skill 时，agent 会怎么错

> **性质**：真实运行记录，不是事后补写的说明。
> **取证方式**：把下面 6 条真实用户原话发给一个**未加载任何技能包**的通用 agent，
> 按它的默认理解直接作答，记录它的第一动作、是否做淘汰判断、是否要求出处。
> **取证时间**：2026-09-15　**原始输出**：`red-out-rts.json`（同目录）

## 二、逐条判定：裸模型错在哪

**判定口径**：不看它"有没有要材料"（那是尽职，不是本 Skill 的价值），而看它**有没有做三重验证与取舍**。

### R1 —— 直接把素材抄成了 Skill，没有过闸门 ★核心失败

题面里已经把纪要内容给全了，所以它不需要索要材料——**它直接起草了 SKILL.md**。

这是本 Skill 要拦的头号错误：**"把纪要转成一份 skill 文档" ≠ 蒸馏**。它跳过了：

- **五路并行提取**：没有区分框架 / 原则 / 案例 / 反例 / 术语，直接把三条规则平铺
- **三重验证**：没有问"这三条各自有几处独立佐证？""能回答素材没明说的新场景吗？""裸模型自己说不说得出来？"
- **淘汰**：它一条没丢。按正常区间**应该有 50%~75% 被淘汰或降级**——三条规则原样进正文，说明淘汰率 0%
- **出处**：没有要求"张工说的"与"会上共识"分开标注——而题面里"张工说导出的验收要逐字段对齐"恰恰是**单一说话人**，佐证只有 1 处，本该进 `review` 档而不是直接进正文

**失败类型**：产出的是文档，不是 Skill；淘汰率为 0，等于没筛。

### R2 —— 方向对，但没有闸门

它索要原文，且表示会做取舍并要求出处——这是常识级尽职。

- 但它不会给出**具体判据**：≥2 处**互不依赖**的佐证（要跨章节/跨时间戳，同一段说两遍只能算一处）、有预测力、非常识——三条缺一就淘汰或降级。
- 也不会说"淘汰率 50%~75% 属正常，**低于 30% 说明放水了**"，更不会说"判断密度 < 0.3 条/千字就该放弃蒸馏"。
- 题面里那两条（东八区、默认值同步改）它看不出"**非常识**"这一条有多强——而这两条恰恰是裸模型答反的地方。

**失败类型**：判断停在"我会小心的"，没有可判定的闸门。

### R3 —— 选错了产物形态（本属近似命中）

用户要的是**洞察报告**（有结论和引用的文档），不是 Skill。

- 裸模型去索要访谈原文——动作不算错，但它**没有识破"这是一份报告，不是一次蒸馏"**。
- 本 Skill 的判据：**只抄结论不抄判断，换场景立刻失效**；报告是结论的堆叠，Skill 要的是"遇到 X 先看 Y"。
- **失败类型**：把"整理成文档"当成了"蒸馏"，产物形态选错。

### R4 —— 路由错了（本属排除项）

"蒸我自己说的话"要的是**行为规则**，产物是四层行为规则，不是可路由调用的 Skill。

- 裸模型很自然地就去读会话记录了——**它没有意识到这里有个专门的 skill（`self-distill`）**，也不理解"人格克隆只取决策框架、不模仿语气"这条纪律。
- **失败类型**：路由误判，产出形态与需求不匹配。

### R5 —— 越界（本属排除项）

"评哪些该淘汰、按质量打分"是**评测**，不是蒸馏。

- 裸模型去列 skill 条目准备打分——它不会知道评分口径归 `root-skills-eval`，更不会知道本 Skill **明确不评分**（"本技能只产出候选，绝不重造第二套评测标准"）。
- **失败类型**：把评测任务当成蒸馏任务，会造出与家族打架的第二套标准。

### R6 —— 又把固定动作直接落成了 SKILL.md，没有过闸门 ★核心失败

和 R1 同型，但素材类型不同（这次是"走了两年的固定流程"）。

- 它直接产出"触发场景 + 步骤 + 产出物"——**这是流程说明，不是判断集**。
- 题面里真正值钱的判断它没提取出来：**"超过三条的项目单独拎出来"** 是一条带**量级阈值**的判断，而"每条必须落到一个人头上"是一条**准出条件**。裸模型把两者都压平成了"步骤"。
- 它也没问：这个阈值 3 是怎么来的？有没有数据支持？**没有数据支持的阈值写进 Skill 就是把未经检验的数字固化成团队标准**——这正是八条反模式里的一条。
- **失败类型**：流程 ≠ 判断；未经验证的阈值被固化。

---

## 三、结论

**6 条里 6 条都在关键判断上偏离**，其中：

| 失败类型 | 条数 | 对应本 Skill 的哪条规则 |
|---|---|---|
| 直接抄成 Skill、淘汰率 0 | 2（R1、R6） | 三重验证 + 六阶段 + 八条反模式 |
| 缺可判定的淘汰闸门 | 1（R2） | `triple-verification.md` 三条判据 + 淘汰率区间 |
| 产物形态选错（要报告） | 1（R3） | 判断 vs 事实切分 |
| 路由误判（该走 self-distill） | 1（R4） | description 不适用边界 |
| 越界（该走 root-skills-eval） | 1（R5） | 不评分边界 |

**最能说明问题的是 R1 与 R6**：这两条题面**材料给全了**，所以裸模型不需要索要材料，
于是它的默认路径就是"**把素材转写成一份结构化文档**"——而文档正是本 Skill 要拦的东西。

> 对应 Release 清单第 3 项：**创建时留下了可重复的 without-skill 失败基线**。
> 复现方式：把 `red-inputs-rts.json` 的 6 条提示词发给任意未加载本技能的通用 agent，对照上表核对。
