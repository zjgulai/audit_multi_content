# RED 基线：无该 Skill 时，agent 会怎么错

> **性质**：真实运行记录，不是事后补写的说明。
> **取证方式**：把下面 6 条真实用户原话发给一个**未加载任何技能包**的通用 agent，
> 按它的默认理解直接作答，记录它的第一动作与是否做前置验证。
> **取证时间**：2026-09-15　**原始输出**：`red-out.json`（同目录）

## 一、原始记录

| # | 用户原话（节选） | 裸模型第一动作 | 有无前置验证 |
|---|---|---|---|
| R1 | 做个品牌问答智能体，**先帮我写一份 PRD**，写完再开发 | 先问澄清问题（要 10 条真实问题 + 语料/权限边界），**不直接开写文档** | 是 |
| R2 | 客服智能体做得差不多了，**你看能不能上线**？ | 先要验收证据（测试集通过率 + 失败样例），不给结论 | 是 |

## 二、逐条判定：裸模型错在哪

**判定口径**：不只看"它有没有做对常识动作"，而看它**有没有做出本 Skill 固化的那些判断**。

### R1 —— 错在顺序：把"先写 PRD"当成了起点

用户明说"先写 PRD，写完再开发"，裸模型的第一动作是**继续追问需求**——听起来负责，但方向错了。

- 它接受的前提是"**先有文档，再验证可行性**"。本 Skill 的判据相反：**先用 TUI + 通用 Agent 把问题真解决一次，拿到真实可用的答案，再逆推工作流、最后才补规格**。
- 裸模型不会告诉你"PRD 不必前置"，也不会要求"没跑通过不给进下一阶段"。
- **失败类型**：跳过前置验证，把一个尚未被验证的方案往文档阶段推。

### R2 —— 错在判据：问对了方向，但没有判据

它要了"测试集通过率 + 失败样例"——这是常识级的尽职。

- 但它给不出本团队的**上线线**：`composite_100 >= 85`、未环境降级、证据强度 `strong`、且**同场景明显优于裸模型**。缺任一条都不放行。
- 它也不会提"判定强度 `real` / `structural`"的区别，更不会说"任何一轮都没有 `real` 用例时必须写明本次评测不代表能力水平"。
- **失败类型**：判断停在"看起来靠谱"，没有可判定的门禁。

### R3 —— 错在数活儿：把工具和回执都算成了"活"

它给出的清单是**答案卡片 / 拒答回执 / 检索日志**三件。

- 按本 Skill 的判据，**交出去的东西不一样才算两件活**。检索日志是过程产物、拒答回执是行为约束的副产物，把它们算成独立交付物会让"这个 agent 能干几件活"虚高，直接导致评测出题范围和职责负例对不上。
- 裸模型也没有 `len(deliverables)` 这个概念，不会要求"每件活都要能写出一条工作流（输入 → 步骤 → 交付物）"。
- **失败类型**：交付物定义虚高，业务方对齐的和实际评测覆盖的不是同一批东西。

### R4 —— 错在拆法：给的是横向分块，不是垂直切片

"分块拆解草案（含风险点与验收物）"是**按模块/层级**分的，典型横向切片。

- 本 Skill 要求**垂直切片**：每一片纵向贯穿所有层、一片做完就能独立演示、体量塞得进一个全新上下文窗口，且**每张工单必须声明 `blocked by`**。
- 横向切片的后果做过的都知道：进度不可见，到集成那天才发现问题。
- **失败类型**：拆解粒度错，返工成本到阶段 4 才暴露。

### R5 —— 部分做对，但仍缺判据

它要了真实数据再搭链路——方向对。

- 但"从头做出来"这五个字它没有拆成**七阶段 + 20 道门禁**，也不会在四个点停下来等用户拍板（需求方向 / 接缝 / 拆解粒度 / 上线判定）。
- 特别是**接缝**：本 Skill 要求"理想 1 个、取能找到的最高点、优先用已有，且必须在写规格时和用户确认"。裸模型完全不会提这件事。
- **失败类型**：流程能走个大概，但最贵的那几个决定（接缝）没人把关。

### R6 —— 错在越界：直接答应给"成品包"，不问该不该做

用户要 demo，它就准备给最小可运行包。

- 本 Skill 的第一步是**入口三筛**：结果是否不确定 / 是否需要人在回路 / 是否会重复（≥3 次）。**三条全中才做 Agent**；不中就该走脚本、规则引擎或表格。
- 而且默认取向是**垂类优先**，不做通用。裸模型不会拦这一下。
- **失败类型**：用户说做就做，做出来解决的可能根本不是该用 Agent 解决的问题。

---

## 三、结论

**6 条里 6 条都在关键判断上偏离**，其中：

| 失败类型 | 条数 | 对应本 Skill 的哪条规则 |
|---|---|---|
| 跳过前置验证（TUI 先行） | 1（R1） | 阶段 2 反共识规则 + 门禁 5 |
| 缺可判定的上线门禁 | 1（R2） | 门禁 14/15 |
| 交付物虚高（数活儿） | 1（R3） | `deliverables-rules.md` |
| 横向切片而非垂直切片 | 1（R4） | `seams-tickets.md` 四规则 |
| 接缝无人把关 | 1（R5） | 门禁 7 + `seams-tickets.md` |
| 不做入口三筛就动手 | 1（R6） | 入口三筛 + 垂类优先 |

**关键判断是本 Skill 的存亡依据**：R1/R2/R5/R6 的裸模型回答**读起来都挺像样**——
会追问、会要证据、会要数据。但它们在**判据层**全部缺失。这正是 `SKILL.md` 存在的理由：
不是教模型"要谨慎"，而是给它一组**可判定的门禁**，让"像样"变成"过得了"。

> 对应 Release 清单第 3 项：**创建时留下了可重复的 without-skill 失败基线**。
> 复现方式：把 `red-inputs.json` 的 6 条提示词发给任意未加载本技能的通用 agent，对照上表核对。
