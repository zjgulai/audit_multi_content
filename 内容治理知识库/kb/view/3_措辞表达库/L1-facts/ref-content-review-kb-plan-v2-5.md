## 二、两条被点名要记的建议（逐字摘录 + 原文条件）

### 2.1 「遇到 BLOCK 可以直接返回」——原文的确切条件

> `#L99`（§3.1 链路）：`P0 命中 → 立即 BLOCK（红线零延迟，不等其余层）`
> `#L131`（§3.2 关键②）：`P0 命中时结论可立刻返回 BLOCK（红线零延迟），其余层结果收齐后再并入问题清单`
> `#L210`（§4.4 SLA）：`BLOCK | P0 | **立即** | 超时升级到 项目统筹 + 内容提交方`

**⚠️ 不能简写成「命中 BLOCK 就直接返回」——原文自带两条硬前提：**

1. **只有 P0（法务红线）能零延迟直返**，且是**知识库侧的确定性匹配**（词表／正则／变体，毫秒级）。
   > `#L51`：`BLOCK | 命中明确红线 | P0 确定性命中即 BLOCK；模型侧单轨命中**不得单独定 BLOCK**`
2. **画面类问题不得单独定 BLOCK**（因为给不出逐字摘录）。
   > `#L170`：`视频画面类问题（危险动作/构图/肖像）没有逐字摘录，只能给「帧锚点 + 画面描述」，据此只能判 REVIEW、不得单独定 BLOCK`
3. P0 层**不适用置信度分流**（其余层适用）。
   > `#L58`：`≥0.90 直接输出结论（PASS/BLOCK）；0.70–0.89 → REVIEW「建议人工确认」；<0.70 → REVIEW「不确定，重点人工看」；**P0 层级不适用置信度分流，命中即 BLOCK**`

### 2.2 「模型和知识库一起跑」——原文叫「双轨校验」

> `#L131`（§3.2）：`① 四层同时启动，每层「知识库侧 + 模型侧」同时跑，**互不等待；层内两侧也不互相等待**；…… ③ **没有主判与辅助之分**——每层的两侧都是完整的一遍审查，各自出问题清单，结论在最后一步按「同一问题取交集、不同问题走并集」合并（对齐判据：位置相同 + 类目相同 → 视为「同一个问题」）`
> `#L98`：`知识库规则作为上下文喂给模型，做二次合规校验`

四层各自跑什么（`#L124-129` 原表）：

| 层 | 知识库侧（带条款号+锚点+指纹） | 模型侧（带位置+理由，无库内依据） |
|---|---|---|
| **P0** 法务合规红线 | 词表／正则／变体**确定性匹配**，命中即 BLOCK（毫秒级）；每个词有出处（逐字源/规则原文/等价写法三选一） | 语义边界核查：等义句、英文屈折形态、连字符变体（`FDA-approved`）、隐含声称 |
| **P1** 安全与准确性 | 外部标准条款、产品描述库边界规则 | 危险示范、使用姿势、功能越界；抽奖要件／价格标注／命名规范／产品边界 |
| **P2** 通识与常识 | 内部正负样本（案例参照） | 多模态推理：画面／构图／水印／肖像／比例、场景合理性 |
| **P3** 措辞与表达 | Do not say / Say this instead 词表 | 语境判断并给替代表达建议（不改变主结论） |

**配套四态语义**（`#L45-58`）：PASS 的唯一成立方式 = **两侧都覆盖到该主题且都没发现问题**；两轨冲突降 REVIEW；**拒答不是第四态，是「没有结论」**（任一侧没覆盖即拒答，**不得输出 PASS**，且必须给检索轨迹）。两条铁律：**拒答 ≠ 放行；没命中 ≠ 合规。**
**总纲**（`#L56`）：`本 Agent 输出的是预审结论，PASS / REVIEW / BLOCK 最终都需人工确认后生效——不存在「自动放行」的内容类型。`

## 三、其余可复用的设计决策（§9 共 11 条，`#L386-465`）

| # | 决策 | 原文给出的理由/验收（要点） |
|---|---|---|
| 9.1 | **拒答只能建在消费侧** | 索引层永远给结果（L6 实测 B 组三种模式 `hit@3` 全 0 却都返回 Top3）；成为**依据**必须**同时命中规则层** |
| 9.2 | 画面类零覆盖**只能蒸，不靠改流程** | 9 案里图-1/2/3 知识库侧一次没命中；补规则路径是蒸 |
| 9.3 | 外部标准条款层**顺序不可颠倒** | 解权限 → 抓取回验 → 抽条款 → 编 `E-2` → 蒸规则 |
| 9.4 | **PASS 覆盖边界对扰动不稳** | 实测：删掉图上两行 logo 文字，BM25 `28.755→24.988` 就把「拒答」翻成「PASS」；增删 logo/标点/换行/大小写/全半角要进回归集 |
| 9.5 | 条款号**永久占号** + 版本两层号 | `kb_version`（每类库独立）与 `release_id`（跨库组合发布）不混；同一 H07 曾报出两个条款号（W-1.6 / W-1.53） |
| 9.6 | 中英同义与**屈折/连字符变体漏检** | 中文「不会疼」、英文 `increased her milk supply`、`FDA-approved` 都曾漏判 PASS；复用 L5 `word_level_grounding`（逐字源/规则原文/等价写法三选一） |
| 9.7 | **产品事实库是 PASS 的前置依赖** | 无品类功能边界/型号/认证/测试报告时只能通用预审，不能自动 PASS；一版不区分 SKU，JSON 预留 `model` |
| 9.8 | **OCR 输入版本敏感** | `IBCLC` 读成 `IBCC` 就少一条命中；素材固化到带指纹单一版本，关键 token 回原图局部复核 |
| 9.9 | **OCR 权威引擎 vs 模型直读** | macOS Vision（带指纹可回源）＝权威；模型直读（无指纹）＝仅存疑复核（过不了锚点+sha256+逐字摘录硬闸门） |
| 9.10 | **判定对象错位（审错了对象）** | 两个实测事故：把**用户提问里的示例句**当被审文案判 BLOCK；把**中文列内部批注**当外发文案审。改法＝输入侧显式标注待审对象边界，`risk_items` 指不到位置就不输出 |
| 9.11 | 多语种**一版只走模型侧** + P0 词多语种同义族 | 渠道含 `de.momcozy.com`（实测抓到 `schmerzfrei`）；多语种模型侧命中一律 REVIEW、不单独 BLOCK |
