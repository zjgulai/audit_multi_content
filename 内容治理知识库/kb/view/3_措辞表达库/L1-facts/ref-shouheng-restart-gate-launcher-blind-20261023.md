## 一、故障事实（2026-10-23 实测，切端点部署当场撞上）

我第一次走 §2.7 的重启闸门时，它给出的读数是「重启会生效：无 —— 启动之后没有任何被 import 的模块或被调起的脚本被改过，那这次重启不带来任何运行时变化，先想清楚为什么还要重启」。

而那一轮我改的文件是 `tools/run_shouheng.sh`，它正是 launchd 的 ProgramArguments 实际执行的那一个脚本。也就是说，那句话把一个正在生效的变化说成了不存在。

闸门当时只扫两类东西：一是从 ws_daemon.mjs 出发的 import 图，二是图内代码里写成 path.join(REPO_ROOT, 'tools', 'x.py') 的 spawn 目标。启动器不属于任何一类，所以它永远看不见。这不是「漏了一个文件名」，而是读数的定义域比真实执行入口小。

## 二、代价：为什么这条值得单列一条知识

这条读数在 §2.7 里的定位是「判断时机的唯一硬依据」。它说没有变化，操作者就会放弃一次本该做的重启。当天我确实差点据此跳过，如果真跳过了，端点切换就白改了，而事后从日志里能看到的只有「重启过、但没生效」，这个形状会把人指向完全无关的方向。

一个读数说错话，比没有读数更坏：人会因为它存在而不再自己看。

## 三、同一次部署里的第二个同形状实例

启动器里写了从用户目录读取端点环境文件的一行，紧接着打一行「端点配置 = 中转站地址与模型名」。

看起来一切正常，实际全没生效。原因是从点号加载文件只赋 shell 变量、不导出，于是 exec 起的 node 子进程一个变量都看不到，进程横幅仍是官方端点的地址、密钥来源仍是旧变量，画面层继续报额度不足。

两者的共同点不是配置写错了，而是打印出来的那个值不是被使用的那个值。启动器打印的是「我刚读到了什么」，真正的使用者是「子进程会看到什么」。这与 AGENTS 里「界面上看得见不等于已经生效」是同一种病，也和「读数不许比输入大」是同一种病。

## 四、修法：三类读数与两个可证伪的量

第一，闸门新增第三类读数「另（启动器）」。取值不从代码里抄文件名，而是读 plist 的 ProgramArguments，再与本仓 tools 目录下的同名副本对齐，最后按修改时间过滤。写死名字就又是一张常量表，而常量表永远不会告诉你今天少了什么。

第二，「无变化」那句话改成三类都空才许说。否则某一类有变化时「无」照样出现，读数自己就自相矛盾，读的人不知道该信哪半句。

第三，一次性凭证的摘要要把新读数也算进去。凭证覆盖的是「世界变了没有」，漏一类就等于给旧读数发了一张通行证。

第四，启动器加载环境文件时用 set -a 把整段包起来，并把打印内容改成「密钥是多少个字符」这种能证伪的量。变量名写错或者没有导出，这一格会变成零字符，一眼就能看出来；而「端点配置等于某个地址」在有缺陷的时候照样打印。

## 五、怎么复现与验证

用不带 since 的 check 参数跑一次闸门，输出里必须出现启动器那一段；再用一个远在未来的时间点做反向对照，那一段必须为空，这是为了证明它不是一张常量表；最后跑运维自检，B8 组的三个断言分别是正向列出、反向为空、以及「无变化」那句话必须提到这一类。

三条断言缺一条都不算数：只加正向断言，判据可以写成永远为真；没有「无变化」那句的断言，一类有变化时它照样说「无」，而读的人只会看最后那一行。

## 六、可复用要点（超出本仓的部分）

第一，凡是一份「什么会被重新加载」的读数，必须覆盖真正的执行入口。进程的父级是 launchd、systemd 还是 supervisor 各不相同，但它们执行的那一个文件往往不在任何 import 图里，而它恰恰是最常被改动的那一个。

第二，要区分「我读到了什么」与「消费者会看到什么」。加载、导出、子进程环境是三件不同的事，把第一件打印出来会给出假成功，而假成功比报错难查得多，因为它不产生任何异常信号。

第三，打印的量要挑「配错了就会变」的那一个。长度、指纹、是否为空，这些在出错时会立刻变形；而「配置等于某某」这类量，在出错时依然成立。

第四，同一形状的证据要攒两处再记。这次是闸门看不见启动器，和启动器加载了环境却没导出，看似无关，其实是同一个「读数定义域与实际执行面对不上」的问题，记在一起比分成两条更好用。

第五，任何新加的判据都要配反向对照。没有反向对照的断言等于注释，而注释没有失败信号。

## 七、这次没修的和修不了的

第一，别处有没有同形状的缺口，我没有证据。这次只核了重启闸门这一类读数；其它自检里若也有「只扫某个集合」的写法，需要各自核，不能因为修了这一处就假定全好了。

第二，启动器用 plist 取值这个做法有一个前提：plist 的仓库副本与装到 LaunchAgents 的那一份一致。若有人只在装好的那份上改了路径，读数就对不上，而这件事目前没有判据盯着。

第三，闸门报的是「什么会被重新加载」，不是「重启会不会丢消息」。重启窗口丢消息是另一个问题，靠的是消息时间读数与补发队列，与本条无关，不要拿本条当它们的替代。

第四，本条记录的是 2026-10-23 那一次实测的形状，包括当时的目录结构与 plist 写法。若将来换了 supervisor，取启动器的位置要跟着改，而这条知识本身不会因此失效，因为失效的从来不是「要覆盖执行入口」这句话，而是取值的那段代码。
