# 视图外来条目的存活判据（2026-10-16）—— 给「散文」配一把尺子

> 与 `ref-shouheng-ingest-coverage-blindspot-20261016` 的分工：那一条讲**「该不该落库」没有判据**；
> 本条讲**「落进去之后会不会丢」没有判据** —— 同一族（散文不是闸门），但是两件不同的事。
> 逐行源码留在留底件 `PMO/守衡-视图外来条目判据-20261016.md`（本条的 `source.ref`），正文只留结论与关键行。

---

## 〇、起因

我 2026-10-16 把这一句**写进了 GUIDE**（`kb/l8/meta_src/GUIDE.md` §一「条目（外来）」那一行）：

> ⚠️ `foreign_entry_md` 只出现在 `build_view.py` 里，**没有任何判据守着「视图重建后外来条目还在」** —— 那是散文，不是闸门。

既然自己都写下了「那是散文」，就不能把它留着。Owner：「同意你的推进，**不要影响现有的工作流**」。

## 一、缺口到底在哪（逐行核过，不是推测）

`build_view.py` 报告里的 `ok` **只比派生那一半** —— 它由五项合成：没有 `missing_entries`、没有 `installed_enveloped`、加载器 `E001` 与 `E046` 均为 0、且**加载器条目数等于 `expected_entries`**。
⇒ **`ok=True` 一个字都没说外来条目。**

而它删文件那一跳长这样：先算 `stale_removed`（判据是「**上一轮是派生的、这一轮不是了**」），再逐个 `os.remove`；而 `preserved_foreign` 是**事后**把盘上**剩下**的记一笔 —— **它是统计，不是断言**。所以那句散文当时真的没人守。

## 二、两条路的条目（读 GUIDE 的人最容易混的一处）

| 项 | 派生条目 | 外来条目 |
|---|---|---|
| 文件名 | `cg-*` | `ref-*` |
| 谁产 | `build_view.py`（从 `kb/l3` ＋ `kb/l5` 生成） | **人**走 `kb_ingest` 直接写进视图 |
| 计入 `expected_entries` | 是 | 否（**另记 `foreign_entry_md`**） |
| 2026-10-16 实测 | **509** | **10** |

⇒ `kb_collections` / `kb_search` 报的总数（519）与 `build_view.py` 的 `expected_entries`（509）
**不相等是正常的** —— 那是两个不同的集合，不是漂移。GUIDE 里原先两句都没说，已补。

## 三、判据：`kb/l8/check_view_foreign_survival.py`

**只读，不跑重建** —— 这一条是给「不许影响工作流」配的：

> `build_view.py` **没有非破坏模式**（`--out` 默认就是线上视图 `kb/view`）。
> 为了核一条「重建后还在不在」而**真去重建一次线上视图**，代价与风险都远大于这条读数：
> 重建会重写整个 `kb/view/`，而它正被别人用着（`kb_guide` / `kb_search` / 就绪巡检）。
> 构建报告是 `build_view.py` 自己落的 `kb/l8/view_build_<run>.json`，盘上的条目就在 `kb/view/` 里 ——
> **两样都不需要动。**

判据两半 ＋ 一条可见性：

- **F1** 当下盘上的外来条目 **⊇** 最近一次构建报告里的 `foreign_entry_md`（报告认过的，一条都不许少）；
- **F2** 相邻两次报告之间**只增不减**（外来条目是人工入库的，少一条就是「重建删了」）；
- **F3** **看得见** —— 逐条列出来，不是只报一个数；
- **未测**：一份构建报告都没有 ⇒ F1/F2 无从谈起，记**未测**、不判红。

### 3.1 它第一次真跑就吐了一条假红

按 run 名排序 ⇒ `CHK-20261004-0152`（**10-04**）被排到了 `20261010-1233`（**10-10**）**后面**
（ASCII 里数字 < 字母）⇒ F2 报「后一轮少了一条」，而少的正是 10-05 才入库的
`ref-content-review-kb-plan-v2-5` —— **一条纯粹的假红**。

修法：排序键改取报告自己的 `at`；没有 `at` 的排最后（宁可少比一对，不许比错一对）。
**这一半已钉进反向对照**（`--selftest` 的第 ⑤ 半）—— 少了它，另外四半全绿也照样在真库上吐假红。

> 本仓原话：**一条假红会挤掉一个真问题。**

### 3.2 反向对照 `--selftest`（五半）

| 半 | 喂什么 | 必须 |
|---|---|---|
| ① | 正常（盘上 ⊇ 报告、报告只增） | 不报红 |
| ② | 报告认过、盘上没了 | F1 红 |
| ③ | 后一份报告比前一份少 | F2 红 |
| ④ | 一份报告都没有 | 记未测、不判红 |
| ⑤ | run 名顺序与 `at` 顺序**相反** | 不报红（假阳性钉死） |

## 四、接线：非阻断（这就是「不影响工作流」的落点）

挂进 `ci/run_gates.py` 的 `view_foreign`（非阻断）。

**为什么必须是非阻断、且必须只退 0/3**：`run_gates.py` 对非阻断闸门**分档** —— 退出码 **3 记 WARN**（不改 runner 退出码）；退出码 **1 或 2 记 ERROR，会把 runner 打到退出码 3**。
⇒ 本脚本**只退 0 或 3**（异常也自己兜成 3），**绝不用 1/2** —— 免得一条本意是「读数」的东西把 CI 变红。

### 4.1 「不影响」的实证（前后逐项一致）

| 项 | 我改**之前**那一次（`~/Library/Logs/kb-gates/gates-latest.json`，2026-10-15 14:00:58） | 我改**之后**（2026-10-16 本机全量） |
|---|---|---|
| 退出码 | **3** | **3** |
| `red` | 空 | 无 |
| `errored` | 空 | 无 |
| `infra` | `['perf_bench']` | `['perf_bench']` |
| `warn` | `['verdict_latency']` | `['verdict_latency']` |
| `view_foreign` | 尚不存在 | **PASS** |

⇒ **退出码与四个集合一个字没变，只多了一条 PASS。**
（`perf_bench` 那项基础设施红是**改之前就有的**，与本次无关。）

另跑了两把强制的尺子：`python3 kb/l8/workflow_smoke.py` 退 **0**（契约齐）；`--selftest` **19/0**。

## 五、附带发现：入库闸门把「代码块缩进」当成了「连续重复符号」

本条第一次提交**被 E026 拒收**（内容质量分 48.4，其中语言 0/30）。逐项复算后查明：**不是内容问题，是评分正则的问题。**

宿主插件 `~/.dsh/plugins/dsh-kb/lib/kb.js` 的 `quality()` 里，语言分＝实义字符占比×30，再**减去**「连续重复符号」的惩罚；而那条判「重复」的正则，**它的点号会匹配空格** ⇒ **markdown 代码块的缩进（6 个以上空格）被当成重复符号**，每处扣 5 分。

实测：本条留底件正文 4452 字、实义字符 2429（占比 0.546，本应 16.4 分），而缩进命中 **8 处** ⇒ 扣 40 ⇒ 语言分归 **0**。对照已入库的 10 条参考实现：缩进命中全部为 **0**，语言分 16.8–18.3，总分 62.6–68.7（阈值 60）。
⇒ 通过与否取决于「**有没有写缩进代码块**」，而不是内容质量 —— **任何技术类条目只要贴一段缩进代码，必然被拒**。

**本次处理**：**没有改那个闸门**（它在宿主插件里，改它会影响所有入库 —— 与「不影响工作流」相抵），
改为把长代码块留在留底件、正文用行内代码。**修法建议**：把重复判据的正则从「任意字符」收成「非空白字符」（一行），
它照样能抓「连写六个感叹号」「连写六个 a」这类真复读，但不再误伤缩进。

## 六、还欠着的

- **没有真跑过一次重建**：判据只读历史报告 ⇒ 它现在能保证的是「**报告之间**没少」，
  而不是「**下一次**重建不会删」。要把它升成真闸门，得跑一次（哪怕是写到临时目录的重建）并比对 ——
  那件事**没做**，因为它会动整个视图生成链，超出本次「不影响工作流」的授权。
- **`build_view.py` 的 `ok` 仍然不覆盖外来条目**：本次没有改它（改它＝动生成链）。
  判据是**外挂**的，不是内建的 —— 这一点照实说。
