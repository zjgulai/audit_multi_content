## 一、病灶（一句话）

**两条链在同一分钟起跑就撞同一个 RUN，而撞上的后果是「这单直接失败」，不是「排队」。**

`review_run.sh` 第一步调 `rerun_ledger.py --check-base`，判据是「同一个 BASE 跑过就硬拒」（退出码 **2**）；
`BASE` 由守衡模板 `date +%Y%m%d-%H%M` 生成 —— **分钟级**。
守衡侧 `RETRYABLE_REFUSALS` 不认退出码 2 ⇒ **不进补发队列** ⇒ 后一单直接失败。

## 二、改了什么（4 处，都在名字与日志）

| 文件 | 改动 |
|---|---|
| `tools/agent/tools.mjs` | 命令模板 `%H%M` → `%H%M%S` |
| `tools/agent/tools.mjs` | 新增**观测式**并发读数：`spawnChain()` 唯一 spawn 点，起链打 `[chain] 同时在跑 N 条链`，`finally` 里减；**只记不拦** |
| 知识库仓 `kb/l8/review_run.sh` | `usage` 示例同步到秒级 |
| `tools/test_agent.mjs` | 「模板必须给出 --base 取值方法」那条断言同步，并加反向对照 |

## 三、判据（可复跑）

| 命令 | 读数 |
|---|---|
| `node tools/agent/chain_base.test.mjs` | **通过 9 / 失败 0** |
| 打断：把模板临时退回 `%H%M` | **2 项变红**；逐字恢复后回到 9/0 |
| `node tools/test_agent.mjs` | **通过 303 / 失败 0** |
| `workflow_smoke.s8_playbook()` | **S8 通过**（旗标一致、`bash -n` 过） |

钉住的四件事：① 模板必须秒级；② 旧格式出现即红（`/%H%M(?!%S)/`）；
③ 脚本 usage 与模板同格式；④ `rerun_ledger._norm()` 真的不截断（秒级 BASE 与台账里的分钟级 BASE **不许**判成同一个 RUN；反向对照：同一个 BASE 仍必须被拒）。

## 四、零影响的依据

- `_norm()` 只 `strip()` 不截断 ⇒ 秒级不会被归一化回分钟级；
- 正式脚本里**没有一处**按「年月日-时分」解析 RUN；
- 报告名本来就是秒级（`20261022-101313.review.md`），与 `base` 从来不同源；
- 并发读数只打日志：无等待、无拒绝。

**基线（改动前）**：`base=20261022-1122`（13 位）、`report_path=kb/l7/reports/20261022-112319.review.md`、
台账最新行 `{"base":"20261022-1143","text_sha8":"76a5b466","state":"REVIEW"}`、
旁挂对齐 `✅ 旁挂身份对齐（令牌）｜base=20261022-1122（按单副本）`。
改完后下一单**只应看到 `base` 变 15 位**，其余逐字相同。

## 五、还欠着 / 未测

1. **没在真实单上验过**：真实效果等下一单 —— 核对 `base` 是否 15 位、`旁挂身份对齐` 是否仍 ✅。
2. **同群并行本体没做**：会话锁按需跳过 + `saveMerged`，下一批。
3. 并发读数**只观测不拦**：真要限流时判据现成（`chainInFlight()` 已是准确计数）。
4. 判据第一版把秒级判成红的（正则写错：格式串里 `%H%M` 后跟的是 `%` 不是 `S`）——
   这条记下来，因为「会误报的检查器比没有更糟」。
