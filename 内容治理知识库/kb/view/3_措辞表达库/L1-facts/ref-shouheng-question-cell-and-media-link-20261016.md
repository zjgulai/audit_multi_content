标签换成的字面量，跟着一起进了表。

## 三、为什么必须上传（「原消息链接」不存在）

实测：飞书**没有**「取某条消息链接」的公开能力（`lark-cli im` 全部子命令只有
`chats link`＝**群**分享链接）；消息媒材只能靠 `message_id + file_key` 走鉴权 API 取字节。
⇒ 要让人点得开，只能把字节落到飞书自己的位置，再把那个 URL 写进格子。

两条实测硬约束：① 上传后 `link_share_entity` 默认是 `closed`（**点不开**）；
② **子文件不继承文件夹的设置** ⇒ **每个文件都要单独设一次**。

## 四、形状

`tools/agent/media_link.mjs`：上传 → 设可见范围 → **回读确认**（读到 `tenant_readable` 才算成）。
任何一步没成 ⇒ `url` 为空、**不写链接**（fail-closed：点不开的链接比空格更坏）。

接线（`agent.mjs`）：上传**在回执卡之后起、与链并行**（首次 9.6 s / 之后约 7 s，链约 100 s）——
摆在回执前会顶 PRD §12 的「≤5 秒」；落表时 `awaitLinks` **有界等待**（默认 20 s），
等不到就只留原文并说清是**未测**。字节**重新取一次**（读入阶段那份按红线已删），
取到的临时文件三种结局都删。

「送审问题」的组装只有 `questionForRow` 一处：`对方原话` ＋ 每个媒材一行
`[图片](url)`（视频有真文件名时用文件名当链接文字）。清洗**只认枚举出来的探针头注**，
不写「见到 `【` 就切」—— 真有人写带 `【` 的话，**宁可长，不可错删**。

## 五、旧行：只清洗文本，**链接补不回来**

旧行没存 `message_id` ⇒ 补链接做不到（要链接得重新送审）。
