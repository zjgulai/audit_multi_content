# 守衡审查报告 = 审计报告模式（2026-10-17，21 轮）

白板照片的标题逐字是「审计报告不是模板（V1）」，画的顺序是
**总（state ＋ 1 句话）→ 分（P0 → G1/G2/G3 → rule）→ 执行 @**，
圈起来的判定规则是 `P0 ≥ 1 → Block`、`P1 ≥ 1 且无 P0 → review`。

## 一、定型后的三段（真单 BLOCK 6 处的回读结构）

- **总**：`h1 内容审查报告` → `【审查结论：BLOCK】共发现 6 处必须修改。`（PRD §5.3 逐字）→
  `发现 6（合规 4｜措辞 2）`（只写非零桶）→ `一句话：共 6 处必须修改，其中 P0 红线 2 处、其余 4 处需人工确认；建议先看第 1、2 条`。
- **问题清单**：`## 二、问题清单（P0 → P1 → P2 → P3）` →
  分组标题一行写完（`### P0 红线 · 合规 ｜ 2 条`）→ 每条 `F-01 ｜ 功效宣称 ｜ P0` ＋
  六行引用块（维度 / 位置 / 问题描述 / 原因 / 依据文档链接 / 修改建议）。
- **执行**：`## 三、执行（按问题分派）` → `- **@法务**：跟进问题（第 1、2 条）` →
  PRD 那一句动作（REVIEW ⇒ `建议转 @… 复核。`；BLOCK ⇒ `请修改后重新提交。`）。
- 另有 `## 一、问题总览`：一张六列表（# ｜ 优先级 ｜ 维度 ｜ 位置 ｜ 命中描述 ｜ 承办），只用来扫读。

## 二、为什么结论行那两个东西必须另起一行（最容易踩的一条）

`prd53.conforms()` 判结论用的是整行锚定（`^…$`，REVIEW / BLOCK 两端）。
第一版把「发现 6（…）」接在结论行尾巴上，那一行立刻被读成不合规；
更坏的是两边各有各的绿：kb 只断言子串、守衡只喂夹具，真输出从没被对方量过
（这就是后来补的 S7 跨仓判据要治的形状）。现行口径：结论行之后可以换行加解释，
但不许往那一行里加任何字符。

## 三、六格与「命中描述」

- 六格字段名是 Owner 定的：维度 / 位置 / 问题描述 / 依据文档链接 / 原因 / 修改建议。
  我先前用样张的七个标签（定位、原文、证据指纹、处置…）替换过，被当场驳回「你不要乱改，改回去」。
- 「问题描述」（发生了什么）与「原因」（为什么违规）两格分开；模型侧 prompt 为此新增 `description`。
- 「命中描述」列必须印逐字原文（顺序：`excerpt` → `location` 里「…」的引文 → 拿不到就印 `—`）。
  缺原文时不许拿模型写的描述冒充，那会让整列退化成「该句以…」这种空话。
- 处置动作词（立即停发、24h 内改完再送）已从条目标题里删光，见同一批另一条反例条目。

## 四、飞书 docx 的字号：只有两个旋钮，已经用满

- 指定字号：不能。`lark-cli docs` 没有字号参数；docx 只认 heading 层级与 bold。
- 用 `#####` 让字变小：不能。那仍然是标题，比正文更大。
- 同一块内多行、左对齐、字号小一档：能。多行 `>` 会合并成一个 blockquote，行间用 `<br/>`。
- 一级/二级/三级标题加粗：能。`## **X**` 渲染成 `h2` 里套 `b`。
- 六格搬进引用块，就是为了「对齐 ＋ 小一档」；再想要别的手感只能换 PDF/HTML 渲染器。

## 五、判据（缺一条这套版式就会悄悄退化）

`tools/test_agent.mjs` 第 48 组钉六件事：结论行逐字且紧跟 H1；P 级次序 P0 → P1 → P2 → P3
且维度必须出现在分组标题里；六格齐且旧样张字段名一个都不许出现（反向对照）；
条目标题形状 `F-NN ｜ 类别 ｜ P0`（无处置词）；总览表六列、无斜杠、无编号列、命中列是原文；
第二十一轮新增「节标题必须是『问题清单』，全文不许再出现『分论点』」。

读数：test_agent 262/0、dual_track 自证 126/0、verify_cards 347/0、workflow_smoke rc=0；
卡片那一支（`layout==='card'`）754 字节 == 754 字节，一个字节没动。

## 六、边界（详见本条 not_proves）

「② 影响 / 后果列」不做（Owner 当场裁定）；跨类别重复仍未合并；
「原因」里仍带规则码（待裁决）；一句话由代码算（可复现、算术自洽，语感平）；
旧报告无法真重渲染（结构化条目从未落盘，只存了渲染后的 md，重投用的是留底正文）；
报告里的 `@角色` 只是「该找谁」的标签 —— 飞书云文档里的 @ 不会通知任何人。
