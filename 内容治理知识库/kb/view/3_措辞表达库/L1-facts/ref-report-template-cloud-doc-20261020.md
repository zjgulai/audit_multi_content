# 审查报告（云文档）版式模版 —— 文案 / 图片 / 视频共用一套

> 落库依据：Owner 2026-10-20 逐字「这份报告模版格式必须落库，视频类的也是用这个模版」与「你落库的时候，不要覆盖原库的字数限制功能」。
> 本件是**版式与取数口径**的模版。字数上限**不在本件定义**（见第一节），改上限只改 `kb/l7/registry/prd533-constraints.yaml`。

## 一、本模版管什么、不管什么

管三样：报告正文的**节序与节名**、每一节**印什么、按什么口径取数**、**按素材模态**该换哪两处。

不管三样，各有唯一真源，本件只引用、不复制、不改动：

- **字数上限**。问题描述、原因、修改建议三格的上限，以及「修改建议按标点不计入」的数法，全部由 `kb/l7/registry/prd533-constraints.yaml` 定义（取自飞书 PRD §5.3.3 正文，rev 248，2026-10-19 拉取）；两侧实现是 `tools/agent/prd533.mjs` 与 `kb/l8/prd533_check.py`。本模版**一个字都不复制那些数字**，也不设第二个上限。
- **判定逻辑**。三态、P0、置信度、优先级档在 L5/L6 与 PRD §5.3、§6；本模版只规定它们**印在哪一格**。
- **卡片版式**。群卡片走 `kb/l7/output_template.md`，与报告**措辞一致、版式不同**；Owner 明令卡片不许套报告版式。

## 二、节序（固定；不许改序，不许加缺省节）

1. H1「内容审查报告」—— 文案、图片、视频一律用这个标题（`lark-cli docs +create --doc-format markdown` 靠 H1 定文档标题）。
2. 结论行 —— PRD §5.3 逐字，整行锚定；可以换行补解释，但**这一行里不许加任何字符**。
3. 12 类一级分类汇总 —— 只在问题数达到汇总门槛时印，一行一条，与卡面同一个函数产出。
4. 一句话 —— 只陈述事实与指针：`共 N 处…，其中 P0 红线 p 处、其余 N−p 处…；建议先看第 X 条（一级类·二级类）`。
5. 「## 审查对象」—— 报告里唯一必须**完整**的一格。
6. 异常告警 —— 只在「结论行条数 ＞ 清单条数」或「结论是 BLOCK 却没有一条 P0/BLOCK」时印；正常单一个字不印。
7. 「## 一、问题总览」—— 六列表，只用来扫读。
8. 「## 二、问题清单（P0 → P1 → P2 → P3）」—— 分组标题一行写完，每条一个六格引用块。
9. 「## 三、执行」—— 按结论分两支：BLOCK 打回、不 @ 人；REVIEW 按角色派单、@ 人。
10. 附录 —— 检索读数与媒材读数（卡上不放，报告里不许砍）。
    2026-10-17 起「四、本次未覆盖/未能取证」整节下线；缺口改成逐条可见，不另开一节重复。

## 三、逐节骨架（文案单示例；图片/视频只换「审查对象」与「位置」两处，其余一字不改）

```
# 内容审查报告

【审查结论：BLOCK】共 N 处必须修改。

· <一级分类>类问题：x 个
· <一级分类>类问题：y 个

一句话：共 N 处必须修改，其中 **P0 红线 p 处**、其余 N−p 处需人工确认；建议先看第 X 条（<一级类>·<二级类>）。

## 审查对象

> **送审内容**：文案 N 字｜图片 N 张｜视频 N 段｜链接 N 条
> **文案**：<原文，不截断>
> **图片 1**：[点开查看](<直链>)
> **视频 1**：[点开查看](<直链>)

## 一、问题总览

> 下表按「优先级 → 所属类别」排列，只用来扫读；完整的问题、依据与改法在第二节。

| # | 优先级 | 所属类别 | 位置 | 命中描述 | 承办 |
|---|---|---|---|---|---|
| 1 | P0 | 合规与受监管宣称 | 图 1 第 2 处 | 100% | 法务 |

## 二、问题清单（P0 → P1 → P2 → P3）

### **P0 · 合规与受监管宣称 ｜ 1 条**

**F-01 ｜ 合规与受监管宣称·绝对化与最高级用语 ｜ P0**  —— 有库内条款依据

> **所属类别**：<一级分类>
> **位置**：<按模态给，见第四节>
> **问题描述**：<发生了什么>
> **原因**：<为什么算问题，只说原因、不写建议、不写规则码>

> 结论是 **BLOCK**：这一单**打回**，**不派单、不转人复核**。请按上面每一条的「修改建议」改完，**再重新提交一次**。

请修改后重新提交。
```

REVIEW 单只换第三节：节名改「## 三、执行（按问题分派）」，正文逐角色一行 `- **@角色**：跟进问题（第 N、M 条）`，收尾句换成 PRD §5.3.2 那句，其余节一字不动。

## 四、模态差异只落在两处（「视频也用这个模版」的确切含义）

| 关 | 文案 | 图片 | 视频 |
|---|---|---|---|
| 审查对象 | 印原文，不截断 | `图片 N` ＋ `[点开查看](url)`；拿不到链接写「链接未生成（原因）」 | `视频 N` ＋ `[点开查看](url)`；同左 |
| 位置形态 | `正文第 X 段` | `图 N 第 X 处` | `视频 00:12` |
| 其余 | 完全一致：H1、结论行、分类汇总、一句话、总览表六列、清单六格、执行两支 | 同左 | 同左 |

位置三种形态的真源同样是 `prd533-constraints.yaml::location.patterns`；本模版只负责「该按哪一种」，不负责「算不算命中」。

## 六、四个已知缺口（模版挡不住的，别当成已验证）

1. 库侧位置没有模态分支：`kb/l5/p0_fastpath.py::_position_of()` 只要有行号就拼「正文第 N 段」，不看素材是图还是文案；`kb/l7/review-engine/core/with_kb_evidence.py` 那侧的 location 只做「取到就用、取不到回落全文」。所以图片单会印出「正文第 N 段」。
2. 位置断言不校验模态：`tools/agent/prd533.mjs::checkLocation()` 是「三种形态任一命中即过」，不问「跟素材模态对不对」。上面那条因此不会变红。
3. 一句话的条号与报告编号不是同一个序列：一句话取合并输入序，报告编号取显示序（P0→P3 重排后再编号）。输入序里 P0 不在第一位时，指路条号会指到别的条目；2026-10-19 那张单就是这个形状。
4. 视频档没有线上验收证据：库内相关条目的边界自述「图片/视频那一档只有测试证据」，本次只补上图片档那一条，视频仍只有测试与夹具。
