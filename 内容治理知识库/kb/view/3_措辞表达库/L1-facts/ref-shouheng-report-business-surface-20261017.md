# 报告的三条「对外呈现」规矩（2026-10-17 第二十二轮）

Owner 一条消息三件事，逐字：「1.审查对象，要加进来，比如图片就放点击可打开的链接，文案；
2.每个细分，原因就说原因，别建议，少做少错；3.禁止用任何后台词（recvuJYdOb1Rm1/），别人听不懂的字符编码；
4.修改后重新渲染」。

## 一、审查对象：报告必须说清在审什么

新增一节「## 审查对象」，位置在「一句话」之后、「一、问题总览」之前：结论仍然占第一屏，
对象紧跟其后。三条口径：

- 文案：印对方真写的那段原文（超过 400 字截断并写明「全文 N 字」）。**取 userText，不取 question**
  —— question 是拼给模型看的那一轮，里面夹着我们的探针与 OCR 全文，直接印就是内部指令外发。
- 图片与视频：只印能点开的链接（media_link 上传到飞书云空间并设「组织内可阅读」、回读确认）。
  拿不到链接就照实写「链接未生成（原因）」—— 一个点不开的链接比一句话更坏。
- 素材里自带网址时单列一格（markdown 里长链接会被折断）。

## 二、原因只说原因

改前一条逐字：`H02 催乳/增产/奶量产出承诺（…无 FDA/临床证据）；放松叙事…走 M07 语境守卫；
M01 静音程度夸大（建议改为 low noise / quiet mode）`。
改后：`催乳/增产/奶量产出承诺（…无 FDA/临床证据）`。

丢掉的三类都不是「原因」：① 规则码（H02/M07/M01）是内部编号；② 「走 M07 语境守卫」讲的是规则之间
怎么分工，不是这条为什么命中；③ 「建议改为…」是改法，而改法本来就有「修改建议」那一格。

## 三、禁止后台词

只认有形状的内部标识：内部坐标 `#广告文案明细/rec…/命中片段`、记录主键 `recv…`、消息/会话/用户 id、
表 id `tbl…`、应用 id、模式 id `p-…`、图片 key、32 位以上十六进制（sha/md5）。
裸数字、条款号（W-1.18）、产品型号（M6/M8）、`P0`/`合规`/`全文` 这类正常短值一律不动。
清扫范围是整份报告：问题清单六格加总览表每一格（只清六格时，主键会从表里再漏一次）。

## 四、这一轮最该记住的：判据太宽 = 另一种错

第一版改完全绿，实际翻车四处，全部是「把正常东西一起删了」：

1. 清扫把 URL 的 query 也挖了 ⇒ 直链被打成 `?table=&record=` ⇒ **点开是错页**；
2. 「≤3 字的分段一律丢」把 `P0`、`合规`、`全文` 一起删空 ⇒ 总览表六列只剩一格；
3. `best/#1/No.1/最佳` 被当成内部坐标删成 `best/.1`；
4. 原因结尾的句号被当残渣剃掉。

四条现在都有反向对照：拆掉修法判据就精确变红。教训：**净化类函数的默认方向必须是「只删认得出形状的」，
不是「删掉所有不像人话的」** —— 前者漏删只是难看，后者误删是把正文删空，而且第一眼看着像成功了。

## 五、边界

条款号（W-1.18）**有意保留**：它是依据文档链接的落点与回源入口，删它要连着改溯源四段的口径。
图片/视频那一档目前只有测试证据（被重渲染的那份报告是纯文案单），线上证据要等下一单发图。
那份报告的结构化条目仍未落盘 ⇒ 这一轮的重渲染同样是「用留底正文加同一组显示函数逐行重写」，
不是重跑审查。
