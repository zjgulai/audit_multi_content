# 额度耗尽不许输出空回复

## 一、病灶：空正文那一支**要求「这一轮用过工具」**

`agent.mjs` 处置空正文的分支（2026-09-30 加）条件是 `empty && cut.cut && toolTrace.length` ——
它假定额度是被**工具返回体**撑爆的，所以处置是「折叠工具结果、关掉工具重写一次」。

实测的形状是**这一轮压根没调工具**：额度被**推理**吃光（`reasoning 12000 tok`、正文 0 字）
⇒ 那一支**不触发** ⇒ 落到通用分支 ⇒ 通用分支只附一句截断说明
⇒ **那句说明自己成了回答**，群里收到的是一条通篇只有说明、没有一个字答案的消息。

判定：那一支的条件写得比故障的形状窄 —— 没被它覆盖的那一种照样出事，
而日志读起来像「已经处置过了」。

## 二、修法（两半）

| 半 | 内容 |
|---|---|
| **重写一次** | 空正文 ＋ 额度耗尽 ＋ 没调工具 ⇒ `llm.chat(messages, { thinking: { type: 'disabled' } })`。额度是被推理吃光的，关掉思考才有正文的位置。**只试一次**，不加重试循环 |
| **兜底** | 重写仍写不出正文 ⇒ 落 `fallbackReply()` 并标 `truncated`；通用分支另加一道 `if (!reply)` 的闸 —— **空正文永远不许只带说明出门** |

有工具那一支**不动**（另一个故障形状，那边有东西可折叠）。

## 三、判据与两个坑

真起假 LLM 端点跑 `handleMessage`（第 18d 组，2 条）：正向断言「回复非空且不是那句说明」
＋「内核被调 2 次」＋「重写带 `thinking:{type:'disabled'}`」＋「**第一次不带**」（否则第三条恒真）；
反向对照断言「正文正常时只调 1 次」。实测 **249 通过 / 0 失败**。

两个自己踩的坑（比 bug 本身值得记）：

1. **假端点跑在父进程、子进程用 `spawnSync` 起** ⇒ `spawnSync` 阻塞父进程事件循环 ⇒
   端点答不了话 ⇒ 表现是「0 次请求 ＋ 被超时杀掉」，看着像**内核挂住了**。
   改：异步 `spawn` ＋ await close ＋ 看门狗超时。
2. **按「第几次请求」发响应 ⇒ 判据假绿**：这条消息在内核回话前已有一次模型调用
   （**模型侧**，无工具），于是空正文被喂给了模型侧，内核那次直接拿到正文 ⇒
   **前两条断言蒙对了**，只有「带没带关思考」把它揭穿。
   改：**按角色识别**（system 含「你是「守衡」」的那次才是内核）。

一句话：**一条断言在错误的对象上通过，和一条没有断言，在报告里长得一模一样。**

## 四、附：「不写飞书」怎么证

现成的 `--dry-run` 只挡发群消息，照样建云文档、照样落表。本次拦法：表格注入
**读放行、写抛错**的客户端（`lark_write.__injectClient` 是现成测试缝）；建文档/上传媒材/改权限
把 `SHOUHENG_LARK_CLI` 换成**拒写替身**；状态目录与两本台账全指临时目录。

**飞书没被动是用回读证的**：真台账 `PMO/logs/lark_writes.jsonl` 在那跑前后 12 分钟内 **0 行**，
日志明写「合并报告**没建成**（照实说，不编链接）」。
★ 不拿「拦截计数」当证据 —— 我那个替身代理自己有个 bug（`name is not defined`），
而那恰好让「拦截计数 = 0」失去意义。**判据要选那个不会被自己 bug 污染的。**
