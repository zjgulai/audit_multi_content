## 判定口径

**Complex RED 成立条件**：≥ 2/3 模型失败才视为成立（避免依赖单模型行为）。
判定维度（任一维度失败即该用例 FAIL）：

| 维度 | 失败表现 |
|---|---|
| D1 前置自检 | 不跑阶段 0，直接开始乱试认证；或把登录态问题当权限问题 |
| D2 身份正确性 | 用调不动 Base 的应用；把协作者加在错的应用上 |
| D3 覆盖率 | 漏类（图片未 OCR / 链接只抓一层 / 视频直接跳过 / 未做覆盖率自检） |
| D4 台账 | 漏阶段 4，导致新记录下游永远抽不出来 |
| D5 原因码 | 把"存在但无权限"标 `gone`；用占位或推测内容填充 |
| D6 工具/数据归因 | 把脚本 bug 报成数据缺陷 |

## REFACTOR 阶段必须额外跑的变体

| 变体 | 输入 | 期望行为 |
|---|---|---|
| 权限硬缺口 | 附件为库级「禁止下载」 | 标 `blocked_by_library_setting` + 复开条件，**不重试** |
| 登录态过期 | `token expired` | 发**一条**设备码，只带缺的 scope |
| 表整批重建 | field_id 集合不变但 record_id 全换 | 认领新记录 + 归档旧记录，不误报为"表被改结构" |
| 飞书侧零视频 | `视频素材` 字段全空 | 写 `不适用（附筛选证据）`，不跳过也不报缺失 |
| 模糊输入 | 只说"同步一下"，不给范围 | 走 `--check` 只读档位，不擅自写 |

## 触发边界（should-not）

以下请求**不应**触发本 skill：

- 「这段文案能不能发」→ `kb-content-review`
- 「知识库怎么分层的」「字段定义是什么」→ 读 `_meta/GUIDE.md`
- 「把 L3 的规则改一下」→ 下游优化，不需要跑 L0 同步
- 「帮我写一段产品文案」→ 通用写作
