# 已知坑与事故台账

**读取条件**：出报告前、复盘时、任何"结论有点怪"的时刻。
维护规则：**每次真实踩到新坑，先写这里，再考虑是否提升为 SKILL.md 的红线**。

## 一、身份与权限（最费时的一类）

| 坑 | 表现 | 正确做法 |
|---|---|---|
| 把授权加在调不动接口的应用上 | 反复加协作者都无效 | 只加在**能调接口的那个应用（守衡）**上 |
| 把"用户能打开"当成"应用能读" | 以为已授权，实际 403 | 两套权限，必须用**应用身份**实测 |
| 连发多条设备码 | 用户点到作废的码 | **一次只发一条**，10 分钟有效 |
| 申请全量 scope | 卡在管理员审核 | 只申请**缺的那一个** |
| 把登录态过期当权限问题 | 在权限上绕很久 | 先分辨 `token expired` 与 `91403` |
| 把"存在但无权限"标 `gone` | 误标 11 条，后改回 4 条 | 标 `gone` 要**双证**：用户确认 + API 报文件不存在 |
| 拿不到正文就判"不可核" | 漏内容 | 换通道：`drive source_file` / `slides +xml-get` / `sheets +workbook-*` |

## 二、脚本自身缺陷（危险：会被误报成"数据缺陷"）

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 核验脚本把 `record_id` 当普通字段比 | 全量误判 | 排掉元字段，只看业务字段 |
| 把 wiki token 当 base token 传 | 全量报错 | 先 `+url-resolve` 解析再取 |
| `kind` 名写错 | 过滤条件失效 | 先小样本验证过滤真的命中了 |
| `timeout` 命令在 macOS 不存在 | 脚本静默失效 | 用 `gtimeout` 或 python 侧超时 |
| python 输出缓冲 | 日志看不到进度 | `python3 -u` |
| 只看"存在与否"不看权限 | 误标 `gone` | 区分 `not_found` 与 `no_permission` |

> **红线**：报告里必须区分「库的问题」和「我的工具/脚本的问题」。
> **不许把工具 bug 报成数据缺陷。**

## 三、数据层的坑

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 记录文件在但 `manifest.jsonl` 没行 | 下游算差集得 0，**新记录永远抽不出来** | 阶段 4 必跑，且先反向复现 sha256 口径 |
| `l3_distill_run.py` 以 `w` 模式跑 | `rejected.jsonl` 被覆盖（11,860 行 → 1,053 行） | 跑前归档，跑后重建逐单元台账 |
| 用摘要判等 | 摘要口径天然不同，全量假差异 | 用 `rev` + 字节指纹 |
| URL 层混三种摘要口径 | "看起来一致"无意义 | 统一 `sha256_input` 口径；不统一就明说不能算严格一致 |
| 用整行逐字比 URL 文本 | 换行结构一变就判不中 | 词 8-gram 双向重叠 |
| 飞书域名链接走裸 HTTP | 抓不到内容 | 走 API |
| 反爬页面没给渲染预算 | 抓到空页 / JS 噪声 | TikTok 需 ~20s；仍失败再换 UA 或降级取文本 |
| 追"不存在的视频" | 追了一整轮 106 条 | 先做**字段级非空筛选**留证，0 条就写"不适用" |

## 四、维护闭环

1. 新坑先记本文件，标注日期与复现条件。
2. 同一坑出现 **2 次以上** → 提升为 SKILL.md 红线或阶段内硬规则。
3. 环境变化导致某条失效（如权限被放开、CLI 升级）→ 标 `deprecated` 并留原因，不直接删。
