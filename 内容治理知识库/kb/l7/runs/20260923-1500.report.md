## 13. 自主决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | 检索与引用合成一个 skill（kb-content-review），两段协议在文件内分开写 | 两段是同一能力的两个阶段，中间没有独立使用者；拆开的不对称风险（没按格式引 / 没检索就答）都是幻觉。也不按四类库拆四个：那会把同一套协议复制四份，用 kb_type 区分即可 |
| D2 | 默认 BM25 为主，仅在 BM25 原始分低于门限时启用向量补召；不用等权 RRF 当默认 | L6 实测 bm25_only 的 A 组 hit@3 1.0 / p@3 0.958，hybrid(等权 RRF) 0.875 / 0.542；本批 D 组（规避型）三种模式 hit@3 都是 0.8、向量 p@3 更低 → 两批合起来维持 BM25 为主 |
| D3 | 门限用原始分（BM25 ≥ 8.0 / 余弦 ≥ 0.60），并额外引入覆盖门限（16.0） | RRF 分恒为 0.016393、无区分度；单一门限也不够（A/B 有重叠）。覆盖门限是本批现场发现的缺口：首版没有它时，离题的汽车保养/基金文本因一条偶然过门限的 BM25 命中被判 PASS——现在覆盖信号不成立就拒答 |
| D4 | 引用锚点必须在规则的**全部证据单元**里找真正含摘录的那一个，不能用规则的首个证据单元 | 规则会把上百条来源记录的片段汇总（如 H02 有 102 个证据单元），首个证据单元常常不含被引片段；首版因此有 4 条结论引用不到锚点，按硬闸门被丢弃，改为逐个证据单元确认后归零 |
| D5 | 同一处文案命中多条同义规则时合并为一条，并记下被合并的条款号 | 风险文案改写建议库里有大量近义条目（同一条 More Milk 有 4+ 条），不合并会把问题数虚高、把 ≥3 的分流规则触发得过早 |
