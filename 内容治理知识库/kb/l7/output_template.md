# 内容审查输出模板（三态 + 分流规则）

本文件是 `kb-content-review` skill 的输出契约。**严格照抄格式，不要自由发挥。**
责任人一律从 `kb/l7/registry/l7.json` 的 `approvers` 读，**不写死人名**。

## 统一分流规则（三态都适用）

| 问题数量 | 输出方式 |
|---|---|
| **1–2 个** | **逐条输出**：编号 + `【类别-子类】` + 位置 + 引文 + 原因 + 依据；BLOCK 还要给 `建议` |
| **≥ 3 个** | **只输出分类汇总 + 报告链接**，不逐条列；**完整清单必须真的写到 `kb/l7/reports/<run_id>.review.md`** |

尾部动作：

- PASS → 转 sign-off 责任人
- REVIEW → 建议转复核责任人
- BLOCK → 请修改后重新提交

---

## 1. PASS

```
> 【审查结论：PASS】未发现已知底线风险，可转交 @<sign-off 责任人> 进行 sign-off
```

PASS 的前置条件（不是「没查到」就算过）：**知识库认识这个主题**——命中允许表述（安全词），
或单元层 Top3 里有既被规则引用、原始分又 ≥ `coverage_bm25_min` 的材料。
两条都不成立 → 走拒答，**不许输出 PASS**。

## 2. REVIEW

**问题数量 1–2 个时，逐条输出：**

```
【审查结论：REVIEW】共发现 N 处需人工确认。

1.【<类别>-<子类>】<位置>，<引文/描述>
  **原因**：<为什么这是问题>
  **依据**：《<库名> <版本>》第 <条款号> 条（链接：<url>）

2.【<类别>-<子类>】...

建议转 @<复核责任人> 复核。
```

> 说明：逐条**只有 PRD §5.3.3/§5.3.4 的五格** ——【类别-子类】位置 · 引文 · 原因 · 依据（含链接）·（BLOCK 才有）建议。
>
> ★★ **2026-10-19（Owner 逐字：「去掉锚点」「L0 逐字去掉，飞书链接中依据中已经存在」）：
> 卡上不再有 `**锚点**：<anchor>｜source_sha256：…` 这一行。**
> 它是**库内坐标 + 指纹**（`#广告文案明细/rec…/命中片段`），业务侧读不懂，PRD 的逐条字段里也没有它；
> 而 `L0 逐字（可点直链）`那与「依据」里的 `（链接：…）`**是同一个 URL**，印两遍。
> **溯源没有丢**：`anchor` / `source_sha256` / `entry_url` 仍在 findings、**报告**
> （第 4 节引用契约的「锚点 + 指纹」「L0 逐字（可点直链）」两行与四段溯源表）与入口 JSON 里。
> 判据：`kb/.work/l7_integrity.py` 的 `BLOCK 逐条块无 锚点 行`；`kb/l5/p0_fastpath.py --selftest` 的 ④2/④3。
>
> ★★ **2026-10-14（Owner 裁定）：`**判定**：<事实/推断>｜置信度：…` 这一行已删。**
> PRD §5.3 的逐条模板只有 `原因` / `依据` /（BLOCK 才有）`建议`，三态只出现在**结论行**
> `【审查结论：X】` 一处 —— 逐条再挂一个「判定」，同一张卡上就有两个「判定」，
> 业务侧分不清哪个是结论。`fact_or_inference` / `confidence` 仍在引擎 JSON 里，只是不再渲染。

**问题数量 ≥ 3 个时，只输出分类汇总 + 报告链接：**

```
【审查结论：REVIEW】共发现 N 处需人工确认。

· <类别>类问题：x 个
· <类别>类问题：y 个

→ 查看完整问题清单与修改建议：<可达的链接或路径>

建议转 @<复核责任人> 复核。
```

## 3. BLOCK

**问题数量 1–2 个时，逐条输出：**

```
【审查结论：BLOCK】共发现 N 处必须修改。

1.【<类别>-<子类>】<位置>，<引文/描述>
  **原因**：<为什么必须改>
  **依据**：《<库名> <版本>》第 <条款号> 条（链接：<url>）
  **建议**：<具体怎么改>

2.【<类别>-<子类>】...

请修改后重新提交。
```

> 说明：`建议` 是 BLOCK 专有（PRD §5.3.3），**必填**；`锚点` / `source_sha256` **不上卡**
> （2026-10-19 删，理由见第 2 节那条说明；它们在报告与 JSON 里，一字没少）。
>
> ★★ **2026-10-19（Owner：「必须给建议」）：这一格不再允许「（来源未给修改建议）」这类占位符。**
> 取值顺序（前三档是**库内原话**，第四档是我方兜底）：
>   ① 按命中片段匹配到的 L3 `fix_pairs` → ② 该码首组 `fix_pairs` → ③ 模式表 `suggested_replacement`
>   → ④ **兜底改法表** `kb/l5/advice_book.py`（17 条 P0 模式里 10 条本来落在占位符上）。
> 兜底那句同样受 PRD「修改建议 ≤30 字」约束，出处逐条写在 `advice_book.ADVICE[*].basis` 里
> （**不是编的**：H 系取自同码 L0「边界内容/触发原因/豁免词」，V 系取自 PRD §7.3 与 §5.3.4 模板）。
> 判据：`kb/l5/advice_book.py --selftest`（14/0，含三条反向对照）＋ `p0_fastpath --selftest` ④5–④7。
> ★★ **2026-10-14（Owner 裁定）**：`**判定**` 行与 REVIEW 一样已删（见上文 §2 的说明）。
>
> ★ **2026-10-06：五个标签一律加粗（`**原因**：`）。** Owner 的要求是「方便业务同事识别」——
> 逐条块是给内容方照着改的，标签不加粗时整段是一堵墙。**这是格式要求，不是建议**：
> 生产者那侧由 `kb/l5/p0_fastpath.py` 与 `kb/l7/review-engine/core/review_engine.py` 各写一次，
> 由 `kb/.work/l7_integrity.py` 的 `template_from_engine` 断言（非加粗会红）。

**问题数量 ≥ 3 个时，只输出分类汇总 + 报告链接：**

```
【审查结论：BLOCK】共发现 N 处必须修改。

· <类别>类问题：x 个
· <类别>类问题：y 个

→ 查看完整问题清单与修改建议：<可达的链接或路径>

请修改后重新提交。
```

## 4. 拒答（不是第四态，是无结论）

检索不到依据时**不给三态结论**，按 `no_hit_semantics` 原文输出，并给检索轨迹：

```
【审查结论：无法给出结论（拒答）】未检索到可作依据的知识库条目。

- 查了什么：<原始查询/送审文本摘要>
- 用了几种模式：BM25（最高原始分 <分>）[+ 向量补召（最高余弦 <分>）]
- 为什么判断没有依据：BM25 最高原始分 <分> < 门限 <值>，余弦最高 <分> < 门限 <值>，且规则层 0 命中
- 语义召回标注：<无语义召回（L6 为 bm25_only）｜语义召回可用>
- <no_hit_semantics 原文>
```

**无命中只表示「没检索到依据」，不能推出「合规」。** 规避型文案本来就绕开字面，无命中不是放行理由。

## 5. 位置表达（三类都要支持）

| 类型 | 表达 | 当前状态 |
|---|---|---|
| 文本 | 段落/句子 + 锚点 | 可验 |
| 图片 | `图片 <序号>` + `#img.N` 锚点 | 可验（复用 L1 的 OCR/视觉产出的 `#img.N` 锚点） |
| 视频 | `视频 HH:MM 字幕"..."` + 时间戳锚点 | **无素材，未验证**（本批没有视频素材，实测缺席） |

## 6. 引用行必带

`《<库名> <版本>》第 <条款号> 条` ＋ 链接 ＋ `anchor` ＋ `source_sha256` ＋ 逐字摘录 ＋ `事实/推断` ＋ 置信度（高/中/低）。
**引用不到本地锚点的结论不许输出**（`kb/l7/registry/l7.json` → `citation_contract.hard_gate`）。
