# 核对范围 · 覆盖矩阵

**读取条件**：进入"核对"动作前读本文件。SKILL.md §2 只保留三条不可协商的硬规则，
逐类字段口径全部在这里。

## 总则

飞书侧有几种资源类型，就有几条核对结论。任何一类都**不允许静默跳过**，
必须落在四种状态之一：

`已对齐` ｜ `不适用（附证据）` ｜ `读不到（原因码）` ｜ `不可核（原因码）`

## 一、必须核对的对象与硬性规则

| # | 资源类型 | 从飞书侧怎么取 | 核对规则（硬性，不是可选） | 判等口径 | 产物落哪层 |
|---|---|---|---|---|---|
| ① | **表格记录 · 文本字段** | `base +record-list` 全量 | 逐条逐字段比：文本/数字/日期/单选/多选/人员/公式值；**空值也比** | 规范化后 `sha256(record_fields)`（键排序、剔除 `last_modified_*`）+ 值级 diff | `kb/l0/records/` |
| ② | **表格字段结构** | `base +field-list` | `field_id ↔ 字段名 ↔ 类型` **三项都比** | 字段集合与类型逐项比 | `kb/l0/registry/kb.json` 的 `schema_snapshots` |
| ③ | **图片附件** | 记录里的附件字段 | **必须 OCR 出文案**；先取字节 → OCR → 抽文本 | 字节 `sha256(file_bytes)`；OCR 文本另算 | 字节 → `kb/l0/attachments/`；OCR 文本 → **L1** |
| ④ | **视频素材** | 记录里的附件字段 | **必须提字幕 + 抽关键帧**：字幕转文本、关键帧按图片走 OCR；两条都要 | 字节 `sha256(file_bytes)` + 字幕文本 | 字节 → `kb/l0/attachments/`；字幕/关键帧文本 → **L1** |
| ⑤ | **云空间文件**（pdf/ppt/xlsx/docx/其他） | `drive +preview --type source_file`（**原件**，不是预览） | 取原件字节 → 按真实后缀解析抽正文；扫描版 PDF 抽不出字 → 走 OCR | 字节 `sha256(file_bytes)` | 原件 → `kb/l0/`；正文 → L1 |
| ⑥ | **幻灯片 slides** | `slides +xml-get` | 取 XML 全文当正文；**不许因"CLI 没命令"判不可核** | `sha256(doc_text)` | 正文 → L0/L1 |
| ⑦ | **电子表格 sheets** | `sheets +workbook-*` | **逐工作表**取值，不能只取第一个 sheet | `sha256(doc_text)` | 正文 → L0/L1 |
| ⑧ | **文档 docx** | `docs +read` | 取全文；对象级无权限走 `auth-and-permissions.md` 第 2 步 | 版本号 `rev` **+** `sha256(doc_text)` 两条 | 正文 → L0/L1 |
| ⑨ | **base / table / wiki 节点** | `base +url-resolve`、表清单 | 每个 base/节点都要有"可达/不可达 + 表清单"结论；**wiki token 别当 base token 用** | 可达性清单 + 表清单 | `kb/l0/links/` + 台账 |
| ⑩ | **记录里的内嵌链接** | L0 记录里出现的 URL 字段 | **必须下钻两层**：第 1、2 层抓正文落快照；**第 3 层只记边、不抽内容** | `sha256(url_text)` | 快照 → `kb/l1/sources/`；边 → `kb/l0/links/graph.jsonl` |
| ⑪ | **外部网页链接** | URL 字段里指向飞书域外的地址 | **同一口径**重抓后比对；源侧真失效（404/403/域名挂）单列 | 同一层必须统一 `sha256_input` 口径 | `kb/l0/` 资源文件 |
| ⑫ | **其它附件 / 未知类型** | 兜底 | 能抽文本就抽；抽不了写明**具体原因码**，不许留空 | 按类型 | 台账 |

## 二、按类型的补充要求（踩过坑的，必须写进结论）

### 图片
- **必须 OCR，不是可选。** OCR 产物落 L1，L0 只存字节 + 指纹（L0 只登记，不摘要）。
- 字节取不到时，原因只可能是 `no_scope`（缺 `drive:file:download`）或
  `blocked_by_library_setting`（库级"禁止下载/复制/打印"）——**两者结论完全不同**，
  必须做完 `auth-and-permissions.md` 第 3 步的决定性实验再写。
- 认不出来的图单列，不许留空、不许编文本。
- 缓存闸门 `vision-jxa-2.0`：新旧图 `file_token` 交集为 0 时缓存不可复用。

### 视频
- 规则是"字幕 + 关键帧"，但**先核实飞书侧到底有没有视频**：
  对 `视频素材` 字段做**字段级非空筛选**并留证。
- 若结果为 0 条（该字段可能是预留字段）→ 结论写
  **`不适用（飞书侧视频素材 0 条，附筛选证据）`** —— 既不能跳过，也不能报成"缺失"。
- 每次同步都要重新筛一次（万一这次有了）。
- 视频字节与图片走同一套下载权限。

### 链接
- 分两类不要混：**飞书域名链接走 API**（裸 HTTP 拿不到）；**外链走 HTTP / 无头渲染**。
- **下钻深度硬性两层**，第 3 层留边不留文。
- 下钻失败的链接要在阶段 10 的核验里有交代，不能静默丢。

### 云空间文件
- `存在但无权限` ≠ `已删除`。标 `gone` 要**双证**：用户确认 + API 报文件不存在（如 `981003`）。
- 过滤条件要写清楚，别把"存在但无权限"误标成 `gone`。

### docx / sheets
- 判等**别用摘要**（摘要口径天然不同），用 **`rev` + 字节指纹**。

## 三、覆盖率自检（收尾必做）

```text
S_feishu = 飞书侧实际出现的资源类型集合
S_report = 报告里出现过结论的资源类型集合
必须满足 S_feishu ⊆ S_report
```

缺哪类，就回到本文件第一节补做，**不许直接收口**。
报告末尾必须打印这张矩阵：每类一行 = 类型 + 状态 + 条数 + 原因码。
