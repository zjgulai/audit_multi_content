# Gotchas：错误 + 修正

按"错在哪 → 怎么改"写。踩到一条就补一条，**不要重写整篇说明**。

---

## 阶段 0

**错**：什么都想做一个通用 Agent。
**改**：垂类优先。能用一句话说清"只服务哪类人、哪类事"，说不清就收窄。

**错**：只因为"老板想做 Agent"就立项。
**改**：过入口三筛，逐条要证据。"大概会重复"不算证据，要频次数字。

---

## 阶段 1

**错**：跳过追问直接写需求文档。
**改**：frontier 不空不动手。7 问逐条有答案才算过门禁 3。

**错**：只给一个方案。
**改**：至少 2 个候选并说明取舍。备选是给需求方拍板用的。

**错**：把 Agent 能自己查的事实拿去问用户。
**改**：查事实是 Agent 的活。派 subagent 去查文件/代码/数据，只把**决策**摆到用户面前。

**错**：一轮里把用户还没法回答的问题也问了（它依赖本轮未决问题）。
**改**：只问 frontier。依赖未决问题的，属于下一轮。

**错**：替用户拍板。
**改**：每个决策编号 + 附推荐答案，然后**停下等答复**。

---

## 阶段 2

**错**：先写 PRD / 先写规格，再验证方案。
**改**：TUI 先行。先用通用 Agent + RAG/Skill 真解决一次，拿到真实可用的答案，再逆推工作流、补规格。**没跑通过不给进阶段 3。**

**错**：用"我觉得应该可行"代替跑通记录。
**改**：门禁 5 要的是带输入原文与输出原文的运行记录。

**错**：一个原型想验证好几个问题。
**改**：一个原型只回答一个设计问题。**选错要验证的分支（该验 UI 的去验逻辑）等于全废。**

**错**：原型做成了产品，混进主代码。
**改**：一次性分支；结束时答案折回规格，原型留作一手来源。

**错**：接缝选太多 / 太低 / 新造一套。
**改**：理想 1 个、取最高点、优先用已有。**必须在写规格时和用户确认。**

**错**：`acceptance` 写成实现细节（"返回 200"、"调用 search_kb"）。
**改**：翻译成业务方看得懂、判得了的句子。

---

## 阶段 3

**错**：横向切片（"先把所有表结构做完"）。
**改**：垂直切片四规则——纵向贯穿所有层、能独立演示、塞得进一个上下文窗口、该预重构的先预重构。

**错**：不声明阻塞边。
**改**：`blocked by` 必填，没有就写"无（可立即开始）"。

**错**：把宽重构硬切成垂直片。
**改**：走 expand → migrate → contract。每批阻塞于 expand，让 CI 在批次间保持绿。

**错**：所有工单塞进一个文件。
**改**：一票一文件，从 `01` 编号，阻塞项在前。

**错**：拆完直接发布。
**改**：先 quiz 三问（粒度 / 阻塞边 / 合并或再拆），**迭代到用户批准为止**。

---

## 阶段 4

**错**：接缝没定就写测试。
**改**：未确认不写。写了要重构时测试全废。

**错**：先写实现再补测试。
**改**：必须在 green 之前有 red。

**错**：一次做多张工单。
**改**：一片一上下文。上下文爆掉就 review 不了。

**错**：跳过类型检查/单测，最后跑一次全量。
**改**：类型检查与单测频繁跑，全量套件最后跑一次。定位成本差一个数量级。

**错**：直接扔全量上下文给下一个 Agent。
**改**：用交接文档，**只引用路径/URL 不复制正文**；密钥与 PII 一律删掉。

---

## 阶段 5

**错**：用 LLM 自评。
**改**：自评准确率低，等于没评。判分用确定性方法，评委独立。

**错**：判不了就编一个标准答案。
**改**：拿不出可校验的作答一律判 `fail`。**空作答 = fail**，没有中间态。

**错**：拿 `stdout_head`（截断串）去解析判分。
**改**：判分走 `stdout_full`；`stdout_head` 只用于报告展示。截断串会让大输出 Agent 恒判 error。

**错**：把非零退出码当成崩溃。
**改**：它是结论信号（unhealthy / fail 时退出非零）。判据是"能否解析出 JSON 对象"。

**错**：把 `evals/` 目录里的假密钥当成被测方缺陷。
**改**：密钥与静态扫描都跳过 `evals/`，否则安全用例的夹具会把评测器自己判成不达标。

**错**：环境问题当成能力问题。
**改**：如实标 `environment_degraded`，分数**不代表能力上限**，但**必须照常输出并标注**。

**错**：只报分数不报证据强度。
**改**：任何一轮都没有 `real` 用例时，必须写明"本次评测不代表能力水平"。

**错**：不做裸模型对照就上线。
**改**：同场景裸模型对照是固定动作，结果落盘。结论是"明显优于"才保留。

---

## 阶段 6

**错**：自动修 `content` 类问题。
**改**：`content` 交还人工。改提示词让某个 `must_contain` 通过是对测试集过拟合，不是提升能力。只有 `structural` 可自动修。

**错**：修复直接改源目录。
**改**：**只改副本，源只读**；回归通过才放行；封顶轮数超限如实标"修复失败"。

**错**：把环境问题写成成长。
**改**：成长曲线只统计真正校验了作答内容的用例。"证据不足"是合法结论。

**错**：拿一次 run 就立规则。
**改**：同一模式要 **≥2 次独立 run** 才立规则（门禁 18）。

---

## 资产

**错**：把文档转成 markdown 就叫蒸馏。
**改**：产出的是文档，不是 Skill。交给 `蒸馏` 走 RIA++ 结构。

**错**：把常识写进 Skill。
**改**：过三重验证第三条——裸模型自己也能说出来的，不许写进正文。写了就是同质化，池子越大越难维护。

**错**：识别不确定却照写（白板字迹、语音转写）。
**改**：标注"不确定"，**不许猜**。猜错会把识别错误固化成团队标准。

**错**：自己创建的 Skill 自己不用。
**改**：自己都不敢用，说明 Skill 有缺陷。**必须优先自用。**
