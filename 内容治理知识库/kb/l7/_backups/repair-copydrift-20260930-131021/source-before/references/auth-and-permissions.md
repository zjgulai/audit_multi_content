# 凭据、身份与权限判定

**读取条件**：阶段 0 前置自检、任何 `401/403`、任何"读不到但对象存在"的情况。

## 一、身份清单

| 身份 | profile | app_id | 飞书侧显示名 | 能力 |
|---|---|---|---|---|
| **可用** | `dsh-kb` | `cli_aa2243de0438dcd7` | 「守衡」 | **bot 身份可读 Base / 记录 / 附件**；user 身份 = 刘华丽 |
| **不可用** | 默认 profile | `cli_aa2e11d952f85be9` | 「刘华丽的飞书CLI」 | **调不动 Base 接口** |

**关键结论**：记录层 / 结构层核对走 **bot 身份**，**不需要设备码**。
只有对象级权限必须走用户身份时才需要登录。

`~/.dsh/bin/lark-cli` **不在 PATH**，所有命令前先：

```bash
export PATH="$HOME/.dsh/bin:$PATH"
```

## 二、设备码规则（省时间的关键）

- **一次只发一条**。10 分钟有效，连发会顶掉上一条，用户会点到作废的那条。
- 码里**只放缺的那一个 scope**，不要把全量 scope 再申请一遍（会卡在管理员审核）。
- 只有 `token expired` / `token_missing` 才发码；**权限类报错不是登录问题**。
- 用户点完后立刻复验一次 `auth status`，别假设已生效。

## 三、权限问题判定四步（照顺序问，别乱试）

### 第 1 步：是登录态还是权限？

| 报错 | 结论 |
|---|---|
| `token expired` / `token_missing` | **不是权限**，登录态掉了 → 发一条设备码 |
| `91403` / `1063002` / `40403 DENY` | 资源级 ACL → 进第 2 步 |
| `403`（附件字节） | 能力或对象级限制 → 进第 3 步 |

### 第 2 步：资源级 ACL

- 要所有者在**能调接口的那个应用（守衡）**上加协作者。
- **「用户自己打开得开」≠「应用读得到」，是两套权限。**
- 把协作者加在调不动接口的应用（刘华丽的飞书CLI）上是**白做**——这是高频错误。
- 明确写进缺口清单：`对象 + 原因码 + 要人做什么 + 复开条件`。

### 第 3 步：附件字节 403 —— 决定性实验

用**同一身份**上传一个小文件，再把它下载回来：

| 实验结果 | 结论 | 该怎么办 |
|---|---|---|
| **下得回来** | 是**库级限制**（Base「禁止下载、复制、打印」）。加 scope 没用，**连所有者也被挡** | 标 `blocked_by_library_setting`，写明复开条件与"不要再重试" |
| **下不回来** | 缺 `drive:file:download` | 申请该 scope |

> 这一步是整个流程里最省时间的：不做这个实验，就会在"加 scope"和"找所有者"之间反复绕。

### 第 4 步：拿不到正文但对象存在 → 换通道，不要放弃

| 目标 | 通道 |
|---|---|
| Drive 原件 | `drive +preview --type source_file`（拿到的是**原件本身**，按真实后缀落盘） |
| 幻灯片 | `slides +xml-get` |
| 电子表格 | `sheets +workbook-*` |

## 四、复开条件模板

缺口清单里每条写清：

```text
对象     : <base/table/record/附件名>
原因码   : blocked_by_library_setting | no_scope | no_permission | gone | not_found
要人做   : <例如：把「守衡」加成该 Base 的可阅读协作者>
复开条件 : <例如：取消库级「禁止下载、复制、打印」后重跑阶段 5>
重试策略 : 不重试（等条件变化后由下一轮同步自动覆盖）
```
