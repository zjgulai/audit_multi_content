## 二、改动清单（逐项可回滚）

### 2.1 `core/with_kb_evidence.py` —— 依据只算一次

| 项 | 内容 |
|---|---|
| 新增 | `--findings-out <path>`：现跑完之后，把依据落成 run 内中间产物 |
| 新增 | `--findings-from <path>`：直接读缓存，**不再 `subprocess` 跑 `review.py`** |
| 新增 | 缓存格式 `kb-evidence-findings-cache/1`，落 `schema` / `cached_at` / `text_sha256` / `source` / `payload` |
| **新增校验（核心）** | 读缓存时校验 ① schema ② **`text_sha256` 必须等于本次文本的 sha256** ③ payload 是对象。任一不过 → 报错返回，**宁可重跑也不复用可疑依据** |
| 新增可见性 | 输出 `evidence_meta.findings_source = {mode: live\|cache, path, cached_at}`；非 JSON 档打印「依据来源：复用缓存 …（未重跑 review.py）」 |
| 默认行为 | **不变**：不给新参数时，仍每次现跑 `review.py` |
| 为什么加文本指纹 | 缓存最容易出的错不是读不到，而是**读错**：把 A 文案的依据算到 B 文案上 —— 那会让结论看着有据可查、实际张冠李戴 |
