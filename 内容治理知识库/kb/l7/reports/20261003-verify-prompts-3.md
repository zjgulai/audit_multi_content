# 新会话验证 · 3 个提示词（**裸问版** · 2026-10-03 · L7 进闸门后）

针对本轮改动（`LAYER_PREFLIGHT_LAYERS` 从 3 层扩到 **4 层**：L4/L5/L6/**L7**）设计的三条用例。

## ★ 为什么这三条**故意不加尾巴**

你要验的是「**自动化**skill 工作流」—— 也就是「**你不用提醒，它自己走**」。
如果在提示词里写「必须走 L4–L7、必须发飞书」，那验的是「**它听不听话**」，
不是「**它自动不自动**」：模型照着你给的清单执行，闸门过没过都不说明问题。

所以三条都只给「**一句话 + 素材**」。**不许补任何要求**。
（要对照组的话，尾巴那句话在文末 §对照，但那是另一次实验，别混着做。）

---

**① 全链路基线（文字 · 高命中）** —— 验「四层 + 三态 + 飞书两件」整条链
```
这条 Amazon listing 能过审吗？不合规就给我打回。
Momcozy Wearable Breast Pump — FDA certified, hospital grade, painless pumping, 100% safe, no leaking, doctor recommended
```
**期望**：`BLOCK`（多条 P0 / 违规宣称）；**BASE 四层审计红 0**；飞书云文档 + 表行都出现。

**② 让位到专项（产品宣称 · 要回源 L0）** —— 验「让位只换判定主体，层前置**不豁免**」
```
我们的吸奶器到底能不能说「FDA 认证」？这句话能不能上 listing？
Momcozy 吸奶器已通过 FDA 认证
```
**期望**：判定主体 = **产品宣称核验**（`routes.yaml` 让位表；**不是** `kb-review` 兜底）；
但层前置**照样跑满四层**（这是最常被省掉的一环）；结论里每条依据带 **L0 记录直链**。

**③ 干净素材（PASS · 抄近路陷阱）** —— 验「0 问题也**不许**跳链」
```
这句广告语能不能发？
Momcozy 穿戴式吸奶器，三种模式九档吸力，单双边可选。
```
**期望**：`PASS` / 0 问题 —— 但**照样**要有 BASE、四条审计红 0、飞书云文档；
表行「报告链接」列**按 PRD 留空**（问题数 < 3），**本地** `kb/l7/reports/<run>.review.md` **必须有**。
**这条最容易暴露"抄近路"**：素材干净 ⇒ 偷懒的跑法会直接给 PASS、连 BASE 都不建。
2026-10-03 那条外来会话的 L7 就是红的、报告却写着 `红合计 0` —— 本条正是抓这个。

## 验收：4 条硬指标（**别只看结论**）

1. **出现 BASE**（形如 `20261003-XXXX`）——没给 BASE 却出了三态结论 ⇒ **它在裸奔**。
2. **逐层核四条审计**（在库根执行，`<BASE>` 换成它给的）：
   ```bash
   for R in <BASE>-L4 <BASE>-L5 <BASE>-L6 <BASE>-L7; do
     sh kb/kbpy l7/scripts/skill_invocation_audit.py --run $R
   done
   ```
   **L7 那一条也必须是红 0 / 退出码 0** —— 2026-10-03 起它在闸门内了。
   L4–L6 会带 **黄 1（E5 预演落章）**，**属正常**（评审前置不许 `--apply`）；
   报告若标了「本单未落盘、是机制证据」= 合规；没标 = 漏披露。
3. **结论带四段溯源**：条款号(L4) + 规则/命中片段(L3) + `anchor`/`source_sha256`(L2/L1) +
   **L0 可点直链** ＋ 逐字原文。
   sha 只许写「**与 L0 记录值比对一致**」，**写「重算通过」就是编的**（本地算不出）。
4. **飞书两件自动出现**（你没说"发飞书"）：云文档（打开**第 1 行 = 报告标题**）＋ 表行记录号。
   且它**没问**你 内容 ID / 渠道 / 产品线 / 版本 —— 那几列应是 `AUTO-<hash前12>` / `未指定` / `v1.0`。

## 不通过长什么样（对着这张表判）

| 看到的 | 说明它跳过了什么 |
|---|---|
| `NEEDS_INPUT（层前置缺失…）` / 退出码 3 | **驱动循环没跑**（或跑了 L4–L6 但 **L7 没留会话痕** —— 本轮新闸门抓的就是这个） |
| 只有本地报告、没有飞书链接 | **没走发布件**（该默认发） |
| 只有 `L4/L5/L6` 三层、没有 `<BASE>-L7` | ④ 层没跑齐（旧口径） |
| 问你要 内容 ID / 渠道 / 版本 | 自动化默认没生效 |
| 依据里只有条款号、没有 L0 直链 | 溯源四段缺第 4 段 |
| 结论是手写的（没 `review_id`） | **手搓**，不是引擎产出 |

## 三条纪律

- **同一时间只跑一个会话**：先 `sh kb/kbpy l7/scripts/kb_loop_claim.py claim --base <BASE>`；
  `exit 3` = 别人在跑 ⇒ **停下，别抢**（全局单槽，不同 BASE 也挡）。跑完 `release`。
- **同一段素材重复审 = 覆盖同一行**（内容 ID `AUTO-<content_version 前 12 位>` 幂等）；
  三条素材天然三行 —— 不用手工编号。
- 想清场：删行 `lark-cli base +record-delete --profile dsh-kb --base-token RY2UbCRjXaeeWwscUPScVN5AnQc --table-id tblCXPQVzfFWWCon --record-id <rec> --yes`；
  删文档 `lark-cli drive +delete --profile dsh-kb --file-token <docx> --type docx --yes`。
