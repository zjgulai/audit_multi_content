## 4. 顺带撞出来的第二件事：`.md` 信封态（`sed -i` 版）

为了改名，我用了 `sed -i ''` 批量替换。结果 **4 个 `SKILL.md` 被宿主读成乱码，当场从宿主 skill 目录里消失**：`kb-manage`、`kb-review`、`图片安全审查`、`视频安全审查`。

**同一个文件、同一时刻，三个读者三个字节数**：

| 读者 | 图片安全审查/SKILL.md |
|---|---|
| bash / `wc` / `cat` | 6614 B，内容正确 |
| python | 2518 B，内容正确 |
| **宿主 node** | **8706 B，首 3 字节是 U+FFFD + 二进制** |

- 这不是新现象：`kb/l7/scripts/daily_health.py:24` 早就写着「python 写 `.md` 会落成『stat 虚高 4096』的信封态（宿主读成乱码）」，第 177 行还给了安全通道。
- **本轮新增的事实是：`sed -i` 同样触发。** 原表述只点名了 python，会让人以为「不用 python 就没事」。
- 安全通道（实测）：`cat f > tmp && mv tmp f` 重写即修好；`.py / .yaml / .txt` **不受影响** —— 本次被 `sed` 碰过的 `.py/.yaml/.txt` 三个读者读数完全一致，只有 `.md` 出事。

**全库体检**（两个树 8151 个 `.md/.txt`，逐文件比 node 视角与 python 视角）：

| 位置 | 信封态个数 |
|---|---|
| `kb/l8` | 567 |
| `kb/.work` | 510 |
| `kb/l7`（其中 reports 50） | 57 |
| **`kb/l0`–`l6` 活跃层** | **0** |
| **装载位 `~/.dsh/skills`** | **0**（本次修完之后） |
| 合计 | **1078（差值一律 +4096）** |

→ 信封态**只长在 python 写出来的、非活跃路径的产物上**（l8 导出件、`.work` 中间件、reports）。活跃层和装载位是干净的。

**已修**：本次 `sed` 碰过的 10 个 `.md` + AI 溯源两副本，全部用安全通道重写。重扫 20 个文件，三个读者读数**完全一致**。
