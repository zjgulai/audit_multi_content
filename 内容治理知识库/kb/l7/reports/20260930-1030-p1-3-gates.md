## 2. 每道闸门：它到底在防什么（逐条带实测数）

### L1 —— OCR 缓存复用门槛落到实处

- **旧声明**：`kb/.work/kb_ocr_gate.py::ocr_cache_reusable`（**一个函数引用**——没人调用就不是闸门）。
- **现在**：遍历 `kb/l1/media/_cache/*.json` 的 **169 条**缓存，逐条调用那个函数。
- **为什么值得红**：`kb/l8/ocr_attachments.py:153` 的复用分支就是「按 file sha256 命中缓存 →
  过门槛就复用」。缓存里只要有一条不达标（坏引擎版本 / `sha256_state` 非 full / 正文含 U+FFFF /
  整图丢失），命中它的图就会把**坏 OCR 正文**灌进 L1 —— 脏数据入口，比断链隐蔽。
- **实测**：169 条全部可复用，`ocr_version` 分布 `{vision-jxa-2.0: 169}` → **过**。
- **不做**：不判断 OCR 文本的**质量**（那要人看或模型判），只判「能不能复用」。

### L2 —— 把一条**不可计算**的等式换成 5 条可证的判据

- **旧声明**：`每类库：L1 中有内容的资源数 == 被切分资源数 + 明确跳过资源数（差额必须为 0）`。
- **实测这条式子算不出来**：按当前快照重算，合计差 23（逐库 −20 / +64 / −4 / −13 / −4）。
  原因不是数据坏了，是**两个数不同时点**：左边是今天的快照（L0 失效/撤回会把资源移出输入集），
  右边是历次 run 累积的产出。**照抄它 = 每天报一个假红。**
- **台账真实语义也是实测出来的**：`unit_count` 是**每次 run 的增量**，资源单元数 =
  它所有 `split` 行之和（逐资源验证 1624/1626 相符；另两种口径只 1520/1626、1320/1626）。
- **改成 5 条可证的**：① 台账行可解析 ② run 内序列合法（允许 `invalidated → split/skipped`
  这 114 处重切对，其余非法）③ 账实**上下界**（`max(各行) ≤ 实际 ≤ Σ(split 行)`）
  ④ 产物归属（有单元必须至少有过 split 行）⑤ 上游可溯（split 行必须能在 L1 找到出处）。
- **实测**：全过；说明项：被作废后仍留产物 306 个资源、滞后 311 个资源未切分、`unit_count`
  口径歧义（三口径 106 / 2 / 306 不符）→ 要 L2 层主在 `l2.json` 里把口径写死。
- **口径待裁项（不是红）**：`manifest_l2.jsonl` 第 **1456 行**是一行变更记录
  （`change: add_field_rule_eligible`，20260924-1240），不是资源行。它可能是层引擎有意写的，
  也可能是不该写进来的 —— 属人裁，故打印 + 给修法，**不判红**。

### L3 —— 1729 条证据逐条回指 + 自报键逐键声明

- **旧声明**：`reconcile_partition.check == true：只产出 + 只拒绝 + 既产出又拒绝 == 输入集；

  且重建后**粒度变了**（`kind` 分布里 `unit_level` 5858 行是单元级，其余是资源级）。
  三个数没有一个能从现台账复算出来 → 这是**自报块没跟着 2026-09-29 的台账重建走**。
- **现在判什么**：① 三形态候选件的 **1729 条** `evidence_units` 逐条回指 L2 单元
  （`unit_id` 存在 + `source_sha256` + `anchor` 三件套一致）—— **实测 0 条失败**；
