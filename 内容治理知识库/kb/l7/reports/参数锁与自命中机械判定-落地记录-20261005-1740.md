# 参数锁 + 自命中机械判定 · 落地记录（2026-10-05 17:40）

## 一句话

同一个文案素材四轮跑出 **PASS / REVIEW / REVIEW / PASS** —— 根因**不是判据不稳，是 agent 每轮自己发明了参数**。
本次把两件事锁死：**引擎参数**（手册写死）与**自命中判定**（从 agent 心证改为机械检查）。

## 根因（从会话留痕核出，非推测）

| 轮次 | 文案结论 | 多传的参数 |
|---|---|---|
| R1 | PASS | 无 |
| R2 | （S5 实验轮） | — |
| R3 | REVIEW | `--findings-from <agent 自建目录>/findings-registered.json` |
| R4 | REVIEW | 同上 |
| R5 | PASS | 无 |

会话留痕里 agent 自己的原话确认机制：
> *"The self-hit is discovered by the L4 subagent, not by the evidence engine."*

而引擎侧对「反例 / 禁区」**零消费者**（`with_kb_evidence.py` 里 grep 该二词 = 0 命中）；
库里这样的条款有 **181 条**。⇒ 这件事过去没有机械判据，全靠临场裁量。

## 阈值不是拍的（阴性对照实测）

拿**库内条款两两**做阴性对照（同域套话，能构造出的最苛刻反面样本），n=600，按逐字段判据测：

| 量 | 值 |
|---|---|
| 比值 p50 / p90 / p99 | 0.088 / 0.185 / 0.333 |
| 第 5 名 | 0.429，但**逐字只剩 3 字** |
| 比值 ≥ 0.90 的对数 | **4 对**，全是整条包含（1.000） |

⇒ 取 `ratio ≥ 0.90` **且** `run ≥ 80`，600 对阴性对照**误报 0**。
两把闸缺一不可：`advice` 字段中位长度为 **0**，短字段上比值天然虚高（只看 ratio 会误报）；
只看 run 会把「短素材整段出现在长条款里」当成自命中（会漏报真样本）。

**过程中自查并修掉一个真缺陷**：最初把条款文本拼成 `sample_body + advice` 一起比，
于是「素材只有样本正文」时比值被空的 `advice` 稀释到 **0.71 → 漏报**。改成**逐字段各算各的**后命中。

## 两条必须当面说的事

### ① 部署坑：不重启守衡，这次修复不生效

`tools/agent/tools.mjs` 的 `REVIEW_PLAYBOOK` 是**模块级 IIFE**（读盘一次），而守衡是 **launchd 常驻进程**。
实测：守衡 pid 起于 **11:10:02**，手册 mtime **17:35:25** ⇒ 不重启的话，喂给 headless agent 的**还是旧手册**。
已 `launchctl kickstart -k` 重启（新 pid 83631），新进程读到的 `REVIEW_PLAYBOOK` = **4707 字符**（旧版 2322），两节俱全。

### ② 顺手核出一个「静默降级」：`--content-type` 的 help 与代码不一致

`--help` 写「写飞书表用的内容类型（如 listing 文案 / 主图）」，
但判据在 `with_kb_evidence.py::_coverage_for`：只拿 `content_type.strip().lower()` 比对 `image` / `video`。

⇒ 图片单若填「主图」这类中文描述，**不报错**，但 coverage 闸门**静默失效**（一个模态都不要求）。
本件**只把真相写进手册（以代码为准），未改代码、未改 help** —— 改判据要单独报批。
