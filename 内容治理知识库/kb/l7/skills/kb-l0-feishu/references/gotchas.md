# 已知坑与事故台账

**读取条件**：出报告前、复盘时、任何"结论有点怪"的时刻。
维护规则：**每次真实踩到新坑，先写这里，再考虑是否提升为 SKILL.md 的红线**。

## 一、身份与权限（最费时的一类）

| 坑 | 表现 | 正确做法 |
|---|---|---|
| 把授权加在调不动接口的应用上 | 反复加协作者都无效 | 只加在**能调接口的那个应用（守衡）**上 |
| 把"用户能打开"当成"应用能读" | 以为已授权，实际 403 | 两套权限，必须用**应用身份**实测 |
| 连发多条设备码 | 用户点到作废的码 | **一次只发一条**，10 分钟有效 |
| 申请全量 scope | 卡在管理员审核 | 只申请**缺的那一个** |
| 把登录态过期当权限问题 | 在权限上绕很久 | 先分辨 `token expired` 与 `91403` |
| 把"存在但无权限"标 `gone` | 误标 11 条，后改回 4 条 | 标 `gone` 要**双证**：用户确认 + API 报文件不存在 |
| 拿不到正文就判"不可核" | 漏内容 | 换通道：`drive source_file` / `slides +xml-get` / `sheets +workbook-*` |
| **取设备码时用管道截断输出** | URL 与 `device_code` 被吞掉 → 被迫**重发一条**，违反"一次只发一条"，用户可能点到作废的码 | 取码一律 `--no-wait --json > 文件` 再解析；`device_code` 落临时文件供完成步骤用。**别用 `head`/`tail`** |
| **把"缺 scope 的行"当终态** | 登记时缺 scope 的行长期挂着没人回头（实测 3 slides + 1 sheet 挂了一整天），而 scope 早已被放开 | `sha256_state=no_scope` 是**每轮必修的欠账**：每轮复验，具备就补读补登记（`kb/l8/close_stale_scope_gaps.py`） |
| **拿"一张表能读"外推到全部** | 用 bot 跑 `--apply`，把读不到字段定义的两张表快照刷成 **0 字段** | preflight 要**跨表跨 Base 抽样**并输出能力矩阵；脚本在字段读失败时**拒写快照** |

## 二、脚本自身缺陷（危险：会被误报成"数据缺陷"）

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 核验脚本把 `record_id` 当普通字段比 | 全量误判 | 排掉元字段，只看业务字段 |
| 把 wiki token 当 base token 传 | 全量报错 | 先 `+url-resolve` 解析再取 |
| `kind` 名写错 | 过滤条件失效 | 先小样本验证过滤真的命中了 |
| `timeout` 命令在 macOS 不存在 | 脚本静默失效 | 用 `gtimeout` 或 python 侧超时 |
| python 输出缓冲 | 日志看不到进度 | `python3 -u` |
| 只看"存在与否"不看权限 | 误标 `gone` | 区分 `not_found` 与 `no_permission` |
| **脚本读死历史快照路径** | 新数据对脚本**不可见**（实测 `ocr_attachments.py` 硬编码 09-29 的快照 → 当天新增 7 条记录的 21 张图它一张都看不见，手工换快照才跑通） | 输入快照必须**按 RUN 绑定**；跑前先 print 目标条数与来源路径，条数为 0 先怀疑路径 |
| **一次性基线型闸门** | 判据只比"某次快照"，数据合法一变就**必红**；红久了没人看 —— 比不检查更糟 | 要留**承认通道**（带必填理由）并写进报告；判据应是"变的是不是本轮造成的" |
| **检查器自身在干跑里空转** | 重跑不带 `--apply` 的脚本只在 dry-run 打一行就退出，检查却以为它跑过了（实测 L6 幂等检查因此注定 FAIL） | 检查调用要**断言进程真的干了活**（工作计量 > 0 或确有产物），别只看退出码 |
| **把产物文件名写死 + 判定取反** | 收口脚本（`retro.py` 第一版）三处文件名与真实不符、且"缺跑"循环遍历了**已找到**的键，于是每轮都把**已跑过的阶段报成缺失** —— 一次误报 9 个"漏跑"，差点让我回头重跑全链路 | 产物**按关键词从 runs 目录实际发现**，不写死名字；判"缺"要遍历**全部已知键减去已找到**；"本 RUN 没有但别的 RUN 下有"单列为 `stages_elsewhere`（性质是 run_id 不统一，不是漏跑） |
| **python 直接建/截断文件 → 信封态** | 内容其实是完整明文，但 bash 侧 `stat`/`wc -c` 看到「真实长度 **+4096**」，harness 的 read 工具按 stat 尺寸读，于是判成 `binary file`、**读不了**（实测 `references/gotchas.proposals.md` 被 `retro.py` 追加后当场读不了） | 只要是脚本产出的文件，一律 **写 `/tmp` → 子进程 `/bin/cp` 覆盖**。**不要**用 `open(path,"w"/"a")` 建或截断；也**别信 `os.replace()`** —— 它当场尺寸对得上，下一轮再 `stat` 又变信封（实测骗过我一次）。已经信封的：python 读出真内容 → `/tmp` → `cp` 覆盖，改完用 bash `stat` 与 python `os.path.getsize` **对一次尺寸**，并**换一个新的 shell 再对一次** |
| **核验脚本把 User-Agent 写死成"假 Chrome"**（2026-10-08 实测） | **整批假红，且假红极像真故障**：`fda.gov` 对假 Chrome UA **整站返 404**（连 `/` 与 `/robots.txt` 都 404），于是 3 条 FDA 监管依据 + CDC 被判「失效」，**差点被当成紧急事项去修数据**。反向陷阱：`ftc.gov` 恰好相反（默认 UA 403、伪装 UA 200）——**同一个 UA 在不同站点的效果相反** | 核验/抓取脚本**一律用解释器默认 UA**；需要伪装时用**环境变量**显式传（`L0_URL_UA` / `L0_UA_NEW`），**不许写死在代码里**。判「页面失效」前先做**决定性实验**：同机同分钟、只换 UA（或换无头渲染）再打一次；两次结论不一致 ⇒ 是**反爬**，不是失效。实测该修法把 `unreachable` **17 → 6**、假红 **8 → 0** |
| **对账不认台账里的「坏键」标记**（2026-10-08 实测） | 5 条非 URL 的键（「材料链接」字段的**显示文本**被当年抓取器当成主机名，如 `url:http://W1利益点边界表(SWMYUF`）被当真 URL 去抓 → `UnicodeEncodeError` / `unknown url type`，**每次对账都重报一遍**，噪声盖住真信号 | 台账 09-29 已给它们定性：`change=l0_url_bad_key_note`、`status_reason` 写「**供下游忽略**」。判据两条：① 键体不是 `http(s)://` 开头；② `status_reason`/`change` 含「坏键」或 `bad_key`。**命中即跳过并单列**，不进对账分母（实测跳过 5 条，工具错 5 → 0） |
| **重抓后不登记退役**（2026-10-08 实测） | 重抓把资源重切出新单元，但**旧单元仍留在 `kb/l2/units.jsonl`**（append-only）；`l6_scope_lib` 的资源级护栏此时失效（最新 `result` 从 `invalidated` 变成 `split`）⇒ **旧正文（含 JS 噪声）继续进 L6 索引**。实测一次重抓留下 **48 条未登记旧代 / 168,989 字，且当时全在索引里** | 重抓**必须紧跟** `kb/l8/l2_align_current.py <RUN> --apply --skill <本层 skill>`。现已**接进** `recrawl_all_urls.py` 收尾（`--apply` 时自动调用；失败**不静默**、打印手动命令）。跑完自查：**未登记退役的旧代单元 = 0**、**退役账 ∩ L6 索引 = 0** |

> **红线**：报告里必须区分「库的问题」和「我的工具/脚本的问题」。
> **不许把工具 bug 报成数据缺陷。**

## 三、数据层的坑

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 记录文件在但 `manifest.jsonl` 没行 | 下游算差集得 0，**新记录永远抽不出来** | 阶段 4 必跑，且先反向复现 sha256 口径 |
| `l3_distill_run.py` 以 `w` 模式跑 | `rejected.jsonl` 被覆盖（11,860 行 → 1,053 行） | 跑前归档，跑后重建逐单元台账 |
| 用摘要判等 | 摘要口径天然不同，全量假差异 | 用 `rev` + 字节指纹 |
| URL 层混三种摘要口径 | "看起来一致"无意义 | 统一 `sha256_input` 口径；不统一就明说不能算严格一致 |
| 用整行逐字比 URL 文本 | 换行结构一变就判不中 | 词 8-gram 双向重叠 |
| 飞书域名链接走裸 HTTP | 抓不到内容 | 走 API |
| 反爬页面没给渲染预算 | 抓到空页 / JS 噪声 | TikTok 需 ~20s；仍失败再换 UA 或降级取文本 |
| 追"不存在的视频" | 追了一整轮 106 条 | 先做**字段级非空筛选**留证，0 条就写"不适用" |
| **把三种"重复"混成一个数字** | 报"有重复"没人知道该不该修（源侧本来就重复 vs 我们自己存重了，处置完全相反） | 分开报，各自有各自的结论：**A 磁盘字节重复**（同一份字节存多份，真占空间）／**B 台账行重复**（同一资源同一状态被重复登记，膨胀）／**C 逻辑重复**（同一素材被多条记录引用 —— **源侧事实，必须保留**）。用 `kb/l8/audit_l0_duplicates.py` 一次出三段 |
| **写入者无条件追加台账** | 13 个脚本都往 `manifest.jsonl` 追加，**没一个检查"和上次一样吗"**：实测 5,361 行 / 2,112 个唯一资源（膨胀 2.5 倍），1,621 行是空转再登记；一次全量同步源侧没变也会再写约 700 行 | 用 `kb/l8/l0_ledger.py` 的 `append_changed()`：**有变化才追加**，未变的刷新 `kb/l0/registry/last_seen.json`（保住"还活着"，别把"失踪"和"没查"搞混）。判等只看 `status/sha256/sha256_input/sha256_state/revision` |
| **把源侧的重复当成自己的 bug 去"修"** | 看到一份图存了 21 次就删掉 20 份 → 覆盖了源侧真实状态（那是 21 个不同 file_token） | 先**回源核对 token 数**：飞书该记录/字段上真有 21 个附件才算数。合并字节是**存储策略**决定（硬链接/内容寻址），要人拍板，脚本不自动合并 |

## 四、维护闭环

1. 新坑先记本文件，标注日期与复现条件。
2. 同一坑出现 **2 次以上** → 提升为 SKILL.md 红线或阶段内硬规则。
3. 环境变化导致某条失效（如权限被放开、CLI 升级）→ 标 `deprecated` 并留原因，不直接删。

## 五、问人的坑

| 坑 | 后果 | 正确做法 |
|---|---|---|
| **把选项丢给人、不给建议** | 用户 2026-09-30 明确要求：**每次跟你确认的所有事情，都需要带上你的建议** —— 只列 A/B/C 让人挑，等于把判断推回给人，确认一次的成本反而更高 | 每条待确认项四要素俱全：事实（带证据路径）/ **我的建议（明确指出做哪个）**/ 理由（代价·风险·可逆性）/ 取舍（其他选项差在哪、不做会怎样）；建议项排第一（SKILL.md §6.1） |
| 用"等你决定"掩盖"没想清楚" | 用户拿到一堆无判断的问号，只能反问回来，来回几轮 | 真的形成不了建议时，明说**缺哪条信息**才能形成，并给出取那条信息的动作与代价 |
