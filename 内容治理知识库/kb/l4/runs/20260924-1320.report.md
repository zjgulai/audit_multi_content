### 3.3 为什么这 101 个单元是「毒单元」而不是「新增知识」

```
$ python3 - <<'PY'   # 23 条记录会进单元的字段 → L0 角色
  From                   text    23 段  ✗ 非 content
  材料审核状态             status  23 段  ✗ 非 content
  材料链接                link    23 段  ✗ 非 content
  知识库分类              status  23 段  ✗ 非 content
  编号-自动生成            other   23 段  ✗ 非 content
  细分                   text    10 段  ✗ 非 content
  知识库分类说明-自动映射     other    8 段  ✗ 非 content
  agent使用范围           text     3 段  ✗ 非 content
总段数 136；role==content 的段数 0
→ L3 按 role=='content' 过滤后仍能成为「规则候选」的单元数 = 0
→ 会被 L3 当元数据丢弃、但已在 L2 落成单元的「孤儿」数 = 136
```

三条硬结论：

1. 这 23 条记录的**全部 8 个字段都是元数据角色**（`text/status/link/other`，无一个是 `content`）——
   它们是「收料容器」的登记信息（收件人、审核状态、材料链接、编号、分类），不是知识本体。
2. 真切之后这 101 个单元在 L3 会被 `role=='content'` 过滤器**全部丢掉**（0 条能成为规则）：
   **净增知识 = 0，净增噪声 = 101**。
3. 更严重的是它会**打破上一批刚定下的 L3 对账恒等式**
   `只产出 546 + 只拒绝 8736 + 既产出又拒绝 187 + 两者都无 0 == 9469`：
   这 101 个单元既不产出也不被拒绝 → 「两者都无」由 **0 变 101**。
   而重跑 L3 蒸馏不在本批权限内，所以它们会**永久悬空**，成为不可解释的残差。

### 3.4 处置

- **不修 emitter、不追加更正台账、不动 `9_未归类`**（保持 38）。
