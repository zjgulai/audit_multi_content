## 12. 自主决策及其依据

1. **发现并标注 lark-cli 的 `drive +inspect` 全程缺 `drive:drive.metadata:readonly` scope**
   - 依据：改用 `wiki +node-get` 解析 wiki 节点 + 按 URL 路径轻量判别类型；wiki 链接 100% 解包成功。仍是只读。
2. **把「入口表记录」与「通过筛选的 record 所指向的子资源」分开归属**
   - 依据：规格要求资源必须同时有 kb_type 与 status，且只取「审核状态=通过」的记录。故 31 条记录全部登记（排除项也留痕），但只有 20 条通过记录派生出子资源；记录本身按 R5 兜底 unknown，四类库归属落在子资源上。
3. **kb_type 采用入口表自带的 `知识库分类` 标签，而不是自己判定业务域**
   - 依据：源侧已有分类标签，直接采信可避免硬约束 4（不判定 9 大业务域）与「不猜」；标签为「其它」或空时不归任何一类库。
4. **为 7 张下钻到的关联表补表名级规则（R18–R24，均限定 scope_table 只对该表生效），置信度中**
   - 依据：这 7 张表没有分类字段，若一律 unknown 会把 367 条资源打成未归属；表名与内容形态已足够指向某一类库，故按表名映射并在规则 note 里标注「置信度中」。因为按表名映射，R18（内容公式→措辞表达库）与 R19（专家修订汇总表→内部样本库）实际被 R24（数据表所在 Base 的表已各自命中）挡住而不命中，已在 0 命中清单中列出。
5. **`规则库` 表资源记 unknown，但记录级按 R6/R7 分流**
   - 依据：该表是双态表（外部法规 与 内部品线规则混装），表级无单一 kb_type；写进 registry 的 `table_unknown_allowlist` 而不是硬塞一个类型。
6. **同名不同角色的字段用 `field_role_table_overrides` 覆盖**
   - 依据：`来源链接` 在规则库是 link、在别处可能不是；用「表名::字段名」限定，避免误下钻。
7. **sheet / slides / file 资源不哈希内容，标 `sha256_state=no_scope`**
