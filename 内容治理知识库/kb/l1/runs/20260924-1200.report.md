## 9. 自主决策

| 1 | 把差集①里「L0 有效但 L1 无记录」的 11 条**前几批欠账**一并补抽，而不是只抽批次的 441 条 | 任务判据是「L0 有效资源数 == L1 有内容 + 明确排除 + 失败，差额 0」，只抽 441 条会留下 11 条黑洞；且硬约束 5 禁止「既没被处理、也没登记原因」的资源存在 |
| 2 | `invalidated` 用作 gone 在 L1 的失效状态（而非 `gone`） | L1 的 status 词汇表描述的是**抽取动作的结果**（ok/extracted/pending_fetch/no_scope/…），gone 是上游的生命周期状态；用 invalidated + upstream_status=gone 两段信息更清楚，也和 L2/L3 读法一致 |
| 3 | gone 的 L1 产物**就地改 status 并保留文件**，不移动、不删除 | 任务写明「不要删」「审计要」；就地改 + 台账追加行满足约束 3，且比移动更能保住路径引用 |
| 4 | 失败判定用 `failed`（本层失败）与 `unreachable`（源侧不可达）两个状态分开 | 两者含义不同：`failed` 是本层处理失败（OCR 失败 / scope 拿到了但读失败），`unreachable` 是源侧取不到；混成一个会让失败原因不可归因 |
| 5 | 分母排除 `no_scope` / `forbidden` / `no_content_expected` / `empty` / `invalidated` / `retracted` | 这些不是「该抽到而没抽到」：前者是权限边界、后者是本来无正文/已失效。把它们塞进分母会把成功率算成假的低，也违背任务「写清每个 status 是否计入分母」的要求 |
| 6 | `no_scope` 47 条**不重试**，只把 scope 探测结果写进行 | 任务明确「仍不可用保持 scope_missing 并写明缺哪个 scope，不要重试」；且实测 scope 列表未变 |
| 7 | `forbidden` 7 条只追加一行写原因，连状态都不改 | 任务要求「保持不动、逐条写明被禁原因（这是要留痕的负面知识）」 |
