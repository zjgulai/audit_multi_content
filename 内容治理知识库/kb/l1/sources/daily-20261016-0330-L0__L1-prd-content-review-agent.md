## 1. 背景与目标

### 1.1 背景
美国市场内容产出量大、审核机制不统一：

- 广告二创月均约 500 条，高峰约 3000 条，当前无固定审核机制，是最高风险端口。
- 吸奶器品线红人内容月均 100-200 条，已有两轮审核，但规则未完全统一。
- 品牌设计部 AI 平面素材每日产出，核心痛点是通识常识错误。
- 品牌社媒、PR、专家、独立站内容分散在 NAS、GD、飞书 Drive、Figma 等多处。
- 法务仅固定覆盖 listing、TVC、上市物料包、EDM，高频内容无固定介入通道。

### 1.2 目标
建立统一的内容发布前审查 Agent，实现：

- 排雷：识别消费者安全、品牌信任、合规、经营风险，覆盖 brief 与发布前完整内容。
- 分流：PASS / REVIEW / BLOCK 三态结论，自动转交对应负责人。
- 提效：降低人工逐条审核负担，优先处理 REVIEW / BLOCK。
- 留痕：审核记录绑定版本，支持统计、复盘、知识库回流。
- 准确：预审结论争取达到 90% 以上准确性，避免给人工复核增加麻烦。

## 4. 核心流程

内容提交方提交 brief 或完整发布内容
        ↓
Agent 预审（规则优先级分层执行，见第 6 章）
        ↓
PASS / REVIEW / BLOCK
        ↓
PASS → 一句话总结
        - brief：转 brief 提交方 / 内容制作方
        - 完整内容：转对应 sign-off 负责人
REVIEW → 明确需再审查点 + 依据 + 文档链接
        → 转法务 / 医学 / 专家 / 北美
BLOCK → 总结需修改点 + 依据 + 文档链接
        → 返回内容方修改后重新提交
        ↓
人工复核 / 负责人确认
        ↓
发布 / 记录回流知识库

## 5. 功能需求

### 5.1 输入方式

### 方式一：飞书群 @Agent 预审

- 内容提交方在飞书群直接 @Agent，发送文字、图片、视频、链接或文件。
- brief 支持：直接粘贴文字、发送飞书文档链接、上传 Word / PDF。Agent 解析文字内容；若 brief 含图片/视频参考，按对应能力审查，第一阶段以文字为主。
- Agent 自动识别内容类型和内容阶段（brief / final_content），调用对应审查能力。
- 输出三态结论（详见 5.3 输出规范）。
- 支持 @ 指定下一步审核人，或由 Agent 按规则自动 @。

### 方式二：批量上传 + 批量扫描

- 内容批量上传到指定位置：飞书多维表、NAS 共享盘、结构化 URL 列表。
- 多维表需包含“内容阶段”字段，可筛选 brief 或 final_content。
- Agent 批量扫描后：
- 输出整体结论摘要；
- 在飞书多维表中批量生成每条内容的审查结论；
- 支持按 PASS / REVIEW / BLOCK 筛选、导出、统计。
-

### 5.2 审查能力
brief 审查重点：

- 合规底线：禁用词、医疗宣称、绝对化用语、目标市场法规。
- 产品宣称：功能边界、型号差异、认证表述。
- 达人披露：广告属性、合作披露要求。
- 不审创意方向、不审投放策略、不审转化目标。审查维度：

- 消费者安全：错误示范、危险使用、误导性操作。
- 品牌信任：专业性受质疑、公开点名、达人争议。
- 合规：法规、平台政策、医学宣称、广告用语、绝对化用语。
- 经营风险：投诉、下架、返工、投放损失。
- 产品准确性：功能边界、型号差异、允许/禁止描述。

## 5.3 三态结论输出规范
Agent 输出三态结论时，必须先标注问题所属维度，再给出总结和建议。

### 5.3.1 问题分类枚举
每个问题必须归入以下一个 issue_category：

- 合规
- 消费者安全
- 品牌信任
- 经营风险
- 产品准确性
- 措辞表达
- 人物肖像与 AI
- 其他报告分类汇总时，按该枚举统计。

### 5.3.2 PASS

- 一句话总结，说明未发现已知底线风险。
- 动作：
- brief：转 brief 提交方 / 内容制作方。
- 完整内容：转对应 sign-off 负责人。
- 示例：
- 【审查结论：PASS】未发现已知底线风险，可转交 @陈静姝 进行 sign-off。

### 5.3.3 REVIEW
问题数量 1-2 个时，逐条输出：
text
【审查结论：REVIEW】共发现 2 处需人工确认。1.【合规-医疗宣称】视频 00:12 字幕“治疗堵奶”涉嫌医疗宣称。  原因：母婴内容不得出现治疗、治愈等表述。  依据：《合规措辞库 v1》第 3.2 条（链接：https://...）2.【消费者安全-使用姿势】图片 1 中吸奶器使用姿势可能误导。  原因：吸奶器使用姿势可能误导消费者。  依据：《产品描述库-吸奶器》第 2.1 条（链接：https://...）建议转 @法务 @医学顾问 复核。
问题数量 ≥ 3 个时，只输出分类汇总 + 报告链接：
text
【审查结论：REVIEW】共发现 5 处需人工确认。· 合规类问题：3 个· 消费者安全类问题：1 个· 措辞表达类问题：1 个→ 查看完整问题清单与修改建议：https://feishu.cn/review/xxx建议转 @法务 @医学顾问 复核。

### 5.3.4 BLOCK
问题数量 1-2 个时，逐条输出：
text
【审查结论：BLOCK】共发现 2 处必须修改。1.【合规-绝对化用语】图片文字“最安全”为绝对化用语。  原因：广告法禁止使用“最、第一、最佳”等绝对化用语。  依据：《广告法禁用语》第 1 条（链接：https://...）  建议：改为“经过安全测试”等可验证表述。2.【消费者安全-车内场景】视频 00:08 宝宝未坐安全座椅。  原因：内容不得呈现未使用安全座椅的画面。  依据：《车内场景审查规则》第 1 条（链接：https://...）  建议：替换为宝宝坐在安全座椅内的画面。请修改后重新提交。
问题数量 ≥ 3 个时，只输出分类汇总 + 报告链接：
text
【审查结论：BLOCK】共发现 4 处必须修改。· 合规类问题：2 个· 消费者安全类问题：1 个· 产品描述类问题：1 个→ 查看完整问题清单与修改建议：https://feishu.cn/block/xxx请修改后重新提交。

### 5.3.5 输出格式设计说明

- 问题数量阈值默认 3，支持配置。
- 报告链接生成条件：issue_count >= 3。
- 报告内容：完整问题清单，每条包含：维度、位置、问题描述、原因、依据文档链接、修改建议。
- 报告按 issue_category 分组展示，支持导出为飞书文档或 PDF。
- 报告链接有效期 ≥ 30 天，存于飞书云文档，仅授权角色可访问。
- 若 P0 命中，即使问题数量 <3，也必须在结论中明确 P0 红线。

## 6. 规则优先级与分层审查机制

### 6.1 设计背景

不同规则类型对模型推理的需求、响应速度和审查准确率要求差异显著。法务合规类规则命中即需拦截，常识性错误需要语义理解，措辞规范相对可容忍。如果不做分层，所有规则走同一推理链路，会导致两个问题：一是法务红线规则被模型“过度推理”后误判为不违规，二是大量低风险内容消耗模型算力、降低整体吞吐效率。

行业内容审核的通行做法是采用漏斗式分级过滤：第一层快速拦截（关键词、规则引擎），第二层深度推理（大模型语义理解），第三层人工复核。轻量规则先跑，大模型算力只用于真正需要深度理解的少数内容。

### 6.2 规则优先级分层设计

将审查规则按业务紧要性、监管要求和风险严重程度分为四个优先级层级，不同层级使用不同的审查策略和模型能力：

优先级
 | 层级名称
 | 规则类型
 | 典型规则
 | 审查策略
 | 模型能力要求
 |
P0
 | 法务合规红线
 | 法律法规、平台政策、一票否决项
 | 医疗功效宣称、绝对化用语、未使用安全座椅、儿童独留车内、未授权肖像
 | 规则引擎精确匹配 + 关键词黑名单
 | 无需大模型推理，正则/关键词命中即输出 BLOCK
 |
P1
 | 安全与准确性
 | 消费者安全、产品描述准确性
 | 喂养姿势错误、辅食月龄不符、安全座椅安装错误、产品功能边界
 | 大模型语义理解 + 规则引擎辅助
 | 需要语义理解场景、判断行为是否构成危险示范
 |
P2
 | 通识与常识
 | 常识性错误、场景合理性
 | 画面场景不符合常识、模特月龄不匹配、AI 素材背景安全细节错误
 | 大模型语义理解 + 视觉识别
 | 需要多模态推理和常识判断
 |
P3
 | 措辞与表达
 | 措辞规范、表达建议
 | 品牌语气不一致、用词不精准、可优化但非违规的表述
 | 大模型生成建议
 | 不涉及硬性拦截，输出改进建议即可
 |

### 6.3 分层执行流程

内容输入
    ↓
第一层：P0 法务合规红线快速扫描
（关键词/正则匹配，毫秒级）
    ├── 命中 → 结论锁定 BLOCK，默认停止后续扫描
    └── 未命中 → 进入第二层
    ↓
第二层：P1 安全与准确性审查
（大模型语义理解）
    ├── 命中红线 → BLOCK
    ├── 不确定 → REVIEW（转对应专业团队）
    └── 未命中 → 进入第三层
    ↓
第三层：P2 通识与常识审查
（大模型多模态推理）
    ├── 发现常识错误 → BLOCK 或 REVIEW
    └── 未发现 → 进入第四层
    ↓
第四层：P3 措辞与表达建议
（大模型生成建议）
    └── 输出优化建议（不影响 PASS/BLOCK 结论）
    ↓
汇总三态结论

执行规则：

- P0 命中后，结论立即锁定为 BLOCK，默认停止 P1-P3 扫描，以节省算力；报告仅列 P0 问题。
- 如配置 continue_scan_after_p0=true，可继续扫描 P1-P3，但不得改变 BLOCK 结论，报告列全部问题。默认关闭。
- P1 与 P2 可并行执行，按最高风险等级输出结论。
- P3 仅输出建议，不改变 PASS/BLOCK 结论。
- 当多条规则同时命中时，按最高优先级输出；同层级多问题全部列出。

### 6.4 行业实践依据

内容审核行业的核心做法是“规则优先级分层 + 分级匹配”：

- 权重分配：将规则分为硬性规则（违法违规内容）和软性规则（低质量文本），硬性规则权重最高（例如权重 10），软性规则次之（例如权重 5）。

- 分级匹配：第一层高频硬性规则快速匹配（关键词黑名单），匹配成功立即处理；第二层低频软性规则异步检测（语义分析），降低延迟。先用正则匹配敏感词（毫秒级响应），再调用 NLP 模型分析语义（秒级响应）。

- 冲突解决：当多条规则同时命中时，采用“最高权重优先 + 人工复核兜底”模式。例如，一条内容同时命中广告规则（权重 50%）和涉政规则（权重 90%），系统优先拦截涉政内容。

- 漏斗式三层架构：第一层快速拦截（关键词、规则引擎和轻量模型），第二层深度推理（中高风险内容进入大模型审核层），第三层人工复核（边界模糊、高敏感度内容）。
本 PRD 的 P0-P3 四层设计即基于上述行业实践，结合母婴品类审查场景做了适配。

### 6.5 规则配置要求

每条规则必须包含：

- 规则 ID
- 规则内容
- 优先级层级（P0/P1/P2/P3）
- 风险等级（Critical / High / Medium / Low）
- 适用产品线
- 适用渠道
- 适用内容类型
- 依据来源链接
- 生效版本
- 负责人

### 6.6 置信度与分流策略

置信度区间
 | 处理策略
 |
≥ 0.90
 | 直接输出结论（PASS / BLOCK）
 |
0.70 - 0.89
 | 输出 REVIEW，标注“建议人工确认”
 |
< 0.70
 | 输出 REVIEW，标注“不确定，建议人工重点看”
 |
P0 层级规则不适用置信度分流，命中即 BLOCK，置信度记为 1.0。

### 7.3 一票否决项（P0 级，命中即 BLOCK）

以下为 P0 级硬性规则，命中即驳回，不进入后续审查层级：

- 车内出现未使用安全座椅 / 反向安装错误 / 成人未系安全带 / 安全座椅装副驾 / 儿童独留车内
- 医疗功效宣称（治疗、预防疾病等）
- 绝对化用语（最、第一、最佳、100%、纯天然等）
- 无依据的销量/排名宣称
- 危险行为示范（如无人看护下水、趴睡、怀抱乘车等）
- 未成年人未经授权出镜 / 隐私暴露
- AI 深度合成内容未标识

## 8. 输出方式汇总

### 8.1 飞书群交互

- 支持 @Agent 触发。
- 支持文字、图片、视频、链接、文件。
- Agent 回复三态结论，按 5.3 规范输出，并 @ 下一步负责人。
- 支持内容方回复“已修改，重新提交”，Agent 重新预审。
- 支持人工复核结论回流，更新记录。

### 8.2 批量扫描与多维表

- 批量上传入口：飞书多维表、结构化 URL、NAS 路径。
- 多维表字段：
- 内容 ID、产品线、渠道、内容类型、内容阶段（brief / final_content）、内容原文
- Agent 结论、置信度、问题数量、问题分类汇总、报告链接
- 人工复核人、复核结论、sign-off 人
- 状态：待审 / 已修改 / 已发布
- 支持按品线、渠道、内容阶段、风险类型统计。

### 8.3 报告链接

- 问题数量 ≥ 3 时，生成完整报告并返回链接。
- 报告内容：完整问题清单（维度、位置、问题描述、原因、依据链接、修改建议），按维度分组展示。
- 报告存储于飞书云文档，链接有效期 ≥ 30 天。
- 支持导出为飞书文档或 PDF。

## 9. 人工复核与 sign-off

- REVIEW 自动转对应专业团队（法务、医学、专家、北美）。
- BLOCK 返回内容方修改，修改后重新提交。
- PASS 转 sign-off 负责人，负责人确认：
- Agent 审查记录完整；
- REVIEW 已有人工结论；
- BLOCK 已修改并重新提交；
- 发布版本与送审版本一致。
- 人工复核结论回流知识库，更新规则权重和正负样本。

## 10. 记录与统计

### 10.1 记录要求
每次审查生成唯一 review_id，绑定：

- content_id
- content_version
- content_stage：brief / final_content
- decision：PASS / REVIEW / BLOCK
- issue_count
- issue_summary_by_category
- report_url（问题 ≥3 时生成）
- 人工复核结论重新提交生成新版本、新 review_id。记录保存 ≥1 年。

### 10.2 日常统计指标
说明：

- 不统计“覆盖率”，因为需要人工登记应审总数，轻量跑不现实。
- 不统计误报率、漏报率、知识库回流数量，作为试点评估专项，不做日常统计。
- 准确率通过每周抽检评估，不进入日常统计。

### 10.3 抽检

- 每周抽检已 PASS 内容 ≥100 条或 5%，取高者。
- 抽检用于评估准确率、P0 漏报，结果回流知识库。

## 11. 准确性要求与评估

### 11.1 目标

- 整体三态准确率 ≥ 90%。
- BLOCK 精确率 ≥ 95%。
- P0 漏报率 = 0。

### 11.2 评估方式

- 以人工复核和每周抽检为金标准。
- 准确率 = 三态结论一致数 ÷ 总审查数。
- BLOCK 精确率 = 正确 BLOCK ÷ 全部 BLOCK。
- P0 漏报率 = P0 应命中未命中数 ÷ P0 应命中总数。
- 不达标时，优先修规则、补样本、调模型。

## 12. 非功能需求
脱敏轻量原则：

- 内部审核已单独开权限的，可不强制打码。
- 报告链接、导出文件、模型训练样本、日志，建议脱敏或去标识。
- 不对外分享、不训练、不导出时，仅靠权限控制即可。

## 13. 权限与安全
安全原则：

- 默认最小权限。
- 报告链接仅授权角色可访问。
- 导出需权限；导出文件按需脱敏。
- 模型训练使用脱敏样本；如需原始素材，需法务审批。
