# 评审链执行手册（给 headless agent 的一页）

> **为什么有这一页**（2026-10-05 实测）：评审链的 headless agent 一单做 **63 次工具调用**，
> 其中一次是 **42 秒的全库递归 grep**；端到端 4~10 分钟里约八成是它自己"想怎么做 + 满库探索"，
> 而**四层前置只占 7.7 秒**。PRD §12 要单条判定 ≤10/20/60 秒，PRD 自己写的路线是
> 「正则毫秒级 → NLP 模型**秒级**」—— 差的是**执行形态**，不是判据。
>
> 这一页把它从「探索者」压成「执行者」：**流程不再由它发明，证据不再由它重挖。**
> **它不改变任何判据**：skill 照旧逐层真加载（工作流不变）、闸门照旧红即停、结论照旧只能由引擎产出。

## `--content-type` 只许取这三个值（**help 文本与代码不一致，以代码为准**）

| 素材 | 逐字取 | 代码会因此多要什么 |
|---|---|---|
| 文字 / listing / 文案 / 字幕 | `text` | 无额外要求 |
| 图片 / 主图 / 图上文字 | `image` | `image` + `ocr` 两个模态的 provider 佐证，拿不到就记 `coverage.incomplete`（**缺口**） |
| 视频 / 画面 / 口播 | `video` | `video`/`audio`/`ocr`/`asr`/`keyframes` 五个模态的佐证，拿不到就记缺口 |

⚠️ `--help` 写的是「写飞书表用的内容类型（如 listing 文案 / 主图）」—— **那句话会骗你**。
判据在 `with_kb_evidence.py::_coverage_for`：只比对 `image` / `video`。
**填「主图」这种中文描述不报错，但会让 coverage 闸门静默失效**（匹配不上 ⇒ 一个模态都不要求）。
这是**静默降级**，比报错更坏 ⇒ 图片单元必须逐字填 `image`。

⚠️ **链接没有自己的模态**：正文按 `text` 送。引擎对 `text` 恒记 `complete`，
**它不核「链接到底抓到了没有」** ⇒ 抓不到正文就如实报「缺输入」，**不许**拿空 `--text` 跑出 `PASS`。

## 图单：四种画面事实**必须**在回复里逐项写（缺一项本单不收 · Owner 2026-10-21）

病灶（实测）：一张母婴插画里「奶瓶倒着放」没被审到。查下来 skill **真的加载了**
（`image_skill_gate.load.verdict=loaded`），判定主体也出了结论 —— 但四类画面事实**一条都没写**，
而流程上没有任何东西会红。⇒ **「加载了 skill」≠「执行了 skill 里那道视觉核对」。**

图单的回复里必须逐项写这四类，每项给结论与依据：

| 类别 | 结论只能是 | 依据要求 |
|---|---|---|
| 婴幼儿姿势 | `有` / `无` / `未测` | 判 `有` ⇒ 必须写看到了什么、在哪个位置；判 `未测` ⇒ 必须写原因 |
| 产品状态 | 同上 | 同上 |
| 场景关系 | 同上 | 同上 |
| 隐私 | 同上 | 同上 |

- 依据**只能来自画面读数**（守衡给的那一格），**不许**拿 OCR 文字冒充画面事实；
- 只提类别名、不给结论 **不算覆盖**（判据不认，闸门也不认）；
- **判据与闸门**：`tools/agent/visual_checklist.mjs`（四类缺一项 ⇒ 不收）＋
  `agent.mjs` 的结论计算处（图单缺项 ⇒ 表行结论压成 `NEEDS_INPUT`，卡上写明缺了哪几类）。
  ⚠️ 文字单、视频单**不触发**这条（它们没有这四类）。

### 读数边界（2026-10-21 加）：读数里有「姿态异常的容器」，清单**必须**点名

画面读数现在会给容器类物件标 `orientation`（`正放/倒置/侧放/悬空/贴边/看不清`）。
**当读数里出现「倒置/侧放/悬空/贴边」的容器（瓶/杯/罐/盒/壶）时，清单里必须有一项 `有` 点到它**
—— 否则判红，理由写「画面读数里有姿态异常的容器（…），视觉核对清单没提」。
这是唯一能咬到「**看见了却装没看见**」的判据；读数里压根没有容器时它不咬（那是读数的账，
见下面那条读数稳定性判据）。

### 读数稳定性（同日加）：读数本身不稳，就不许当视觉源

实测同一张图两次读数，物品栏**不一样**（10:46 有「白色小瓶」，11:18 床头柜小物件全没了）。
判据：`node tools/check_scene_stability.mjs --image <图> --runs 5` ——
同一张图连读 5 次，**每次都必须读到容器类物件**，否则判「读数不可用」（退出码 1）。
⚠️ 它只判「稳不稳」，不判「有没有倒着放」（那是读数模型的能力问题）。

## 六条禁止（每条都对应一次实测到的浪费或一次实测到的错）

1. **不要自己全库 `grep`/翻目录找依据** —— 引擎**已经**在 L3 + L5 + L6 上检索过；
   实测有 agent 花 **42 秒**递归 grep，那是重复劳动。
2. **不要重复跑前置或审计** —— 第 3 步那条命令里已经跑过并核过（四道审计红 0 才算过）。
3. **不要为了"确认"把同一个文件读第二遍** —— 一次读全，别来回。
4. **不要绕开第 3 步那条命令自己去拼引擎参数** —— 尤其 `--findings-from`：
   它的合法来路**只有引擎自己写的缓存**，**不许**指向你自己拼的 JSON
   （自造参数**不报错**，只会让同一个素材给出不同结论 —— 实测同一文案四轮跑出 PASS/REVIEW/REVIEW/PASS）。
5. **不要改判据、不要绕闸门** —— 闸门红就停；结论只能由引擎产出，**不许手写三态或条款号**。
6. **不要追问内容 ID / 渠道 / 产品线 / 版本** —— 缺省自动补（`AUTO-<content_version 前 12 位>` / 未指定 / 未指定 / v1.0）。

## 什么时候**可以**离开这 4 步

- 前置红 / 审计非零 ⇒ **停下并如实报**（哪一层、什么原因），**不许**带着坏输入往下走；
- 退出码 `3` ⇒ **库忙**（别的会话认领中），**不是闸门红**，两者必须分开报；
- 引擎给 `NEEDS_INPUT` ⇒ 那是**拒答**，如实转述为「结论未知」，**不许**说成通过；
- `selfhit_check` 给 `status=error` ⇒ 那是**「没查成」，不是「没命中」**；
- 素材属 P0 快路已拦的红线（守衡入口会直接给 BLOCK）⇒ 本手册不适用，那单不会到你这里。
