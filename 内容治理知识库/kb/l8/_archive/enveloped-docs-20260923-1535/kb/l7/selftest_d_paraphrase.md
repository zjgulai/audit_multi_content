## 结论：在这类查询上向量有没有价值

1. **三种模式的 hit@3 完全相同（各 4/5 = 0.8）**，precision@3 上 `bm25_only` 与两种加权融合都是 0.533，`vector_only` 反而更低（0.467）。
2. 向量确实在个别查询上**看得更准**：「最佳、第一名这种说法有问题吗」BM25 三条全不对题（把它们当成'最佳'字面的术语修订），向量直接命中「吸力夸大用语」规则；「能不能说产品是医院同款」向量三条全中（U03:hospital / M05:hospital-grade 与其修改建议）。
3. 但向量在「说能帮妈妈通乳算不算踩线」上明显更差（0/3 相关），把三条无关的专家修订排到前面——它的邻域偏宽，在短查询上会把'同话题'和'对题'混为一谈。
4. 两种加权融合都没有超过纯 BM25：0.7/0.3 因为权重偏向 BM25，结果与 BM25 完全一致；0.5/0.5 换来了个别好结果，同时把 BM25 的正确答案挤掉一条，净收益为 0。

**最终结论：维持 BM25 为主。** 在这组规避型查询上，向量没有可测出的净增益，因此**不建议**改默认路径、也不给具体融合权重；向量只保留「BM25 原始分低于门限时补召」的角色（与 `kb/l7/registry/l7.json` 的 `retrieval.vector_fallback` 一致）。

**没有预设结论**：上一批说明向量在字面重合型查询上没用，这一批说明它在规避型查询上也没有稳定的净增益——两批合起来才敢下「维持 BM25 为主」的判断。若要继续用向量，需要先换更强的多语模型再测，而不是调权重。
