# 逐单元拒绝台账：原因码口径与字段

> 读取条件：写原因码、读台账、判「蒸不出来的算不算失败」时读本文件。

## 台账是什么

`kb/l3/rejected.jsonl` 是**逐单元**台账：每一行记的是「这个单元为什么没进候选」。
它是知识，不是中间缓存 —— 记的是「我们试过、被谁拦、为什么」。

**被拒不是失败。** 蒸不出来就如实记账，比硬蒸出一条永远不命中的空跑规则有价值得多。

## 字段

| 字段 | 含义 |
|---|---|
| `kind` | 原因码（合法值见下表，**不许自造**） |
| `reason` | 人读原因（同一原因码的写法要统一，否则按 reason 分组会分成两个桶） |
| `resource_id` / `unit_id` | 指回上游（行级锚点） |
| `anchor` | 单元在源文里的逐字定位 |
| `source_sha256` | 源指纹；缺失即不可回指 |
| `rebuild_note` | 台账重建时写入的自证信息（重建轮次、计数） |

## 原因码（合法值）

| kind | 含义 | 硬蒸会怎么误导 |
|---|---|---|
| `unit_level` | 单元级未成规则（义务不成立 / 无可判定对象） | 产出永远「未命中」的空跑规则，污染命中率 |
| `sample_only_no_verdict` | 只有样本、没有判定结论 | 下游会把它当已判样本引用 |
| `no_rule_derivable` | 信息不足以推出「命中 → 替换」对 | 逼出编造的条件 |
| `absorbed_as_reason` | 已作为某条规则的理由被引用 | 重复计入，虚增覆盖率 |
| `no_clause_text` | 没有条款正文（导航页 / 脚本壳 / 截断件） | 抽出来的不是条款 |
| `clause_not_actionable` | 条款不可执行（原则性表述、无阈值） | 交给人裁的活被写成机械判定 |

## 一行合格的拒绝记录要能回答

1. **为什么蒸不出来**（原因码 + 一句话）；
2. **硬蒸会怎么误导下游**；
3. **什么条件下翻案**（补了哪个字段 / 哪份源就能重蒸）。

四段缺一，业务侧就没法拿它跟上游对齐 —— 那就只算「没做」。

## 台账重建

```bash
kb/kbpy l8/l3_reject_ledger_rebuild.py <RUN> --apply
```

收敛后**必须**重建，否则会重演 11,860 → 1,053 行的行数回归（见 `l3-redlines.md`）。
重建后要核：分母是不是当轮 L2 单元数；重建前后计数是否可自证（`rebuild_note`）。

## 计数口径

- 台账分母是 **L2 单元数**，不是条款数；台账行数天生比条款数大一个量级，这是正常的。
- 判断「漏没漏」不能只看两个总数，要做集合差并以 `unit_id` 为分母**归因到 0**。
- 台账现为**逐单元级**；历史事故前的 11,860 行是**资源级** —— 两个数不同量纲，不可直接比。
