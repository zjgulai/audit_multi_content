### 为什么 `evidence-groups.yaml` 必须 `require_on_new: false`

实测确认：E042 = **0**。

### `vocabulary.yaml` 的意义（本次最实质的修复）

`kb_search` 检索前会用词表把查询词扩成「主词 + 别名」（别名权重 0.5）。
**`vocabulary.yaml` 缺失 = 不扩词**，这正是「库里有规则却搜不到」的根因。

别名来源全部可溯源，三个来源：
1. `l7/registry/l7.json → vocabulary.categories` 的**子类名 + 类别名 + 规则码 + label 枚举词**
2. 同文件的 `prd_7_3_vetoes` 原文措辞 —— ⚠ **`prd_7_3` 挂在类别级，子类没有这个键**（第一版读成子类级，
   漏掉了「医疗功效宣称 / 绝对化用语 / 最 / 第一 / 100% / 纯天然」）
3. PRD §5.3 输出示例里的**业务自然叫法**（【合规-医疗宣称】【合规-绝对化用语】【消费者安全-使用姿势】【消费者安全-车内场景】）
   —— 加载器是**双向包含**匹配（`s.includes(t) || t.includes(s)`），所以「医疗宣称」当不了「医疗功效宣称」的子串，必须逐字挂上

`entries`（只影响排序加分）通过「视图标题里的规则码」关联：L2-concepts 标题形如 `[H07]` **本身就是规则码**；
L1-facts 标题形如 `[W-2.1]` 是**条款号**、需经 `l3` 的 `article_no → rule_code` 换码。
