## 三、⚠️ 写通道结论修正（本次踩到并纠正）

迁移第一版用 `sed -e 's/^tier: L2$/tier: L1/' src > dst` 写盘 —— **56 条全部落成信封**
（`ls` 8122/13690 字节，node 读到首字节 `88 7d 1c`）。

受控实验（同一段 34 字节内容、六个写入者，读回一律用加载器同一运行时）：

| 写入者 | ls 字节 | node 读到的形态 | 判定 |
|---|---|---|---|
| `cat src > f.md` | 34 | `---` | **明文 ✅** |
| `cp src f.md` | 34 | `---` | **明文 ✅** |
| `<DSH>` node `fs.writeFileSync` | 34 | `---` | **明文 ✅** |
| **`sed 's/…/' src > f.md`** | **4130** | `88 7d 1c…` | **信封 ❌** |
| `python3 open(…,"w")` | 4130 | `88 7d 1c…` | **信封 ❌** |
| `perl -e 'print'` | 4130 | `88 7d 1c…` | **信封 ❌** |

**结论：决定落盘形态的是「谁发起写入调用」，不是「有没有用 shell 重定向」。**

→ 这**修正了 `kb/l8` 记录的措辞**「用 node / `/bin/cp` / **bash 内建重定向**写 `.md`，所有读取者读到的都是明文」。
   该说法只在写入者是 `cat` / `cp` / 无程序的内建重定向时成立；
   **`sed` / `awk` 也是重定向，但它们落信封**。

**更新后的纪律（建议写进 `_meta/GUIDE.md` §八 与 L8 的 loading-link）**：
> 往装载位写 `.md` 一律走 **node `fs.writeFileSync`** 或 **`cat` / `cp`**；
> **禁用 `sed` / `awk` / `python` / `perl` 直接写 `.md`**（它们都被注入层封成 4096 字节前缀信封）。
> 写完必须**读回断言**：字节数 + 逐字节内容一致（能对上就说明没落信封）。

修正后 56 条用 node 从归档重做，实测 **L1-facts 509 条 / 明文 509 / 信封 0**。
