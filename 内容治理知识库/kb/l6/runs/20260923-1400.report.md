## 8. 检索怎么用

```bash
python3 kb/l6/retriever.py --query "宣称疗效的表述" --top 5
python3 kb/l6/retriever.py --query "FDA approved claims" --top 5 --json
python3 kb/l6/retriever.py --query "医生推荐" --mode bm25 --kb-type internal_sample
python3 kb/l6/retriever.py --selftest
```

输出每行含 rank / RRF 得分 / **unit_id** / **anchor** / 来源表 / source_sha256 / 各索引名次（`bm25_zh=#n vector=#n`）。融合方式：先在 bm25_zh / bm25_en 两个语言子索引之间按名次融合，再与 vector 名次融合；RRF 只用名次不用原始分，规避 BM25 分与余弦分量纲不同。

## 9. 自主决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | 本机没有现成 embedding 模型/接口，但外网可达，于是装 ONNX 路线的 fastembed 并用多语模型自建向量 | 任务首选是「向量+BM25」；onnxruntime 本机已有，fastembed 不拉 torch（省约 2GB）。全程用真实模型算向量，没有用随机数/哈希/零向量充数 |
| D2 | 向量只建一套多语索引，不按语言分成两套 | BM25 必须分语言是因为切法不同；向量用同一个多语空间，中文查询才能命中英文素材（这批素材 41% 是英文），这正是不做分库的理由 |
| D3 | 检索文本只取 unit.text，不把字段名/标题拼进去 | 拼上「命中片段」这类字段名会让所有查询都命中同名单元，污染检索；字段名留在元数据里供过滤 |
| D4 | 中文单字段退化 unigram，而不是丢弃 | bigram 对单字段切不出词，丢掉会让这类单元检索不到；退化规则写进 registry，可核对 |
| D5 | 融合用 RRF（k=60）：先在 bm25_zh / bm25_en 之间融合，再与向量融合；不做 rerank | BM25 分与余弦分量纲不同，RRF 只用名次；rerank 模型按任务要求留到后面 |
| D6 | P0 证据单元（321 条）不入向量，但仍进 BM25 | 任务只规定「P0 不入向量」；BM25 是词面检索，与 kb/l5/matcher.py 的确定性匹配不冲突，去掉反而丢召回 |
| D7 | 把「内容没变就不写文件」做进建索引流程，连 mtime 都不动 | 第一版无条件重写投影/registry，自检发现重跑 mtime 会变；改成按内容比对后再写，重跑做到零写入 |
| D8 | 首轮探测误判网络不可达（curl 超时只给 3 秒），保留该记录并写明误判原因 | 留痕要能解释「为什么一开始记的是 bm25_only」，不能悄悄改掉 |
| D9 | macOS BLAS 对 1578×384 的矩阵乘会误报 divide-by-zero/overflow，retriever 里局部屏蔽并附验证结论 | 实测输出全有限、与逐行点积最大差 5.6e-17，属误报；屏蔽只关警告，不改数值，且真出现非有限值会退回逐行计算 |
| D10 | 自验判断给三档（相关/弱相关/不相关），命中率只按「相关」算 | 避免用「弱相关」把数字做漂亮；弱相关单独写在 note 里 |
