## 1. 件1：补 `gone` 检测能力

### 实现方式

新增公共库 `kb/.work/kb_l0_scan_lib.py`（`SCANNER_VERSION=0.7`），把 gone 检测做成链路上的**一等能力**而不是一次性脚本，供后续每批复用：

| 函数 | 职责 |
|---|---|
| `assert_all_records_scope(manifest)` | **断言源侧清单是 all_records 口径**：`query_context.record_scope == "all_records"` 且未带 `--view-id`；不满足直接抛错，防止视图筛选伪造 gone |
| `source_key_list(table_id, records, attachment_fields)` | 由源侧本轮实读记录 + 附件字段，生成源侧全量 key 清单（记录 key + 附件 key） |
| `detect_gone(latest, table_id, src_rec, src_att)` | 台账有效 key × 源侧清单 做**双向差集**：台账有源侧无 → gone；源侧有台账无 → 必须登记的缺口（不静默丢） |
| `assert_accounting(...)` | **闭环断言**，不闭环就抛错（见下） |
| `eval_rule(registry, ...)` | 规则**真求值**（件9） |

### 口径（写进库，后续每批照此执行）

```
{
  "status": "gone",
  "since": "20260924-1100",
  "rule": "台账有效 key 与源侧全量 key 清单（all_records 口径、不带视图筛选）做差集 → 差集内落 gone",
  "assertion": "gone + 在库 + excluded + retracted == 该表历史键全集；且 源侧清单 == 在库 + excluded",
  "reasons": [
    "source_record_removed",
    "parent_gone"
  ],
  "placement": "gone 的资源文件移出库目录到 kb/l0/_archive/gone-<run_id>/（保留不删除，与 retracted 同款处置）",
  "note": "gone ≠ retracted：retracted 是口径排除（不该在库），gone 是源侧删除（曾经在库、现在没了）"
}
```

### 断言结果

| 恒等式 | 左值 | 右值 | 差额 | 结果 |
|---|---|---|---|---|
| A：gone + 在库 + excluded + retracted == 该表历史键全集 | 643 （202 + 441 + 0 + 0） | 643 | **0** | ✅ 通过 |
| B：源侧清单数 == 在库 + excluded | 441 | 441 | **0** | ✅ 通过 |

> **字面口径说明**：任务写的字面式是 `gone + 在库 + excluded == 源侧清单数`。按字面只有当「源侧清单数」读作**该表历史键全集**（源侧本轮清单 ∪ 台账历史 key）时才成立，即 identity_A；若把「源侧清单数」读作**本轮源侧实读清单**，成立的式子是 identity_B（源侧清单 == 在库 + excluded），此时 gone 是「曾经在库、现已不在源侧」的部分，不参与分母。两个式子差额都为 0。

另外，`detect_gone` 的反向差集（源侧有、台账无 → 必须登记）本批为：记录 201 条、附件 240 条 —— 正是件5 要登记的量，两条链路互为印证，**没有静默丢**。
