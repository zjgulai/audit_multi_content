四、降级与事故留痕

事故 1 · 第一遍盲测全批作废（cwd 泄漏，我方 harness 缺陷）
  • 现象：第一遍把每条用例的 cwd 放在 evals/work/<paper><round>/item-XXXX，被测会话从自身 cwd 用 ls .. 即可走到回填员侧产物， 38 个会话真读了 cases-a.json / cases-b.json（含「预期结果」列），另有 36 个只在目录列表里看见文件名。

  • 处置：全批作废，原件留 rounds-INVALID-cwdleak/ 与 work-INVALID/（留档可审，不参与任何计分）； rt.py 改为 cwd 落在评测产物树之外（/tmp/kbrecall-eval-cwd/<paper><round>/item-XXXX）； 会话归档定位改用 realpath（macOS 上 /tmp → /private/tmp，否则找不到会话目录）； 同题重跑（题面未改：被测会话收到的始终只有「提示词」列原文，第一遍泄漏的是会话自己翻到的文件）。 第二遍复扫：SEVERE 0 / MILD 0。本报告所有 A/B 卷数字一律取自第二遍。
降级 2 · 调用题的斜杠在 headless 一次性会话里未被宿主展开（环境限制，非 skill 缺陷）
  • 实测：headless 只接受 task... 位置参数（dsh --profile eval-l0 --help 无任何斜杠相关开关）， /kb-recall … 以字面文本落地：会话归档里该 user/message 的 text 就是 /kb-recall 召回…， 既无 skill 工具调用、也无 <skill_content name="kb-recall"> 注入。
