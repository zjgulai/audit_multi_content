## 必须知道的三件事（诚实披露）

1. **盲测做过三次，只有最后一次生效**。第一遍把每条用例的 cwd 放在评测产物树内，被测会话用 `ls ..` 就能翻到
   `cases-a.json`（含「预期结果」列）——38 个会话命中，**全批作废**。第二遍把 cwd 移到 `/tmp` 后仍有 7 个会话
   用 `grep -rl` 找到答案键、5 个读到评测脚本。于是对其中的会话做**第三次密封重跑**（运行期把整棵评测产物树
   `chmod 000`）。最终生效的 189 条记录复核：**答案键泄漏 0**；其中 3 条判定由「加载/触发」改回「未加载」——
   改动方向**对被测 skill 更不利**，没有做任何对我有利的替换。
2. **`--check-only` 是 exit 2（如实保留）**。它报「用例 42 的回复是摘要」；实为 checker 启发式命中了真实原文里的
   「关键内容摘要」四字。已用 `_eval/verify_verbatim.py` 对 **189/189 条回复**与会话归档逐字节比对，全部一致；
   按「禁止改写原文」优先，未改字，改用 `--allow-empty-replies` 生成并留痕。`--validate-only` 为 exit 0。
3. **调用题存在环境降级**。headless 一次性会话**不展开斜杠**（`/kb-recall` 以字面文本落地，无 `skill` 工具调用、
   无 skill 正文注入），故调用门槛改按「等效加载」判定并留痕（严格口径字段仍在 `rounds/*.jsonl` 里可复核）。
