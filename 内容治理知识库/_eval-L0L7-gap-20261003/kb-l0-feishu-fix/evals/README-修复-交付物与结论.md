   - **Output Quality 被 flaky 封顶在 15**：flaky 8 条 → −10（上限）。flaky 主要来自**边界题的

## 三、本轮必须留痕的三条异常（都不掩盖）

### 3.1 ★★ 测试台接线缺陷（会造成「假分数」）

- **现象**：第一版复测线落盘的 15 条记录 `reply=""`、`session_id=null`、`skills_loaded=[]`，
  而模型其实答了（正文落在被截断的 `stdout_tail` 里）。
- **根因**：`session_dir_for()` 用 `os.path.abspath(cwd)` 拼会话目录名，而 macOS 上 `/tmp`
  是 `/private/tmp` 的软链接 ⇒ 算出 `--tmp-…`、真实目录是 `--private-tmp-…` ⇒ 永远读不到会话。
  **若拿去评分，全部用例都会被判「不触发」，P/R/F1 全是假的。**
- **修法**：改 `os.path.realpath`；**找不到会话即抛 `SessionMissing` 中止**（fail loud）；
  `reply` 只从 `session.jsonl` 逐字取完整 assistant 文本，`raw_stdout/raw_stderr` 另存旁路字段
  **不顶替** `reply`；补齐 `session_found/session_id/session_dir/skills_loaded/skill_tool_calls/reply_chars`。
- **留痕**：坏数据整批作废 → `_harness/_broken-wiring-20261004/`（3 个 jsonl + `WHY.md`），**不进任何评分**。
- **复测线第二次中断**：首轮用 `nohup` 起的 runner 随 turn 结束被终止（轮次文件 mtime 停在 08:10–08:13）
  → 改用**受管后台任务** `bash run_all_a.sh`（单 job 内含 6 分片）。

### 3.2 ★★ 保真度事实：盲测沙箱只读且提权无审批通道 ⇒ fail-closed

被测会话自述（逐字，可回源核对）：

> 「本会话文件沙箱为**只读**，且升级审批无通道，官方脚本 `align_l0_feishu.py` 因要写快照/报告而
> **跑不起来**（`PermissionError: Operation not permitted: 'kb'`）。我改用**只读等价路径**：
> `lark-cli base +record-list --format json` 流式拉取 + 内存比对……」

即：本 skill 的**写档阶段（阶段 3/4/5 的 `--apply`）在盲测里跑不动**，被测模型改走只读等价路径。
**触发判定不受影响**（路由看 description 与加载证据），但它影响「回复里有多少数字是现场跑出来的」。

### 3.3 输出前闸门的一次 checker 误报（与源版同一坑，照先例修）

- `build-final-report.py` 的自检把 `<td>` 单元格里的子串 **`nan`** 当非法数据 —— 而用例 67 的提示词
  含 `tenant_access_token`（**te·nan·t**）。
- **源版先例**：`_harness/test-cases.before-nanfix.html` 显示上一批踩过同一坑，
  修法是把该单元格里的 `app_secret` / `tenant_access_token` 包成 `<code>`（**仅呈现层，+26 字符**）。
- **本轮照同一先例、同一粒度**处理：只改**触发误报的那 1 个 `<td>`**（+26 字符），
  **AI 回复正文与提示词文字一字未动**。（首遍我误做成全文档批量包裹 +988 字符，已回退重做。）
