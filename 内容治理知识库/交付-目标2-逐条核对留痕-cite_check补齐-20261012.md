## 一、结论：**123 / 123 补齐**（三格）

| 格 | 改前 | **改后** |
|---|---|---|
| `cite_check.anchor` | 0 / 123 | **123 / 123** |
| `cite_check.source_sha256` | 0 / 123 | **123 / 123** |
| **顶层 `anchor`** | 0 / 123 | **123 / 123** |

**为什么是同一个形状**：又是「**数据在库里，只是没搬**」—— 同一行的 `evidence_units[0]` 里
`anchor`（`#l.1-1`）/ `seg_anchor`（`#l.1-1/seg-8`）/ `source_sha256` **三样全都有**，
只是没投进 `cite_check`。与 P0 条款号那次（`p0_patterns` 11/11 无号、L4 映射里全有）**同一个病**。

## 二、为什么**可以**机械投影（前提先证，不假设）

实测：**123 条每条恰好 1 个 `evidence_unit`**（分布 `{1: 123}`），且 123/123 都带 anchor 与 sha
⇒ **取哪个零歧义**。这是本件敢用脚本而不是逐条人判的唯一理由。

## 三、★ 措辞红线：写的是「**坐标与指纹**」，不是「**通过**」

AGENTS.md 逐字：「sha 的措辞红线：只能写「**与 L0 记录值比对一致**」，**不许**写「重算通过」——
L0 的 sha 输入是 `record_fields` 这个字段 blob，本地 L0 件**不含**该 blob ⇒ **重算在本地结构上不可能**。」

⇒ 落成三格，**逐条写在数据里**：

```json
"verify_mode": "local_projection",
"verify_note": "★ 值逐字取自同一行 evidence_units[0]，不是回源重算 …… 要真核对须点 L0 飞书直链。",
"projected_from": "evidence_units[0]"
```

**本件给的是「原文在哪、指纹是多少」**（xlsx 逐字要的正是这两样），**不是**「这条我已经核过了」。
