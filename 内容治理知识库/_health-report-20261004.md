### 等级口径（我第一版写错过，此处更正）

`kern.memorystatus_vm_pressure_level` 是**动态变化**的枚举，不是静态状态码。本机内核自己暴露的三个阈值给出了权威映射：

```
kern.memorystatus_purge_on_warning:   2
kern.memorystatus_purge_on_urgent:    5
kern.memorystatus_purge_on_critical:  8
```

→ **2 = warning、5 = urgent、8 = critical**（1 = normal）。

**实测**：采集期间读到 **2（warning）**，约 1 分钟后已回落到 **1（normal）**。

**更正说明**：我第一版把 2 写成「macOS 认定的 critical」，**这是错的** —— 2 是 warning 档，尚未到 critical。虽然不该写错，但更正后的结论方向不变：因为**真正硬的事实是「交换 94.7% 打满 + pageins 6,325 页/秒」**，那两条与压力等级无关，本身就足以支撑「内存是本次最差项」。压力等级是动态的、会自己回落，不适合当作唯一判据。

### 已确认事实：实测换页仍在进行

20 秒窗口实测（`vm_stat` 差值）：

- **pageouts +1542 / 20s**（约 **77 页/秒**，仍在往外写）
- swapouts +0 / 20s
- **pageins +126,508 / 20s**（约 **6,325 页/秒 ≈ 103 MB/s** 在读回）

### 合理推测

**当前的主要矛盾是 I/O 排队，不是 CPU 空转。** 依据：空闲 CPU 实测有 0.5%–30%，但 load 稳定在 11–15；同时 pageins 高达 6,325 页/秒而 swapouts 已为 0 —— 说明内存已顶到交换上限、不再往外压，但缺页读回仍在高频发生，进程在等 I/O。

**推翻条件**：若 pageins 降到个位数/秒而 load 仍维持 13+，则主因要重新归到 CPU/进程 churn。

**这个量级已影响可用性**：compressor 5.5 GB + wired 11.2 GB = 16.7 GB 被锁死，真正能弹性使用的只剩约 7 GB，却要装下 Chrome（16 进程 682 MB）、Lark（14 进程 643 MB）、DSH（17 进程 2.74 GB）、Kaspersky（3.4 GB）等一大堆常驻程序。

### 个人观点

重启是最直接的缓解手段（清掉 5.5 GB 压缩器和 8.7 GB 交换），但**这是治症状**：只要开机后仍同时跑「Kaspersky 实时监控 + 3 个 DSH 实例 + 评测 harness + Chrome/Lark」，一天内会回到同样状态。治本要从下面「跑飞的进程」入手。

## 6. 本次体检的边界（哪些我没能验证）

诚实标注，避免这份报告被当成比它实际更权威的东西：

1. **kavd 到底在干什么——未验证**。非 root 读不到其 fd 与 syscall，无法区分「正在全盘扫描」与「空转」。报告里只说「持续占半个核」这个事实，未对它下「异常」的结论。
2. **写入量未逐进程归因**。386 GB/天是磁盘层累计值，我推测主因是 harness + 浏览器，**没有用 I/O 追踪逐进程证实**（`fs_usage` 受权限限制且超时）。
3. **瞬时 %CPU 波动极大**（kavd 在 91%–284% 之间跳），所以单次采样不可信；报告结论基于「累计 CPU ÷ 运行时长」与多次采样，不基于任一单点。
4. **内存压力等级是动态的，不是静态结论**。采集时 `kern.memorystatus_vm_pressure_level=2 (warning)`，约 1 分钟后回落 `1 (normal)`。**我第一版误把 2 当成 critical，已更正**（权威映射来自内核自身的 `purge_on_warning=2 / urgent=5 / critical=8`）。这条提醒：单次读到的压力等级不能当定论，所以我改用「交换余量 + pageins 速率」这两个不会自己跳动的量作为主判据。同时说明：即便当时是 warning 而非 critical，也不代表负载轻 —— 30 秒窗口内 swapouts 增量为 0，说明系统当时**已经停止向交换区换出**（没地方换了），而 pageins 仍高达 6,325 页/秒。
5. **`ps` 的 `time` 字段是 MM:SS 不是 HH:MM**。我第一版算错过（把 3414:45 当成 3414 小时），已修正为 56.92 小时。若你复核数字，请按 MM:SS 解析。
