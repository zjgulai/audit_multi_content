## 二、前缀怎么定（`W-` / `S-` / `E-` / `P-` / `X-`）

**前缀 = 库前缀**，取自这条素材的 **`kb_type`（属于哪个库）**，
**不取自 `form`，也不取自文件名**。

| 前缀 | `kb_type`（库） | 库标签 | 目录 |
|---|---|---|---|
| `E` | `external_standard` | 1_外部标准库 | `1_外部标准库` |
| `S` | `internal_sample` | 2_内部正负样本库 | `2_内部正负样本库` |
| `W` | `wording` | 3_措辞表达库 | `3_措辞表达库` |
| `P` | `product_desc` | 4_产品描述库 | `4_产品描述库` |
| `X` | `unknown` | 9_未归类 | `9_未归类`（**不得分配**） |

**前缀 ↔ 形态不是一一对应** —— 实测反例：

- `kb/l4/canonical/sample_case.jsonl` 一个文件里**同时**挂着两个前缀：
  `W-3.*`（157 条，`kb_type=wording`）与 `S-1.*`（201 条，`kb_type=internal_sample`）。
  **同载体文件、不同库、不同前缀** —— 所以按文件名猜前缀一定错。
- `SKILL.md §2` 写「`C-` = scoped_clause」与实测不符：`scoped_clause` 用的是 **`E-`**（`kb_type=external_standard`）。
  `kb/l4/canonical/*.jsonl` 里**不存在任何 `C-` 号**。

## 五、给新一批规则排号：操作口径

1. **定库** —— 看这条素材的 `kb_type` → 决定前缀 `E`/`S`/`W`/`P`。
   是 `unknown` 的**先归类再编号**，不许发 `X-`。
2. **定段** —— 看 `form`，按 `block_by_library` 找段：
   - 形态**已有**（如又是一条 `wording_entry`）→ 进已发段**续号**，取该段 `next_seq`；
   - 形态**是新的**（如首次产出 `wording_boundary`）→ 用对应 `reserved_unused` 段，**从 `.1` 起发**。
3. **定次序** —— 段内按**内容派生的稳定不可变 id 升序**：
   `wording_entry` / `wording_revision_pair` → `rule_id`；
   `sample_case_*` → `case_id`；`scoped_clause` → `clause_id`。
   **不用** `support_count` / 风险等级 / 时间 / 文件行序 —— 否则规则一增删，已发号就错位。
4. **不复用** —— 重跑时已在册的 id **沿用原号**；新规则取该段 `next_seq`；
   **规则后来消失，它的号也不回收、不再发给别的规则**。
