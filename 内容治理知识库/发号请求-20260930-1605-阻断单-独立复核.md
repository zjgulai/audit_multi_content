## 5. 附带（也是本次新查）：现在强行发号会**撞号**

```
canonical 四形态文件     1242 个号（W-1 56 · W-2 453 · W-3 157 · S-1 201 · E-1 375），唯一 1242
台账 numbering.issued    仅 2 段：W-1(56) + W-2(453) = **509** 个号
canonical 有号而台账查不到 = **733**（W-3:157 · E-1:375 · S-1:201）
台账有号而 canonical 查不到 = 0
```

- `l4_article.py` 是**覆盖式写 `l4.json`** 的脚本，只认它看得见的段。
- 谁按现台账跑一次 `--apply`，引擎会认为 `E-1 / S-1 / W-3` 三段**从未发过号**，
  从 `next_seq=1` 重发 → 新号与 canonical 里**已在用的同号正面相撞**。
- 即「号不复用」这条红线**在当前状态下已经守不住**。
- 属**记账缺口**，`l4_gate.py` C1–C6 **不查这一项**（所以闸门是绿的）。
- 交 `kb-check` 立检查项 / `kb-repair` 处置，**不属本次授权**。

**另**：`order_key = kb_type（库）→ 形态段 → rule_id（字典序）`，**不是文件行序** ——
"取最后一行 +1" 也会撞号（实测末行 `r-14056187c2923e38` 的号是 `W-2.36`，首行 `r-37b49eadb72d7dc2` 是 `W-1.18`）。
