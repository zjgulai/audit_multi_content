## 2. ★★ 核心设计：**两态拆成三态**（本项此前正是栽在这个读法上）

```
not_wired       台账/口径件/写入器 缺一        → no_data（原因「机制未接」）
wired_no_input  已接线、但**没人判过**         → no_data（原因「等首批人工复核」）★ 当前在这里
measured        有人判过                      → 数量 = 事件条数（按 target_layer 分组）
```

**为什么 `wired_no_input` 不能报 `measured: 0`**：
「没人判」与「有人判了、且全都与机器一致」是**两件事**。后者是**合法读数**（真的没有纠错），
前者不是 —— 报 0 就会退回本项要消灭的那个错读法：「核过了，没有回流」。

判界 = `kb/l7/reports/audit-sample-ALL.csv` 与金标集里**「机器结论 + 人判」都非空**的行数。
实测：**100 行已就绪，列「人判」0/100 空** ⇒ `wired_no_input`。

## 3. 计数口径（口径真源在 `return-flow.yaml`，此处只摘）

- **算事件**：人工判定 ≠ 机器结论，**且**人工给了明确三态（PASS/REVIEW/BLOCK）
- **不算事件**：① 机人一致（无纠错信息）② 人判 `NEEDS_INPUT`（**无纠错依据** —— 把「不知道」当成「知道它错了」）
- **算事件**：机器 `NEEDS_INPUT` 而人给了明确三态（机器判不了、人判了 ⇒ 最该回流的一类）
- **落层**：机器放行∧人拦 ⇒ **L1-L2**（漏放 ⇒ 缺负样本）；机器拦∧人放 ⇒ **L3**（误报 ⇒ 规则过严）

## 4. ★ 红线（**「我构造」的题带来的独有风险**）

| 红线 | 判据 | 为什么 |

| `source == 我构造` ⇒ `applies_to=count_only` | 代码级 | 构造题测准确率没问题，但拿它改规则权重会**把规则朝不存在的素材上调**（过拟合虚构样本） |
