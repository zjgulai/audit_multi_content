## 二、★★ 拒绝理由是**写死的假诊断**（代码级证据）

`kb/l3/rejected.jsonl` 里这 3 条的理由逐字是：

> `条款文本不可判定：非自然语言条款（页面脚本 / base64 编码载荷），无法给出判定条件与阈值`

**但正文是标准中文自然语言。** 追到代码，`kb/l8/l3_distill_run.py:426-443`
——**「外部标准库」整段就是这些**：

```python
# ============================================================ 外部标准库
ext_rec = collections.defaultdict(lambda: collections.defaultdict(list))
for u in kept:
    if u["kb_type"] == "external_standard":
        ext_rec[u["resource_id"]][u["unit_type"]].append(u)
for rid, grp in sorted(ext_rec.items()):
    cl = grp.get("clause", [])
    if not cl:
        ... rejected.append({"kind": "no_clause_text", "reason": "未产出可用条款文本（正文为页面脚本或编码载荷）…"})
        continue
    for u in cl:
        ... rejected.append({"kind": "clause_not_actionable",
                             "reason": "条款文本不可判定：非自然语言条款（页面脚本 / base64 编码载荷），无法给出判定条件与阈值"})
```

**这段里没有任何检测** —— 没有 CJK 占比、没有 base64 特征、没有脚本标签判断。
**凡是 `external_standard` 的 `clause` 单元，一律拿到这条理由。**
⇒ 它是**占位符**，但**读起来像诊断**。

## 五、我的推荐（带代价）

**推荐 ①：分两步实现「外部标准蒸馏路径」——先修假理由，再补路径。**

**第 1 步（小、必要、安全）：把假诊断换成真原因。**
- 做法：在写 `clause_not_actionable` 之前**先真检测**（CJK 占比 / base64 特征 / 脚本标签）；
  检测不过 ⇒ 才写「非自然语言条款」；检测通过但本层无路径 ⇒ 写**真原因**
  「**外部标准 clause 单元尚未实现蒸馏路径（本层 stub）** —— 不是源料问题」。
- 为什么必须先做：这条假理由**正在骗人**（工单已被骗一次）。不修，后面每个读台账的人都会
  把 2709 条真条款当成垃圾，永远不会回头碰它们。
- 代价：改 `kb/l8/l3_distill_run.py`；**但改完要重跑 L3 才生效**，而重跑会**覆盖写**
  `candidates/{rules,sample_cases,scoped_clauses}.jsonl` 与 `rejected.jsonl`
  ⇒ 按 `kb-clause-extractor` 红线①，**跑前必须先把 `rejected.jsonl` 归档并校验 sha256**。

**第 2 步（真做「抽成规则」）：把 `clause` 单元蒸成规则。**
- **形态建议：复用已有的 `scoped_clause`**（L4 已有该形态 **375 条**、已占段位 **E-1**）
  ⇒ **不必新开 form** ⇒ **不牵动 L4 的发号分段**（这是最大的成本差异）。
  ⑧ 的条目（"婴儿睡姿为仰卧，不可趴睡"）本质就是「**适用范围受限的断言**」，与该形态同构。
- **代价 / 前提**：
  1. **L3 是另一会话今天在动的车道**（15:23 写过 `rules.jsonl` / `l3.json`）⇒ 重跑前**要等它停**；
  2. 要过 `l3_gate.py`（证据逐条回指）与 A3「只追加：既有候选行逐字节未变」；
  3. **E-1 段现在装的是 ⑥ 那 375 条元数据**（"郭嘉"那种）—— 把 ⑧ 的真条款放进同一段，
     是"段位复用"还是"要先清掉垃圾"，**这是口径问题，要人裁**（我不自决）；
  4. ⑧ 是"常识清单"形态，**蒸不出来的条目要如实进拒绝台账**，不许硬凑。

**次选 ②：只做第 1 步（修假理由），第 2 步另开一批。**
- 代价：⑧ 这一批仍出不了规则，但它让**全部 7 条外部标准材料**的真相第一次可见。

**不推荐 ③：跳过修理由、直接写蒸馏路径。**
- 那样会在**一条假的诊断**上盖新逻辑，下一个读台账的人仍然被误导；且无法证明"新路径真的覆盖了那 2709 条"。
