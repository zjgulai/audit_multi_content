## 一、机制依据（代码级，非推测）

宿主实现 `@deepseek-ai/dsh-tool-skill/lib/index.js`：

```js
:18   const DEFAULT_CATALOG_DESCRIPTION_MAX_LENGTH = 500;
:27   catalogDescriptionMaxLength: z.number().default(DEFAULT_CATALOG_DESCRIPTION_MAX_LENGTH)
:338  const normalized = value.replaceAll(/\s+/g, " ").trim();
      return normalized.length <= maxLength ? normalized : `${normalized.slice(0, maxLength - 3)}...`;
```

⇒ **skill 目录里每条 description 的生效面 = 折叠空白后的前 500 字**（可见区实为 **497** 字，末尾补 `...`）。
**>497 的部分对路由模型完全不可见。** 规范上限 1024 只管「能否通过校验」，不管「模型见不见得到」。

⇒ 本表口径：先 `" ".join(desc.split())` 折叠，再按 497 判可见。审计脚本 `tools/audit_description_visibility.py`
（规则单元**由脚本按 `、；。` 机械切分**，不手写清单，避免只挑对自己有利的规则）。

## 五、结论与动手顺序（供第 6/7 步用）

1. **6 件的首要动作 = 把判归句前移进 497 字可见区**（不是先压正文长度）。
   优先级按超窗量排：`kb-recall` > `kb-canonical-lookup` > `kb-p0-check` > `kb-media-extractor` > `kb-check` > `kb-clause-extractor`。
2. **kb-ingest-extractor 单独处理**：改 `不适用（各自点名）` → 判归句；顺带把自身名字纳入可见区。
3. **kb-recall 额外一条**：`--apply` 安全句（pos=556）被切，属**安全维度**，优先级等同判归句。
4. 压缩手法参照 L0 的成功做法（v1.3.0：触发词 12→11、邻居改极简 `→kb-xxx`，折叠后 **499**，27 条规则全可见）——
   **先删冗余、再改极简箭头式判归**，**不要删触发词**（L0 v1.2.5 的教训：删触发词把正例变成 FN）。
5. ⚠️ **不改正文长度**这件事本轮不作为主杠杆：正文超限只值 Progressive 13→15（2 分），
   而判归句可见性直接对应 Trigger（最多 25 分档）与 FP。
