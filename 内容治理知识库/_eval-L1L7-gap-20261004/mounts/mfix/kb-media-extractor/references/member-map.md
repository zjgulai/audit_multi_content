# 与其他成员的关系 ＋ 删除边界

> 读这份文件的时机（见 SKILL.md §8）：需要判断「这件事归谁」「删了会不会伤到别人」时。

## 一、成员关系

| 关系 | 成员 | 说明 |
|---|---|---|
| 上游 | `kb-l0-feishu` | L0 字节与对账；**它不跑下游**，本 skill 自己按幂等键收敛 |
| 下游 | `kb-ingest-extractor` | L1 内容 → 知识单元 |
| 只读查询 | `kb-recall` | 召回单元（不重建索引） |
| 编排 | `kb-pipeline` | 整链按 `layers.yaml` 拓扑序跑（本 skill 是 L1 的 owner） |
| 体检 / 修复 | `kb-check` / `kb-repair` | 闸门红了的定位与修复 |

## 二、删除边界（什么能删、什么绝不能删）

| 对象 | 能不能删 | 为什么 |
|---|---|---|
| `kb/l1/media/_cache/*.json` | ❌ **不得删** | 它是 l1_gate 的**校验对象**；删了闸门失去判据，且**不可逆**（要重跑走幂等键收敛，不是删库重来） |
| `kb/l1/media/**` 工作副本 | ⚠️ 只能经 `--purge-images` 且有预演 | 它清的是**工作副本**，**不是 L0 原图**；不带预演就跑 = 越界 |
| `kb/l0/**` 字节 | ❌ 本 skill **无权删** | 字节归 `kb-l0-feishu`；删它要走那条链 |
| `kb/l1/manifest_l1.jsonl` 的行 | ❌ 不得手删 | 下游按它算活跃集；行丢了 ⇒ 新记录永远抽不出来 |

## 三、一句话

**本 skill 的写入只落 L1 的 media 区与单元索引；L0 的字节一个都不碰。**
