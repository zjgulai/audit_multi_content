## 裁定 ③ 的处置：track_a 长度判据改不改

**用户问：算不算改判定口径？**

- **定性**：严格说**算**（它改的是 `root-skills-eval` 的打分器，改后所有历史报告与基线不再可比）。
- **更准确的定性**：track_a 该维度名叫"description **触发质量**"，而 1024 是**规范上限**、不是**触发相关量**；
  真正决定触发的是折叠后 500 字窗口。拿 1024 评触发质量 = **给一个不影响触发的量打分** ⇒ 更贴近**机制缺陷**。
- **★ 用户裁定（2026-10-04）：不能改 `root-skills-eval`。** ⇒ 本项**关闭**，作为已裁定事项不再讨论；
  可见性审计的定位就此固定为「优化输入 + 报告 advisory」，**永不进 `composite_100`、永不当门禁**。
- **结论（本轮执行口径）**：**不改**。四条理由：
  1. 会摧毁可比性 —— 正要给 3 件从未评过的 skill 补基线，口径一动这些基线连同 L0 五轮记录全部作废；
  2. 机制已被 track B 抓住 —— 规则不可见 ⇒ 触发盲测必然表现为 FP/FN，track B 是路由的地面真值，
     track A 不必复述同一信号；
  3. 动机不可自证 —— 恰在需要分数上涨时改尺子，即使正当也无法与刷分区分；
  4. 诱惑极大 —— track_a 的 description 维度 25 分 × 权重 20/105，是最容易"不改进 skill 就制造分数"的地方。
- **落地**：可见性审计作为**优化输入 + 报告 advisory 字段**（**不进 composite_100、不当门禁**）；
  给家族立反馈单（代码级证据 `dsh-tool-skill/lib/index.js:18/27/338`），定性写"机制缺陷修正"，
  **下个口径版本连同全量重跑基线一起上**。
- **反方已记录**：若家族认定"触发质量维度本就该按生效窗口评"，则属 bug fix 而非口径变更 ——
  **但程序上仍须版本化，不能在本批中途改**。两条路结论相同。

1. `tools/prep_skill.py` 的 `PATCH_TMPL` 写死 `{mount}`；
2. `tools/run_a.py` 的自检 2 **要求** profile 里出现 `<mount>`（否则拒跑）；

#### 七·补 ★★ 隔离手法又踩两个坑（v2 / v3 初版），都以"整轮作废"为代价

**坑 1：改目录名 ≠ 移走。** v2 把装载位挪到 `~/.dsh/skills/<skill>.PARKED` —— **还在被扫描的根里面**。
加载器扫 `<root>/*/SKILL.md`，`.PARKED` 目录照样算一个 skill，而**条目名取自 frontmatter 的 `name`**

（反过来 media 那轮用同一手法却渲染到挂载位 —— 同一配置、两件结果不同，**说明同名冲突本身不确定**。）
⇒ 正确做法：**挪到一切被扫描的根之外**，如 `~/.dsh/_parked-skills/<skill>`。
被扫描的根：`<projectRoot>/.dsh/skills`(100) / `<projectRoot>/.agents/skills`(200) /
`customSkillDirs`(300) / `~/.dsh/skills`(400) / `~/.agents/skills`(500) / bundled。

**坑 2：未加花括号的 `$VAR` 紧跟多字节字符 ⇒ bash 当场崩。**
v2 挂在第 37 行 `$m`（后接中文）、v3 初版挂在第 64 行 `$PARKED`（后接中文 `）`），
报 `m�: unbound variable` / `PARKED�: unbound variable`。

⇒ **本仓库所有 shell 脚本里变量展开一律写 `${VAR}`**（v3 已全部改完并 `bash -n` 通过）。

⇒ 已改成 `desc_collapsed()` 缺文件返回 `None`；并新增**同名影子副本扫描**
