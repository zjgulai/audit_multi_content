# 知识库用到的 skills —— 打包说明

本目录是 **Momcozy 内容治理知识库所属 skill 成员**的打包件。它**不是源**，
是三个真实来源的快照集合 —— 谁权威见下表。改 skill 请改源，不要改这里。

打包时间：2026-10-16　｜　打包依据：`kb/l7/registry/skills.yaml`（登记表）

---

## 一、成员集怎么来的（不是数出来的，是登记表派生的）

口径：`skills.yaml` 里 `scope=本项目` **且** `status=生产`，剔除
`root-skills-*`（skill 评测家族，不是知识库成员）与 `lark-*`（宿主工具），
再把 `brand-*` 按 `routes.yaml → frozen_expectation.dir_name_map` 映射成中文安装目录名。

结果：**27 个成员**（14 个 `kb-*`/`brand-*` ＋ 13 个中文专项）。

> ⚠️ **一处对不上的地方，照实写在这里**：仓内 `AGENTS.md` 写的是
> 「26 个 skill（14 个 `kb-*`/`brand-*` ＋ **12** 个中文专项）」，而
> `routes.yaml` 的 `dir_name_map` 实测有 **13** 条映射。
> 本次按**登记表实测的 27 个**打包。这个出入**没有被我改掉** —— 改 `AGENTS.md`
> 是另一件事，需要 Owner 定哪个数才对。谁先碰到谁去核。

## 二、三处来源（同名不同物，别搞混）

| 目录 | 是什么 | 权威性 |
|---|---|---|
| `安装位-27个成员/` | `~/.dsh/skills/` 下的**实际安装副本**（27 个） | **运行时真正被加载的就是这份** |
| `库内源-l7skills/` | 库内 `kb/l7/skills/`（含 `-fix` 修复副本） | 其中 9 个是**安装位软链的真身**，即 kb 成员的权威源 |
| `登记源-中文专项-登记表所指/` | `~/Desktop/skill/内容治理中文skill/` | 13 个中文专项在 `skills.yaml` 里登记的 `source` |

### 一个实测发现（会影响你怎么看 `安装位-27个成员/`）

`~/.dsh/skills/` 下 **9 个 kb 成员是软链接**，指向库内 `kb/l7/skills/` 的同名目录：

```
kb-canonical-lookup, kb-check, kb-clause-extractor, kb-content-review,
kb-ingest-extractor, kb-l0-feishu, kb-media-extractor, kb-p0-check, kb-recall
  → 内容治理知识库/kb/l7/skills/<同名>
```

所以：**光把安装位目录塞进 git 是不够的** —— git 只会存一个指向库外的链接，
换台机器就是断链、等于包里没内容。本包里的 `安装位-27个成员/` 是
**解引用后的真内容**（`cp -RL`），可以独立自证：27 个都有 `SKILL.md`、无软链残留。

### 顺带记一条坑（下次别再踩）

安装位里有些 skill 的文件是**只读**（`r--r--r--` / `dr-xr-xr-x`）。
`rm -rf` 和 `cp` 覆盖都会被挡 ⇒ **重做本包前先 `chmod -R u+w`**。
我第一次重做时正是被它挡住，结果包变成新旧混合的脏状态，已清空重做。

## 三、内嵌 git 仓库怎么处置的（★ 差点静默丢内容）

实测发现**三处内嵌 git 仓库**，`git add` 时会被记成 **gitlink（mode 160000）**——
即**只存一个提交指针、内容一条都不进仓**。第一次推送就踩了：
`库内源-l7skills/` 与 `登记源-中文专项-登记表所指/` 推上去是**空的**。

三处（**都无 remote，历史只在本机**）：

| 位置 | 提交数 | 跟踪文件 |
|---|---|---|
| `kb/l7/skills/.git` | 6 | 110 |
| `skills-打包/库内源-l7skills/.git` | 6 | 110（同上，是副本） |
| `skills-打包/登记源-中文专项-登记表所指/.git` | 2 | 95 |

**处置**：内嵌历史**无损**打成 bundle 放在 `_内嵌仓库历史/`，
再把内嵌 `.git` 从**本仓内副本**移走 ⇒ 工作树内容变成正常文件、可被正常跟踪。

```bash
git clone _内嵌仓库历史/l7-skills.bundle /tmp/x     # 6 次提交、110 个文件
git clone _内嵌仓库历史/登记源-中文专项.bundle /tmp/y  # 2 次提交、95 个文件
```

两个 bundle 都已**实际克隆验证过**（不是"打包成功"就算）。源目录的 `.git` **一个字没动**。

> ★ 这是本仓第二次被同一类事咬：`.gitignore` 的 `skills/` 无前导斜杠会静默吞掉
> `kb/l7/skills/`（已锚定为 `/skills/`）。两次的形状一样 ——
> **git 不会报错，只会"少收"，而少收看起来和成功一模一样。**

## 四、本包**不含**什么

- 不含 `root-skills-*`（评测家族）与 `lark-*`（宿主工具）—— 它们不是知识库成员。
- 不含各 skill 的评测产物（`eval-reports/` 等由评测跑出来的机器产物，
  在 `库内源-l7skills/` 里也不做筛选，原样保留）。
