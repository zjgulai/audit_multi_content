# 路由表：L3 该接什么、该让位给谁

> 读取条件：用户问「这个该走谁」，或入口被显式点名到别的成员时读本文件。

## 一句话分界

**抽条款 = 把条款文本读成可判定的规则候选（L3）；切单元 = 把素材拆成可召回的单元（L1→L2）。**
前者要 `rule_id`，后者要 `unit_id`。问「我要 unit 还是要 rule」，答案就出来了。

## 让位表（沾到关键词但不归本层）

| 用户说法 | 归属 | 为什么不归 L3 |
|---|---|---|
| 抽条款 / 条款级单元 / 规则蒸馏 / 规则候选 / 拒绝台账 / 蒸馏漏了没 | **本 skill** | — |
| 素材切成单元、补切、重切、L1 抽取、L2 切分 | `kb-ingest-extractor` | L3 吃的是已切好的单元，不负责切分 |
| 图片 / 视频 / 附件 OCR、字幕、关键帧 | `kb-media-extractor` | 媒体转文本是 L1 媒体，不是规则层 |
| 发号 / 定稿 / 晋升 canonical / 分配条款号 | `kb-pipeline`（L4，`--apply`） | 发号是写操作，且号永不复用 |
| 查条款号是多少 / 定稿了没有 / canonical 状态 | `kb-canonical-lookup` | 只读查询，不写库 |
| 是不是 P0 / 命中哪些 P0 模式 | `kb-p0-check` | L5 判定层 |
| 召回单元 / 查资料 / top-k | `kb-recall` | L6 召回层 |
| 跑 L0→L7、同步知识库、建索引 | `kb-pipeline` | 整链编排 |
| 全库体检、闸门过没过 | `kb-check` | 只报不改 |
| 闸门没过要修 | `kb-repair` | 以一条已红闸门为输入 |
| 依据是什么 / 条款号 / 逐字摘录 / source_sha256 | `kb-content-review` | 评审链依据组件 |
| 这段内容能不能发（三态结论） | `kb-review` | 评审链入口 |
| 数 L3 目录 / 行数清点 | 只读清点 | 清点不是抽取，也不是蒸馏 |
| 抽取准确率评测 / 打分 / 优先修复队列 | `kb-check` | 评的是流程质量，不是产出条款 |
| 周报 / 汇报材料 / PDF 制作 / 飞书推送 / 目录树整理 / 嵌入聚类 | 各自归属 | 本层不出这类产物 |

## 入口被点名到别的成员时

用户打了 `/kb-ingest-extractor`、`/kb-pipeline` 这类斜杠，但诉求内容是 L3 的活：

1. **不抢入口**：先按被点名成员的层别回答该成员能做什么；
2. **说明串层**：一句话讲清「你点的是 A 层，你要的动作在 B 层」；
3. **写明交接点**：确属 L3 时说明由谁接管、交接需要什么（源文本 / `resource_id` / `RUN`）；
4. 用户在明确知道层别后仍要 L3，才接管。

## 顺序协作（L1→L2→L3→L4）

裸文本进不了 L3。最小前置链：

```
源文本 → L0 落源（resource_id + 版本 + 指纹）
      → L1 单元 → L2 切分（产出 unit_id + anchor + source_sha256）
      → L3 抽条款 + 蒸馏（本 skill）
      → L4 发号定稿（kb-pipeline --apply）
      → L5 P0 / L6 索引
```

缺 L2 单元时蒸馏会空转 —— 此时先说要补 `kb-ingest-extractor` 的切分，**不要**硬跑一轮。
