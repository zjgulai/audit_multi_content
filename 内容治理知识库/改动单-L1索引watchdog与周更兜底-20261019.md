# 改动单 · L1 索引 watchdog 与周更兜底（2026-10-19）

**状态**：**已执行（2026-10-19，Owner 会话同意；A+B+C 一轮）**。
**背景**：10-19 的 L1 索引告警暴露三件事，且它们叠在一起会互相掩盖：

- **A** ③c 是 agent 任务书里的一步；周更停在 L0 时它不会执行（这次就是）。
- **B** `L1_INDEX_STALE_H` 仍是 25h（按日更写的），周更后即使健康也会天天报。
- **C** `check_weekly_run_ran()` 被巡检自己的 `daily_health` 记录喂饱 ⇒ 永远绿；且它只要求「任意一层跑过」，L0 单独跑过也算「这一轮跑成了」⇒ 10-18 停在 L0 没被它报。

## A. 把 ③c 变成驱动里的确定性 shell 步

**文件**：`kb/l8/daily_via_skill.sh`
**位置**：agent 结束 + `observe_layers.py --land` 之后、`daily_digest.py` 之前（约 line 145–157 之间）。
**代码草案**（与现有步骤同风格：DRY 跳过、失败只喊不改退出码、写 LOG）：

```bash
# ③c L1 索引重建（确定性执行；不依赖 agent 记得，也不受「停在 L0」影响）
if [ "$DRY" = "1" ]; then
  log "⏭ 只读预演（DRY=1）⇒ 跳过 L1 索引重建"
else
  if python3 kb/l1/index/rebuild_l1_index.py --write --run "$BASE" >>"$LOG" 2>&1; then
    _l1chk=$(python3 kb/l1/index/rebuild_l1_index.py --check 2>&1); _l1rc=$?
    printf '%s\n' "$_l1chk" | tail -4 | tee -a "$LOG"
    if [ "$_l1rc" = "0" ]; then
      log "   ✅ L1 索引：重建 + --check [OK]"
    else
      log "   ❌ L1_INDEX=FAIL（--check rc=$_l1rc）—— 见上面的 [OK]/DRIFT"
    fi
  else
    log "   ❌ L1_INDEX=WRITE_FAIL"
  fi
fi
```

**同时**：`kb/l8/daily_via_skill.md` 的 ③c（line 65–81）从「agent 必做」改成「驱动已做；agent 只需核对日志里的 `L1 索引` 行」；若保留 agent 步骤，须写明「驱动做过后，agent 的 ③c 只做 `--check`」，避免双跑。
**理由**：这次不是「agent 忘了」，是「闸门红即停」按规程停在 L0；把 ③c 留在 agent 里，任何一次早停都会再跳过它。
**代价**：驱动每周多一次重建（16102 行，秒级；纯投影，内容不变时零行差）；失败只记 `L1_INDEX=FAIL`，不改变日更退出码（与 observe/digest/P0/git 同档），由 watchdog 兜底。
**不取回滚备份的理由**：索引是**纯投影**（源真相在 `kb/l1/` 的批次资源与台账），重建可从源再生成；每次跑备份 4MB 会累积无价值副本。真要留底，`--write` 前 `cp` 到 `kb/l7/_backups/l1-index-auto-<ts>/` 即可，属可选。

## B. 把 L1 索引 watchdog 的阈值对齐周更

- docstring（line 1029–1043）：把「阈值 25h = 一个日更周期 + 1h」「重建一天一次」改成「8 天 = 一个周更周期 + 1 天；重建在周更收尾由驱动执行」。
- 告警标题（line 2300）：「**日更的** ③c」→「**周更的** ③c」；`fix` 文案（line 1065–1069）：「若连着两天」→「若连着**两轮周更**」。
- 自证（⑭a–f，line 1502–1510）：把 26h → 8 天+1h；6 天样本仍 False；保留「阈值可传」⑭f。
- 若想更精确：可改成「索引 mtime ≥ 最近一个排期时刻 + 宽限」的判据（复用 `last_due()`），但周更跑批窗口（03:30–04:30）会误报，需加 grace；**推荐先做 8 天 + A**，把「这轮跑没跑」交给 C 的周更门。

**理由**：阈值是「一个周期 + 余量」的口径；周期从 1 天变 7 天，阈值必须跟着变，否则健康状态也天天红。
**代价**：改的是判据，必须重跑 `--selftest`（⑭a–f 会变）并更新注释；8 天后才红意味着「③c 真没跑」的发现变慢——由 C 的周更门在 12h 内兜。

## C. 修周更兜底：不被只读体检喂饱，且要求「整轮」跑成

**文件**：`kb/l8/watch_review_readiness.py`（`check_weekly_run_ran`，line 633–691）＋ `kb/l7/scripts/layer_freshness.py`（`_latest_run_record`，line 189–215）

**C1. 排除只读体检记录**：`_latest_run_record` 现在把 `kb/l7/runs/` 里所有 `.json` 按 mtime 取最新；`daily_health` 每 ~30 分钟写一条 `source="daily_health"` 的记录（巡检自己的新鲜度检查会调 `freshness.py` → `daily_health.py`）⇒ L7 的 `run_at` 永远新鲜。**改法**：`_latest_run_record` 跳过 `source == "daily_health"`（只读体检不是层运行）；L7 的 `run_at` 回落到 sidecar 的 `executed_at` 或真实的 L7 运行记录。反向对照：在临时 KB 里放一条 `daily_health` 记录 ⇒ 不得算「跑过」。

**C2. 要求整轮（L1–L7）都跑成**：`check_weekly_run_ran` 现在取 `newest = max(per_layer.values())`，只要有**任意一层**在窗口内跑成就 True —— 10-18 只有 L0 跑过，它照样绿。**改法**：遍历**必跑集**（建议 `L1..L7`；L0 可因令牌/流程跳过，不进必跑集），要求每层都有 `run_at >= due - WEEKLY_COVER_H` 且 `change_state ∈ {produced_changes, no_new_input}`；缺哪层就报哪层（新增 `missing_layers`），`fix` 仍给 kickstart。反向对照：真造「只有 L0 跑过」的样本 ⇒ 必须 False（这正是 10-18 的形状）。

**C3. 让自证可注入**：`check_weekly_run_ran()` 目前只收 `now` / `path`，没有 `kb_root`，自证只能拿真库当输入。现成的 ㉓h 就是**时间炸弹**：它把时间推到 10-26、断言「真库最近一次跑成在 10-16」；10-24 之后真库的 `daily_health` 记录会让它由 False 变 True，自证会自己变红。**改法**：加 `kb_root=KB_DIR` 参数；自证用临时 KB 造三态（全跑成 / 只 L0 跑成 / 全没跑成），不再依赖真库。反向对照：删掉 C1/C2 的过滤器 ⇒ 对应用例精确变红。

**理由**：兜底要问的是「这一轮**整条链**跑成了没有」；现在是「有没有任何人在此刻前跑过任何一层」，而且这个「跑过」可以被巡检自己的只读体检满足。
**代价**：动两处判据（L7 的 run_at 来源 + 周更门语义），影响面比 A/B 大；必须单独立项，跑 `--selftest` 全量 + `workflow_smoke.py` + `check_agents_md_drift.py`，并补 ㉓j/㉓k 反向对照。**不许**由日更或本次修复顺手改。
