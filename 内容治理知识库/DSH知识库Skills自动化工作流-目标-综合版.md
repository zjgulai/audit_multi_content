## 一、目标陈述

**把 DSH 本机的内容治理知识库（L0–L7 全链），从"每层能跑、但没人串起来"改造成一条 skills 驱动的自动化工作流：**

> 入口一句话「这个评审一下」→ 供给链把库跑到最新可用 → 评审链按需消费库产出 → 出一份带证据链的三态评审报告。

关键词是**接通，不是重搭**：层 skill、引擎、闸门都已存在，目标是让它们**被真正调用、逐层递进、并留下可核的证据**。

---

## 二、目标的五个要素

| 要素 | 内容 |
|---|---|
| **谁跑** | **skills**。L0–L7 每层由该层绑定的 skill 承接（`kb-l0-feishu` → `kb-ingest-extractor`(L1/L2) → `kb-clause-extractor` → `kb-canonical-lookup` → `kb-p0-check` → `kb-recall` → `kb-check`），全链由 `kb-pipeline` 编排；评审面由 `kb-review` 家族承接。 |
| **输入** | 一句自然语言 + 待审内容（原型：「这个评审一下」）。 |
| **过程** | 两段：**供给链**（L0→L7 逐层，先查后建）→ **评审链**（按模态与命中分派 2–6 个成员）。逐层"都碰"是硬要求，但**在线只走查询档**，重建走离线写档且必须人开闸。 |
| **输出** | **kb-content-review 格式的评审报告**：三态结论（PASS / REVIEW / BLOCK）+ 六要素依据（库名+版本 / 条款号 / 锚点 / source_sha256 / 逐字摘录 / 出处在哪），落盘留痕。 |
| **可复跑** | 跑通的路径要固化下来（路由 + skill 文本 + 验收判据），换个人、换一天能原样重跑，而不是一次性演示。 |

## 三、完成定义（DoD）—— 什么算"跑通"

**这四条是我替你拟的验收线，需要你确认或改。**

| # | 验收条件 | 为什么是它 |
|---|---|---|
| **D1** | **同一个 RUN 内**，L0–L7 每层都留下落章（`kb/<层>/runs/<RUN>*.json`），且 `skill_invocation_audit` 的 E2 判绿 | 现在"每层都调了 skills"这句话**没有任何证据**：`skills` 字段是调用方自报，结构上不可能为假 |
| **D2** | 一句「这个评审一下」→ **40–60 秒内**出报告 | 慢于此说明走成了写档重建，不是在线链路 |
| **D3** | 结论**可核**：依据要素齐；库覆盖不到时**拒答**而不是硬给结论 | 这是"评审"能被人信的前提 |
| **D4** | 供给链不再红：L0 闸门绿 + 数据不陈旧 | 库不新鲜时出的结论不诚实（`freshness.py` 会退 3 拒答） |
| **D5** | 可复跑：同样的输入再来一次，结果与留痕一致，无需重新摸索 | 区分"跑通过一次"和"有一条工作流" |

## 四、优先级顺序（按你的排序，不是我的）

1. **skills 本身**——有哪些已安装 / 哪些真可用 / 哪些要新建。这是主要矛盾。
2. **供给链跑通**——先把 L0→L7 的数据供给做成稳定可复跑的。
3. **评审链接上**——它是消费面，数据依赖供给链，所以排在后面。
4. **接守衡（飞书侧机器人）**——最终消费端，明确推后。

质量先于串联：先把每层 skill 的质量提上来（参照 `root-skills-creator` 的标准），再谈怎么串。

---

## 五、边界（明确不做）

- **不做绣花**：数据不齐、数据优化都属于后期，不能挡跑通。
- **暂不接守衡**，也不为它改知识库结构。
- **不重搭**：不推翻现有分层、引擎与闸门，只做接通与补齐。
- **不越写档红线**：写权威库必须人开闸；修复一律在副本、不写回源。

## 七、两处必须你拍板的地方（综合时暴露出来的分歧）

**① 「每层都是 skills 执行」有两种读法，只能选一种：**

- **读法 A（务实版）**：每层由该层 skill 声明的**引擎**执行，且**agent 逐层真的加载该 skill**、留下落章。→ 不动执行主体，代价小，D1 可达成。**我建议 A。**
- **读法 B（字面版）**：每层 skill 由 agent **实际执行**，执行主体从 Python 脚本换成 agent。→ 工作量大、风险高，且 L4/L5/L6 的 skill 是只读的，加载了也不产生写。

**② 目标是否包含"无人在环"？**
你 9-30 问过"自动化（无人在环、由调度触发 skill）"的状态是"没有"。但你给的原型是"**我输入**：这个评审一下"（人在环）。
→ 我按**第一阶段 = 人在环一句话**来综合，**无人在环定时调度列为第二阶段**。若你要一步到位，目标和 DoD 都要重写。
